MAIN-U1-C02 — Intelligent Agents

Book: AI & Machine Learning — Complete Visual & Mathematical Textbook
Part: Unit I — Artificial Intelligence
Chapter ID: AI-I-02
Prerequisites: MAIN-U1-C01 — What Is Artificial Intelligence?
Course connection: Unit I — Introduction to Artificial Intelligence
Primary course source: lecture-intelligent-agents.pdf (Philipp Koehn, Artificial Intelligence: Intelligent Agents, 5 February 2026)
Learning level: Beginner → conceptual mastery → exam-ready

0. What you should be able to do after this chapter

By the end of this chapter, you should be able to:

  • explain what an agent is in plain English and in formal terms;
  • explain the relationship between an agent and its environment;
  • distinguish sensor, percept, percept sequence, effector, and action;
  • explain the agent function
\[ f:P^*\rightarrow A \]

and understand what each symbol means; - explain rationality without confusing it with perfection, omniscience, or guaranteed success; - identify and design a suitable performance measure; - understand autonomy, reactivity, proactivity, and interaction with other agents; - classify environments using properties such as accessible/inaccessible, deterministic/nondeterministic, episodic/sequential, static/dynamic, discrete/continuous, and the presence of intelligent adversaries; - explain the major agent types in the supplied lecture: table-driven, simple reflex, memory-based, goal-based, and utility-based agents; - understand why internal state, goals, and utility become necessary as environments become more complicated; - work through the vacuum-cleaner world and self-driving-car examples; - identify where the course material ends and where a universal extension begins; - connect intelligent agents to the search algorithms studied in the next chapters.

1. First question: what is an agent?

Before learning the formal definition, imagine a few ordinary things:

  • A person crossing a road.
  • A thermostat controlling a room.
  • A robot vacuum cleaning a floor.
  • A navigation system choosing a route.
  • A software assistant reacting to a user's request.

All of them have a common pattern:

Something exists in some world, receives information about that world, and does something in response.

That “something” is the agent.

👨‍🏫 Hinglish intuition
Socho agent ko ek aise worker ki tarah jo duniya ko directly nahi, balki apne **sensors ke through** samajhta hai. Jo information usse milti hai uske basis par woh action leta hai. > **Dekho → samjho → decide karo → action lo.** This cycle is the heart of intelligent-agent thinking.

2. The agent–environment loop

2.1 The most important diagram in this chapter

flowchart LR
    E[Environment] -->|Percepts / observations| S[Sensors]
    S --> A[Agent]
    A -->|Actions| F[Effectors / Actuators]
    F --> E

How to read the diagram

There are four main pieces:

Environment
The world in which the agent operates.

Sensors
The mechanisms through which the agent receives information.

Agent
The decision-making system.

Effectors / actuators
The mechanisms through which the agent changes or interacts with the environment.

The supplied lecture uses the same basic agent–environment idea and describes the agent function as a mapping from percept histories to actions. [lecture-intelligent-agents.pdf, slides 1–2]

👨‍🏫 Teacher explanation — English
The agent does not normally have magical access to the entire world. It receives **percepts**, processes them using its internal mechanism, and produces **actions**. Those actions may change the environment, which then changes what the agent perceives next. This creates a loop:
\[ \text{Environment} \rightarrow \text{Percept} \rightarrow \text{Agent decision} \rightarrow \text{Action} \rightarrow \text{Environment changes} \rightarrow \cdots \]
👨‍🏫 Teacher explanation — Hinglish
Agent ek room ke andar baitha hua insaan samjho. Uske paas camera, microphone ya temperature sensor ho sakta hai. Woh room ko directly “dekh” nahi raha; sensors se information aa rahi hai. Phir agent decide karta hai ki kya karna hai. Action ke baad room ki state badal sakti hai, aur next moment sensors ko different information mil sakti hai.

3. Agent kya dekhta hai? — Percepts

A percept is the information an agent receives from the environment through its sensors at a particular point in time.

The lecture uses examples such as a person's visual/audio/touch information and gives a vacuum cleaner percept such as:

\[ [A,\ Dirty] \]

meaning, in that simplified world, the agent is at location A and the location contains dirt.

Important distinction

Do not confuse these three:

Term Meaning
Sensor The mechanism that collects information
Percept The information received
Percept sequence The history of percepts received so far

Example: human

Sensor: eyes
Percept: “There is a red car in front of me.”
Percept sequence: what you have seen over the last several moments.

The lecture notes that percepts can be described at different levels of abstraction: at a lower level they may be raw sensor signals; after preprocessing they can represent objects, locations, textures, colors, auditory features, and so on. [lecture-intelligent-agents.pdf, slide 7]

👨‍🏫 Hinglish
Sensor **dekhne/sunne/measure karne ka instrument** hai. Percept **jo information mili** woh hai. Aur percept sequence matlab **ab tak jo information mili uska history**.

4. Agent kya karta hai? — Actions

An action is what the agent does through its effectors/actuators.

Examples from the supplied material:

  • move left;
  • move right;
  • suck dirt;
  • steer;
  • accelerate;
  • brake;
  • speak/display.

Sensor vs effector

Receives information Produces action
Sensor Effector / actuator
Camera Motor
Microphone Wheel steering system
GPS Brake system
Temperature sensor Heater control
👨‍🏫 Hinglish
**Sensor = input side** **Effector = output/action side** Ek simple memory trick: > **Sensor se information IN. Effector se action OUT.**

5. The formal agent function

The lecture gives the agent function as:

\[ f:P^*\rightarrow A \]

This looks intimidating initially, but it is simple once every symbol is decoded.

5.1 What is \(P\)?

\(P\) represents the set of possible percepts.

For a tiny vacuum world, percepts might include:

\[ [A,Clean],\quad [A,Dirty],\quad [B,Clean],\quad [B,Dirty] \]

5.2 What is \(P^*\)?

The superscript * here means a sequence of percepts of arbitrary finite length, including the possibility of a sequence with no percepts yet.

So instead of looking at only the current percept, the function can conceptually take the entire percept history.

5.3 What is \(A\)?

\(A\) is the set of possible actions.

For the vacuum world:

\[ A=\{Left,Right,Suck,NoOp\} \]

5.4 What is the function saying?

The equation:

\[ f:P^*\rightarrow A \]

means:

Given a percept sequence, the agent function specifies which action should be taken.

👨‍🏫 Hinglish
Simple language mein: > **Jo information ab tak mili hai → uske basis par kya action lena hai.**

6. Vacuum Cleaner World — your first complete agent example

The vacuum world is one of the most important teaching examples in the supplied lecture.

6.1 The simplified world

Imagine two locations:

+-----------+-----------+
|     A     |     B     |
|  🧹       |           |
|           |   dirt    |
+-----------+-----------+

The agent can be in either A or B.

Each square can be:

  • clean;
  • dirty.

The agent has possible actions:

\[ Left, Right, Suck, NoOp \]

The course notes explicitly give percepts such as [A, Dirty] and actions Left, Right, Suck and NoOp. [lecture-intelligent-agents.pdf, slides 2–3]

6.2 A simple reflex behaviour

Suppose the current percept is:

\[ [A,Dirty] \]

The obvious action is:

\[ Suck \]

Suppose the percept is:

\[ [A,Clean] \]

Then the simple table/program in the lecture chooses:

\[ Right \]

Likewise:

\[ [B,Clean]\rightarrow Left \]
\[ [B,Dirty]\rightarrow Suck \]

This is the idea of mapping perception to action.

7. Percept → decision → action

Let's slow this down.

Suppose:

Agent at A
Room A = Dirty

The sensor detects dirt.

Stage 1 — Perception

\[ P_t=[A,Dirty] \]

Stage 2 — Agent processing

The program asks:

“What should I do when I am at A and it is dirty?”

Stage 3 — Action

\[ A_t=Suck \]

Stage 4 — Environment changes

The square becomes clean.

Stage 5 — Next percept

The next percept may be:

\[ [A,Clean] \]

The cycle continues.

The mental model

perceive
Environment ---------> Agent
     ^                  |
     |                  |
     +------ action <---+

8. What makes an agent “intelligent”?

A common beginner misunderstanding is:

“If something reacts, it must be intelligent.”

Not necessarily.

A system can have a fixed reaction rule without having sophisticated intelligence.

The supplied lecture defines an intelligent agent as one that perceives its environment via sensors and acts rationally upon that environment with its effectors. [lecture-intelligent-agents.pdf, slide 6]

So an important word is:

Rationally

That leads to the central idea of this chapter.

9. Rationality

9.1 What does rational mean here?

The lecture describes a rational agent as one that chooses the action expected to maximize its performance measure based on the information available so far and its available knowledge.

In simplified form:

\[ \text{Choose the action with the highest expected performance.} \]

This is not the same as:

  • always being correct;
  • knowing everything;
  • always succeeding;
  • predicting the future perfectly.

The supplied lecture explicitly separates rationality from omniscience and clairvoyance and notes that a rational agent is not necessarily successful because its percepts may be incomplete and action outcomes may be uncertain. [lecture-intelligent-agents.pdf, slides 4 and 9]

9.2 Rational ≠ omniscient

Omniscient means knowing everything that is relevant, including the eventual consequences of actions.

Real agents usually do not have that knowledge.

Example

You leave home carrying an umbrella because the weather looks uncertain.

You later discover that it never rained.

Was taking the umbrella irrational?

Not necessarily.

You acted using the information available at decision time.

👨‍🏫 Hinglish
Rational agent ka matlab future dekhne wala agent nahi hai. > **Us time jo information available thi, uske basis par best reasonable decision lena = rationality.**

10. Performance measure — how do we decide whether an action is good?

An agent needs a way to judge how well it is accomplishing its task.

That is the performance measure.

The lecture gives examples such as:

  • false-alarm rate;
  • false-dismissal rate;
  • speed;
  • resources required;
  • environmental impact.

[lecture-intelligent-agents.pdf, slide 9]

Why this matters

Suppose two navigation agents reach the same destination.

Agent A: takes 30 minutes and uses more fuel.
Agent B: takes 35 minutes but uses far less fuel.

Which one is better?

There is no answer until we define what “better” means.

If our performance measure is only:

minimize travel time

Agent A may be preferred.

If it is:

minimize fuel while safely reaching the destination

Agent B may be preferred.

Core lesson

Rationality is always relative to a performance measure.

11. Performance measure is not the same as the agent's internal goal statement

Do not mix these ideas.

A designer may describe a desired task in words:

“Clean the room.”

But a measurable performance criterion could be:

“Keep every square clean for as many time steps as possible while minimizing unnecessary movement.”

The second is measurable.

That makes it useful for evaluating behaviour.

👨‍🏫 Hinglish
Goal ko sentence mein bolna easy hai. Performance measure ko **measure kar paana** zaroori hai.

12. A deeper view of rational action

The lecture's idealized rational-agent idea can be represented conceptually as:

Current percept history
        +
Built-in knowledge
        +
Acquired knowledge
        ↓
Possible actions
        ↓
Expected outcomes
        ↓
Performance measure
        ↓
Choose action with greatest expected value

This explains why rationality involves information gathering as well.

The lecture explicitly notes that rationality is not “rational ignorance”: if information can materially improve a decision, an agent may need to seek that information. [lecture-intelligent-agents.pdf, slide 9]

13. Properties of an agent

The supplied lecture identifies several useful properties.

13.1 Discrete agent

A discrete agent receives percepts and produces actions in discrete steps.

13.2 Reactive

It responds to what is happening in the environment.

13.3 Proactive / goal-directed

It can act because it wants to reach some future desirable state, not merely because of a current stimulus.

13.4 Autonomous

Its behaviour is determined by its own experience rather than being completely dictated by a designer.

The lecture explicitly defines autonomy in terms of the agent using its own experience and notes that surviving agents need enough built-in knowledge plus the ability to learn. [lecture-intelligent-agents.pdf, slides 10–11]

👨‍🏫 Hinglish mental model
- **Reactive:** “Jo abhi hua uska response do.” - **Proactive:** “Aage kya hoga, socho aur plan karo.” - **Autonomous:** “Har baar designer ka instruction wait mat karo; experience se khud decide karo.”

14. Agent types — why different agents exist

A major theme of the lecture is that different environments require different agent designs.

The supplied lecture includes:

  1. Table-driven agents
  2. Simple reflex agents
  3. Agents with memory
  4. Goal-based agents
  5. Utility-based agents

The important question is not only:

“What are their definitions?”

but:

“Why do we need increasingly sophisticated agent architectures?”

The progression is roughly:

Fixed lookup
   ↓
Current percept only
   ↓
Current percept + internal state
   ↓
State + goals + future reasoning
   ↓
State + utility + trade-offs

15. Table-driven agent

Idea

A table-driven agent stores a table that maps percept sequences to actions.

Conceptually:

Percept sequence Action
[A, Dirty] Suck
[A, Clean] Right
[B, Dirty] Suck
[B, Clean] Left

The supplied lecture describes this as using a percept-sequence/action table stored in memory and notes that it can require a very large lookup table. [lecture-intelligent-agents.pdf, slide 13]

Analogy

Imagine trying to prepare for every possible conversation by memorizing one response for every complete conversation history.

The table could become enormous.

👨‍🏫 Hinglish
Ye approach basically bolti hai: > “Jo situation ki exact history table mein mili, uska answer nikaal do.” Simple, but scalability is terrible.

16. Simple reflex agent

A simple reflex agent uses condition–action rules.

General structure:

IF condition
THEN action

Example:

IF dirt detected
THEN suck

The supplied lecture describes these agents as stateless: they do not retain memory of past world states. [lecture-intelligent-agents.pdf, slide 13]

Real-life analogy

A bathroom motion light:

IF motion detected
→ turn light ON

It reacts to the current condition.

Strength

Simple and fast.

Limitation

If the current percept does not contain enough information to decide correctly, the agent can fail.

17. Why memory is necessary

Imagine two different world situations produce the same current percept.

If the agent looks only at the present percept, it cannot tell them apart.

This is why the lecture introduces internal state.

The lecture explains that sensors do not usually reveal the complete world state at every instant, so an agent can encode past percepts through an internal state. [lecture-intelligent-agents.pdf, slide 18]

Analogy: walking in a building

Suppose you enter a corridor and see exactly the same three doors you saw earlier.

Your current visual input may look similar.

But your memory of:

“I already checked the left door.”

changes what you should do next.

👨‍🏫 Hinglish
Current camera frame same ho sakta hai, lekin **history different** ho sakti hai. Isliye memory agent ko context deti hai.

18. Agent with memory / internal state

Conceptually:

Current percept
      +
Previous internal state
      ↓
New internal state
      ↓
Action

A useful abstraction is:

\[ state_t = UPDATE(state_{t-1},\ percept_t) \]

This equation is a universal explanatory abstraction, not a verbatim course equation. Its purpose is to show the role of memory.

Important idea

An agent's internal state is a compact representation of relevant history.

It does not necessarily store every raw percept forever.

19. Goal-based agent

Sometimes knowing what the world currently looks like is not enough.

The agent also needs to know:

What state am I trying to reach?

The supplied lecture defines a goal as a description of a desirable situation and describes goal-based agents as considering future events and possible action sequences. [lecture-intelligent-agents.pdf, slide 21]

Example

Navigation agent:

Current state:

At Delhi

Goal:

Reach Jaipur

There may be many possible actions. The goal tells the agent what counts as success.

Why this changes the architecture

A reflex agent can say:

“Road is blocked → turn right.”

A goal-based agent asks:

“Which sequence of actions eventually gets me to Jaipur?”

That question leads directly into search algorithms.

Important bridge

Goal-based reasoning is one of the reasons Unit I moves from agents into search.

20. Utility-based agent

A goal can be too coarse when multiple successful outcomes exist.

Suppose a car has three possible routes:

  • fastest but expensive;
  • slower but safer;
  • moderate time and moderate cost.

A binary goal such as:

“Reach destination.”

cannot distinguish among these successful outcomes.

A utility function gives a numerical measure of desirability.

The supplied lecture writes:

\[ U:State\rightarrow\mathbb{R} \]

and describes utility as a measure of success/happiness associated with a state. It notes that utility-based decision-making supports trade-offs between conflicting goals and between the probability and importance of outcomes. [lecture-intelligent-agents.pdf, slide 23]

Interpretation

\[ U(state)=\text{how desirable that state is} \]
👨‍🏫 Hinglish
Goal bolta hai: > “Mujhe destination tak pahunchna hai.” Utility poochta hai: > “Destination tak **kaise** pahunchna sabse worthwhile hai?”

21. Goal vs utility

This distinction is extremely important for exams.

Goal-based Utility-based
Asks whether a desirable state is achieved Measures how desirable states are
Can be binary/satisficing Supports graded preferences
Good for “reach / don’t reach” Good for trade-offs
Does not by itself rank all successful states Can rank alternatives

Simple analogy

Suppose you are buying a laptop.

Goal: Buy a laptop that can run your software.

Many laptops satisfy this.

Utility: Among them, compare price, battery life, performance, weight and display quality.

Utility gives you a way to rank the alternatives.

22. Environment properties

Agent design depends heavily on the environment.

The supplied lecture classifies environments by several properties:

  1. Accessible vs inaccessible
  2. Deterministic vs nondeterministic
  3. Episodic vs sequential
  4. Static vs dynamic
  5. Discrete vs continuous
  6. With or without intelligent adversaries

[lecture-intelligent-agents.pdf, slides 25–27]

We will learn these one by one.

23. Accessible vs inaccessible

Accessible

An environment is accessible when the agent's sensors provide access to the complete state information needed to choose an action.

Example

A small digital board where every relevant variable is visible.

Inaccessible

Some relevant information is hidden or unavailable to the sensors.

Example

Driving a car:

You cannot directly see:

  • around a building;
  • what another driver's hidden intention is;
  • everything behind you without sensors/mirrors/cameras.
👨‍🏫 Hinglish
**Accessible:** “Jo decision ke liye zaroori hai, woh information mujhe mil rahi hai.” **Inaccessible:** “Kuch important information hidden/missing hai.”

24. Deterministic vs nondeterministic

Deterministic

Given the current state and your action, the next state is fully determined.

Conceptually:

\[ (current\ state, action)\rightarrow one\ known\ next\ state \]

Nondeterministic

The same action may lead to different possible outcomes.

Example

You press a physical elevator button. You expect a particular response, but external events can interfere.

👨‍🏫 Hinglish
**Deterministic:** “Action karunga to result fixed hai.” **Nondeterministic:** “Same action se multiple possible results aa sakte hain.” The lecture notes that in an accessible and deterministic environment, the agent does not need to deal with the same kind of uncertainty associated with inaccessible/nondeterministic settings. [`lecture-intelligent-agents.pdf`, slide 25]

25. Episodic vs sequential

Episodic

Each episode is largely independent of previous episodes.

The action in one episode does not meaningfully affect the next episode.

Example

Classifying an isolated image.

Sequential

Current actions affect future situations.

Example

Driving a car.

Your steering decision now changes where the vehicle is one second later.

👨‍🏫 Hinglish
**Episodic:** “Ye problem khatam, next problem fresh.” **Sequential:** “Aaj jo action liya, uska effect agle step par padega.” Sequential environments therefore create a greater need for planning.

26. Static vs dynamic

Static

The environment does not change while the agent is thinking.

Dynamic

The environment may change while the agent is deciding.

Example

A printed Sudoku puzzle is essentially static while you think.

A road full of moving vehicles is dynamic.

Why this matters

In a dynamic world:

Thinking itself takes time, and the world can move while you think.

This is a crucial AI-system-design issue.

27. Discrete vs continuous

Discrete

There is a limited set of distinct percepts/actions/states relevant to the model.

Examples can include board-game positions or a small finite command set.

Continuous

Important variables can take values over a continuous range.

Examples:

  • speed;
  • steering angle;
  • temperature;
  • time;
  • physical position.
👨‍🏫 Hinglish
**Discrete:** “Countable separate choices.” **Continuous:** “Values smoothly change over a range.”

28. Intelligent adversaries

Some environments contain other agents that actively reason and try to improve their own outcomes.

In such environments, your agent cannot assume that the world is simply passive.

The supplied lecture specifically notes that intelligent adversaries introduce strategic/game-theoretic considerations. [lecture-intelligent-agents.pdf, slide 26]

Example

Chess.

Your opponent is not a wall or a tree.

They are also choosing actions.

That is why game playing becomes a separate AI topic later in Unit I.

   ↓

   ↓

33. Agent architecture summary

Agent type Main idea Memory? Future reasoning? Trade-offs?
Table-driven Lookup percept sequence in a table Stored table Not conceptually necessary No
Simple reflex Condition → action No internal state No No
Memory-based Maintain internal state Yes Limited/depends on design Not necessarily
Goal-based Choose actions to achieve goals Usually state Yes Limited compared with utility
Utility-based Rank outcomes with utility Usually state Yes Yes

Do not memorize the table blindly.

Understand why each additional capability exists.

35. Rationality in one example

Suppose a robot must clean a room.

Possible actions:

  • move to A;
  • move to B;
  • suck;
  • do nothing.

Suppose the robot currently senses:

\[ [B,Dirty] \]

A rational response is likely to be:

\[ Suck \]

But imagine the robot's battery is critically low and the performance measure heavily penalizes energy use.

Now the best action may be different.

This shows:

Rational action depends not only on the current percept, but also on the task, performance measure, knowledge and possible consequences.

36. Rationality is not “always choose the action that turned out best”

This is a classic conceptual trap.

Suppose action A had a high expected value based on the information available, but an unlikely event caused a poor result.

Calling the action irrational merely because the outcome was bad is incorrect.

The rationality question is:

Was the decision appropriate given the information and knowledge available when the action was chosen?

Not:

Did the action guarantee the best possible outcome?

37. Common beginner mistakes

⚠️ Mistake 1 — Agent = robot
False. The lecture explicitly includes humans, robots, softbots and thermostats as examples of agents. [`lecture-intelligent-agents.pdf`, slide 2]
⚠️ Mistake 2 — Sensor = percept
False. A sensor collects information; the percept is the information received.
⚠️ Mistake 3 — Rational = omniscient
False. A rational agent can lack complete information.
⚠️ Mistake 4 — Rational = guaranteed successful
False. The environment can be uncertain or partially observed.
⚠️ Mistake 5 — Goal and utility are identical
Not exactly. Goals identify desirable states; utility provides a graded measure of desirability.
⚠️ Mistake 6 — Memory means storing every past sensor reading
Not necessarily. The lecture's idea is an **internal state** that captures relevant history.
⚠️ Mistake 7 — Dynamic means nondeterministic
No. These are different dimensions. - **Dynamic:** environment changes over time. - **Nondeterministic:** action outcomes are not uniquely determined. An environment can be dynamic and deterministic, or dynamic and nondeterministic.

40. Answer key — compact

A1: An intelligent agent perceives its environment through sensors and acts rationally using effectors.
A2: Sensor = information-gathering mechanism; percept = information received.
A3: It maps a percept sequence to an action.
A4: Rationality uses available information; omniscience assumes complete knowledge.
A5: It defines how success is measured.
A6: Acting based on the agent's own experience rather than being completely controlled by the designer.
A7: Reflex uses current percept/rules; memory-based agents maintain internal state.
A8: Because actions are chosen partly for their effect on reaching a future desirable state.
A9: It lets the agent rank alternatives and trade off competing objectives.
A10: Deterministic → action uniquely determines the next state; nondeterministic → multiple outcomes may be possible.
A11: Episodic → episodes are independent; sequential → current actions affect future states.
A12: Static → world does not change while thinking; dynamic → it may change while thinking.
A13: Table-driven, simple reflex, memory-based, goal-based, utility-based.
A14: It has incomplete information, uncertainty, sequential decisions, dynamic changes, continuous variables and interactions with other agents.
A15: An intelligent opponent actively chooses responses, so the agent must consider strategic consequences.
