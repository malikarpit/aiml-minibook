MAIN-U1-C11 — Minimax & Alpha-Beta Pruning

Main Book chapter: Unit I — Artificial Intelligence
Topic ID: AI-U1-C11
Primary source: lecture-game-playing.pdf — Philipp Koehn, Artificial Intelligence: Game Playing, 17 February 2026
Prerequisites: MAIN-U1-C10 Game Playing, game trees, utility, MAX/MIN

1. Concept Identity

What problem are we solving?

We already know that game search contains an opponent.

The next question is:

How do I choose my move if I assume my opponent will also choose intelligently?

The answer for deterministic, perfect-information, two-player games is minimax.

Then comes the practical problem:

What if the game tree is so large that evaluating every branch is impossible?

The answer is alpha-beta pruning.

These two ideas should be learned together:

GAME
  ↓
GAME TREE
  ↓
MINIMAX
  ↓
Too many nodes
  ↓
ALPHA-BETA PRUNING
  ↓
Same decision, less unnecessary search

The supplied lecture explicitly introduces minimax for perfect play and then asks whether every path really needs to be explored, leading to alpha-beta pruning.

2. One-Minute Intuition

Imagine you are playing a game and you have three possible moves.

For each move, your opponent can respond.

You therefore do not judge a move by its best possible continuation.

You judge it by its best guaranteed outcome against the opponent's best response.

That is the minimax idea.

YOUR MOVE
                 │
       ┌─────────┼─────────┐
       A         B         C
       │         │         │
    Opponent   Opponent  Opponent
       │         │         │
   best reply  best reply best reply
       │         │         │
     value       value     value
       │         │         │
       └─────────┼─────────┘
                 ▼
          choose the MAX

Your opponent is not trying to help you reach your favourite branch.

They choose the branch that gives you the worst outcome.

So:

You maximize, assuming the opponent minimizes.

3. Teacher Explanation — English

Minimax assigns a value to each game state by recursively evaluating future possibilities.

At a MAX node, the player chooses the successor with the highest value.

At a MIN node, the opponent chooses the successor with the lowest value from MAX's perspective.

The values therefore propagate upward from terminal states:

Terminal utilities
        ↑
      MIN/MAX
        ↑
      MIN/MAX
        ↑
      MIN/MAX
        ↑
       Root

The value arriving at the root tells MAX which move is best assuming MIN plays optimally.

The supplied lecture describes minimax as choosing the move with the highest minimax value, defined as the best achievable payoff against best play.

4. Teacher Explanation — Hinglish

Socho tum game khel rahe ho.

Tumhare paas teen moves hain.

Ab tum har move ke liye sochoge:

“Agar opponent smart hai, toh woh mere against sabse dangerous reply kaunsa karega?”

Phir tum ye maanoge ki opponent wahi reply karega.

Uske baad tum compare karoge:

“In worst-case situations mein mere liye kaunsa move sabse better hai?”

Simple line:

“Main best choose karunga, opponent apna best karega — jo mere liye worst hoga.”

Isi liye naam hai:

MAX + MIN = MINIMAX

5. Formal Assumptions

Classical minimax is most straightforward for a game with:

  • two players;
  • deterministic transitions;
  • perfect information;
  • alternating turns;
  • terminal outcomes with utility values;
  • a zero-sum/opposing-objective interpretation.

The supplied lecture specifically describes minimax as the method for deterministic, perfect-information games.

If chance is added, we need expectiminimax.

If important information is hidden, a simple fully observed game tree is no longer enough.

6. Start With the Smallest Possible Example

Suppose MAX has one move, then MIN has one move.

MAX
                /         \
              A             B
            MIN           MIN
           /   \         /   \
          3     5       2     9

The leaf values are utilities from MAX's perspective.

Step 1 — Evaluate MIN nodes

At the left MIN node:

\[ \min(3,5)=3 \]

At the right MIN node:

\[ \min(2,9)=2 \]

So the tree becomes:

MAX
               /     \
              3       2

Step 2 — Evaluate MAX

\[ \max(3,2)=3 \]

Therefore MAX chooses A.

7. Why Did MIN Choose the Smaller Value?

Remember the viewpoint.

Leaf values are written from MAX's perspective.

So if MIN can force:

3 or 5

MIN chooses 3 because 3 is worse for MAX.

Similarly:

2 or 9

MIN chooses 2.

👨‍🏫 Hinglish
> “MIN ko MAX ka score kam se kam karna hai.”

8. The Minimax Recurrence

Let \(V(s)\) be the minimax value of state \(s\).

For a terminal state:

\[ \boxed{V(s)=U(s)} \]

where \(U(s)\) is the utility.

For a MAX state:

\[ \boxed{V(s)=\max_{a\in Actions(s)}V(Result(s,a))} \]

For a MIN state:

\[ \boxed{V(s)=\min_{a\in Actions(s)}V(Result(s,a))} \]

The mathematics is simple once the viewpoint is correct:

MAX takes max; MIN takes min.

9. Why Recursion Is Natural Here

A game state can lead to another game state, which leads to another game state.

So a state can be evaluated by asking the same question about its successors.

Evaluate this state
       ↓
Evaluate successor
       ↓
Evaluate successor's successor
       ↓
Eventually reach terminal state
       ↓
Propagate value backward

This is why minimax is naturally expressed recursively.

10. Utility Values

For a tiny game we can use:

\[ +1=\text{win} \]
\[ 0=\text{draw} \]
\[ -1=\text{loss} \]

But more complex games may use richer utility scales or an evaluation function.

The supplied lecture notes that exact numerical values can be transformed monotonically without changing deterministic game behaviour because only the order matters.

Beginner interpretation

If one position is ranked above another, the exact spacing between their scores may not matter for choosing between them.

11. A Larger Worked Example

Consider:

MAX
                ┌────────┴────────┐
                A                 B
                │                 │
               MIN               MIN
             /     \           /     \
            C       D         E       F
           / \     / \       / \     / \
          3   5   2   9     4   6   1   7

Evaluate C

\[ V(C)=\max(3,5)=5 \]

Evaluate D

\[ V(D)=\max(2,9)=9 \]

Evaluate MIN under A

\[ V(A)=\min(5,9)=5 \]

Evaluate E

\[ V(E)=\max(4,6)=6 \]

Evaluate F

\[ V(F)=\max(1,7)=7 \]

Evaluate MIN under B

\[ V(B)=\min(6,7)=6 \]

Root MAX

\[ V(root)=\max(5,6)=6 \]

Therefore MAX chooses B.

12. Visual Method — Write Values Bottom-Up

When solving a minimax numerical question on paper, use this method:

1. Write terminal utilities.
2. Move one level upward.
3. If it is MIN → choose smallest.
4. If it is MAX → choose largest.
5. Repeat until root.
6. Root value gives the minimax choice.

This should become automatic.

13. Minimax Algorithm — Conceptual Pseudocode

MINIMAX-VALUE(state):
    if state is terminal:
        return utility(state)

    if state is MAX:
        return maximum value of successor states

    if state is MIN:
        return minimum value of successor states

The important thing is not the syntax.

The logic is:

Recursively determine the value of all possible future responses, then apply MAX/MIN according to whose turn it is.

14. Completeness and Optimality

The supplied lecture gives:

Complete?

Yes, if the tree is finite.

Optimal?

Yes, against an optimal opponent.

Time

\[ \boxed{O(b^m)} \]

Space

\[ \boxed{O(bm)} \]

for depth-first exploration as described in the lecture.

where:

  • \(b\) = branching factor;
  • \(m\) = maximum depth searched.

15. The Main Problem: Exponential Growth

If each position has roughly \(b\) legal moves, then after \(m\) levels the number of leaves is roughly:

\[ b^m \]

For example, with:

\[ b=10,\quad m=6 \]

we already get around:

\[ 10^6=1,000,000 \]

leaf paths.

If we double the depth, the tree becomes vastly larger.

The lecture uses chess as the motivating example and notes that exact minimax over a realistic chess tree is infeasible.

So now we need to ask:

Do we really need every calculation?

16. Alpha-Beta Pruning — The Big Idea

Alpha-beta pruning removes branches that cannot possibly change the final minimax decision.

That means:

We skip work, not information that could affect the answer.

This distinction is essential.

MINIMAX
   ↓
Explore branch
   ↓
Obtain information
   ↓
Realise another branch cannot matter
   ↓
PRUNE IT

The supplied lecture explicitly describes alpha-beta pruning as safe and says pruning does not affect the final result.

17. Teacher Explanation — Alpha-Beta in English

Suppose MIN is choosing between two options.

You already know MIN has a way to obtain a value of 3 from one branch.

Now you start exploring another branch and discover that MAX can force that branch to be worth at least 5.

MIN already has a choice giving 3.

MIN will never choose the branch that is guaranteed to give MAX at least 5.

So there is no need to calculate the rest of that branch.

That remaining computation can be pruned.

18. Teacher Explanation — Hinglish

Socho MIN ke paas already ek option hai jisse MAX ko sirf 3 milta hai.

Ab doosre branch mein tum dekhte ho ki MAX ko minimum 5 milne wala hai.

MIN bolega:

“Mujhe 3 wala option mil raha hai. Main 5 kyun choose karunga?”

Toh doosre branch ka baaki calculation irrelevant ho gaya.

Bas wahi irrelevant part prune kar dena hai.

Alpha-beta ka kaam answer change karna nahi, useless calculation bachana hai.

19. What Are Alpha and Beta?

The supplied lecture gives the key definitions:

Alpha \(\alpha\)

The best value available to MAX so far on the current path.

Beta \(\beta\)

The corresponding best bound for MIN.

The central pruning idea is:

if a branch becomes worse than a value already guaranteed elsewhere, the opponent would never allow that branch to determine the final choice.

The lecture specifically states that if a value is worse than alpha for MAX, MAX will avoid it, allowing that branch to be pruned; beta is defined analogously for MIN.

20. Alpha-Beta Initial Values

At the root, we typically start with:

\[ \boxed{\alpha=-\infty} \]
\[ \boxed{\beta=+\infty} \]

Interpretation:

  • MAX has not yet found any useful lower guarantee;
  • MIN has not yet found any useful upper guarantee.

As the search proceeds, these bounds become tighter.

21. The Pruning Condition

A common operational form is:

\[ \boxed{\alpha\ge\beta \Rightarrow prune} \]

Why?

Because once the bounds cross, the current branch cannot improve the final decision.

Memory anchor

Alpha catches up with beta → stop searching this branch.

22. Full Alpha-Beta Example — Step 1

Consider:

MAX
                ┌────────┴────────┐
                A                 B
                │                 │
               MIN               MIN
             /     \           /     \
            3       5         2       9

Search A first.

At A's MIN node:

  • evaluate 3;
  • MIN now has a possible value of 3;
  • evaluate 5;
  • MIN keeps 3.

So:

\[ V(A)=3 \]

At the root:

\[ \alpha=3 \]

because MAX now knows it can guarantee at least 3 by choosing A.

23. Full Alpha-Beta Example — Step 2

Now explore B.

B is a MIN node.

Evaluate its first child:

\[ 2 \]

So MIN already has a way to make the value of B at most 2.

From MAX's point of view:

\[ \alpha=3 \]

and at B:

\[ \beta=2 \]

Now:

\[ \alpha\ge\beta \]

because:

\[ 3\ge2 \]

Therefore the remaining child with value 9 does not need to be explored.

Why?

Because MIN already has the option of choosing 2.

MIN would never choose 9 when trying to minimise MAX's result.

So we can prune 9.

24. Visualising the Pruning

Before pruning:

MAX
            /     \
          MIN      MIN
         /  \      /  \
        3    5    2    9

After alpha-beta discovers that 9 cannot matter:

MAX
            /     \
          MIN      MIN
         /  \      /  \
        3    5    2   ✂ 9

The important point is:

We did not discover that 9 has no value.

We discovered that its exact value cannot affect the decision.

25. Another Way to Think About the Same Prune

MAX already has:

\[ 3 \]

guaranteed.

MIN can force B to:

\[ \le2 \]

because MIN has already found a child worth 2.

Therefore B can never beat MAX's currently known option A.

The rest of B is irrelevant.

This is the key conceptual skill behind alpha-beta:

You do not need an exact value for a branch once you already have a proof that the branch cannot win the comparison.

26. Why Move Ordering Matters

Alpha-beta is most effective when good moves are explored early.

Suppose the best move is found quickly.

Then alpha becomes strong early and many later branches can be pruned.

Conversely, poor move ordering may delay useful bounds, reducing pruning.

The supplied lecture explicitly states:

Good move ordering improves pruning effectiveness.

The lecture further says that with perfect move ordering, the time complexity becomes approximately:

\[ \boxed{O(b^{m/2})} \]

which roughly doubles the depth that can be searched for the same exponential-scale effort.

27. Why “Same Answer” Matters

A pruning method is useful only if it is safe.

Alpha-beta does not say:

“I think this branch is probably bad.”

It says:

“Given the bounds already established, this branch cannot influence the root decision.”

Therefore the final minimax choice remains unchanged.

That is why alpha-beta is fundamentally different from risky forward pruning.

28. Forward Pruning vs Alpha-Beta

Property Alpha-Beta Forward Pruning
Removes branches Yes Yes
Uses proven bounds Yes Often heuristic judgement
Final minimax value preserved Yes Not guaranteed
Risk Safe under assumptions Can discard a move that later becomes good

The supplied game lecture makes exactly this distinction: alpha-beta is safe; forward pruning is risky because an initially inferior position may lead to a better later position.

29. Recursive Alpha-Beta Logic

Conceptually:

ALPHA-BETA(state, α, β):

    if terminal:
        return utility(state)

    if MAX:
        value = -∞
        for each child:
            value = max(value, ALPHA-BETA(child, α, β))
            α = max(α, value)
            if α ≥ β:
                break
        return value

    if MIN:
        value = +∞
        for each child:
            value = min(value, ALPHA-BETA(child, α, β))
            β = min(β, value)
            if α ≥ β:
                break
        return value

The exact programming syntax is secondary here.

Understand the information flow:

MAX → increases α
MIN → decreases β
α ≥ β → prune

30. Alpha and Beta — The Teacher Mental Model

Think of them as current guarantees.

Alpha

“MAX already knows I can get at least this much.”

Beta

“MIN already knows I can hold MAX to at most this much.”

When those guarantees cross:

MAX guarantee
      ≥
MIN guarantee

      ↓

This branch cannot change the result.

That is the cleanest mental model for remembering the pruning condition.

31. Resource-Limited Minimax

Real systems often cannot search to terminal states.

The supplied lecture's approach is:

Terminal test
    ↓
Cutoff test

Utility
    ↓
Evaluation function

So minimax becomes something like:

Game root
   ↓
Search to depth d
   ↓
Cutoff positions
   ↓
Evaluate positions
   ↓
Back up values using MIN/MAX

This is often called depth-limited minimax.

The evaluation function estimates desirability instead of exact terminal utility.

32. Evaluation Function Mathematics

The supplied lecture gives a weighted feature model for chess:

\[ \boxed{Eval(s)=w_1f_1(s)+w_2f_2(s)+\cdots+w_nf_n(s)} \]

For example, one feature may count the difference in the number of queens.

The idea is:

Game position
      ↓
Feature 1 ──× weight 1 ──┐
Feature 2 ──× weight 2 ──┤
Feature 3 ──× weight 3 ──┤
                         ▼
                  Evaluation score

Later in ML, this structure will look very familiar:

features × learned weights → output

33. Historical Practical Connection

The supplied lecture describes how evaluation weights can be learned from a database of played games:

Games
 ↓
Game positions
 ↓
Features
 ↓
Known result
 ↓
Learn useful weights
 ↓
Evaluation function

It also mentions self-play as another learning route.

This becomes a beautiful bridge to your Unit II/III material.

34. Minimax vs Alpha-Beta

Property Minimax Alpha-Beta
Decision principle MAX/MIN Same MAX/MIN
Searches all branches? In basic form, yes No, when safe pruning is possible
Final result Optimal under assumptions Same minimax result
Main advantage Conceptually straightforward Less computation
Worst-case asymptotic depth complexity \(O(b^m)\) \(O(b^m)\) worst case
Good move ordering Helpful Extremely important
Perfect ordering — About \(O(b^{m/2})\) in the lecture's idealised statement

The supplied lecture describes alpha-beta as safe and gives the idealised perfect-ordering complexity result.

35. A Critical Distinction: Complexity Is Not the Same as Runtime

Big-O notation describes how computation scales with the size of the search tree.

It does not tell you an exact runtime on a specific machine.

For game AI, actual performance also depends on:

  • move ordering;
  • pruning frequency;
  • implementation efficiency;
  • transposition handling in more advanced systems;
  • evaluation cost;
  • hardware.

For this chapter, focus first on the formal complexity given by the course.

36. Solved Games and Practical Search

A game is considered solved when an optimal strategy can be computed.

The lecture notes:

  • Tic-Tac-Toe is trivially solved;
  • Checkers was weakly solved in 2007 with a guaranteed draw under perfect play;
  • much larger games such as Chess and Go were historically too complex for complete exact solving.

This illustrates why game AI often combines:

Search
+
Pruning
+
Approximation
+
Stored knowledge
+
Learning

rather than relying on exhaustive search alone.

37. Alpha-Beta Through a Sports Analogy

Imagine you are selecting a team strategy.

You already know one strategy guarantees a reasonable result.

While analysing another strategy, you discover a response from the opponent that makes that strategy definitely worse than your current guaranteed option.

Do you need to analyse every later consequence of the discarded strategy?

No.

Once its best possible outcome cannot beat your current option, you can stop.

That is the intuition behind alpha-beta pruning.

38. Three Levels of Understanding

You should understand alpha-beta at three levels.

Level 1 — Intuition

“Stop evaluating a branch that cannot affect the final decision.”

Level 2 — Bound logic

Alpha and beta represent current guarantees; when \(\alpha\ge\beta\), prune.

Level 3 — Algorithmic execution

Update alpha at MAX, update beta at MIN, test the cutoff after child evaluation.

If you know only Level 1, you may understand the idea but fail a numerical question.

If you know only Level 3, you may memorise the algorithm but not understand why it works.

You need all three.

39. Common Mistakes

Mistake 1 — Mixing MAX and MIN

At a MAX node choose the largest child value.

At a MIN node choose the smallest child value.

Mistake 2 — Reading leaf values from MIN's perspective

Unless the problem explicitly defines otherwise, utilities are commonly written from MAX's perspective.

Mistake 3 — Pruning whenever a node “looks bad”

That's not alpha-beta.

There must be a bound-based reason the branch cannot affect the final choice.

Mistake 4 — Thinking alpha is always the root score

Alpha is a running bound associated with the current path.

It changes as the search progresses.

Mistake 5 — Forgetting that move ordering affects pruning

Same tree + different order can lead to very different amounts of pruning.

40. Worked Numerical — Alpha-Beta Trace

Consider:

MAX
               ┌──────┴──────┐
               A             B
             MIN           MIN
            /   \         /   \
           3     8       2     7

Explore A

At A:

\[ \beta=8 \]

then:

\[ \beta=\min(\infty,8)=8 \]

After seeing 3:

\[ \beta=3 \]

So:

\[ V(A)=3 \]

At root:

\[ \alpha=3 \]

Explore B

First leaf = 2.

So at B:

\[ \beta=2 \]

Now:

\[ \alpha=3\ge2=\beta \]

Therefore the leaf 7 is pruned.

Root still chooses A because:

\[ \max(3,2)=3 \]

The important thing is that we never needed to inspect 7.

41. Why the Pruned Value Can Be Anything

In the previous example, suppose the second leaf under B were:

\[ 1000 \]

instead of 7.

Would B become better for MAX?

No.

MIN already has the option 2.

So MIN will choose 2, not 1000.

Therefore the exact value of the second leaf is irrelevant.

It could be:

\[ 7, 100, 1000, 10^9 \]

and the root decision remains the same.

This is why pruning is logically safe.

42. The Most Important Alpha-Beta Insight

A branch can be computationally irrelevant before it is numerically fully evaluated.

This is a general AI idea:

intelligent computation is not only about computing values faster; it is about determining which values do not need to be computed at all.

The supplied lecture explicitly connects alpha-beta pruning to reasoning about which computations are relevant, calling it a form of metareasoning.

43. What Alpha-Beta Does NOT Do

Alpha-beta does not:

  • change the game rules;
  • change terminal utilities;
  • change MAX/MIN logic;
  • magically solve an infinite game tree;
  • guarantee dramatic pruning under every move order.

It only removes branches that cannot affect the current minimax result.

44. Connection to A*

Do not confuse:

\[ \alpha,\beta \]

with:

\[ g(n),h(n),f(n) \]

They belong to different mechanisms.

A*

Uses:

\[ f(n)=g(n)+h(n) \]

to guide path search.

Alpha-beta

Uses:

\[ \alpha,\beta \]

as bounds during adversarial game-tree evaluation.

Both are examples of avoiding unnecessary computation, but they do it for different reasons.

B. Alpha-Beta Numerical

Given:

MAX
                /     \
              MIN     MIN
             /  \     /  \
            5    9   3    X

Search left-to-right.

  1. What is alpha after the left MIN node?
  2. What is beta at the right MIN node after seeing 3?
  3. Is X pruned?
  4. What is the root value?

Answer

\[ \min(5,9)=5 \]

\[ \alpha=5 \]

Right MIN sees 3:

\[ \beta=3 \]

\[ 5\ge3 \]

Root value:

\[ \max(5,3)=5 \]

C. Conceptual Trap

Why is it possible to prune a node even when its exact numerical value is unknown?

Answer: because bounds already established elsewhere prove that the exact value cannot alter the final minimax choice.

48. Formula Card

Minimax terminal

\[ \boxed{V(s)=U(s)} \]

MAX

\[ \boxed{V(s)=\max_a V(Result(s,a))} \]

MIN

\[ \boxed{V(s)=\min_a V(Result(s,a))} \]

Alpha initial value

\[ \boxed{\alpha=-\infty} \]

Beta initial value

\[ \boxed{\beta=+\infty} \]

Pruning

\[ \boxed{\alpha\ge\beta \Rightarrow prune} \]

Basic minimax time

\[ \boxed{O(b^m)} \]

Basic minimax space in the course's depth-first framing

\[ \boxed{O(bm)} \]

Idealised alpha-beta time with perfect ordering

\[ \boxed{O(b^{m/2})} \]

The last result is the supplied lecture's idealised perfect-ordering case.

MINIMAX:

MAX chooses max.

MIN chooses min.

Values move from leaves to root.

ALPHA: MAX's best guarantee so far.

BETA: MIN's best guarantee so far.

ALPHA ≥ BETA: this branch cannot matter → prune.
