1. Why This Chapter Exists

In C30–C33, the network learned to compute a prediction and a loss.

We can now write the training problem as:

\[ \text{Choose parameters }\theta\text{ that make the loss small.} \]

But one question is still unanswered:

How do we actually change millions of parameters in a useful direction?

The central mechanism is gradient descent.

The complete training story becomes:

Parameters
   ↓
Forward pass
   ↓
Prediction
   ↓
Loss
   ↓
Gradient
   ↓
Which direction increases the loss?
   ↓
Move in the opposite direction
   ↓
New parameters
   ↓
Repeat

This is the bridge between a neural-network architecture and an actual learning procedure.

The supplied resource guide identifies prac_7_neural_network.ipynb as covering neuron parameters, activations, losses and gradient-descent concepts. It also maps calculus, gradients and gradient descent to the Unit III dependency chain. The supplied Lecture10 copy.pdf provides the broader regularized-optimization and learned-representation context. The detailed training equations in this chapter are a standard mathematical expansion used to make that concept self-contained.

2. One-Minute Intuition

English

Imagine standing on a foggy mountain and trying to reach the lowest point.

You cannot see the whole landscape. You can only determine the local slope around your feet.

If the slope points upward when you move north, you move south instead.

Repeat:

Look at local slope
       ↓
Move downhill
       ↓
Recalculate
       ↓
Move downhill again
       ↓
Eventually approach a low point

Gradient descent does exactly this in a parameter space.

The difference is that instead of your position being described by two physical coordinates, it may be described by thousands or millions of neural-network parameters.

Hinglish

Socho tum ek pahaad par ho aur tumhe sabse neeche wali jagah tak pahunchna hai, lekin fog ki wajah se poora mountain dikh nahi raha.

Tum local slope check karte ho.

Agar current direction mein height badh rahi hai, toh uske opposite jaoge.

ML mein:

Gradient batata hai loss kis direction mein sabse tez badh raha hai.

Isliye hum uske opposite direction mein move karte hain.

Gradient → uphill direction
Negative gradient → downhill direction

Bas isi idea ko parameters par repeatedly apply karna gradient descent hai.

3. The Optimization Problem

Suppose a neural network has parameters collected into one object:

\[ \theta. \]

Here \(\theta\) may contain:

  • weights;
  • biases;
  • and, depending on the model, other trainable parameters.

The training objective is:

\[ \boxed{ \theta^*=\arg\min_{\theta}J(\theta) } \]

where \(J(\theta)\) is the objective or loss over the training data.

For a dataset of \(n\) examples, a common empirical objective is:

\[ J(\theta)=\frac{1}{n}\sum_{i=1}^{n}\ell(f_\theta(x_i),y_i). \]

Terminology

Term Meaning
Parameter Quantity learned from data, such as a weight or bias
Objective / loss Quantity we try to minimize during training
Gradient Vector of partial derivatives with respect to parameters
Learning rate Step-size control in the update
Iteration / update One parameter-change step
Epoch One complete pass through the training set
Batch Set of training examples used to compute an update

4. Math You Need Now — Derivative First

Before gradients, understand the one-variable derivative.

For a function

\[ f(x), \]

the derivative

\[ f'(x) \]

describes local rate of change.

For example:

\[ f(x)=x^2 \]

has

\[ f'(x)=2x. \]

At \(x=3\):

\[ f'(3)=6. \]

So near \(x=3\), increasing \(x\) increases \(f(x)\).

At \(x=-3\):

\[ f'(-3)=-6. \]

So increasing \(x\) locally decreases \(f(x)\).

The sign matters

Derivative > 0 → increasing x increases f
Derivative < 0 → increasing x decreases f
Derivative = 0 → locally flat

That is the key idea gradient descent generalizes.

5. From Derivative to Gradient

A neural network has many parameters.

Suppose:

\[ \theta=(\theta_1,\theta_2,\ldots,\theta_p). \]

The loss is:

\[ J(\theta_1,\ldots,\theta_p). \]

We can ask:

  • how does the loss change when \(\theta_1\) changes?
  • how does it change when \(\theta_2\) changes?
  • and so on.

Collect those partial derivatives:

\[ \boxed{ \nabla_\theta J = \begin{bmatrix} \frac{\partial J}{\partial \theta_1}\\ \frac{\partial J}{\partial \theta_2}\\ \vdots\\ \frac{\partial J}{\partial \theta_p} \end{bmatrix} } \]

This is the gradient.

Interpretation

The gradient points in the direction of the steepest local increase of the function.

Therefore:

\[ -\nabla_\theta J \]

points in the local steepest-descent direction.

This is why the algorithm is called gradient descent.

6. The Core Update Equation

The central formula of this chapter is:

\[ \boxed{ \theta\leftarrow\theta-\eta\nabla_\theta J(\theta) } \]

where:

Symbol Meaning
\(\theta\) Current parameter vector
\(J(\theta)\) Current objective/loss
\(\nabla_\theta J\) Gradient of loss with respect to parameters
\(\eta\) Learning rate
\(-\eta\nabla_\theta J\) Parameter change

Formula reading

Read it as:

New parameter = old parameter − learning rate × gradient.

The minus sign is essential because the gradient points uphill.

7. Why the Minus Sign?

Suppose one parameter has gradient:

\[ \frac{\partial J}{\partial w}=+4. \]

That means increasing \(w\) locally increases the loss.

To reduce the loss, we should decrease \(w\).

Gradient descent does:

\[ w_{new}=w_{old}-\eta(4). \]

If \(\eta=0.1\):

\[ w_{new}=w_{old}-0.4. \]

Now suppose:

\[ \frac{\partial J}{\partial w}=-4. \]

Increasing \(w\) locally decreases the loss.

Then:

\[ w_{new}=w_{old}-0.1(-4) =w_{old}+0.4. \]

So the minus sign automatically makes the movement go downhill.

8. Visualizing One-Dimensional Gradient Descent

Consider:

\[ J(w)=(w-3)^2. \]

The minimum is at:

\[ w^*=3. \]

The derivative is:

\[ J'(w)=2(w-3). \]

Suppose:

\[ w_0=0,\qquad \eta=0.25. \]

Then:

\[ J'(0)=2(0-3)=-6. \]

Update:

\[ w_1=0-0.25(-6)=1.5. \]

Next:

\[ J'(1.5)=2(1.5-3)=-3. \]
\[ w_2=1.5-0.25(-3)=2.25. \]

Next:

\[ J'(2.25)=2(2.25-3)=-1.5. \]
\[ w_3=2.25-0.25(-1.5)=2.625. \]

The parameter moves toward 3:

0 → 1.5 → 2.25 → 2.625 → 2.8125 → … → 3

This is the simplest possible gradient-descent trace.

9. Worked Example — Complete Update

Suppose:

\[ J(w)=3w^2+2w+5. \]

Step 1 — Differentiate

\[ \frac{dJ}{dw}=6w+2. \]

Step 2 — Current parameter

Let:

\[ w=2. \]

Then:

\[ \frac{dJ}{dw}=6(2)+2=14. \]

Step 3 — Learning rate

Let:

\[ \eta=0.05. \]

Step 4 — Update

\[ w_{new}=2-0.05(14) \]
\[ \boxed{w_{new}=1.3} \]

Interpretation

The gradient was strongly positive, so the update moved \(w\) downward.

12. Why Scaling Helps Optimization

You already studied feature scaling in Unit II.

The same principle reappears here.

Suppose one feature varies around:

\[ 0\text{–}1 \]

while another varies around:

\[ 0\text{–}1,000,000. \]

The resulting parameter landscape can have very different sensitivities in different directions.

A gradient-based optimizer may then face an awkward geometry.

Conceptually:

Poorly scaled landscape

        ______
      /        \
     /          \
     \          /
      \________/

Long narrow valley

versus a better-conditioned situation:

______
    /        \
   |          |
    \________/

More balanced directions

This is one reason standardization can be useful before gradient-based learning.

13. Gradient Descent for a Neural Network

Now replace the simple parameter \(w\) with all trainable network parameters.

For a network:

\[ \theta=\{W^{(1)},b^{(1)},W^{(2)},b^{(2)},\ldots,W^{(L)},b^{(L)}\}. \]

Training becomes:

Initialize W, b
      ↓
Forward pass
      ↓
Compute loss J
      ↓
Compute gradients
      ↓
W ← W − η ∂J/∂W
b ← b − η ∂J/∂b
      ↓
Repeat

Critical point

Gradient descent tells us how parameters are updated.

It does not by itself tell us how to efficiently calculate every partial derivative in a deep network.

That second problem is the job of backpropagation.

This distinction is extremely important:

Backpropagation
→ efficiently computes gradients

Gradient descent
→ uses gradients to update parameters

C35 develops the first part.

14. Batch, Stochastic and Mini-Batch Gradient Descent

Suppose the objective is:

\[ J(\theta)=\frac1n\sum_{i=1}^{n}\ell_i(\theta). \]

There are several ways to estimate the gradient.

14.1 Batch Gradient Descent

Use the entire training set for one update:

\[ \nabla J(\theta) = \frac1n\sum_{i=1}^{n}\nabla \ell_i(\theta). \]

One update uses all examples.

Intuition

Read every student's answer before deciding how to adjust the teaching.

Advantages

  • exact gradient of the chosen empirical objective;
  • stable update direction;
  • conceptually simple.

Limitation

A large dataset can make each update expensive.

14.2 Stochastic Gradient Descent

Use one example at a time:

\[ \theta \leftarrow \theta-[0m \eta\nabla\ell_i(\theta). \]

The update direction is noisy because it is based on one example.

Intuition

Adjust your teaching after hearing one student's response.

Behaviour

The path may look noisy:

●
  ●
 ●
   ●
  ●
    ●
     ●

but the noise can still lead the process toward useful low-loss regions.

14.3 Mini-Batch Gradient Descent

Use a subset of examples:

\[ B\subseteq\{1,\ldots,n\}. \]

Then:

\[ \boxed{ \theta \leftarrow \theta- \eta \frac1{|B|}\sum_{i\in B}\nabla\ell_i(\theta) } \]

Mini-batch training is a practical compromise between:

Batch → stable but potentially expensive

SGD → cheap noisy updates

Mini-batch → moderate computation + moderate noise

Important terminology note

In modern ML discussions, the word “SGD” is sometimes used broadly for stochastic or mini-batch variants. In an exam, state exactly what convention you are using.

15. What Is an Epoch?

An epoch is one complete pass through the training dataset.

Suppose there are:

\[ 10,000 \]

training examples.

If batch size is:

\[ 100, \]

then one epoch contains approximately:

\[ \frac{10,000}{100}=100 \]

parameter updates, assuming a simple full-partitioning setup.

So:

1 epoch
= all training examples have been processed once

An epoch is not the same as an update.

17. The Role of Initialization

Gradient descent needs a starting point.

So we begin with initial values:

\[ \theta_0. \]

Then:

\[ \theta_1 = \theta_0-\eta\nabla J(\theta_0). \]

The starting point matters because different initializations can lead to different optimization trajectories, especially in non-convex models.

Why not set every weight to the same value?

If identical neurons start identically and receive identical inputs, they can remain symmetric and learn redundant functions.

Therefore practical neural-network initialization aims to preserve useful variation rather than giving every unit the same starting state.

A full treatment of initialization schemes is beyond the immediate syllabus core, but this symmetry idea is important.

18. Convex vs Non-Convex Optimization

You saw convexity in Linear Regression.

For a suitable convex objective:

local minimum
      =
(global) minimum

Neural-network loss surfaces are generally more complicated and are not globally guaranteed to be convex.

Therefore gradient descent can encounter structures such as:

  • local minima;
  • saddle points;
  • flat regions;
  • steep regions;
  • parameter symmetries.

Important correction to a common oversimplification

It is tempting to say:

“Gradient descent always finds the global minimum.”

That is not a general statement about neural-network training.

The guaranteed geometry you saw for convex least squares should not automatically be transferred to deep networks.

19. Saddle Points

A saddle point is a point that can look flat in some directions while still allowing the function to decrease in other directions.

A visual analogy:

\        /
       \      /
        \____/
        /    \
       /      \

A point can behave like a minimum along one direction and a maximum-like turning point along another.

This is why:

\[ \nabla J=0 \]

does not universally mean:

“We have reached the unique global minimum.”

It means only that the first-order slope information is zero at that point.

20. Stopping Conditions

Gradient-based training can stop for several reasons.

Small parameter change

\[ \|\theta_{t+1}-\theta_t\| \lt \varepsilon \]

Small gradient

\[ \|\nabla J(\theta_t)\|\lt \varepsilon \]

Loss improvement becomes small

\[ |J_{t+1}-J_t|\lt \varepsilon \]

Fixed training budget

For example:

Stop after K epochs

In practical ML, stopping is usually a training-design decision rather than simply “keep updating until the formula becomes exactly zero.”

21. Gradient Descent vs Closed-Form Solutions

Compare two situations.

Least-squares linear regression

For suitable assumptions, we can derive a closed-form solution.

Neural network

With many layers and nonlinear activations, a simple closed-form parameter solution is generally unavailable.

So we use iterative optimization:

Initial parameters
      ↓
Gradient
      ↓
Update
      ↓
Gradient
      ↓
Update
      ↓
...

This difference is conceptually important.

22. Worked Neural Example — A Single Trainable Weight

Suppose a one-parameter toy model is:

\[ \hat y=wx. \]

Take one training example:

\[ x=2,\qquad y=6. \]

Use squared loss:

\[ J(w)=\frac12(wx-y)^2. \]

Then:

\[ J(w)=\frac12(2w-6)^2. \]

We can differentiate:

\[ \frac{dJ}{dw} = (2w-6)(2) =4w-12. \]

Suppose:

\[ w=1, \qquad \eta=0.1. \]

Gradient:

\[ 4(1)-12=-8. \]

Update:

\[ w_{new}=1-0.1(-8)=1.8. \]

Prediction before update:

\[ \hat y=1(2)=2. \]

Prediction after update:

\[ \hat y=1.8(2)=3.6. \]

The weight moved in a direction that improves the fit for this example.

This is a deliberately tiny model so that every training step can be seen explicitly.

23. Why the Gradient Is Not “the Answer”

The gradient is a local direction signal, not a complete future plan.

Suppose the landscape curves strongly.

A direction that looks excellent at the current point might lead into a region where the geometry changes.

That is why the algorithm repeatedly recomputes the gradient.

Current point
   ↓
Local information
   ↓
Small movement
   ↓
New point
   ↓
New local information

This is the same reason a hiking analogy should not be interpreted as “one gradient tells you the whole route.”

24. Gradient Descent and Backpropagation — Do Not Confuse Them

This distinction is exam-critical.

Question Gradient Descent Backpropagation
Main job Update parameters Compute gradients efficiently
Key equation \(\theta\leftarrow\theta-\eta\nabla J\) Chain-rule recursion through layers
Needs derivatives? Yes Yes
Works only for neural networks? No Primarily taught for layered differentiable networks
Where used? Regression, neural nets, many optimizers Neural-network training

One-sentence memory anchor

Backprop tells you how wrong each parameter was; gradient descent decides how to change it.

The sentence is intentionally simplified. More precisely, backpropagation computes derivatives of a loss with respect to intermediate quantities and parameters; an optimizer then uses those gradients to update the parameters.

25. Common Misconceptions

Misconception 1 — “The gradient points toward the minimum.”

Not generally.

The gradient points toward steepest local increase.

Gradient descent moves in the opposite direction.

Misconception 2 — “A zero gradient always means the global minimum.”

Not for a general non-convex neural-network objective.

Misconception 3 — “Large learning rate means faster training.”

It can mean larger steps, but excessively large steps can overshoot or become unstable.

Misconception 4 — “One epoch means one update.”

No.

An epoch is one pass through the dataset; the number of updates depends on batch size.

Misconception 5 — “Backpropagation and gradient descent are the same algorithm.”

They are related but distinct mechanisms.

Misconception 6 — “More epochs are always better.”

Training longer can reduce training loss while eventually hurting generalization if the model begins to overfit.

    M1 --> BC1["Bias Correction:
m̂ₜ = mₜ / (1 - β₁ᵗ)"]
    M2 --> BC2["Bias Correction:
v̂ₜ = vₜ / (1 - β₂ᵗ)"]
    BC1 --> UPDATE["Parameter Update:
w ← w - η · m̂ₜ / (√v̂ₜ + ε)"]
    BC2 --> UPDATE
    UPDATE --> DONE(["Adam Optimizer Step Finished ⚡"])
PYTHON
import numpy as np

class AdamOptimizer:
    def __init__(self, lr=0.001, beta1=0.9, beta2=0.999, eps=1e-8):
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.eps = eps
        self.m = None
        self.v = None
        self.t = 0

    def update(self, w, grad):
        if self.m is None:
            self.m = np.zeros_like(grad)
            self.v = np.zeros_like(grad)
        
        self.t += 1
        self.m = self.beta1 * self.m + (1.0 - self.beta1) * grad
        self.v = self.beta2 * self.v + (1.0 - self.beta2) * (grad ** 2)
        
        m_hat = self.m / (1.0 - self.beta1 ** self.t)
        v_hat = self.v / (1.0 - self.beta2 ** self.t)
        
        w_next = w - self.lr * m_hat / (np.sqrt(v_hat) + self.eps)
        return w_next

opt = AdamOptimizer(lr=0.1)
w = np.array([2.0, -3.0])
grad = np.array([10.0, 0.01])
w_updated = opt.update(w, grad)
print("Original weights:", w)
print("Updated weights:", w_updated.round(4))

GRADIENT DESCENT

\[ \gt \boxed{\theta\leftarrow\theta-\eta\nabla_\theta J(\theta)} \gt \]

Meaning: move parameters opposite the local steepest-increase direction.

Symbols:

  • \(\theta\): trainable parameters
  • \(J\): objective/loss
  • \(\nabla_\theta J\): gradient with respect to parameters
  • \(\eta\): learning rate

Trigger: “Update the weights using gradient descent.”

Common mistake: forgetting the negative sign.

27. Formula Card — Mini-Batch Gradient

\[ \boxed{ \theta \leftarrow \theta- \eta \frac1{|B|} \sum_{i\in B} \nabla_\theta\ell_i(\theta) } \]

Read it as:

Calculate the average gradient over the chosen mini-batch and take one downhill step.

28. Algorithm — Gradient Descent

Problem

Minimize a differentiable objective:

\[ J(\theta). \]

Inputs

  • objective function;
  • initial parameters;
  • learning rate \(\eta\);
  • stopping condition.

Procedure

1. Initialize θ
2. Repeat:
      a. Compute J(θ)
      b. Compute ∇θ J(θ)
      c. θ ← θ − η ∇θ J(θ)
3. Stop according to the chosen criterion
4. Return θ

In a neural network

The “compute gradient” step is normally supplied efficiently by backpropagation.

So practical training becomes:

Forward pass
→ loss
→ backpropagation
→ gradients
→ optimizer update

29. Complexity Intuition

For a parameter vector with \(P\) trainable parameters, one update conceptually involves computing information related to those parameters and the selected batch.

The exact computational cost depends on:

  • number of layers;
  • matrix dimensions;
  • batch size;
  • activation functions;
  • architecture;
  • implementation details.

For a dense layer with weight matrix:

\[ W\in\mathbb R^{d_{out}\times d_{in}}, \]

the number of weights is:

\[ d_{out}d_{in}. \]

Gradient computation must produce a derivative for every trainable parameter.

The important conceptual point is:

A neural network may have a huge parameter space, so efficient gradient computation is essential.

30. Connection to Regularization

You already learned:

\[ J_{reg}(\theta) = J_{data}(\theta)+\lambda\Omega(\theta). \]

Gradient descent can optimize this regularized objective too.

Then:

\[ \nabla J_{reg} = \nabla J_{data}+ \lambda\nabla\Omega \]

when the penalty is differentiable at the point considered.

So regularization changes the objective being optimized; gradient descent remains the optimization mechanism.

This connects Unit II Ridge/Lasso to Unit III neural-network training.

31. Advanced Optimizers — Preview Only

Many practical systems use optimizer variants that modify plain gradient descent.

Examples include:

  • momentum-based methods;
  • AdaGrad;
  • RMSProp;
  • Adam.

These methods add mechanisms such as accumulated directional information or adaptive step scaling.

They are useful to know as terminology, but they do not replace the core conceptual sequence:

loss
→ gradients
→ parameter update

The immediate syllabus core here remains gradient descent.
