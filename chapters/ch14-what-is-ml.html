MAIN-U2-C14 — What Is Machine Learning?

Main Book: AI & Machine Learning — Visual + Mathematical Self-Learning Textbook
Unit: II — Machine Learning Fundamentals
Topic ID: ML-U2-C14
Prerequisites: MAIN-U1-C01 to MAIN-U1-C13 at a conceptual level; basic algebra and the idea of data
Primary course source: Lecture07.pdf — Introduction to Machine Learning, Lecture 7: Machine Learning Paradigms and Performance Metrics, Prof. Subrahmanya Swamy Peruru, IIT Kanpur
Next: MAIN-U2-C15 — Machine Learning Paradigms

1. Why are we learning this first?

Before learning linear regression, logistic regression, decision trees, or neural networks, you need to answer a much more basic question:

What exactly is a machine learning system doing?

A beginner often hears:

“Machine learning means the computer learns from data.”

That is directionally correct, but too vague to help you reason about an actual model.

In this book, we will gradually turn that sentence into a complete mental model:

Real-world problem
       ↓
       Data
       ↓
Features / inputs
       ↓
Learning procedure
       ↓
Model
       ↓
Prediction
       ↓
Loss / error
       ↓
Improve the model
       ↓
Generalize to unseen data

Your Lecture 7 begins with a practical motivation: ML is especially useful when explicit rules or formulas are hard to write and when data exists but the input-output relationship is complex. Course source: Lecture07.pdf, slide 3.

2. One-minute intuition

English

Machine learning is a way of building a predictive or decision-making system by using data to learn a useful relationship instead of manually writing every rule.

Imagine you want a computer to recognize handwritten digits.

You could try to manually write rules such as:

“If the top line curves this way and the lower loop has this shape, call it a 5.”

That becomes extremely difficult because handwriting varies.

Instead, you can provide many examples:

Image of 5 → label 5
Image of 5 → label 5
Image of 3 → label 3
Image of 8 → label 8
...

A learning algorithm uses these examples to construct a model that can make predictions on new images.

👨‍🏫 Hinglish
> Computer ko har rule manually batane ke bajaye hum usse bahut saare examples dete hain. Computer un examples mein patterns dhoondhkar ek **model** banata hai. Phir wahi model naye example par prediction karta hai.

3. The important distinction: programming rules vs learning from data

Traditional programming

A simplified picture is:

Rules + Data
     ↓
  Program
     ↓
 Output

The programmer specifies the logic.

For example:

IF temperature < 20°C
THEN turn heater ON

Machine learning

A simplified picture is:

Examples / Data + Learning procedure
                  ↓
                Model
                  ↓
          Predictions on new data

The model's parameters are learned from examples.

Analogy — teaching a child

Suppose you want to teach a child what a mango is.

You could try to provide a perfectly complete rulebook:

“A mango must have exactly this shape, this colour, this texture...”

Or you could show many examples:

“This is a mango.” “This is also a mango.” “This one is a mango.”

The child gradually learns a useful concept from examples.

That analogy is useful, but it is not a formal definition of ML. A machine-learning algorithm does not literally think like a child.

4. When should we use Machine Learning?

Your Lecture 7 gives two especially useful situations:

Situation 1 — Explicit rules are hard to write

Examples:

  • handwritten digit recognition;
  • image classification;
  • speech recognition;
  • complicated pattern recognition.

The problem is not necessarily that rules do not exist. The problem is that writing all the useful rules explicitly may be difficult or impractical.

Situation 2 — The input-output relationship is complex

Imagine:

house information ─────────→ price

There may be many interacting factors:

  • area;
  • location;
  • number of rooms;
  • age;
  • other features.

Rather than manually writing every combination, we can use data to learn a function that maps input features toward the desired output.

Course source: Lecture07.pdf, slide 3.

5. The ML problem in symbols

Now we introduce a little mathematics.

Suppose one example is represented by:

\[ (\mathbf{x}_i,y_i) \]

where:

  • \(\mathbf{x}_i\) = input/features for example \(i\);
  • \(y_i\) = target/output for example \(i\).

If there are \(n\) training examples, the dataset can be written as:

\[ \mathcal{D}=\{(\mathbf{x}_i,y_i)\}_{i=1}^{n} \]

Your Lecture 7 uses exactly this notation for supervised learning. Course source: Lecture07.pdf, slide 5.

👨‍🏫 Hinglish
> \(\mathbf{x}\) ko tum “input ki information” samjho aur \(y\) ko “jo answer chahiye” samjho. For house-price prediction:
\[ \mathbf{x}=\text{house features} \]
and:
\[ y=\text{house price} \]

6. What is a feature?

A feature is an input variable or measurable property used by the model.

For a house-price example:

Feature Possible value
Area 1400 sqft
Bedrooms 3
Bathrooms 2
Age 8 years

These together form an input vector:

\[ \mathbf{x}= \begin{bmatrix} 1400\\ 3\\ 2\\ 8 \end{bmatrix} \]

Real-world analogy

Think of selecting a student for a sports team.

You might consider:

  • height;
  • speed;
  • endurance;
  • previous performance.

These are features.

The model uses the features as evidence for a prediction or decision.

7. What is a label / target?

A label, target, or response is the output we want to predict in supervised learning.

Examples:

Email features → spam / not spam
House features → price
Image → cat / dog
Student information → exam score

Notice that the output can be different kinds of things.

That leads to two common supervised-learning settings, which your Lecture 7 explicitly names:

Regression

The target is continuous, such as:

\[ y\in\mathbb{R} \]

Example:

house size → price

Classification

The target is a discrete class:

\[ y\in\{1,2,\ldots,K\} \]

Example:

email → spam / not spam

Course source: Lecture07.pdf, slide 6.

8. What is a model?

A model is the learned function or structure that transforms inputs into predictions.

A simple abstraction is:

\[ \hat{y}=\hat{f}(\mathbf{x}) \]

Here:

  • \(\mathbf{x}\) = input;
  • \(\hat{f}\) = learned model/function;
  • \(\hat{y}\) = predicted output.

The hat symbol is useful:

\[ \hat{f} \]

means this is the learned estimate of the underlying relationship, rather than a claim that we know the perfect true function.

👨‍🏫 Hinglish
> Model basically woh “seekha hua mechanism” hai jo input dekhkar answer predict karta hai.

9. Training and inference

These two words will appear everywhere.

Training

The model uses available data to learn its parameters.

Training data
     ↓
 Learning algorithm
     ↓
 Learned parameters/model

Inference / prediction

After training, the model receives a new input and produces an output.

New unseen input
      ↓
    Model
      ↓
 Prediction

Analogy — exam preparation

Training is like practicing with many questions before an exam.

Inference is like receiving a new question during the exam.

The whole point of practice is not merely to memorize the old questions; it is to perform on new questions.

That is exactly why unseen data matters so much.

10. The central objective: generalization

A model can perform extremely well on the training examples and still be poor on new data.

So the real objective is not:

“Memorize the training dataset.”

The objective is:

Learn a relationship that works well on unseen examples from the relevant data-generating process.

Your Lecture 7 explicitly warns that performance depends on how well the learned function predicts on unseen data. Course source: Lecture07.pdf, slide 5.

This idea will become much more important in the next chapters on hypothesis classes, bias-variance and overfitting.

11. Why do we need a loss function?

Suppose the real answer is:

\[ y=100 \]

and your model predicts:

\[ \hat y=92 \]

How do we tell the learning algorithm that this prediction is imperfect?

We need a numerical way to measure error.

That is the purpose of a loss function.

A general loss can be written as:

\[ \ell(\hat y,y) \]

It takes the prediction and the true answer and returns a measure of how bad that prediction is.

Intuition

Prediction + Truth
       ↓
     Loss
       ↓
“How wrong were we?”

The learning process can then try to find a model that produces a small loss on the training data.

12. The supervised-learning objective

Your Lecture 7 expresses supervised learning as:

\[ \hat f\in \arg\min_{f\in\mathcal H} \frac{1}{n} \sum_{i=1}^{n} \ell(f(\mathbf{x}_i),y_i) \]

Do not panic.

We will unpack it piece by piece.

Step 1 — \(f(\mathbf{x}_i)\)

The model receives example \(\mathbf{x}_i\) and predicts an output.

Step 2 — Compare prediction with \(y_i\)

The true answer is known for supervised training.

Step 3 — Calculate loss

\[ \ell(f(\mathbf{x}_i),y_i) \]

This tells us how wrong the prediction was.

Step 4 — Add errors across examples

\[ \sum_{i=1}^{n} \ell(f(\mathbf{x}_i),y_i) \]

Step 5 — Average them

\[ \frac{1}{n} \sum_{i=1}^{n} \ell(f(\mathbf{x}_i),y_i) \]

Step 6 — Find the best candidate in \(\mathcal H\)

\[ \arg\min_{f\in\mathcal H} \dots \]

We are asking:

Which allowed model gives the smallest average training loss?

The set \(\mathcal H\) is the hypothesis class. We will study it carefully later.

Course source: Lecture07.pdf, slide 5.

13. What does \(\arg\min\) mean?

This notation looks intimidating at first.

Suppose:

\[ f_1\rightarrow 8 \]
\[ f_2\rightarrow 3 \]
\[ f_3\rightarrow 5 \]

where the numbers are training losses.

Then:

\[ \arg\min_f L(f)=f_2 \]

because \(f_2\) produces the smallest loss.

👨‍🏫 Hinglish
> **min** = smallest value. > **arg min** = “kaunsa option smallest value de raha hai?” So:
\[ \arg\min \]
does not return the minimum number itself; it identifies the **argument/input/model that achieves it**. This notation will appear repeatedly in ML.

14. A complete beginner example

Suppose you have three models for predicting house price:

Model Average training loss
Model A 120
Model B 80
Model C 95

The learning objective chooses Model B because it has the smallest training loss.

But there is a warning:

Lowest training loss does not automatically mean best model on unseen data.

A sufficiently flexible model can memorize training examples.

That is why the later concepts of generalization and overfitting are essential.

15. Training error vs test/generalization performance

We need two different ideas.

Training error

How well does the model fit data it was trained on?

Test / unseen-data performance

How well does the model perform on examples it did not use to fit its parameters?

The conceptual goal is:

Good training performance
          +
Good unseen-data performance
          ↓
      Generalization

Why this matters

Imagine a student memorizes the exact answers to 100 practice questions.

Training performance may look excellent.

Then the teacher asks a new question using the same underlying idea.

If the student cannot solve it, memorization did not become understanding.

ML has an analogous problem.

16. The ML pipeline you must remember

PROBLEM
                    ↓
                 DATA
                    ↓
          REPRESENT INPUTS
                    ↓
           CHOOSE MODEL CLASS
                    ↓
                TRAIN
                    ↓
             CALCULATE LOSS
                    ↓
        OPTIMIZE / FIT PARAMETERS
                    ↓
            EVALUATE UNSEEN DATA
                    ↓
               GENERALIZE

Different ML algorithms mainly change the model class, loss/objective, and learning procedure.

That is why learning the common ML skeleton is more useful than memorizing isolated algorithms.

17. Parameters vs hyperparameters

These two words are often confused.

Parameters

Values learned from training data.

Examples:

  • weights in linear regression;
  • coefficients in a model;
  • neural-network weights.

Hyperparameters

Settings selected before or around training rather than learned in the same parameter-fitting step.

Examples may include:

  • learning rate;
  • tree depth;
  • number of neighbours in K-NN;
  • regularization strength.

Analogy

Think of cooking.

The final taste depends on the ingredients actually used in the dish.

Parameters are somewhat analogous to the quantities adjusted as part of the learned recipe.

Hyperparameters are more like choices you make about the recipe or cooking process before/around the cooking procedure.

The analogy is only for intuition; exact ML training protocols vary.

18. A crucial question: what does “learning” really mean?

A model is said to learn when its parameters are adjusted using data so that its behavior improves according to a defined objective.

That means:

Before learning
     ↓
Parameters produce weaker predictions
     ↓
Data + learning algorithm
     ↓
Parameters change
     ↓
Predictions improve according to objective

The system does not necessarily discover truth in a philosophical sense.

It learns a parameterized representation or mapping that performs according to the chosen objective and data.

This distinction becomes important when we later discuss:

  • overfitting;
  • biased datasets;
  • distribution shift;
  • fairness;
  • limitations of evaluation metrics.

19. Why one model is not automatically the “best” model

A model can be good or bad relative to a task, dataset and evaluation criterion.

For example:

  • a simple model may generalize better on one dataset;
  • a complex model may capture more structure on another;
  • a model may have excellent accuracy but poor recall for a safety-critical task;
  • a model with low training loss may overfit.

Therefore always ask:

Best according to which objective, which data, and which evaluation metric?

This mindset will prevent many later mistakes.

20. Mathematical lens

For this chapter, the mathematics you actually need is modest.

Dataset

\[ \mathcal D=\{(\mathbf x_i,y_i)\}_{i=1}^{n} \]

Model prediction

\[ \hat y=\hat f(\mathbf x) \]

Loss

\[ \ell(\hat y,y) \]

Average training loss

\[ \frac{1}{n}\sum_{i=1}^{n} \ell(f(\mathbf x_i),y_i) \]

Learning objective

\[ \hat f\in\arg\min_{f\in\mathcal H} \frac{1}{n}\sum_{i=1}^{n} \ell(f(\mathbf x_i),y_i) \]

The most important thing is not memorizing every symbol immediately.

You should be able to narrate the formula in words:

Choose an allowed model that minimizes the average loss on the training examples.

21. Hinglish recap

Machine learning mein hum problem ko data ke through solve karne ki koshish karte hain.

Input ko generally \(\mathbf{x}\) se represent karte hain aur target ko \(y\) se.

Model \(\hat f\) input lekar prediction \(\hat y\) deta hai.

Training mein hum dekhte hain ki prediction kitni galat hai — isko loss ke through measure karte hain.

Phir learning algorithm model ke parameters ko aise adjust karta hai ki objective improve ho.

Lekin sirf training data par achha perform karna enough nahi hai. Humein unseen data par bhi achha perform karna hai. Isi ko generalization samajhne ki direction mein pehla step samjho.

22. Common misconceptions

Misconception 1

“Machine learning means the computer can learn anything.”

Correct

No. Learning depends on:

  • data;
  • model class;
  • objective/loss;
  • learning procedure;
  • assumptions;
  • evaluation setting.

Misconception 2

“Low training error means the model is good.”

Correct

Not necessarily. Unseen-data performance matters.

Misconception 3

“A model is the same as its training data.”

Correct

The model is the learned function/structure used to make predictions; the training data is what the learning procedure uses to fit it.

Misconception 4

“Learning means memorizing examples.”

Correct

Memorization can happen, but useful learning aims for generalization to unseen examples.

24. Worked thinking exercise

Suppose a model predicts the following for three houses:

House True price Predicted price
A 100 98
B 200 210
C 150 140

Do not calculate a specific metric yet.

Instead answer:

Step 1

What is the role of the feature vector \(\mathbf x\)?

Step 2

What is \(y\)?

Step 3

What is \(\hat y\)?

Step 4

Why would a loss function be useful?

Step 5

Would perfect performance on these three training examples prove that the model generalizes well?

No. We would need appropriate evaluation on unseen data.

25. University Exam Lens

📝 2-mark questions
- Define machine learning. - Why is ML used when explicit rules are difficult to write? - Define feature. - Define target/label. - Define loss function. - What is generalization?
📝 5-mark question — Explain the basic ML learning process
Recommended structure: 1. Define ML in the context of learning from data. 2. Explain input/features and target. 3. Explain training and model fitting. 4. Explain loss. 5. Explain prediction on unseen data. 6. Mention generalization.
📝 10-mark question — Explain supervised learning mathematically
Suggested structure: 1. Introduce labelled dataset. 2. Define \(\mathbf{x}\) and \(y\). 3. Write:
\[ \mathcal D=\{(\mathbf x_i,y_i)\}_{i=1}^n \]
4. Introduce \(\hat f\). 5. Define loss. 6. Write the average-loss objective. 7. Explain \(\mathcal H\). 8. Explain why unseen-data performance matters.

Exam trap

Do not say:

“Machine learning finds the perfect function.”

A safer statement is:

“The learning procedure selects/fits a model according to an objective using available data.”
