3. Search in one sentence

Search is the systematic exploration of a problem's possible states in order to find a path or solution satisfying a goal.

A search algorithm therefore needs:

  • a representation of states;
  • possible actions/successors;
  • a goal test;
  • often a cost model;
  • and a rule for deciding which node to expand next.

Your Basic Search lecture explicitly frames search strategies around node-expansion order and evaluates them by completeness, time, space and optimality.

4. The first big distinction: what kind of problem are we solving?

Type A — Ordinary path-finding / state-space search

Examples:

  • route finding
  • puzzle solving
  • robot navigation

You usually care about a sequence of actions.

Type B — Configuration/optimization problem

Examples:

  • timetable generation
  • n-queens
  • TSP-style configuration

You may care mainly about the final configuration rather than the whole path.

This motivates local search.

Type C — Constraint problem

You need a complete assignment satisfying restrictions.

This motivates CSP methods.

Type D — Competitive game

Another intelligent agent is actively choosing actions too.

This motivates game trees, minimax and alpha-beta.

5. The search tree vocabulary map

Before comparing algorithms, make sure these words are not mixed up.

Term Meaning
State Representation of a world configuration
Node Search-tree data structure associated with a state and search information
Parent Previous search node
Child Generated successor node
Depth Number of steps from the root
Path cost g(n) Cost accumulated from the start to the node
Frontier / fringe Generated but not yet expanded candidates
Explored / closed set Already processed states/nodes in graph search
Goal test Checks whether a state satisfies the goal
Branching factor b Maximum number of successors per node
Solution depth d Depth of the relevant/least-cost solution in standard analysis
Maximum depth m Maximum depth of the state space, possibly infinite

Your Basic Search lecture makes a particularly important distinction: a state is the physical configuration, while a node is the search data structure that additionally carries parent, children, depth and path-cost information.

6. The one question behind uninformed search

Uninformed search has no special estimate of which state is close to the goal.

So it uses a fixed structural rule.

BFS  → shallowest
UCS  → lowest path cost
DFS  → deepest
DLS  → deepest, but bounded
IDS  → increasing depth limit
👨‍🏫 Hinglish
> “Sabke paas same basic problem hai. Difference sirf itna hai ki **next node choose karne ka rule kya hai**.”

7. BFS — think “level by level”

Mental model

A queue at a college office:

First person who entered the queue is served first.

That is the FIFO idea.

Core rule

Expand the shallowest unexpanded node.

Data structure

FIFO queue.

Main strength

Finds shallow solutions and is complete under standard finite-branching assumptions.

Main weakness

Memory.

The lecture explicitly notes the high space requirement.

8. DFS — think “follow one road deeply”

Imagine walking through a maze and taking one corridor as far as possible before backtracking.

Core rule

Expand the deepest unexpanded node.

Data structure

LIFO stack.

Main strength

Low memory relative to breadth-first exploration.

Main weakness

Can get lost in very deep or cyclic spaces; not optimal.

9. UCS — think “cheapest so far”

Suppose every road segment has a different cost.

Counting how many roads you used is not enough.

You need the accumulated cost.

Core rule

Expand the lowest-cost node according to g(n).

Key connection

When every step has the same cost:

\[ UCS \equiv BFS \]

in behaviour.

This is one of the most useful conceptual bridges in the whole search chapter.

10. DLS and IDS — controlling depth

DLS

DFS with a hard depth limit.

IDS

Repeated DLS with increasing limits.

The clever idea is:

Combine DFS-like memory behaviour with BFS-like shallow-solution discovery under the relevant unit-cost conditions.

Memory anchor

DFS + limit       = DLS
DLS + growing limit = IDS

11. The master uninformed-search table

Algorithm Selection rule Complete? Optimal? Main memory idea Core risk/issue
BFS Shallowest Yes* Yes* Very high Memory explosion
UCS Lowest g(n) Yes* Yes* under standard assumptions High Many low-cost nodes
DFS Deepest No in general No Low Infinite/deep traps
DLS Deepest up to l Yes if l ≥ d No Low May cut off solution
IDS Increasing depth limit Yes Yes* Low Repeated shallow work

* depends on standard assumptions stated in the course, such as finite branching and appropriate step-cost conditions.

12. Why do heuristics change the game?

Uninformed search knows:

“Here are the possible actions.”

It does not know:

“Which one is likely to move me toward the goal?”

A heuristic adds that missing problem-specific information.

\[ \boxed{h(n)=\text{estimated remaining cost to a goal}} \]

Analogy

GPS-style thinking:

“I do not know the complete future route yet, but this estimate tells me which direction is promising.”

13. Greedy vs A* — the crucial difference

Greedy

Uses:

\[ \boxed{h(n)} \]

It asks:

“Which node looks closest to the goal?”

A*

Uses:

\[ \boxed{f(n)=g(n)+h(n)} \]

It asks:

“Which node has the best estimate when I consider both the cost already spent and the cost still estimated?”

👨‍🏫 Hinglish
Greedy: > “Bas aage ka estimate dekh.” A*: > “Ab tak kitna laga + aage kitna lag sakta hai, dono dekh.”

14. What makes a heuristic admissible?

Define the true optimal remaining cost:

\[ h^*(n) \]

Then:

\[ \boxed{0\le h(n)\le h^*(n)} \]

The key word is:

never overestimate

At a goal:

\[ \boxed{h(G)=0} \]

This property is crucial to A* optimality under the assumptions of the course treatment.

15. Heuristic quality matters

Two heuristics can both be admissible but differ in how informative they are.

For the 8-puzzle, your lecture gives:

\[ h_1(n)=\text{misplaced tiles} \]

and:

\[ h_2(n)=\text{total Manhattan distance} \]

If:

\[ h_2(n)\ge h_1(n) \]

for all nodes and both are admissible, then h2 is more informative in the dominance sense used by the lecture.

The lecture illustrates that this can drastically reduce the number of nodes expanded by A*.

16. The full informed-search map

INFORMED SEARCH
      │
      ├── Best-first framework
      │       │
      │       ├── Greedy → h(n)
      │       └── A*      → g(n)+h(n)
      │
      └── Iterative improvement
              │
              ├── Hill climbing
              ├── Local beam
              ├── Simulated annealing
              └── Genetic algorithms

Important distinction

A is an exact search method with a heuristic-guided expansion rule* under its assumptions.

Hill climbing / simulated annealing / genetic algorithms are used for approximate/local optimization and do not provide the same guarantee structure.

17. Why does local search exist?

Sometimes:

The path is not the important part.

You care about finding a very good final configuration.

Then storing the whole search tree can be wasteful.

Core loop

Current state
      ↓
Neighbouring states
      ↓
Choose/improve
      ↓
New current state
      ↓
Repeat

Failure modes

  • local maxima;
  • plateaus;
  • ridges;
  • loss of diversity.

The informed-search lecture uses TSP and n-queens to illustrate this style of problem.

18. The local-search family in one picture

Method What it keeps How it moves
Hill climbing One current state Better neighbour
Random restart One state at a time, multiple starts Restart when stuck
Local beam k states Keep best successors across them
Simulated annealing One current state Sometimes accepts worse move
Genetic algorithm Population Selection + crossover + mutation

Memory anchor

Hill = climb.
Beam = keep several.
Annealing = occasionally go down to escape.
Genetic = evolve a population.

19. CSP — the other special kind of search problem

A CSP is not merely:

“Find a path.”

It is:

Assign values to variables so that all constraints are satisfied.

Core triad

\[ \boxed{Variables + Domains + Constraints} \]

Example: map colouring

Variables → regions
Domains   → available colours
Constraints → adjacent regions cannot share a colour

Search intelligence

CSP methods try to fail early:

  • MRV
  • degree heuristic
  • LCV
  • forward checking
  • arc consistency

That is the central idea:

Do not waste search on assignments that can already be shown impossible.

20. Games change the problem fundamentally

Ordinary search often assumes the environment is not actively making strategic choices against you.

A game has another decision-maker.

So a solution is not simply:

“Go left, left, right...”

It is a strategy that accounts for possible opponent responses.

The supplied Game Playing lecture explicitly frames an unpredictable opponent this way.

22. Minimax in one mental model

Two players:

  • MAX wants the value high.
  • MIN wants the value low.

Recurrence intuition

At MAX:

\[ \boxed{V(s)=\max_{a}V(Result(s,a))} \]

At MIN:

\[ \boxed{V(s)=\min_{a}V(Result(s,a))} \]

The exact notation can vary by presentation, but the idea is universal:

Choose the move that remains best against the opponent's best response.

23. Alpha-beta pruning

Alpha-beta does not change what minimax should decide under the same conditions.

It avoids exploring branches that cannot improve the final backed-up value.

Alpha

Best value MAX can already guarantee on the current path.

Beta

Best value MIN can already guarantee on the current path.

Prune when the remaining branch cannot possibly change the decision.

Memory anchor

Minimax = decide.

Alpha-beta = decide without wasting computation.

24. Resource-limited play

Real games are not solved completely at every move.

So:

\[ TERMINAL\ TEST \rightarrow CUTOFF\ TEST \]

and:

\[ UTILITY \rightarrow EVALUATION \]

This gives:

Search to practical depth
       ↓
Evaluate cutoff states
       ↓
Back up values
       ↓
Choose move

Major issues

  • horizon effect
  • unstable positions / quiescence
  • approximate pruning
  • learned evaluation

25. The Unit I decision tree

When you see a new problem, ask these questions.

Question 1

Is this an AI problem that can be represented by states and actions?

If no → you may need a different formulation.

If yes → continue.

Question 2

Is the path/action sequence the solution?

If yes → ordinary state-space search may fit.

If no, and the final configuration is what matters → local search may fit.

Question 3

Are there hard constraints on variable assignments?

If yes → CSP formulation may be appropriate.

Question 4

Is another intelligent player deliberately choosing responses?

If yes → game/adversarial search.

Question 5

Do we have useful domain knowledge that estimates closeness to a goal?

If yes → informed search may be useful.

27. The complexity symbols you must know

You will repeatedly see:

  • b = branching factor
  • d = depth of the shallow/least-cost solution
  • m = maximum depth
  • l = depth limit
  • C* = cost of an optimal solution in contexts where that notation is used

Why these matter

Search spaces grow roughly like:

\[ b^d \]

That is why a small increase in depth can produce an enormous increase in work.

👨‍🏫 Hinglish
> “Branching factor thoda sa bhi bada ho aur depth badhe, toh possibilities explode kar sakti hain.”

28. The “why” behind algorithm properties

Do not memorize these as isolated facts.

BFS uses memory because...

It keeps a broad frontier of shallow candidates.

DFS uses less memory because...

It follows one deep path rather than storing an entire breadth layer.

Greedy can fail because...

It trusts apparent closeness and ignores the cost already spent.

A* can be optimal because...

Under the required assumptions, its admissible heuristic does not overestimate remaining cost, so the evaluation preserves the necessary ordering for optimal search.

Hill climbing fails because...

Local information can trap it away from the global optimum.

Alpha-beta helps because...

Some branches can no longer influence the final minimax choice.

CSP heuristics help because...

They reduce branching or expose failure earlier.

30. The deepest mental connection

All these methods are different answers to one meta-question:

How should limited computation be allocated among competing possibilities?

That is why this unit is foundational.

AI is not merely:

“run an algorithm.”

AI is often:

Represent → reason → prioritize → act.

34. Practice Set — classify the problem

For each scenario, identify the most natural formulation.

Place queens on a chessboard so no two attack one another.

D

35. Practice Set — algorithm selection

Q1

A tree has finite branching, all step costs are 1, and the goal is guaranteed to be at shallow depth. Which methods are naturally relevant, and what is the trade-off?

Q2

A graph has variable positive edge costs. Why might BFS fail to return a least-cost solution?

Q3

A heuristic estimates remaining cost but is sometimes too high. Why does that matter to the standard A* optimality argument?

Q4

A local-search problem has many local maxima. Name two strategies that can help escape them.

Q5

A game tree is too large to search to terminal states. What additional mechanisms are needed?

41. Common Unit I traps

Trap 1

BFS is always optimal.

Only under the required cost assumptions, such as equal step costs in the basic treatment.

Trap 2

DFS is faster than BFS.

There is no universal guarantee. It can be much faster in some problem structures and much worse in others.

Trap 3

Greedy and A* are the same.

No.

Greedy uses h(n).

A* uses g(n)+h(n).

Trap 4

An admissible heuristic is exact.

No. It can underestimate.

Trap 5

More heuristic value always means better heuristic.

Only within the correct comparison setting. Dominance requires the relevant pointwise relationship and admissibility.

Trap 6

Alpha-beta changes minimax's decision.

Under its standard safe-pruning assumptions, it preserves the minimax result.

Trap 7

CSP is just ordinary graph search with different terminology.

CSP has a distinct variable-domain-constraint representation and specialized propagation/order heuristics.
