MAIN-U1-C04 — Uninformed Search

Main Book: AI & Machine Learning — Complete Visual & Mathematical Textbook
Unit: I — Artificial Intelligence
Chapter ID: AI-I-C04
Learning mode: Beginner → intuition → formalism → worked examples → exam → recall
Course lens: University of Delhi DSC-14 Artificial Intelligence and Machine Learning
Primary course source: lecture-basic-search.pdf
Prerequisites: MAIN-U1-C02 — Intelligent Agents, MAIN-U1-C03 — Problem Formulation

0. Why this chapter exists

You already know that an intelligent agent can have a goal and a set of actions. You have also learned how a real-world problem can be converted into an initial state, actions/successor function, goal test, and path cost.

But there is a new problem:

Once we have a problem, how does the agent actually find a solution?

That is the job of search.

Suppose you are in a huge building and need to find one particular room. You know where you started and what corridors you can take, but you do not have a map telling you the correct path. You must decide:

Which corridor should I explore first?

A search strategy is essentially a rule for answering exactly that question.

The lecture describes a search strategy by the order in which it expands nodes and evaluates strategies using completeness, time complexity, space complexity, and optimality. It defines the important parameters b, d, and m for this analysis. [lecture-basic-search.pdf, slides 18–19]

1. One-minute intuition

Imagine that every possible action creates more possibilities.

Start
                             |
                 ┌───────────┴───────────┐
                 ▼                       ▼
                Way A                   Way B
                 |                       |
           ┌─────┴─────┐           ┌────┴────┐
           ▼           ▼           ▼         ▼
         A1            A2          B1        B2
         |                         |
       ...                        ...

You cannot explore everything forever.

So a search strategy tells the agent:

“Among all currently available possibilities, which one should I explore next?”

Different strategies answer differently:

  • BFS: “Explore the shallowest possibilities first.”
  • DFS: “Go as deep as possible along one path first.”
  • UCS: “Explore the path that has cost the least so far.”
  • DLS: “Go deep, but never beyond this depth limit.”
  • IDS: “Try depth 1, then depth 2, then depth 3, and so on.”

The first two—BFS and DFS—are explicitly named in your university syllabus. UCS, DLS and IDS appear in your supplied lecture and are valuable both for understanding the full search family and for building the bridge to later search methods. [lecture-basic-search.pdf, slides 18–49]

2. Hinglish teacher explanation

Search ko simple language mein socho.

Tumhare paas ek starting point hai aur ek goal hai. Beech mein bahut saare possible raaste hain. Problem yeh hai ki tumhe pata nahi kaunsa raasta sahi hai.

Ab tumhe ek rule chahiye:

“Next kaunsa option try karna hai?”

Yahi rule search strategy hai.

Agar tum bolte ho:

“Pehle nearest/upper level ke saare options check karunga, phir next level par jaunga.”

toh tum BFS jaisa soch rahe ho.

Agar tum bolte ho:

“Ek raasta pakadta hoon aur usmein jitna deep ja sakta hoon jaunga. Agar dead end mila toh wapas aunga.”

toh tum DFS jaisa soch rahe ho.

Is chapter ka main idea bas itna hai:

Search = possibilities ko systematically explore karke goal tak pahunchna.

3. What exactly is being searched?

We do not directly search the messy real world.

We first convert the problem into a state space.

For example, in a route-finding problem:

  • a state can be a city,
  • an action can be driving from one city to another,
  • a path is a sequence of cities,
  • the goal is reaching the destination.

Your Basic Search lecture emphasizes that problem formulation abstracts away irrelevant real-world details so that a state space that can actually be searched can be constructed.

Important mental distinction:

Real world → abstract problem → state space → search tree/graph → solution

4. Search tree: the mental picture you must own

A search process is usually visualized as a tree.

flowchart TD
    A[Initial State] --> B[State B]
    A --> C[State C]
    B --> D[State D]
    B --> E[State E]
    C --> F[State F]
    C --> G[State G]

Each time the search expands a node, it generates its possible successors.

The supplied lecture defines tree search as simulated exploration in which successors of already-explored states are generated; a node is selected for expansion according to the search strategy. [lecture-basic-search.pdf, slides 16–17]

5. State vs Node — a common confusion

This distinction is easy to miss and extremely important.

5.1 State

A state is a representation of a physical configuration or situation.

Example:

“I am in Delhi.”

or

“The puzzle tiles are arranged like this.”

5.2 Node

A node is the search data structure that represents a state inside the search tree.

A node can contain information such as:

  • state
  • parent
  • children/successors
  • depth
  • path cost g(n)

The lecture explicitly notes that states do not inherently have parents, children, depth or path cost; nodes do. [lecture-basic-search.pdf, slide 17]

👨‍🏫 Hinglish intuition
State = **actual situation**. Node = **that situation plus the search-system bookkeeping around it**. Think: > State = “Room 204” > > Node = “Room 204 reached from Room 101 after 3 steps with cost 7.”

6. Tree search vs graph search

The first major structural choice is whether we treat each generated occurrence independently or remember states that we have already seen.

Tree search

Tree search can generate the same state again through a different path.

A
├── B
│   └── D
└── C
    └── D    ← same state may appear again

Graph search

Graph search maintains information about previously explored states so repeated-state situations can be avoided.

This matters because failing to detect repeated states can make an otherwise manageable problem explode in size. The lecture explicitly notes this issue near the end of the search discussion.

👨‍🏫 Hinglish
Tree search: > “Jo bhi route mila, naya branch bana do.” Graph search: > “Agar ye state pehle hi dekh chuka hoon, toh same cheez baar-baar kyun explore karun?”

7. The generic tree-search procedure

The lecture gives a general pattern:

  1. Start with the initial state.
  2. Keep candidate nodes in a frontier/fringe.
  3. Select a leaf/node according to the search strategy.
  4. If it is a goal, return the solution.
  5. Otherwise expand it and add its successors.
  6. Repeat until a solution is found or there are no candidates.

A simplified version is:

TREE-SEARCH(problem, strategy)

1. Put the initial state into the search tree.
2. Repeat:
   a. If there are no candidates, return failure.
   b. Choose a leaf/node according to strategy.
   c. If it is a goal, return the corresponding solution.
   d. Otherwise expand it and add successors.

[lecture-basic-search.pdf, slide 16]

The only major thing that changes from one search strategy to another is how the next node is chosen.

That is the key that lets you understand the entire family rather than memorizing independent algorithms.

8. The frontier / fringe

The frontier (also called the fringe) contains generated but not yet fully processed search candidates.

Imagine people waiting in line to be served.

Different search algorithms use different rules for that waiting line.

flowchart LR
    A[Generated nodes] --> B[FRONTIER / FRINGE]
    B --> C[Search strategy chooses one]
    C --> D[Expand node]
    D --> A

Analogy: hospital token system

Suppose 20 patients are waiting.

  • FIFO queue → oldest patient first.
  • LIFO stack → newest patient first.
  • Priority queue → patient with highest priority first.

The search algorithm is doing something very similar with nodes.

9. What makes one search strategy different from another?

Your lecture evaluates search strategies using four major criteria. [lecture-basic-search.pdf, slide 18]

9.1 Completeness

Will the algorithm always find a solution if one exists?

This is about finding something, not finding the best thing.

Example

If a route exists from A to B, a complete algorithm is guaranteed to eventually find one under the assumptions of the algorithm.

9.2 Time complexity

How much computation/search work do we perform?

In search, this is usually described using the number of nodes generated or expanded.

9.3 Space complexity

How much memory must the algorithm keep at once?

This becomes crucial for BFS because BFS can keep a very large frontier in memory.

9.4 Optimality

Does the algorithm always return the least-cost solution?

Do not confuse:

Complete = finds a solution.

with:

Optimal = finds the best/least-cost solution.

An algorithm can be complete but not optimal.

10. The three parameters you must know

Search complexity is often described using three symbols. [lecture-basic-search.pdf, slide 18]

Symbol Meaning
b Maximum branching factor of the search tree
d Depth of the least-cost solution
m Maximum depth of the state space; may be infinite

Branching factor b

If each node can produce at most 3 children, then roughly:

a\text{-like branching factor} \approx 3

We call this b = 3.

👨‍🏫 Hinglish
`b` = ek node se **maximum kitne naye raaste nikal sakte hain**.

Solution depth d

If the shallowest/least-cost solution is 5 steps deep:

\[ d=5 \]
👨‍🏫 Hinglish
`d` = **solution tak pahunchne ke liye kitni depth chahiye**.

Maximum depth m

This is how deep the state space can go.

It may be:

  • finite
  • enormous
  • effectively infinite

DFS becomes dangerous when m is very large or infinite.

11. Why exponential growth is scary

Suppose:

\[ b=3 \]

Then the number of nodes by depth roughly grows like:

Depth 0 → 1
Depth 1 → 3
Depth 2 → 9
Depth 3 → 27
Depth 4 → 81
Depth 5 → 243
Depth 6 → 729

You can see why even a small branching factor becomes a serious problem as depth grows.

Real-life analogy

Imagine asking one person a question, and they give you 3 possible answers. Each answer leads you to 3 more people, and each of those 3 gives 3 more possibilities.

You are not growing by +3.

You are growing by multiplication.

That is why search can become exponential.

12. Uninformed Search — what does “uninformed” mean?

An uninformed search algorithm does not have special knowledge telling it which direction is promising.

It only uses information already supplied by the problem definition.

The lecture lists these uninformed strategies:

  • Breadth-first search
  • Uniform-cost search
  • Depth-first search
  • Depth-limited search
  • Iterative deepening search

[lecture-basic-search.pdf, slide 19]

Important contrast

Later, when we study informed search, we will use an additional estimate called a heuristic.

So:

UNINFORMED SEARCH
Problem definition only
        ↓
BFS / UCS / DFS / DLS / IDS

INFORMED SEARCH
Problem definition + heuristic information
        ↓
Greedy / A*

This distinction is foundational.

13. BFS — Breadth-First Search

Syllabus status: ★★★★★ Core
Chapter importance: Very high
Main idea: Expand the shallowest unexpanded node first.

13.1 Why “breadth”?

Think about the word breadth: wide.

BFS spreads outward layer by layer.

A                depth 0
           /     \
          B       C             depth 1
        / |       | \
       D  E       F  G          depth 2
      /                  \
     H                    I      depth 3

BFS will not normally dive from A → B → D → H immediately.

Instead, it processes:

A → B → C → D → E → F → G → H → I

subject to the exact goal-test convention and child ordering.

14. BFS in everyday life

Analogy: finding a friend through social connections

Suppose you want to find someone in a large college network.

You know Arjun directly.

First check:

  • Arjun's friends.

Then:

  • friends of Arjun's friends.

Then:

  • friends of friends of friends.

You are moving one relationship layer at a time.

That is BFS thinking.

👨‍🏫 Hinglish
> “Pehle saare 1-step wale options, phir saare 2-step wale, phir 3-step wale.”

15. BFS data structure: FIFO queue

The lecture describes BFS as expanding the shallowest node and implementing it with a FIFO queue. New successors go at the end of the queue. [lecture-basic-search.pdf, slides 21–24]

FIFO = First In, First Out.

Real-world analogy

A normal queue at a ticket counter.

Front → [A] [B] [C] [D] ← Back
         ↑
      served first

If B is added after A:

[A, B, C]

A leaves before B.

This is exactly the basic mechanism behind BFS.

16. BFS — algorithmic idea

1. Put the initial node in the queue.
2. Remove the front node.
3. If it is the goal, stop.
4. Otherwise expand it.
5. Put its children at the back of the queue.
6. Repeat.

Pseudocode

BFS(problem):
    frontier ← FIFO queue containing initial node

    while frontier is not empty:
        node ← remove_front(frontier)

        if node is goal:
            return solution(node)

        expand node
        add successors to the back of frontier

    return failure

This is the logic, not a programming implementation.

17. BFS worked example

Use this teaching graph:

flowchart TD
    A((A)) --> B((B))
    A --> C((C))
    B --> D((D))
    B --> E((E))
    C --> F((F))
    C --> G((G))
    D --> H((H))
    E --> I((I))

Let the goal be I.

Step 0

Frontier = [A]

Expand A.

Add B and C.

Frontier = [B, C]

Step 1

Remove B.

Add D and E.

Frontier = [C, D, E]

Step 2

Remove C.

Add F and G.

Frontier = [D, E, F, G]

Step 3

Remove D.

Add H.

Frontier = [E, F, G, H]

Step 4

Remove E.

Generate I.

Frontier = [F, G, H, I]

Eventually I becomes the selected goal node under the lecture's basic tree-search convention.

What did BFS do?

It did not care that H was directly below D.

It cared about depth.

It finished exploring the shallower layers before diving deeper.

18. BFS traversal order — memory picture

Depth 0:        A

Depth 1:       B  C

Depth 2:      D E F G

Depth 3:     H   I

BFS idea:
        left → right
        layer → layer

Memory anchor

BFS = “level by level.”

19. Why BFS can find a shallowest solution

Suppose every action has the same cost—say, every move costs 1.

Then a solution at depth 2 costs:

\[ 2 \]

and a solution at depth 5 costs:

\[ 5 \]

Since BFS explores depth 2 before depth 5, it encounters the shallowest solution first.

Therefore, with equal step costs, BFS is optimal with respect to path cost.

Critical qualification

Do not memorize:

“BFS is always optimal.”

The supplied lecture states:

BFS is optimal if cost = 1 per step; it is not optimal in general.

[lecture-basic-search.pdf, slide 25]

20. BFS completeness

The lecture states:

Complete? Yes, if b is finite.

Why?

If the solution is at a finite depth and every node has a finite number of children, BFS keeps systematically exhausting one finite layer before moving to the next.

Eventually it reaches the solution depth.

👨‍🏫 Hinglish
> “Agar har level manageable hai aur solution finite depth par hai, BFS levels ko skip nahi karega. Isliye eventually solution tak pahunch jayega.”

21. BFS time complexity

The lecture gives:

\[ O(b^{d+1}) \]

for time complexity in the standard exponential search-tree analysis. [lecture-basic-search.pdf, slide 25]

Why?

The number of nodes grows rapidly with depth.

Approximate levels:

\[ 1+b+b^2+\cdots+b^d \]

and in the standard asymptotic treatment this becomes dominated by the largest term.

22. BFS space complexity

The lecture gives:

\[ O(b^{d+1}) \]

because BFS must keep a large frontier in memory. [lecture-basic-search.pdf, slide 25]

This is BFS's famous weakness

BFS is memory hungry.

👨‍🏫 Hinglish
> “BFS ko sabko yaad rakhna padta hai jo aage explore karna hai. Isliye RAM bahut jaldi bhar sakti hai.”

23. BFS property card

Property BFS
Selection rule Shallowest unexpanded node
Data structure FIFO queue
Complete? Yes, if b is finite
Optimal? Yes, when every step has equal cost
Time O(b^(d+1))
Space O(b^(d+1))
Main strength Finds shallow solutions systematically
Main weakness High memory usage

Exam memory line:

BFS = FIFO + shallowest + complete + unit-cost optimal + exponential memory.

24. DFS — Depth-First Search

Syllabus status: ★★★★★ Core
Main idea: Expand the deepest unexpanded node first.

This is the opposite mental picture of BFS.

BFS says:

“Let me spread out.”

DFS says:

“Let me go down one path.”

25. DFS visual intuition

Using the same tree:

A
           /     \
          B       C
        / |       | \
       D  E       F  G
      / \
     H   ...

With left-to-right child ordering, DFS tends to behave like:

A → B → D → H

before backing up to try another branch.

Real-life analogy

Imagine exploring a building with many corridors.

You choose one corridor and say:

“I will keep following this corridor until I reach a dead end.”

Only then do you return and try another branch.

That is DFS.

26. Hinglish explanation of DFS

“Ek raasta pakdo aur usmein jitna deep ja sakte ho jao. Dead end mila? Backtrack karo. Phir next branch try karo.”

The word to remember is:

DEPTH

27. DFS data structure: LIFO stack

The lecture describes DFS as using a LIFO queue, meaning successors are put at the front. [lecture-basic-search.pdf, slides 36–40]

LIFO = Last In, First Out.

Everyday analogy

A stack of plates.

[D] ← placed last, removed first
     [C]
     [B]
     [A]

This naturally creates depth-first behavior.

28. DFS — algorithmic idea

1. Put the initial node on a stack.
2. Remove the top node.
3. If it is the goal, stop.
4. Otherwise expand it.
5. Put successors so that the desired next child is on top.
6. Continue deeply.
7. Backtrack when a branch is exhausted.

Pseudocode

DFS(problem):
    frontier ← LIFO stack containing initial node

    while frontier is not empty:
        node ← remove_top(frontier)

        if node is goal:
            return solution(node)

        expand node
        add successors to the frontier

    return failure

The exact order in which siblings are placed on the stack affects the traversal order.

30. DFS completeness

The lecture states DFS is not complete in general because it can fail in spaces with infinite depth or loops. [lecture-basic-search.pdf, slide 41]

Example: infinite branch

A
└── B
    └── C
        └── D
            └── E
                └── ...

Suppose the goal is somewhere in another branch:

A
├── B → C → D → E → ...
└── GOAL

A naive DFS can keep going forever down the left branch and never return to try the right branch.

👨‍🏫 Hinglish
> “DFS agar galat deep path mein fas gaya, toh wahi jaata reh sakta hai.”

31. Repeated states and DFS

The lecture notes that DFS can be modified to avoid repeated states along the current path, making it complete in finite spaces under the relevant assumptions. [lecture-basic-search.pdf, slide 41]

This is why blindly memorizing:

“DFS is incomplete.”

is not precise enough.

A better exam statement is:

Standard DFS is not complete in infinite-depth spaces or spaces with loops; with repeated-state/path checking it is complete in finite spaces under the stated assumptions.

32. DFS time complexity

The lecture gives:

\[ O(b^m) \]

where m is the maximum search depth. [lecture-basic-search.pdf, slide 41]

The danger is obvious if:

\[ m \gg d \]

That means the state space may have very deep branches even though a shallow solution exists.

DFS might spend huge effort exploring the wrong depth.

33. DFS space complexity

The lecture gives:

\[ O(bm) \]

which is linear in the depth, compared with BFS's exponentially growing memory requirement. [lecture-basic-search.pdf, slide 41]

This is DFS's major attraction.

👨‍🏫 Hinglish
> “DFS zyada cheezein memory mein ek saath nahi rakhta; woh mostly current deep path aur kuch pending branches sambhalta hai.”

34. DFS optimality

The lecture states:

DFS is not optimal.

Why?

Because it may find a solution down a deep/expensive branch before a much shallower or cheaper solution elsewhere.

Example

A
        /   \
       B     C
       |     |
       D     G ← shallow goal
       |
       E
       |
       G ← deep goal

If DFS explores the left branch first, it may reach the deeper goal before considering the shallow right branch.

Therefore:

Finding a solution ≠ finding the best solution.

37. When would you conceptually prefer BFS?

BFS is attractive when:

  • the solution is expected to be shallow;
  • step costs are equal and you want a shallowest/least-step solution;
  • you can afford the memory needed for the frontier.

Example

Finding the minimum number of edges in an unweighted graph.

38. When would you conceptually prefer DFS?

DFS is attractive when:

  • memory is limited;
  • the search space is very deep but solutions may be found deep down;
  • you can tolerate the possibility of exploring a poor/deep branch first.

Important caveat

DFS's low memory usage does not mean it is always the better practical choice. The search space's structure matters.

39. Uniform-Cost Search (UCS) — lecture extension and bridge

Syllabus status: Supporting / lecture material; not explicitly named in DSC-14 Unit I.
Why study it here? It makes the difference between depth and cost clear and provides a direct conceptual bridge to A*.

The lecture defines UCS as:

Expand the least-cost unexpanded node.

Implementation:

frontier is ordered by path cost, lowest first.

[lecture-basic-search.pdf, slide 27]

39.1 Why BFS is not enough when costs differ

Consider:

A → B → G
costs: 1 + 1 = 2

A → C → D → G
costs: 0.2 + 0.2 + 0.2 = 0.6

The second route has more steps but lower total cost.

BFS focuses on depth.

UCS focuses on path cost.

That distinction is fundamental.

39.2 UCS mental model

Frontier:

Node      path cost
-------------------
A            0
B            4
C            2   ← choose C
D            7

The smallest accumulated cost is selected.

👨‍🏫 Hinglish
> “Kitne steps hue ye main issue nahi hai. Ab tak total kitna cost hua hai, woh dekho.”

39.3 UCS and BFS relationship

The lecture explicitly states:

UCS is equivalent to BFS when all step costs are equal.

[lecture-basic-search.pdf, slide 27]

That is a beautiful connection:

Equal step cost
      ↓
least path cost ↔ shallowest depth
      ↓
UCS behaves like BFS

40. Depth-Limited Search (DLS)

Syllabus status: Supporting / lecture material.
Idea: DFS + a maximum allowed depth.

The lecture defines DLS as depth-first search with a depth limit l; nodes at depth l are not expanded. [lecture-basic-search.pdf, slide 43]

Why?

DFS's big problem is getting lost forever in very deep spaces.

DLS says:

“You may go deep—but only up to here.”

A
               /   \
              B     C
             / \
            D   E
           /
          X

limit l = 2

A(depth0)
B(depth1)
D(depth2) ← stop expanding here
👨‍🏫 Hinglish
> “Depth ka speed limit laga do.”

41. DLS properties

Under the standard analysis from the lecture:

  • Complete if the depth limit is at least the solution depth under the relevant assumptions.
  • Time depends on the depth limit, commonly expressed as O(b^l).
  • Space is commonly O(bl).
  • It is not generally optimal.

The depth limit l is the key new parameter.

42. Iterative Deepening Search (IDS)

Syllabus status: Supporting / lecture material.
Main idea: Repeat depth-limited search with progressively larger limits.

The lecture gives the process directly: [lecture-basic-search.pdf, slide 43]

  1. Start at depth 1.
  2. Perform depth-first search.
  3. If the solution is found, stop.
  4. Otherwise increase the limit.
  5. Repeat.

A more conventional sequence may begin with depth 0; the conceptual idea is the same.

43. Why would we repeatedly search?

This initially sounds wasteful.

Why search depth 1 and then throw it away?

Why search depth 2 and then repeat?

Because IDS combines two desirable properties:

  • the low memory behavior of DFS;
  • the shallow-solution guarantee of BFS under the same unit-cost assumptions.

Real-life analogy

Suppose you are searching for a person in a building but don't know which floor they are on.

You could explore one corridor endlessly.

Or you could say:

“First I'll inspect up to floor 1.”

“Not there? Now inspect up to floor 2.”

“Not there? Now up to floor 3.”

This is iterative deepening.

          / \

        / |   | \
       D  E   F G

45. IDS properties

The supplied lecture states: [lecture-basic-search.pdf, slide 48]

  • Complete: Yes.
  • Time: O(b^d) in the standard asymptotic treatment.
  • Space: O(bd).
  • Optimal: Yes, if step cost = 1.

The lecture also gives a numerical comparison showing how IDS can use much less node expansion than BFS in a particular example while retaining the low-space behavior. [lecture-basic-search.pdf, slide 48]

46. Why repeated work is sometimes acceptable

IDS repeats work near the top of the tree.

For example, nodes close to the root may be expanded several times.

But the number of nodes grows exponentially with depth, so the deepest level dominates the total work.

Hence the repeated shallow work is often a reasonable trade-off for drastically lower memory usage.

52. Common misconceptions

Misconception 1: “BFS is always optimal.”

Wrong.

Correct:

BFS is optimal when every action/step has equal cost under the standard assumptions.

Misconception 2: “DFS always uses constant memory.”

Wrong.

The lecture gives:

\[ O(bm) \]

That is low compared with BFS's exponential memory, but it is not literally O(1).

Misconception 3: “Complete means optimal.”

Wrong.

Complete = guaranteed to find a solution under assumptions.
Optimal = guaranteed to find the least-cost solution.

Misconception 4: “DFS always reaches the goal faster.”

Wrong.

DFS can be fast when its first deep branch happens to contain a solution, but there is no guarantee.

Misconception 5: “Depth means cost.”

Wrong.

Depth counts actions/levels.

Path cost sums the costs of those actions.

That distinction becomes crucial when you move from BFS to UCS and later A*.

Misconception 6: “A state and a node are the same thing.”

Not exactly.

A state is the represented configuration; a node is the search structure carrying the state plus path/search information. [lecture-basic-search.pdf, slide 17]

Misconception 7: “Uninformed means random.”

No.

Uninformed search is still systematic. It simply does not use a special heuristic estimate.

53. Formula and property cards

Formula Card — BFS

\[ T = O(b^{d+1}) \]

Meaning

Approximate exponential time in the depth of the shallowest solution.

Memory trigger

b^(d+1) → expensive memory.

Formula Card — DFS

\[ T = O(b^m) \]
\[ S = O(bm) \]

Meaning

Time depends on the maximum depth m; memory grows roughly linearly with depth under the standard analysis.

Formula Card — IDS

\[ T = O(b^d) \]
\[ S = O(bd) \]

Condition for optimality

Equal/unit step costs in the standard formulation.

54. A small mathematical derivation: why the tree size grows exponentially

Suppose each node has at most b children.

Then:

Depth 0:

\[ 1=b^0 \]

Depth 1:

\[ b=b^1 \]

Depth 2:

\[ b^2 \]

Depth 3:

\[ b^3 \]

So the number of nodes through depth d is approximately:

\[ 1+b+b^2+\cdots+b^d \]

This is a geometric series.

Its dominant term grows exponentially with d, which is why search can become computationally expensive very quickly.

Why this matters

It explains why:

  • a small increase in depth can be expensive;
  • heuristics later become valuable;
  • memory can become a bigger problem than raw computation.

57. Exam-style numerical: complexity reasoning

Suppose:

\[ b=4,\quad d=3 \]

For BFS, the asymptotic form is:

\[ O(b^{d+1}) \]

Substitute:

\[ O(4^4)=O(256) \]

This does not mean the algorithm literally expands exactly 256 nodes in every implementation. It demonstrates how the asymptotic expression grows with branching factor and solution depth.

Exam warning

Do not convert Big-O notation into an exact node count unless the question explicitly asks for an exact count and gives enough information to compute it.

58. Exam-style conceptual question

Question

Explain why IDS can combine the low space requirement of DFS with the shallow-solution behavior of BFS.

Model answer structure

  1. IDS performs depth-limited DFS.
  2. It starts with a small depth limit.
  3. If the goal is not found, it increases the depth limit and repeats.
  4. Like DFS, each individual pass uses depth-bounded memory.
  5. Like BFS, it does not skip a shallower solution and systematically increases the explored depth.
  6. Under unit step costs, the lecture states IDS is complete and optimal.

59. Why search strategy analysis matters

Search algorithms are not just different code implementations.

They represent different assumptions and trade-offs.

SEARCH STRATEGY
                          |
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
      What first?      Memory?          Guarantee?
          |               |               |
      depth/cost       high/low      complete/optimal

A good AI engineer therefore does not ask:

“Which algorithm do I remember?”

They ask:

“What does the problem structure allow me to exploit?”

That is the beginning of intelligent problem solving.

73. Final memory sheet

The five phrases

BFS: shallowest first.

UCS: cheapest path first.

DFS: deepest first.

DLS: deepest first, but stop at a limit.

IDS: increase the depth limit gradually.

The four evaluation words

Complete? Will I find a solution?

Optimal? Will I find the best one?

Time? How much computation?

Space? How much memory?

The three symbols

b = branching factor
d = solution depth
m = maximum depth
