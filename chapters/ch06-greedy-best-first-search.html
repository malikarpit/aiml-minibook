2. One-minute intuition

English

Greedy Best-First Search says:

“I don't care very much about how much I have already spent. I mainly care about which option currently looks closest to the goal.”

So if three nodes are waiting in the frontier:

A → h(A) = 20
B → h(B) = 8
C → h(C) = 13

Greedy chooses B, because 8 is the smallest heuristic value.

👨‍🏫 Hinglish
> **Greedy ka mindset:** “Jo option abhi destination ke sabse paas *lag raha hai*, usko pehle try karo.” Usko yeh primary concern nahi hai ki tum us node tak pahunchne mein pehle kitna cost kar chuke ho.

3. The analogy — choosing a restaurant in an unfamiliar mall

Suppose you want to reach a restaurant on the top floor of a huge shopping mall.

You have several possible corridors in front of you.

A shopkeeper tells you approximate distances to the restaurant:

Corridor A → looks 120 m away
Corridor B → looks 70 m away
Corridor C → looks 40 m away

A simple greedy decision is:

“Go toward C. It looks closest.”

That is exactly the role of h(n).

Where the analogy breaks

Real roads, corridors and search graphs may have obstacles, one-way paths, stairs, blocked passages or expensive detours.

So:

“Looks closer” is not the same as “is part of the cheapest complete route.”

That distinction is the reason Greedy Search is not generally optimal.

5. What is Best-First Search?

The supplied lecture frames Best-First Search as follows:

Use an evaluation function for each node, interpret that value as an estimate of desirability, and expand the most desirable unexpanded node.

The fringe/frontier is kept ordered according to that evaluation. The lecture then identifies Greedy Search and A* as important special cases. Course source: lecture-informed-search.pdf, slides 5–6.

So the general pattern is:

Best-First Search
                        │
             choose an evaluation function
                        │
               score candidate nodes
                        │
             expand the best candidate
                      /     \
                     /       \
                Greedy         A*
                 h(n)        g(n) + h(n)

The difference between these two will become the central comparison in C07.

6. The key idea: `h(n)`

The heuristic function is written as:

\[ \boxed{h(n)} \]

where n is a node/state being considered.

The supplied course lecture defines:

\[ \boxed{h(n)=\text{estimated cost from }n\text{ to the closest goal}} \]

For road navigation, the lecture uses straight-line distance to Bucharest as the example heuristic. Course source: lecture-informed-search.pdf, slide 9.

Symbol-by-symbol

Symbol Meaning
n current candidate node
h(n) estimated remaining cost from n to a goal
goal state we are trying to reach
👨‍🏫 Hinglish
> `h(n)` basically poochta hai: **“Agar main abhi is node par hoon, toh goal tak roughly kitna aur jaana padega?”**

7. Heuristic is an estimate, not the solution

Suppose:

\[ h(A)=15 \]

This does not mean the actual remaining cost is exactly 15.

It means:

According to our chosen heuristic, the remaining cost is estimated to be 15.

There may be an actual cheapest remaining cost of 18, 15, 11, or another value, depending on the problem and the heuristic.

This is why you must not write:

“h(n) is the remaining cost.”

Instead write:

“h(n) is an estimate of the remaining cost.”

That single word — estimate — matters.

8. Why call it “Greedy”?

The word greedy means that at each decision point the algorithm makes the locally attractive choice according to its current information.

It does not begin by solving the whole route optimally in its head.

It asks:

“Which available option looks best right now?”

👨‍🏫 Hinglish memory
> **Greedy = “Abhi jo best lag raha hai, woh karo.”** This is useful because the name itself should remind you of the algorithm's behavior.

9. Greedy Best-First Search evaluation function

For Greedy Best-First Search:

\[ \boxed{f(n)=h(n)} \]

In other words, the search priority is determined directly by the heuristic.

The algorithm therefore expands the node with the smallest h(n) when lower values represent closer estimated distance/cost.

Example

Suppose the frontier is:

Node h(n)
A 12
B 5
C 9
D 18

Greedy chooses:

\[ \boxed{B} \]

because:

\[ 5 \lt 9 \lt 12 \lt 18 \]
👨‍🏫 Hinglish
> “Sabse chhota heuristic value = sabse promising lag raha hai.”

10. What Greedy does **not** look at

This is the most important setup for understanding A*.

Suppose:

Node Cost already spent g(n) Estimated remaining h(n)
A 2 10
B 100 4

Greedy looks only at h(n):

\[ h(A)=10,\qquad h(B)=4 \]

Therefore it prefers B.

But B has already cost 100 to reach.

Greedy does not combine these two quantities in its decision rule.

The important mental contrast

GREEDY

“How close does this node look?”
             ↓
           h(n)

A* (next chapter)

“How expensive has my route been + how much seems left?”
             ↓
        g(n) + h(n)

This is the central conceptual bridge from C06 to C07.

11. The Romania example

The supplied lecture uses the classic Romania route-finding problem and defines the heuristic as the straight-line distance to Bucharest.

Conceptually:

Current city
     │
     │  straight-line estimate
     ▼
Bucharest

The road network itself may require turns and detours, but straight-line distance provides a quick estimate of how far the destination appears to be.

A small original example

Suppose the frontier contains:

Arad      h = 366
Sibiu     h = 253
Fagaras   h = 178
Pitesti   h = 98

Greedy would prefer Pitesti, because 98 is the smallest heuristic.

The exact values and the full Romania expansion sequence in the supplied course slides should be followed from the course example rather than replaced by this teaching example.

12. Step-by-step Greedy example

Consider this original search graph:

Start
                 /     \
                A       B
              /  \     / \
             C    D   E   F
                  |       |
                  G       Goal

Suppose the heuristic values are:

A = 8
B = 5
C = 7
D = 2
E = 6
F = 1
G = 3
Goal = 0

Step 0

Frontier:

[A, B]

Values:

A → 8
B → 5

Greedy picks B.

Step 1

Expand B.

New frontier:

[A, E, F]

Values:

A → 8
E → 6
F → 1

Greedy picks F.

Step 2

Expand F.

Its successor is Goal.

Frontier now contains:

[A, E, Goal]

Since:

\[ h(Goal)=0 \]

Goal is selected.

Result

Greedy reaches the goal through:

Start → B → F → Goal

What did Greedy do?

At each step it asked only:

Which candidate has the smallest heuristic?

13. Why Greedy can be fooled

Now change the graph:

Start
                /     \
             Route A   Route B
               |          |
           looks close   looks farther
               |          |
              Goal       Goal

Imagine:

Route A:
  h = 2 at the beginning
  but the actual road contains a huge detour

Route B:
  h = 6 at the beginning
  but the road is almost direct

Greedy prefers Route A because:

\[ 2 \lt 6 \]

even though Route B may ultimately be much cheaper.

The core lesson

A low heuristic value can make a node attractive without making the complete path optimal.

That is why Greedy Search is not generally optimal.

14. A concrete trap: “closest-looking” is not “cheapest route”

Think about driving.

A road may physically point toward your destination but be:

  • blocked later,
  • full of detours,
  • restricted,
  • expensive,
  • or connected to a dead end.

A heuristic may see “close” while the full route sees “bad”.

Greedy is deliberately willing to take this risk because it prioritizes the current heuristic estimate.

15. Greedy Search algorithm

Plain-English procedure

  1. Put the initial node into the frontier.
  2. Look at the candidate nodes in the frontier.
  3. Compute/use h(n) for each.
  4. Select the node with the smallest heuristic value.
  5. If it is the goal, return the solution.
  6. Otherwise expand it.
  7. Add the resulting children to the frontier.
  8. Repeat.

Pseudocode

GREEDY-BEST-FIRST-SEARCH(problem)

    frontier ← priority queue ordered by h(n)
    insert initial node into frontier

    while frontier is not empty:
        n ← remove node with smallest h(n)

        if n is a goal:
            return solution(n)

        expand n
        insert its successor nodes into frontier

    return failure

The exact implementation details can vary between tree-search and graph-search versions. The supplied lecture frames Best-First Search in terms of a fringe ordered by desirability and describes Greedy as the h(n) special case. Course source: slides 5–9.

16. What does “priority queue” mean here?

A normal queue says:

“First come, first served.”

A priority queue says:

“The most important/lowest-priority-score item gets served first.”

For Greedy:

Smaller h(n) → higher search priority

Everyday analogy

Imagine a hospital triage queue.

It isn't simply:

“Who arrived first?”

Instead, cases are ordered according to a priority score.

Greedy similarly orders nodes according to the chosen search score.

17. Tree Search vs Graph Search

A subtle but important point:

Tree Search

The search can generate the same state multiple times through different paths.

Graph Search

The algorithm additionally tracks already explored states to avoid repeatedly exploring the same state.

The supplied Basic Search lecture distinguishes a state from a node and explains that a search node contains information such as its parent, children, depth and path cost. Course source: lecture-basic-search.pdf, slide 17.

This matters for Greedy because the supplied lecture notes that it can get stuck in loops, while repeated-state checking changes that behavior.

18. Completeness

A search algorithm is complete if it is guaranteed to find a solution whenever a solution exists, subject to the assumptions of the search setting.

The supplied Greedy Search lecture states:

Greedy Search is not complete in general because it can get stuck in loops.

The lecture gives the example:

Iasi → Neamt → Iasi → Neamt → ...

and notes that in a finite space with repeated-state checking, completeness can be recovered under those conditions. Course source: lecture-informed-search.pdf, slide 15.

👨‍🏫 Hinglish
> “Greedy ek hi attractive direction ke chakkar mein ghoomta reh sakta hai.”

19. Optimality

Greedy Best-First Search is not optimal according to the supplied course lecture.

Optimal means:

If solutions have different costs, the algorithm is guaranteed to return a least-cost solution.

Greedy does not have that guarantee.

It may find a goal quickly while another solution has lower total cost.

Memory anchor

Greedy optimizes the appearance of the next step, not the guaranteed total path cost.

20. Time complexity

For the supplied course framing, Greedy Search has worst-case time complexity:

\[ \boxed{O(b^m)} \]

where:

  • b = maximum branching factor
  • m = maximum depth of the search space

The lecture also emphasizes that a good heuristic can produce dramatic practical improvements. Course source: lecture-informed-search.pdf, slide 15.

What does b mean?

If every node can have approximately 3 children, then:

\[ b=3 \]

What does m mean?

m is the maximum depth of the state space being considered.

Why can this become huge?

Because the number of possible nodes grows roughly like:

\[ 1+b+b^2+b^3+\cdots+b^m \]

which grows exponentially with depth.

21. Space complexity

The supplied lecture gives:

\[ \boxed{O(b^m)} \]

Greedy may need to keep many generated candidates in memory.

The lecture describes the frontier/fringe as a queue and reports O(bm) space in its course notation, where the spacing in the slide is compact. Interpreted in the standard textbook notation, this is O(b^m).

👨‍🏫 Hinglish
> “Greedy sirf ek node yaad nahi rakhta; usko bahut saare candidate nodes memory mein rakhne pad sakte hain.”

22. Why is Greedy sometimes very effective?

Because the heuristic can eliminate a huge amount of obviously unattractive exploration.

Suppose the search space has millions of nodes.

A blind strategy may explore a large portion of them.

A useful heuristic can say:

“These nodes are much less promising; concentrate over here first.”

The supplied lecture explicitly notes that a good heuristic can dramatically improve the practical search effort. Course source: lecture-informed-search.pdf, slide 15.

This is one reason informed search is so important.

23. Greedy vs BFS — same problem, different attitude

Suppose the search tree is:

S
              /     |     \
             A      B      C
            / \    / \    / \
           ... ... ... ... ...

BFS

BFS asks:

“Which node is shallowest?”

Greedy

Greedy asks:

“Which node appears closest to the goal?”

Neither question is universally better. They are different search strategies designed for different assumptions.

24. Greedy vs Uniform-Cost Search

Uniform-Cost Search

Prioritizes:

\[ \boxed{g(n)} \]

So it cares about cost already paid.

Greedy

Prioritizes:

\[ \boxed{h(n)} \]

So it cares about cost estimated to remain.

Mental model

UCS:
“How expensive has my journey been so far?”
          ↓
        g(n)

Greedy:
“How close do I appear to the destination?”
          ↓
        h(n)

This sets up A*:

A*:
“How much have I spent + how much seems left?”
                    ↓
               g(n) + h(n)

25. Greedy vs A* — the essential comparison

Property Greedy Best-First A*
Main score h(n) g(n)+h(n)
Uses cost so far? No Yes
Uses heuristic? Yes Yes
General optimality guarantee No Yes, with the required admissibility conditions in the course framing
Main intuition “Looks closest” “Looks cheapest overall”
Course chapter C06 C07

The simplest memory sentence

Greedy = future estimate only.
A* = past cost + future estimate.

26. Mathematical lens

There is not much difficult mathematics in Greedy itself.

You mainly need to understand:

Function notation

\[ h(n) \]

means a function whose input is a node and whose output is a heuristic value.

Ordering

If:

\[ h(A)=4, \quad h(B)=9, \quad h(C)=6 \]

then:

\[ A \prec C \prec B \]

in the priority order when smaller heuristic values are preferred.

Prerequisite math

  • basic functions
  • inequality comparison
  • arithmetic

No advanced calculus is required for this chapter.

27. Formula Card

Greedy Best-First Search

Evaluation function:

\[ \gt \boxed{f(n)=h(n)} \gt \]

Meaning:

h(n) estimates the remaining cost to a goal.

Selection rule:

Choose the candidate with the smallest h(n).

Memory phrase:

“Pick the node that looks closest.”

Step 1 — Compare

\[ 6 \lt 9 \lt 11 \lt 14 \]

👨‍🏫 Hinglish
> “B ka heuristic sabse chhota hai, toh B sabse promising dikh raha hai.”

29. Worked Numerical — Greedy ignores path cost

Suppose:

Node g(n) h(n)
A 3 12
B 40 5
C 8 9

Greedy compares:

\[ h(A)=12,\quad h(B)=5,\quad h(C)=9 \]

Therefore:

\[ \boxed{B} \]

Even though:

\[ g(B)=40 \]

is much larger than g(A).

Why?

Because Greedy's evaluation is:

\[ f(n)=h(n) \]

not:

\[ f(n)=g(n)+h(n) \]

That second rule belongs to A*.

30. Common misconceptions

Misconception 1

“Greedy Search always finds the shortest path.”

Correct

No. The supplied lecture explicitly marks Greedy as not optimal.

Misconception 2

“The heuristic is the actual remaining cost.”

Correct

No. It is an estimate.

Misconception 3

“Greedy uses both g(n) and h(n).”

Correct

Not in the Greedy evaluation rule used here.

Greedy uses:

\[ \boxed{h(n)} \]

A* uses:

\[ \boxed{g(n)+h(n)} \]

Misconception 4

“Smaller h(n) means the complete route is definitely shorter.”

Correct

It only means the node appears closer according to the heuristic.

Misconception 5

“Informed search means the algorithm knows the answer.”

Correct

No. It has additional problem-specific guidance; it still has to search.

31. Failure Case — heuristic trap

Start
                      /       \
                     A         B
                  h=1           h=8
                   |              |
                detour          direct
                   |              |
                  Goal          Goal

Greedy immediately prefers A because:

\[ 1\lt 8 \]

But if the A branch costs 100 units while B costs 10 units, Greedy's choice is poor from a total-cost perspective.

Lesson

A heuristic can guide search effectively while still being insufficient to guarantee an optimal route when used alone.

32. Course-specific example — Greedy Search on Romania

The supplied lecture uses straight-line distance to Bucharest:

\[ \boxed{h_{SLD}(n)=\text{straight-line distance from }n\text{ to Bucharest}} \]

The course then presents a sequence of Greedy Search examples using the Romania map and step-cost map. Course source: lecture-informed-search.pdf, slides 7–14.

How to study the course example

Do not just memorize the final city sequence.

For every step, ask:

  1. What nodes are currently in the frontier?
  2. What is h(n) for each?
  3. Which has the lowest value?
  4. Which node is expanded?
  5. What new successors appear?
  6. Does the path cost matter to Greedy's current decision?

That is the reasoning the Main Book wants you to learn.

36. Practice Set

A. Conceptual

Q1

38. Memory Anchor

GREEDY = “WHAT LOOKS CLOSEST?”

\[ \gt \boxed{f(n)=h(n)} \gt \]

Smallest h wins.

It can be fast and useful with a good heuristic, but it is not generally optimal and can get into loops without appropriate repeated-state handling.

43. What comes next?

Greedy answered:

“Which node looks closest to the goal?”

But we identified its weakness:

It may ignore how much the route has already cost.

The next question is therefore:

Can we combine the cost already spent with the estimated cost still remaining?

That is the idea behind A*.

\[ \boxed{f(n)=g(n)+h(n)} \]
