1. Why do we need local search?

Imagine that you are solving a very large puzzle.

A normal search method may try to remember many possibilities:

Problem
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
      State A     State B     State C
      /   \       /   \       /   \
     ...  ...    ...   ...    ...  ...

That becomes expensive when the space is huge.

But imagine a different type of problem:

You do not actually care about the route you took. You care only about reaching a very good final configuration.

Examples:

  • arrange a timetable with as few conflicts as possible;
  • place queens so that none attack each other;
  • find a short travelling-salesperson tour;
  • tune a solution until its score improves.

For these problems, keeping the complete search tree may be unnecessary.

The supplied lecture describes this situation explicitly: when the path is irrelevant and the goal state itself is the solution, we can keep a single current state and repeatedly try to improve it. It notes that this uses constant space and can be suitable for online or offline search. Course source: lecture-informed-search.pdf, slides 39–40.

2. One-minute intuition

English

Local search is a family of methods that says:

“I have one current solution. Instead of remembering the whole history, look at nearby alternatives and try to move toward a better one.”

The algorithm behaves more like someone improving a draft than someone mapping every road in a city.

👨‍🏫 Hinglish
> Socho tumhare paas already ek solution hai. Tum har possible solution ka tree banane ke bajaye bas current solution ko dekhte ho aur poochte ho: **“Iske aas-paas koi better solution mil sakta hai?”** Agar milta hai, move karo.

3. The key difference: path search vs state optimization

Classical path search

You usually care about:

Start
  ↓
State
  ↓
State
  ↓
State
  ↓
Goal

The path itself matters because the sequence of actions is the answer.

Local optimization

You often care about the final configuration:

Current configuration
        ↓
   improve it
        ↓
Better configuration
        ↓
   improve it
        ↓
Best configuration found

Analogy

Think of editing a resume.

You don't need to preserve every intermediate draft as a giant tree. You can keep the current draft, try a change, compare the result, and retain the better version.

That is the mental model for local search.

4. State-space landscape — the visual model

A useful way to understand local search is to imagine every possible state placed on a landscape.

▲ quality / value
                    │
              /
\        GLOBAL MAXIMUM
            /    
\        ★
      _____/       
\
     /               
\      local peak
    /    ★             
\    /\
___/____________________\__/  \____

        state space →

Depending on the problem, higher may mean:

  • higher utility;
  • fewer conflicts;
  • lower cost if we reinterpret the landscape as an error/cost surface.

Important

The landscape picture is a mental model, not a literal requirement that every AI problem is physically continuous.

A discrete problem such as n-queens still has a collection of neighbouring configurations; the landscape simply gives us a convenient way to visualize their quality.

5. What is a neighbour?

A neighbour is a state reachable from the current state by a small permitted change.

Examples:

n-Queens

Move one queen to another square.

TSP

Swap or exchange parts of the tour.

Timetable

Move one class to a different slot.

So the definition is problem-dependent:

Neighbourhood = the set of candidate states reachable by one small local modification.

👨‍🏫 Hinglish
> Neighbour ka matlab “mathematically next” nahi hota. Bas current solution mein ek chhota legal change karke jo states ban sakti hain, woh neighbours hain.

6. Hill Climbing

The supplied lecture presents hill climbing as the basic iterative-improvement method and uses the phrase:

“Like climbing Everest in thick fog with amnesia.”

That is a particularly useful intuition for the algorithm. Course source: lecture-informed-search.pdf, slides 42–43.

Why the analogy works

  • Everest → want a very high-quality solution.
  • Fog → cannot see the entire search space.
  • Amnesia → do not remember the whole path/tree.
  • Next move → choose a better neighbour.

7. Hill-climbing procedure

The supplied lecture gives this basic procedure:

  1. Start from a complete solution, possibly randomly generated.
  2. Consider neighbouring states.
  3. If there is no better neighbour, stop.
  4. Otherwise adopt the best neighbour.
  5. Repeat.

Course source: lecture-informed-search.pdf, slide 43.

8. Hill climbing — real-life analogy

Imagine walking uphill in dense fog.

You can only see the ground near your feet.

You check the nearby directions and choose the one that goes upward most steeply.

Then you repeat.

Eventually you may reach a point where every immediately visible direction goes downhill.

You stop.

But there is a problem:

You may be standing on a small hill while a much higher mountain exists somewhere else.

That is the central weakness of hill climbing.

9. The three classic problems of hill climbing

9.1 Local maximum

GLOBAL MAX
                  /\
                 /  \
        local   /    \
        max     /      \
        /\     /        \
_______/  \___/__________
      ↑
 current search may stop here

The current state is better than all immediate neighbours, so the algorithm stops—even though a better state exists elsewhere.

👨‍🏫 Hinglish
> Tum ek chhoti hill ke top par pahunch gaye. Aas-paas koi higher point nahi dikh raha, isliye algorithm bolta hai “done”. Lekin door ek aur bahut badi hill ho sakti hai.

9.2 Plateau / flat region

___________
           \____

Many neighbouring states have the same value.

The algorithm may have difficulty deciding where to move.

9.3 Ridge

A ridge is a narrow region where improving movement may require a combination of moves that is not obvious from the immediate neighbourhood.

Mental model

You are on a narrow mountain ridge. The best direction may not be represented by a single obvious sideways step.

10. Random-restart hill climbing

A direct response to local maxima is:

Try again from another starting point.

The supplied lecture states that random-restart hill climbing can overcome local maxima and is trivially complete under its stated finite-space setup. Course source: lecture-informed-search.pdf, slide 44.

Random start #1 → local maximum → restart
Random start #2 → better region   → restart
Random start #3 → global maximum → STOP
👨‍🏫 Hinglish
> Ek hi starting point par depend mat karo. Multiple random starting points se hill climbing chalao. Kabhi kisi restart se better mountain mil jayegi.

11. Local Beam Search

Instead of keeping only one current state, keep k states.

The supplied lecture defines the idea as:

keep k states and choose the top k among all their successors.

Course source: lecture-informed-search.pdf, slide 45.

Visual

State A ──┬─ A1
                    ├─ A2
                    └─ A3

          State B ──┬─ B1
                    ├─ B2
                    └─ B3

          State C ──┬─ C1
                    ├─ C2
                    └─ C3

                  ↓ rank all successors

          Keep best k states

Important distinction

Local beam search is not simply k independent hill-climbing runs.

The states interact because their successors are pooled and the best k are selected together.

Problem

The lecture notes that all k states can end up on the same local hill.

One proposed idea is to choose k successors randomly but bias that choice toward good ones. Course source: slide 45.

12. Simulated Annealing

Hill climbing refuses to make a worse move.

That is exactly why it can get stuck.

Simulated annealing changes this rule:

Sometimes allow a worse move so that the search can escape a local maximum.

The key idea is to start more willing to explore and gradually become more conservative.

13. The physical analogy — cooling metal

In metallurgy, annealing involves controlled heating and cooling.

For our algorithmic mental model:

High temperature
    ↓
More exploration
More willingness to accept bad moves

    ↓ cooling

Lower temperature
    ↓
Less exploration
More selective

    ↓

Converge toward a good solution
👨‍🏫 Hinglish
> Starting mein algorithm thoda “risk-taking” hota hai. Woh kabhi bad move bhi try kar sakta hai. Jaise-jaise temperature kam hota hai, algorithm disciplined ho jata hai.

14. Simulated annealing — course formulation

The supplied lecture gives the following process:

  1. Reduce temperature T over time.
  2. Compute the best greedy move.
  3. Randomly draw another move.
  4. Compute:
\[ \Delta E = \text{value(random)}-\text{value(best)} \]
  1. Accept the random move with probability:
\[ \boxed{e^{\Delta E/T}} \]

under the lecture's maximization-style formulation.

  1. Otherwise keep the best move.

Course source: lecture-informed-search.pdf, slide 46.

Important intuition

When T is high, the algorithm is more exploratory.

When T becomes low, accepting a worse move becomes less likely.

15. Why allowing bad moves can be useful

Suppose the landscape looks like:

local peak
          /\
         /  \
________/    \______          global peak
                       _________/\
_____________________/           \__

A strict hill climber reaches the first peak and stops.

Simulated annealing may temporarily move downhill:

local peak
    ★
   / \
__/   \____
          \   ← temporary bad move
           \__________
                      /\
                     /  \
                    ★ global

That temporary loss can provide access to a better region.

16. Genetic Algorithms

The supplied lecture describes genetic algorithms as combining stochastic local beam search with generating successors from pairs of states. It also notes that genetic algorithms require states represented as strings and that crossover is useful when substrings represent meaningful components. Course source: lecture-informed-search.pdf, slides 46–47.

Core analogy

Think about selective breeding:

  • you have several candidate organisms;
  • some perform better than others;
  • good candidates are more likely to contribute to the next generation;
  • parts of successful candidates can be recombined;
  • random variation introduces diversity.

The algorithmic version uses a population of candidate solutions.

18. Comparing the local/evolutionary methods

Method Main memory idea Core move Main strength Main weakness
Hill climbing 1 state Best neighbour Very simple, low memory Local maxima/plateaus/ridges
Random-restart hill climbing 1 state per run Best neighbour + restart Escapes bad starts Repeated restarts can cost time
Local beam k states Keep best k successors Multiple regions explored States may converge to same region
Simulated annealing 1 current state Sometimes accept worse move Can escape local maxima Requires temperature/schedule choices
Genetic algorithm Population Selection + crossover + mutation Population-level exploration Representation/fitness design matters

19. Exact search vs approximate local search

Your supplied lecture summarizes the distinction as:

Exact search
├── exhaustive exploration
└── heuristic search such as A*

Approximate search
├── hill climbing
├── simulated annealing
└── genetic algorithms

Course source: lecture-informed-search.pdf, slide 48.

The mental distinction

Exact-search mindset:

“Find a path / answer with a stated guarantee.”

Approximate/local-search mindset:

“Find a very good configuration efficiently, even when exhaustive exploration is impractical.”

This distinction becomes useful when you later study optimization in Machine Learning.

20. A deeper connection to Machine Learning

This chapter is also a bridge toward your ML mathematics.

Hill climbing resembles repeatedly looking for a better objective value.

Gradient descent later does something related—but mathematically rather than by discrete neighbourhood comparison:

Local search
    ↓
Neighbour states
    ↓
Choose a better state

Gradient-based optimization
    ↓
Gradient tells us a direction
    ↓
Update parameters

The resemblance is conceptual, not an identity.

Do not conclude that hill climbing and gradient descent are the same algorithm.

21. Mathematical lens

This chapter needs only light mathematics.

Simulated annealing

\[ \Delta E = E_{random}-E_{best} \]

and the course's acceptance expression:

\[ P(accept)=e^{\Delta E/T} \]

The important ideas are:

  • T = temperature;
  • ΔE = relative quality difference under the lecture's formulation;
  • exponential term controls probability;
  • cooling reduces the willingness to make worse moves.

Connection to optimization

Later, ML will introduce an objective function such as:

\[ J(\theta) \]

and attempt to improve it.

That will be much more mathematical than local search, so this chapter is only a conceptual bridge.

22. Common misconceptions

Misconception 1

“Hill climbing always finds the globally best solution.”

No. Local maxima are a central failure mode.

Misconception 2

“Simulated annealing never makes a bad move.”

No. Its central idea is to sometimes permit worse moves.

Misconception 3

“Local beam search means k completely independent hill climbers.”

No. Their successor sets are pooled.

Misconception 4

“A genetic algorithm is just random guessing.”

No. It uses a population, fitness, selection, recombination and mutation.

Misconception 5

“Local search is always optimal.”

No. These methods are generally designed to obtain good solutions efficiently rather than to provide the same guarantees as exact search.

25. Practice Set

A. Conceptual

Q1

A solution has no better immediate neighbour, but another region of the search space contains a much better solution. Which hill-climbing problem does this illustrate?

Q2

Why can restarting from a different random state help?

Q3

Why is “allowing a bad move” not automatically a bad design in simulated annealing?

Q4

What is the purpose of mutation in a genetic algorithm?

Q5

Why can local beam search lose diversity even though it keeps multiple states?

B. Numerical / reasoning

Q6

Suppose two candidate moves have:

\[ E_{best}=100,\quad E_{random}=96,\quad T=10 \]

Using the lecture's formulation,

\[ \Delta E=96-100=-4 \]

and:

\[ P(accept)=e^{-4/10} \]

Calculate the numerical probability using a calculator.

Q7

Create a small landscape with at least two local maxima and one global maximum. Mark where hill climbing can terminate.

Q8

Design a toy genetic-algorithm population of four binary strings. Assign a fitness function and show one selection+crossover+mutation cycle.

26. Chapter Memory Card

LOCAL SEARCH = IMPROVE THE CURRENT SOLUTION

Hill climbing → always prefer a better neighbour.
Random restart → try another starting point.
Local beam → keep k states.
Simulated annealing → sometimes accept worse moves, then cool down.
Genetic algorithm → evolve a population using fitness, selection, crossover and mutation.
