MAIN-U1-C07 — A* Search

Main Book: AI & Machine Learning — Visual + Mathematical Self-Learning Textbook
Unit: I — Artificial Intelligence
Topic ID: AI-U1-C07
Prerequisites: Problem Formulation, Search Trees/Nodes, Frontier, Uninformed Search, Heuristics, Greedy Best-First Search
Course status: Core Unit I topic
Primary course source: lecture-informed-search.pdf — Philipp Koehn, Artificial Intelligence: Informed Search, 12 February 2026
Previous: MAIN-U1-C06 — Greedy Best-First Search
Next: MAIN-U1-C08 — Local / Evolutionary Search

1. Why do we need A*?

Greedy Best-First Search taught us a powerful idea:

Use a heuristic to estimate how close a node is to the goal.

But we also found its weakness.

Greedy mainly asks:

“Which node looks closest?”

Suppose one path already cost us 100 units, while another path cost only 5 units. If the expensive path has a slightly smaller heuristic, Greedy may still prefer it.

So we want a search strategy that considers both:

  1. how much it has already cost to reach a node, and
  2. how much more it estimates will be needed.

That gives us the core idea of A*.

2. One-minute intuition

English

A* says:

“Don't just ask which node looks close. Also ask how expensive it was to get there.”

It combines:

\[ \boxed{f(n)=g(n)+h(n)} \]

where:

  • g(n) = actual cost already spent to reach n
  • h(n) = estimated cost from n to a goal
  • f(n) = estimated total cost through n

The supplied lecture states exactly this formulation and introduces A* as a method intended to avoid expanding paths that are already expensive. Course source: lecture-informed-search.pdf, slide 17.

👨‍🏫 Hinglish
> **A* bolta hai:** “Sirf destination kitni paas lag rahi hai woh mat dekho. Yahaan tak pahunchne mein kitna kharcha ho chuka hai, woh bhi dekho.” Socho: 
Ab tak ka kharcha + aage ka estimate
          ↓
         A*

3. The journey analogy

Imagine two people travelling to the same destination.

Person A

Has already spent ₹900 and is estimated to need ₹100 more.

Person B

Has already spent ₹300 and is estimated to need ₹400 more.

Their estimated total costs are:

\[ A=900+100=1000 \]
\[ B=300+400=700 \]

A* naturally prefers B under this evaluation.

👨‍🏫 Hinglish
> “Aage ka distance hi nahi dekhna. Abhi tak kitna paisa/effort laga + aage kitna lagega, dono combine karo.” This is the heart of:
\[ \boxed{f(n)=g(n)+h(n)} \]

4. Visual — the three quantities

START -----------------------------> GOAL
        
        [cost already spent]
              g(n)
                ↓
START -------- n ------------------- GOAL
                 \
                  \
                   estimated remaining cost
                         h(n)

Combined estimate:

              g(n) + h(n)
                    ↓

How to read this visual

At node n, the path has already accumulated some real cost.

That is g(n).

From n onward, we do not yet know the true cheapest remaining cost, so we use an estimate.

That is h(n).

Adding the two gives an estimate of the cost of a complete route passing through n.

5. The three symbols you must own

Symbol Meaning Question it answers
g(n) Actual cost from start to n “Mujhe yahaan tak pahunchne mein kitna laga?”
h(n) Estimated cost from n to goal “Goal tak aur kitna lag sakta hai?”
f(n) g(n)+h(n) “Is route ka estimated total kitna hai?”

Memory sentence

g = gone / already gone
h = hopeful estimate ahead
f = full estimated journey

The mnemonic is only a memory aid; use the actual mathematical definitions in formal answers.

6. A* as a Best-First Search strategy

The supplied lecture first defines Best-First Search as a framework that orders the fringe according to an evaluation function. It then identifies A* as a special case.

For A*:

\[ \boxed{f(n)=g(n)+h(n)} \]

So the frontier is prioritized by the smallest f(n).

BEST-FIRST SEARCH
                        │
             choose evaluation function
                        │
              ┌─────────┴─────────┐
              │                   │
         GREEDY                  A*
         f(n)=h(n)          f(n)=g(n)+h(n)
              │                   │
        future estimate     past + future estimate

7. Why `g(n)` and `h(n)` are complementary

Imagine a route to Delhi.

g(n) alone

You might choose the route where you have already spent the least money.

But you could be far away from the destination.

h(n) alone

You might choose the place that looks closest to Delhi.

But you might have taken an extremely expensive route to get there.

g(n)+h(n)

Now the decision includes both effects.

That is the conceptual reason A* is more balanced than Greedy.

8. A* evaluation example

Suppose the frontier contains:

Node g(n) h(n) f(n)=g+h
A 3 9 12
B 5 4 9
C 2 12 14
D 8 5 13

A* compares:

\[ 12,\quad9,\quad14,\quad13 \]

The smallest is:

\[ \boxed{9} \]

so A* chooses:

\[ \boxed{B} \]
👨‍🏫 Hinglish
> B tak aane ka cost 5 tha, aur aage ka estimate 4. Total estimated 9. Sabse chhota hai, isliye B ko expand karenge.

9. A* versus Greedy — the same frontier

Use the same nodes:

Node g h Greedy uses h A* uses g+h
A 2 8 8 10
B 15 4 4 19
C 5 7 7 12

Greedy

Chooses B because:

\[ 4\lt 7\lt 8 \]

A*

Chooses A because:

\[ 10\lt 12\lt 19 \]

This single table is one of the most important comparisons in Unit I.

Mental model

Greedy: “B looks closer.”
A*: “B looks closer, but it was very expensive to reach.”

10. Why does A* need a special heuristic property?

If A* is going to use:

\[ f(n)=g(n)+h(n) \]

and we want strong guarantees about the solution it returns, the heuristic cannot be allowed to behave arbitrarily.

The supplied lecture requires an admissible heuristic.

It states:

\[ \boxed{h(n)\le h^*(n)} \]

where:

\[ h^*(n)=\text{true cost of the cheapest remaining path from }n\text{ to a goal} \]

and also requires:

\[ \boxed{h(n)\ge0} \]

Course source: lecture-informed-search.pdf, slide 17.

11. What is `h*(n)`?

This notation looks scary initially, but it is simple.

\[ \boxed{h^*(n)} \]

means the actual optimal remaining cost from node n to a goal.

So:

h(n)  = our estimate
h*(n) = actual cheapest remaining cost

Example

Suppose the cheapest possible remaining route from A costs 20.

Then:

\[ h^*(A)=20 \]

If our heuristic says:

\[ h(A)=15 \]

that is an underestimate.

If it says:

\[ h(A)=20 \]

it is exact.

If it says:

\[ h(A)=27 \]

it overestimates.

That last case violates admissibility.

12. Admissible heuristic

The course condition is:

\[ \boxed{0\le h(n)\le h^*(n)} \]

English

A heuristic is admissible if it never overestimates the true cheapest remaining cost.

👨‍🏫 Hinglish
> **Admissible = optimistic estimate.** Agar actual remaining cost 20 hai: - `h=12` ✅ - `h=18` ✅ - `h=20` ✅ - `h=21` ❌

Memory anchor

Admissible heuristic kabhi reality se zyada cost nahi bolta.

13. Why optimism is useful

Suppose there is an excellent route hiding somewhere in the search tree.

If the heuristic were allowed to exaggerate its remaining cost wildly, A* could make that route appear more expensive than it really is.

An admissible heuristic provides a lower-bound style estimate of remaining cost.

So A* can reason:

“Even if this estimate is optimistic, this node still cannot be dismissed as more expensive than reality merely because my heuristic exaggerated it.”

The exact optimality reasoning is given later in this chapter.

14. Goal nodes

If G is already a goal node, the true remaining cost is:

\[ h^*(G)=0 \]

For an admissible non-negative heuristic:

\[ 0\le h(G)\le0 \]

Therefore:

\[ \boxed{h(G)=0} \]

Then:

\[ f(G)=g(G)+0=g(G) \]
👨‍🏫 Hinglish
> Goal par pahunch gaye. Aage aur kuch nahi hai. Remaining cost zero.

15. Straight-line distance to Bucharest

The supplied course uses:

\[ \boxed{h_{SLD}(n)=\text{straight-line distance from }n\text{ to Bucharest}} \]

This is a classic navigation heuristic.

Why is it useful?

Because straight-line distance is a direct geometric estimate of separation.

The lecture explicitly uses it as an example that does not overestimate the corresponding actual road distance in the Romania problem. Course source: lecture-informed-search.pdf, slide 17.

16. Visual — straight line versus road path

actual road
        A  ~~~~~~~~~~~~~~~~~~~~~  B
         \                       /
          \                     /
           \                   /
            \_________________/
                  direct line

             A ----------- B
                 h(n)

Interpretation

  • The road route may bend and contain extra distance.
  • The straight-line distance ignores the bends.
  • Therefore it can serve as a lower-bound-style estimate in this kind of map problem.

Important

The geometry itself is not the definition of a heuristic.

The definition is:

A problem-specific estimate used to guide search.

Straight-line distance is one example.

17. A* algorithm — plain-English version

  1. Put the start node into the frontier.
  2. Give it an initial g(n) value.
  3. Compute its heuristic h(n).
  4. Compute:
\[ f(n)=g(n)+h(n) \]
  1. Select the frontier node with the smallest f(n).
  2. If it is a goal, return the solution under the course search assumptions.
  3. Otherwise expand it.
  4. For each successor, compute its path cost g, heuristic h, and combined value f.
  5. Put/update candidates in the frontier according to their f values.
  6. Repeat.

Pseudocode

A*-SEARCH(problem)

    frontier ← priority queue ordered by f(n)=g(n)+h(n)
    insert start node

    while frontier is not empty:
        n ← remove node with smallest f(n)

        if n is a goal:
            return solution(n)

        expand n

        for each successor s of n:
            compute g(s)
            compute h(s)
            compute f(s)=g(s)+h(s)
            insert/update s in frontier

    return failure

The exact details of duplicate-state handling and node replacement depend on the implementation variant. The core course idea is the f=g+h ordering and admissible heuristic requirement. Course source: slide 17.

18. Worked Example — A* from scratch

We will use a small original graph so that every calculation can be seen.

A
                / \
              2/   \5
              /     \
             B       C
            / \     / \
          2/   \6  1/   \3
          /     \ /     \
         D       E       F
          \       |       |
           \4     |2      |2
            \     |       |
             \    |       |
              \   |       |
                Goal

We choose heuristic values:

h(A)=6
h(B)=5
h(C)=4
h(D)=4
h(E)=2
h(F)=2
h(Goal)=0

These are teaching values for this original example. They are not values copied from the supplied lecture.

19. Step 0 — Start at A

At the start:

\[ g(A)=0 \]

Given:

\[ h(A)=6 \]

So:

\[ f(A)=g(A)+h(A)=0+6=6 \]

Frontier:

A: g=0, h=6, f=6

Expand A.

20. Step 1 — Generate B and C

For B:

\[ g(B)=2 \]

and:

\[ h(B)=5 \]

therefore:

\[ f(B)=2+5=7 \]

For C:

\[ g(C)=5 \]

and:

\[ h(C)=4 \]

therefore:

\[ f(C)=5+4=9 \]

Frontier:

Node g h f
B 2 5 7
C 5 4 9

A selects B* because:

\[ 7\lt 9 \]

21. Step 2 — Expand B

B produces D and E.

For D:

\[ g(D)=g(B)+2=2+2=4 \]

Suppose:

\[ h(D)=4 \]

Then:

\[ f(D)=4+4=8 \]

For E through B:

\[ g(E)=g(B)+6=2+6=8 \]

and:

\[ h(E)=2 \]

so:

\[ f(E)=8+2=10 \]

Current frontier becomes:

C: f=9
D: f=8
E: f=10

A chooses D*.

22. Step 3 — Expand D

D connects toward Goal with cost 4.

If:

\[ g(D)=4 \]

then the candidate route through D gives:

\[ g(Goal)=4+4=8 \]

Since:

\[ h(Goal)=0 \]

we have:

\[ f(Goal)=8 \]

The frontier is now conceptually:

Goal: f=8
C:    f=9
E:    f=10

The smallest is Goal.

Therefore A* returns the route:

A → B → D → Goal

with total cost:

\[ \boxed{8} \]

23. What did the A* example teach us?

At every step, A* balanced two ideas.

Already spent

\[ g(n) \]

Estimated remaining

\[ h(n) \]

Combined

\[ f(n)=g(n)+h(n) \]

This is not merely a formula to memorize.

It is a decision rule.

24. The most important dry-run table

Whenever you solve an A* numerical question, build this table:

Node Parent Step cost g(n) h(n) f(n)
... ... ... ... ... ...

Then repeat these steps:

1. Pick minimum f
2. Expand it
3. Compute successor g
4. Read/compute h
5. Add g+h
6. Update frontier
7. Repeat

Exam habit

Never try to do the complete A* calculation mentally.

Write the g, h, and f columns.

It prevents a large fraction of arithmetic and selection mistakes.

25. The optimality idea

The supplied course lecture states that A* is optimal when the admissibility condition is satisfied.

The proof structure in the lecture is important.

Suppose A* has generated a suboptimal goal G2.

Let G be an optimal goal and let n be an unexpanded node on a shortest path to G.

At a goal:

\[ h(G_2)=0 \]

so:

\[ f(G_2)=g(G_2) \]

Since G2 is suboptimal:

\[ g(G_2)\gt g(G) \]

Because the heuristic is admissible:

\[ h(n)\le h^*(n) \]

which gives:

\[ f(n)\le g(G) \]

and therefore:

\[ f(G_2)\gt f(n) \]

So A* will not choose the suboptimal goal G2 before the more promising node on the optimal path.

This is the core logic behind the course lecture's optimality argument. Course source: lecture-informed-search.pdf, slide 29.

26. Explain the optimality proof in plain English

The proof can feel intimidating because of the notation.

Here is the story version.

Imagine:

  • one candidate goal is expensive,
  • another optimal route still has an unexplored node,
  • and our heuristic is optimistic.

The unexplored node on the optimal path cannot look more expensive than the true optimal route.

The bad goal already has its full cost exposed.

Therefore the bad goal gets a larger A* score than some node that still belongs to the good route.

So A* expands the promising optimal-path node first instead of prematurely accepting the expensive goal.

👨‍🏫 Hinglish
> “Agar heuristic overestimate nahi kar raha, toh optimal path ka koi useful node artificially bahut expensive nahi dikhega. Isliye A* ek suboptimal goal ko prematurely choose nahi karega.”

27. The `C*` view from the course lecture

The supplied lecture uses C* for the optimal solution cost and states that A*:

  • expands all nodes with
\[ f(n)\lt C^* \]
  • may expand some nodes with
\[ f(n)=C^* \]
  • does not expand nodes with
\[ f(n)\gt C^* \]

Course source: lecture-informed-search.pdf, slide 30.

Intuition

C* is the cost of the best solution.

So A* concentrates its expansion around nodes whose estimated total cost is compatible with that optimal solution cost.

28. Completeness of A*

The supplied lecture states A* is complete under its stated search assumptions, with the caveat that completeness can fail if there are infinitely many nodes with:

\[ f\le f(G) \]

This is an important example of why algorithm properties should never be memorized as one-word slogans without their assumptions.

For your course-level memory

A* is complete under the stated standard assumptions.

Course source: lecture-informed-search.pdf, slide 30.

29. Space usage

The supplied lecture states that A* keeps all nodes in memory.

So memory can become the major practical limitation.

👨‍🏫 Hinglish
> “A* smart hai, lekin jo candidates consider kar raha hai unko memory mein sambhal ke rakhna padta hai. Huge search space mein memory bottleneck ban sakti hai.” This is one reason search strategy comparisons must include **space complexity**, not just whether the path is optimal.

30. Time complexity intuition

The supplied lecture describes the time behavior of A* in terms of heuristic error and solution length rather than a single simple polynomial bound.

The key course message is:

Better heuristic → potentially much less search.

Poor heuristic → behavior can approach large exhaustive search behavior.

What this means

If:

\[ h(n)=0 \]

for every node, A* becomes equivalent to Uniform-Cost Search in the usual positive-cost setting because:

\[ f(n)=g(n)+0=g(n) \]

So a completely uninformative heuristic provides no additional guidance.

This follows directly from the f=g+h definition and is a useful conceptual connection to the preceding chapter.

31. The spectrum from UCS to Greedy

This is a powerful mental model:

UNIFORM-COST SEARCH

f(n)=g(n)
│
│ gradually add heuristic information
▼

A*

f(n)=g(n)+h(n)
│
│ remove the cost-so-far component
▼

GREEDY

f(n)=h(n)

This is not saying the algorithms are literally produced by “turning a knob”; it is a conceptual way of seeing which information each strategy uses.

32. Heuristic quality

A heuristic can be:

Weak

It provides little information.

Stronger

It gives a more informative estimate while preserving the required property.

Exact

If:

\[ h(n)=h^*(n) \]

then the estimate equals the true optimal remaining cost.

This would provide extremely powerful guidance, although obtaining such a heuristic may itself be as hard as solving the original problem.

33. 8-Puzzle — two admissible heuristics from the course

The supplied lecture gives two heuristic examples for the 8-puzzle.

Heuristic 1 — Misplaced tiles

\[ \boxed{h_1(n)=\text{number of misplaced tiles}} \]

Count how many tiles are not in their target positions.

Heuristic 2 — Manhattan distance

\[ \boxed{h_2(n)=\text{total Manhattan distance}} \]

For each tile, count how many horizontal and vertical grid moves separate it from its target location, then add those values.

The course lecture gives an example where:

\[ h_1(S)=6 \]

and:

\[ h_2(S)=4+0+3+3+1+0+2+1=14 \]

Course source: lecture-informed-search.pdf, slides 31–32.

Misplaced-tile heuristic

If not:

\[ +1 \]

Manhattan distance

It asks:

How many row/column moves away is the tile?

35. Dominance

The supplied lecture introduces an important comparison.

If two admissible heuristics satisfy:

\[ h_2(n)\ge h_1(n) \]

for every node n, then h2 dominates h1.

The lecture states that the dominating heuristic is better for search in this sense because it can provide stronger guidance while retaining admissibility.

Course source: lecture-informed-search.pdf, slide 34.

37. Combining admissible heuristics

The supplied lecture also states:

Given admissible heuristics h_a and h_b, define:

\[ \boxed{h(n)=\max(h_a(n),h_b(n))} \]

Then this combined heuristic is also admissible and dominates both individual heuristics.

Intuition

Suppose:

\[ h_a(n)=5 \]

and:

\[ h_b(n)=8 \]

Then:

\[ h(n)=\max(5,8)=8 \]

If both are valid lower bounds, taking the larger lower bound gives a tighter estimate without crossing the true cost.

Course source: lecture-informed-search.pdf, slide 34.

38. Relaxed problems

One of the most useful heuristic ideas in the supplied lecture is:

Solve an easier version of the original problem and use that solution cost as a heuristic for the real problem.

A relaxed problem removes or weakens some constraints from the original problem.

Because the relaxed problem is easier, its optimal solution cost is no greater than the corresponding optimal cost of the real problem.

Therefore it can provide a lower bound.

Course source: lecture-informed-search.pdf, slides 34–36.

39. 8-Puzzle relaxed-problem intuition

The lecture gives two examples.

Relaxation 1

Allow a tile to move anywhere.

This gives the misplaced-tile style lower bound.

Relaxation 2

Allow a tile to move to any adjacent square without enforcing the full original movement interaction.

This leads to the Manhattan-distance style lower bound.

The essential idea is:

REAL PROBLEM
    │
    │ remove some restrictions
    ▼
RELAXED PROBLEM
    │
    │ solve easier problem
    ▼
LOWER-BOUND COST
    │
    ▼
HEURISTIC

40. Why does relaxation create a lower bound?

Suppose the real problem has many rules.

The relaxed problem removes some rules.

That means the relaxed version has at least as much freedom as the real problem.

So it cannot reasonably require more minimum effort than the original constrained problem.

Therefore:

\[ \text{optimal relaxed cost} \le \text{optimal real cost} \]

This is exactly the lower-bound property that makes the relaxed solution useful as an admissible heuristic.

👨‍🏫 Hinglish
> “Agar rules hata doge, problem easy ho jaayegi. Easy problem ka best possible cost original difficult problem ke best cost se zyada nahi ho sakta.”

41. TSP connection

The supplied lecture then gives the Travelling Salesperson Problem as another example of relaxed-problem reasoning.

The original problem asks for the shortest tour visiting all cities exactly once.

A minimum spanning tree can be used as a lower-bound idea for a related relaxed structure.

The lecture notes that a minimum spanning tree:

  • connects all vertices without cycles,
  • has minimum total edge weight,
  • and gives a lower bound on the shortest open tour in the stated discussion.

Course source: lecture-informed-search.pdf, slides 35–36.

43. When A* returns a goal

A subtle exam question is:

“A goal has been generated. Can I immediately stop?”

The safest course-level understanding is:

A* returns a goal when the goal is selected/expanded according to its search procedure and the applicable assumptions, not merely because a goal node happens to appear somewhere in the frontier.

Why?

Because another frontier node might still have a lower f value and could lead to a cheaper complete solution.

Example

Goal G1: f=20
Node N:  f=12

Even though G1 is already a goal, A* should not treat it as the final answer simply because it has been generated if the search procedure still has a lower-cost candidate to examine.

This distinction is essential when solving dry runs.

44. Common A* misconceptions

Misconception 1

“A* always uses only the heuristic.”

No.

\[ \boxed{f(n)=g(n)+h(n)} \]

Misconception 2

“A* is just Greedy with a different name.”

No.

Greedy ignores g(n) in the evaluation rule used here.

A* includes it.

Misconception 3

“Admissible means the heuristic is exact.”

No.

Admissible means:

\[ 0\le h(n)\le h^*(n) \]

It may be lower than the truth.

Misconception 4

“A larger heuristic is always better.”

Not automatically.

The key requirement is that it remain admissible in the relevant A* optimality setting.

A larger admissible heuristic can be more informative.

Misconception 5

“A* chooses the node nearest to the goal.”

Not exactly.

It chooses according to:

\[ \boxed{g(n)+h(n)} \]

Misconception 6

“If h(n)=0, A* cannot work.”

Wrong.

It simply loses heuristic guidance and reduces to cost-based search behavior:

\[ f(n)=g(n) \]

Frontier:

Q: g=7,  h=5

Compute:

\[ f(P)=4+10=14 \]
\[ f(Q)=7+5=12 \]

\[ \boxed{Q} \]

Important

Do not choose R just because:

\[ g(R)=2 \]

and do not choose Q merely because:

\[ h(Q)=5 \]

You must combine them.

47. Worked Numerical — identify the heuristic problem

Suppose the true remaining costs are:

\[ h^*(A)=12, \quad h^*(B)=20, \quad h^*(C)=7 \]

and a proposed heuristic is:

\[ h(A)=10, \quad h(B)=18, \quad h(C)=9 \]

Check admissibility.

A

\[ 10\le12 \]

valid.

B

\[ 18\le20 \]

valid.

C

\[ 9\gt 7 \]

violates admissibility.

Therefore the heuristic is not admissible over these nodes.

48. Worked Numerical — compare two admissible heuristics

Suppose:

\[ h_1(n)=6 \]
\[ h_2(n)=10 \]

and:

\[ h^*(n)=13 \]

Both are admissible.

Because:

\[ 10\ge6 \]

h2 is the tighter estimate at this node.

If the relationship holds for all nodes and both remain admissible, then the course's dominance rule allows us to say h2 dominates h1.

52. Exam Lens

2-mark — Define A*

A* is an informed best-first search strategy that expands the node with minimum f(n)=g(n)+h(n), where g(n) is the cost so far and h(n) is an estimated remaining cost.

2-mark — Define admissible heuristic

A heuristic is admissible if it never overestimates the true optimal remaining cost, i.e. 0 ≤ h(n) ≤ h*(n).

53. Common exam traps

Trap 1

Using:

\[ f=h \]

for A*.

That is Greedy.

Trap 2

Forgetting to add the path cost:

\[ f=g+h \]

Trap 3

Comparing g values when the question asks for A* selection.

Compare f.

Trap 4

Calling an overestimating heuristic admissible.

It is not.

Trap 5

Stopping merely because a goal has appeared in the frontier.

Follow the search procedure and selection rule.

Trap 6

Saying “admissible means exact.”

It means never overestimating.

55. Recall Answers

  1. It incorporates both the cost already spent and the estimated cost remaining, addressing a key weakness of Greedy.
  2. Actual cost from the start to node n.
  3. Estimated remaining cost from n to a goal.
  4. True cheapest remaining cost from n to a goal.
  5. f(n)=g(n)+h(n).
  6. To estimate the total cost of a solution path through n.
  7. The heuristic never overestimates the true optimal remaining cost.
  8. At a goal, no cost remains.
  9. The frontier node with the smallest f(n) under the search procedure.
  10. Because Greedy ranks by h, while A* ranks by g+h.
  11. With an admissible heuristic, a suboptimal goal cannot be selected before a sufficiently promising node on an optimal path under the course's theorem/assumptions.
  12. The cost of the optimal solution.
  13. A* expands all nodes with f<C*, some with f=C*, and none with f>C* under the course statement.
  14. Misplaced tiles and total Manhattan distance.
  15. If one admissible heuristic is everywhere at least as large as another, it dominates it and can offer stronger guidance.
  16. Relaxing constraints gives an easier problem whose optimal cost is a lower bound for the original problem.
  17. A* reduces to cost-based selection f=g.
