MAIN-U1-C03 — Problem Formulation

Main Book · Unit I — Artificial Intelligence
Concept ID: AI-U1-C03
Status: Mid-sem core
Prerequisites: AI-U1-C02 Intelligent Agents
Next: AI-U1-C04 Uninformed Search
Source of course-specific framing: lecture-basic-search.pdf

0. What this chapter will teach you

By the end of this chapter, you should be able to take an everyday task such as:

“Go from one city to another.”

and turn it into a form that an AI search algorithm can actually work with.

You will learn to identify:

  1. the initial state,
  2. the possible actions / successor function,
  3. the goal test,
  4. the path cost,
  5. the state space,
  6. the difference between a state and a search node,
  7. a path, solution, and optimal solution, and
  8. why abstraction is necessary before search can become feasible.

This chapter is the bridge between:

INTELLIGENT AGENT
       ↓
WHAT DO I WANT?
       ↓
HOW CAN I REPRESENT THE PROBLEM?
       ↓
SEARCH
       ↓
EXECUTE

The supplied Basic Search lecture presents problem solving as a restricted form of a general agent: formulate a goal, formulate the problem, search for a solution, and then execute the resulting sequence of actions. The lecture then formalizes the search problem using the initial state, successor function, goal test and path cost. [Course note: lecture-basic-search.pdf, early problem-solving and formulation slides.]

1. Why does problem formulation exist?

Imagine telling a person:

“Reach the airport tomorrow.”

A human immediately asks or assumes many things:

  • Which airport?
  • Where are you starting?
  • Can you walk, drive, or take a train?
  • Does money matter?
  • Does time matter?
  • Are roads blocked?
  • Is the shortest route the goal, or the fastest route?

An AI system has the same fundamental problem, except it cannot simply rely on common sense to fill in everything.

It needs a formal description of the problem.

👨‍🏫 Teacher explanation — English
A search algorithm cannot operate directly on a vague sentence such as “find the best route.” It needs a structured representation of what the current situation is, what changes are possible, what counts as success, and how a solution is evaluated.
👨‍🏫 Teacher explanation — Hinglish
AI ko bas itna bol dena ki **“Bucharest pahunch jao”** enough nahi hai. Usko exactly batana padega: > abhi kahan ho, kya actions le sakte ho, goal kya hai, aur route ki cost kaise calculate hogi. Yahi **problem formulation** hai.

2. Real-world analogy — route planning

Suppose you are going from Arad → Bucharest.

You have a map with multiple roads.

Oradea
                           |
                         71 km
                           |
                         Zerind
                           |
                         75 km
                           |
                         Arad  -------- 140 -------- Sibiu
                           |                             |
                         118                            99
                           |                             |
                      Timisoara                       Fagaras
                                                         |
                                                        211
                                                         |
                                                     Bucharest

The actual course lecture uses the Romania map as a canonical search example. It begins with the situation “currently in Arad” and a goal of being in Bucharest, then describes states as cities, actions as driving between cities, and a solution as a sequence of cities. [Course note: lecture-basic-search.pdf, Romania example slides.]

Analogy

Think of the map as a game board.

  • A state = where your player currently is.
  • An action = one legal move.
  • The goal = the winning condition.
  • The path cost = how expensive the sequence of moves is.
  • A search algorithm = the strategy used to decide which possibilities to explore.

The important point is that the map contains much more information than the search algorithm necessarily needs.

You do not need to model:

  • what music is playing in the car,
  • what your passengers are wearing,
  • the colour of nearby houses,
  • your favourite food,
  • or every detail of the weather,

unless those details affect the problem you are trying to solve.

That leads to abstraction, which is one of the deepest ideas in this chapter.

3. The problem-solving pipeline

A useful mental model is:

┌────────────────────────┐
│ 1. FORMULATE THE GOAL  │
│ What counts as success?│
└────────────┬───────────┘
             ↓
┌────────────────────────┐
│ 2. FORMULATE PROBLEM   │
│ How do we represent it?│
└────────────┬───────────┘
             ↓
┌────────────────────────┐
│ 3. SEARCH              │
│ Which action sequence? │
└────────────┬───────────┘
             ↓
┌────────────────────────┐
│ 4. EXECUTE             │
│ Perform the actions    │
└────────────────────────┘
👨‍🏫 Hinglish mental model
> **Pehle decide karo “karna kya hai”, phir problem ko machine-friendly form mein describe karo, phir search se route/solution nikalo, phir usko execute karo.** Do not confuse **goal formulation** with **problem formulation**. - Goal formulation asks: **what do I want?** - Problem formulation asks: **what information and actions do I need to represent the task so I can search for that goal?**

4. What is a search problem?

A search problem is a formal description of a task in which we want to find a sequence of actions that takes us from a starting situation to a desired situation.

For the standard single-state problem formulation, your supplied lecture defines the problem using four main items:

  1. Initial state
  2. Successor function
  3. Goal test
  4. Path cost

A solution is a sequence of actions leading from the initial state to a goal state. [Course note: lecture-basic-search.pdf, “Single-State Problem Formulation”.]

Important wording: The successor function represents the available actions by returning action-state pairs. That is why some books present “actions” as a separate item while your lecture presents the successor function directly.

5. The four components

5.1 Initial state

Formal meaning

The initial state is the state in which the problem starts.

For the Romania route problem:

Initial state = In(Arad)

Intuition

It is simply:

“Where am I right now?”

👨‍🏫 Hinglish
> “Abhi starting point kya hai?”

Examples

Problem Initial state
Route finding At Arad
8-puzzle Given starting board configuration
Vacuum world Given robot location + dirt configuration
Robot assembly Initial joint/object configuration
Game Initial board position

The supplied lecture uses route finding, vacuum world, the 8-puzzle and robotic assembly as examples of how states/actions/goals/costs are specified. [Course note: lecture-basic-search.pdf, problem-formulation examples.]

5.2 Successor function

This is one of the most important terms in the chapter.

Definition

The successor function tells us what states can be reached from a given state and which action produces each transition.

Conceptually:

a current state

\[ S(x) \]

maps to a set of action–state pairs.

For example:

Current state: Arad

S(Arad) = {
    (Go-to-Zerind, Zerind),
    (Go-to-Sibiu, Sibiu),
    (Go-to-Timisoara, Timisoara)
}

This is the course note's central idea: from one state, the successor function generates the legal next possibilities. [Course note: lecture-basic-search.pdf, “Single-State Problem Formulation”.]

Do not confuse these

Action = what you do.

Successor state = where you end up.

Successor function = the rule that tells you which action-state transitions are available.

👨‍🏫 Hinglish
> “Agar main abhi is state mein hoon, toh mere paas kaun-kaun se legal moves hain aur har move ke baad main kis state mein pahunchunga?” Yeh poora kaam **successor function** karta hai.

6. A visual way to understand the successor function

CURRENT STATE
                       Arad
                    /   |   \
                   /    |    \
                 /      |      \
                ↓       ↓       ↓
             Zerind   Sibiu   Timisoara

            ↑          ↑          ↑
        action 1    action 2    action 3

The arrows are not merely lines.

Each arrow represents an action.

Each destination represents a successor state.

The important question

If I give you a state but don't tell you its successor function, can a search algorithm know which next states are legal?

No.

So the successor function is what turns a static description of a state into a space of possible actions.

7. Goal test

The AI needs a precise rule for deciding whether a state is a goal state.

Definition

A goal test checks whether the current state satisfies the desired goal.

For Romania:

Goal = Be in Bucharest

The goal test can therefore be represented conceptually as:

Is current_state == Bucharest ?

Explicit vs implicit goal tests

Your course material distinguishes two styles.

Explicit goal test

The goal state itself is explicitly described.

Example:

x = “at Bucharest”

Implicit goal test

The desired state is identified by a property rather than by one named state.

Example:

NoDirt(x)

A vacuum-world state is a goal whenever there is no dirt, regardless of the robot's exact location. [Course note: lecture-basic-search.pdf, “Single-State Problem Formulation”.]

👨‍🏫 Hinglish
> Explicit: “Bucharest pahunch gaye?” > > Implicit: “Har room clean hai?” The second one does not require one exact state label; it requires a **condition** to be true.

8. Path cost

Finding a solution and finding the best solution are not always the same thing.

Suppose there are two routes:

Route A:  Arad → Sibiu → Fagaras → Bucharest
Cost = 450 km

Route B:  Arad → Sibiu → Pitesti → Bucharest
Cost = 418 km

Both reach the goal.

But if the problem says:

Find the least-distance route,

then the second route is preferred.

Definition

Path cost is the total cost associated with a path.

The lecture describes it as additive and uses a step-cost function such as:

a \rightarrow \text{transition from }x\text{ to }y

a \text{ has cost } c(x,a,y) ]

and the path cost is the sum of the step costs along the path. The lecture assumes step costs are non-negative. [Course note: lecture-basic-search.pdf, “Single-State Problem Formulation”.]

Conceptually:

define \qquad

g(n)=\sum_{i=1}^{k} c_i ]

where each \(c_i\) is a step cost on the path.

👨‍🏫 Hinglish
> “Har move ki apni cost ho sakti hai. Puri journey ki cost = saari individual costs ka total.”

The cost can mean different things

Depending on the problem, cost might represent:

  • distance,
  • number of actions,
  • time,
  • money,
  • energy,
  • risk,
  • or another defined quantity.

The problem formulation decides what “good” means.

9. Step cost vs path cost

This distinction is very important.

Step cost

Cost of one transition.

Arad → Sibiu = 140 km

Path cost

Cost of the whole sequence.

Arad → Sibiu → Fagaras → Bucharest

= 140 + 99 + 211
= 450 km

So:

STEP COST = one move
PATH COST = sum of all move costs

Memory anchor

Step = one bill. Path = total shopping bill.

10. State space

Now we introduce a bigger concept.

Definition

The state space is the collection of states reachable through legal actions, together with the transitions between them.

You can imagine it as a graph:

B
        /   \
       /     \
      A       D
       \     /
        \   /
          C
  • Nodes represent states.
  • Edges represent actions/transitions.

The initial state and the successor function together determine the reachable state space for the problem representation.

👨‍🏫 Hinglish
> “State space matlab problem ki duniya ke saare relevant possible situations aur unke beech ke legal transitions.” This is not necessarily the same as the entire physical world. That distinction is crucial.

11. Why don't we represent the entire real world?

Suppose you're solving:

“Drive from Arad to Bucharest.”

The real world contains an enormous amount of detail:

weather
traffic
road surface
music
passengers
car temperature
nearby buildings
fuel
police
road signs
restaurants
clouds
pedestrians
...

A search problem might represent the state simply as:

In(Arad)

That looks ridiculously simple compared with the real world.

But that simplicity is intentional.

The lecture explicitly emphasizes that problem formulation usually requires abstracting away real-world details to create a state space that can feasibly be explored. [Course note: lecture-basic-search.pdf, summary.]

12. Abstraction

What is abstraction?

Abstraction means removing details that are irrelevant to the current problem while retaining the information necessary to solve it.

Everyday analogy

Imagine asking:

“How do I get to Room 204?”

You probably need:

  • building layout,
  • corridors,
  • stairs/lifts,
  • room numbers.

You usually do not need:

  • wall colour,
  • what someone is wearing,
  • exact temperature of every corridor,
  • brand of every light bulb.

Those details exist in reality but are irrelevant to the route-finding task.

👨‍🏫 Hinglish
> “Real life mein bahut saari information hoti hai. AI problem banate waqt sirf wahi information rakho jo solution decide karne ke kaam aati hai.”

13. Why abstraction is difficult

Too little abstraction:

Real world
████████████████████████████████████████

Search problem becomes enormous.

Too much abstraction:

Real world
        ↓
Keep almost nothing
        ↓
Important information disappears.

The goal is:

REAL WORLD
     ↓
REMOVE IRRELEVANT DETAIL
     ↓
USEFUL ABSTRACT STATE
     ↓
FEASIBLE SEARCH

The central trade-off

Less detail → easier search, but greater risk of losing information.

More detail → more faithful model, but potentially much harder search.

This is one reason problem formulation is itself an important AI skill.

14. Example — Romania route finding

The course lecture gives a standard formulation.

Informal problem

“I am on holiday in Romania, currently in Arad, and my flight leaves tomorrow from Bucharest.”

Goal formulation

Be in Bucharest.

Problem formulation

Component Formulation
State Current city
Initial state Arad
Actions Drive to a connected city
Successor function Legal city-to-city transitions
Goal test Current city is Bucharest
Path cost Sum of route distances

Candidate solution

Arad → Sibiu → Fagaras → Bucharest

or another legal sequence ending in Bucharest.

The search algorithm has not yet been chosen here.

That is important.

Problem formulation comes before search strategy.

15. Example — Vacuum World

The supplied lecture also asks you to formulate the vacuum world.

A simple representation uses:

  • robot location,
  • dirt configuration,
  • legal actions.

The Basic Search lecture gives these kinds of formulations and uses actions such as Left, Right, Suck, NoOp. [Course note: lecture-basic-search.pdf, vacuum-world formulation slides.]

One simplified formulation

Component Example

Initial state Given configuration
Actions Left, Right, Suck, NoOp
Goal test No dirt

Visual

ROOM A        ROOM B
      ┌────────┬────────┐
      │        │        │
      │  🤖    │   •    │
      │        │  dirt  │
      └────────┴────────┘

Possible actions:
← Left     → Right     🧹 Suck     ○ NoOp

Notice how a huge physical environment becomes a compact symbolic problem.

That is abstraction in action.

16. Example — 8-puzzle

The supplied lecture formulates the 8-puzzle using the locations of the numbered tiles.

Actions are moves of the blank tile:

  • left,
  • right,
  • up,
  • down.

The goal test checks whether the current board matches the given goal configuration.

The lecture assigns a cost of 1 per move and notes that optimal solution of the general n-puzzle family is computationally difficult. [Course note: lecture-basic-search.pdf, 8-puzzle example.]

A state

┌───┬───┬───┐
│ 1 │ 2 │ 3 │
├───┼───┼───┤
│ 4 │   │ 6 │
├───┼───┼───┤
│ 7 │ 5 │ 8 │
└───┴───┴───┘

The blank is part of the state because its location determines which moves are legal.

Legal transition idea

move UP
             ↑
             │
move LEFT ← [state] → move RIGHT
             │
             ↓
         move DOWN

Not every action is legal from every state.

That is why the successor function matters.

17. State vs node — a very important distinction

Students frequently mix these two words.

They are not exactly the same thing.

State

A state is a representation of a physical configuration of the problem.

Example:

At Sibiu

Node

A node is a search data structure that stores a state plus search-related information.

The supplied Basic Search lecture specifically notes that a node can contain:

  • the state,
  • parent,
  • children,
  • depth,
  • path cost.

It emphasizes that states do not inherently have parents, children, depth or path cost; nodes do. [Course note: lecture-basic-search.pdf, “Implementation: States vs. Nodes”.]

Visual

STATE
┌────────────────┐
│   Sibiu        │
└────────────────┘

NODE
┌─────────────────────────────┐
│ State: Sibiu                │
│ Parent: Arad                │
│ Depth: 1                    │
│ Path cost: 140              │
│ Children: ...               │
└─────────────────────────────┘
👨‍🏫 Hinglish
> State matlab “main kahan/ kis configuration mein hoon”. > > Node matlab “search algorithm ke context mein ye state kis route se aayi, kitni depth par hai, kitna cost lag chuka hai, etc.”

Memory anchor

State = situation. Node = situation + search history.

18. Path

A path is a sequence of states connected by actions.

Example:

Arad
  ↓ drive
Sibiu
  ↓ drive
Fagaras
  ↓ drive
Bucharest

So the path is:

Arad → Sibiu → Fagaras → Bucharest

Important

A path is not a single state.

A path records a sequence of transitions through the state space.

19. Solution

A solution is a path / sequence of actions that reaches a goal state from the initial state.

Example:

Initial
Arad
  ↓
Sibiu
  ↓
Fagaras
  ↓
Bucharest
Goal

This is a solution because it reaches the goal.

There may be many solutions.

20. Optimal solution

An optimal solution is the solution with the best value according to the defined path-cost criterion.

For a shortest-route problem:

optimal = minimum path cost.

For another problem, the objective could be different.

For example:

  • shortest route → minimize distance,
  • fastest route → minimize time,
  • cheapest route → minimize money.

Important insight

“Optimal” does not mean “universally best.”

It means:

best according to the problem's specified cost criterion.

21. A complete problem-formulation diagram

Use this as the chapter's main recall diagram.

flowchart LR
    A[Real-world task] --> B[Goal formulation]
    B --> C[Choose useful abstraction]
    C --> D[Initial state]
    C --> E[Successor function]
    C --> F[Goal test]
    C --> G[Path cost]
    D --> H[State space]
    E --> H
    F --> H
    G --> H
    H --> I[Search strategy]
    I --> J[Solution]
    J --> K[Execute]

How to read it

  1. Start with a real-world task.
  2. Decide what success means.
  3. Remove irrelevant details and choose an appropriate representation.
  4. Define the four problem components.
  5. This creates a search space that algorithms can explore.
  6. A search strategy finds a solution.
  7. The agent executes the resulting action sequence.

22. What exactly is being searched?

This is a subtle but important question.

The algorithm is not searching through every possible detail of reality.

It is searching through the abstract state space you defined.

For route finding:

REAL WORLD
roads + weather + traffic + people + buildings + etc.
                         ↓
                  ABSTRACT IT
                         ↓
STATE SPACE
cities + road connections + costs

This means the quality of the final search result depends partly on the quality of the formulation.

A perfect search algorithm cannot rescue a badly designed problem representation.

23. What makes a good problem formulation?

A useful formulation should be:

23.1 Correct enough

It must preserve the information needed to answer the actual problem.

23.2 Small enough to search

Keeping irrelevant details can make the state space unnecessarily huge.

23.3 Actionable

The successor function must describe which transitions are possible.

23.4 Goal-oriented

The goal test must correctly recognise success.

23.5 Cost-aware

If multiple solutions are possible, the cost function should reflect what “better” means.

These are not separate algorithms. They are design decisions made before the search algorithm runs.

24. Common beginner confusion

Confusion 1 — “State = node.”

Not exactly.

State = configuration.

Node = search record containing a state + search information.

Confusion 2 — “Goal state = goal test.”

They are related but not identical.

  • Goal state = a state that satisfies the objective.
  • Goal test = the procedure used to check whether a state is a goal.

Confusion 3 — “Action = successor function.”

No.

  • action = one possible operation,
  • successor function = the mechanism that describes the legal action-state transitions from a state.

Confusion 4 — “Path cost = step cost.”

No.

step cost = one move
path cost = total across the path

Confusion 5 — “Search algorithm creates the problem.”

No.

The problem formulation exists first.

The search algorithm decides how to explore the formulated space.

Confusion 6 — “More detail always means a better model.”

Not necessarily.

More detail can make the problem computationally infeasible without improving the answer.

That is why abstraction is essential.

25. Worked Example — formulate a route problem yourself

Problem

You are at Jind and want to reach Delhi. You may travel between connected cities. You want the minimum-distance route.

Do not solve the route yet.

We only formulate the problem.

Step 1 — Goal

Reach Delhi.

Step 2 — State

We only need the current city.

State = current city

Step 3 — Initial state

Jind

Step 4 — Actions / successor function

From each city, move to a connected city.

For a state such as Jind:

S(Jind) = legal connected cities

Each transition carries the action “travel to that city”.

Step 5 — Goal test

Current city == Delhi

Step 6 — Path cost

sum of travel distances

Final formulation

Item Answer
Initial state Jind
State Current city
Actions Travel along a connecting road
Successor function Generates connected cities + action transitions
Goal test Current city is Delhi
Path cost Total travel distance

Only after this formulation is complete should we ask:

Which search strategy should solve it?

That question belongs to the next chapters.

26. Worked Example — 8-puzzle formulation

Given a starting board:

1 2 3
4 _ 6
7 5 8

and a target board:

1 2 3
4 5 6
7 8 _

State

Arrangement of the tiles + blank location.

Initial state

The first board.

Actions

Move blank:

  • left,
  • right,
  • up,
  • down,

when legal.

Successor function

Generate all boards reachable by one legal blank move.

Goal test

Check whether the board equals the specified target arrangement.

Path cost

1 for every move.

Solution

A sequence of legal blank moves that reaches the goal.

Optimal solution

The solution requiring the fewest moves under the given unit step cost.

The formulation matches the structure used in the supplied Basic Search lecture. [Course note: lecture-basic-search.pdf, 8-puzzle example.]

29. Why this chapter comes before BFS and DFS

Suppose I say:

“Use BFS.”

You still need to know:

  • BFS on what?
  • What is a state?
  • What are the successors?
  • What counts as the goal?
  • What does a path mean?

Without a formulation, BFS is just a generic mechanism with nothing concrete to operate on.

So the correct learning order is:

37. What you should NOT memorize yet

Do not waste time memorizing isolated wording such as:

“state is an abstract representation of a physical configuration”

without understanding it.

You need to understand the concept first.

For the exam, you should eventually be able to write the formal definition, but the understanding should be:

“State = the relevant current configuration of the problem.”

Likewise:

Node = state + search bookkeeping.

Path = sequence of transitions.

Solution = path reaching a goal.

Optimal solution = best solution under the defined cost criterion.
