MAIN-U4-C48 — AI in Autonomous Vehicles

Main Book: AI & Machine Learning — Visual + Mathematical Self-Learning Textbook

Syllabus position: AI applications — autonomous vehicles
Prerequisites: C14–C29 (ML), C30–C39 (deep learning), C40–C43 (RL/NLP foundations)

1. Why This Chapter Exists

An autonomous vehicle is not simply “a car with a neural network.”

It is a complete AI-enabled decision system that has to:

  • perceive what is around it;
  • understand the situation;
  • predict what other road users may do;
  • decide what to do next;
  • plan a safe path;
  • control the vehicle;
  • react to uncertainty and unexpected events.

The useful mental model is therefore:

AUTONOMOUS VEHICLE
                        │
        ┌───────────────┼────────────────┐
        │               │                │
     PERCEPTION      PREDICTION        LOCALIZATION
        │               │                │
        └───────────────┼────────────────┘
                        ↓
                    PLANNING
                        ↓
                    CONTROL
                        ↓
                VEHICLE / ACTUATORS
                        │
                        └────── feedback ──────►

This chapter is an application synthesis of ideas you already learned elsewhere in the Main Book.

The goal is not to memorize a list of sensors or companies. The goal is to understand how AI/ML components fit into an autonomous system.

2. One-Minute Intuition

Imagine a human driving through a crowded road.

You continuously do something like this:

See road
  ↓
Recognize lane / vehicle / pedestrian
  ↓
Estimate where things are going
  ↓
Decide whether to slow, stop, turn or continue
  ↓
Choose a trajectory
  ↓
Steer + accelerate + brake
  ↓
Observe the changed road
  ↓
Repeat

An autonomous vehicle has to construct a machine version of this loop.

👨‍🏫 Hinglish teacher explanation
Socho tum traffic mein bike ya car chala rahe ho. Sirf saamne dekhna enough nahi hai. Tumhe ye samajhna padta hai: > “Ye object kya hai?” > “Ye kidhar move kar raha hai?” > “Meri lane safe hai?” > “Mujhe brake karna hai ya turn?” > “Turn karunga to vehicle exactly kaise move karegi?” Autonomous driving mein AI ka kaam ek single prediction dena nahi hai. **Perception → understanding → prediction → decision → action** ka full loop banana hai.

## How to read this visual Start at the top. 1. **Sensors** observe the world. 2. Processing converts raw measurements into usable representations. 3. **Perception** extracts objects and scene information. 4. **Localization** estimates where the vehicle is. 5. **Prediction** estimates future behavior. 6. **Planning** selects a desired route/trajectory. 7. **Control** converts that plan into physical commands. 8. The vehicle moves, changing the next observations.

Important distinction

Perception is not planning.

Recognizing a pedestrian is perception.

Deciding to stop for the pedestrian belongs to downstream decision/planning.

4. What Does “Autonomous” Actually Mean?

A vehicle can automate only one part of driving without being a fully autonomous system.

It helps to separate:

  • assistance;
  • perception automation;
  • lane/path control;
  • decision making;
  • full driving-task automation.

The technical idea is that increasing automation moves more of the driving loop from the human to the machine.

Do not use a vague definition

“Autonomous vehicle = car that drives itself” is intuitive but incomplete.

A more useful definition is:

An autonomous vehicle is a cyber-physical system that uses sensing, estimation, machine learning/AI, planning and control to perform some or all driving tasks with reduced human intervention.

The precise operational meaning of “autonomous” depends on the system's claimed capability and operating conditions.

5. AI/ML Tasks Inside the Vehicle

The application can be decomposed into familiar ML problems.

Vehicle task AI/ML framing
Detect cars/pedestrians classification + object detection
Separate drivable road regions segmentation
Identify lane markings vision / geometric estimation
Read traffic signs classification/OCR
Predict another vehicle's motion sequence prediction
Decide among actions planning / decision making / RL concepts
Estimate uncertainty probabilistic modelling / calibrated prediction
Improve perception from data supervised/self-supervised learning
Learn policies in simulated environments reinforcement learning
Monitor system failures anomaly detection / safety monitoring

The same ML concepts from Units II and III reappear here.

6. Sensor Modalities

A real autonomous system can use more than one sensing modality.

6.1 Camera

A camera provides rich visual information.

It can support:

  • object recognition;
  • lane detection;
  • traffic-light recognition;
  • sign recognition;
  • scene understanding.

AI connection

CNN-style visual models are natural candidates for many image-based perception tasks.

Limitation

A camera does not directly hand you a perfect 3D world model.

Lighting, rain, glare, shadows and occlusion can affect perception.

6.2 LiDAR

LiDAR measures ranges using emitted light pulses.

The result can be represented as a point cloud.

Conceptually:

physical world
     ↓
range measurements
     ↓
3D point cloud
     ↓
object / geometry understanding

LiDAR can provide useful geometric information, but sensors have cost, range, weather and integration considerations.

6.3 Radar

Radar measures properties related to radio-wave reflections and can be useful for:

  • detecting objects;
  • estimating relative motion;
  • supporting operation in challenging visibility conditions.

Radar and camera therefore provide different kinds of evidence.

6.4 GNSS + IMU

These support localization and motion estimation.

  • GNSS: positioning using satellite navigation signals.
  • IMU: inertial measurements such as acceleration and angular velocity.

They are often combined with other information rather than treated as flawless absolute truth.

7. Sensor Fusion

Suppose:

  • the camera says “there is an object”;
  • LiDAR says “the object is approximately here in 3D”;
  • radar says “the object is moving toward/away from me.”

Using multiple measurements can produce a more informative system representation.

Camera ───┐
LiDAR ────┼──► Fusion / shared representation ─► downstream AI
Radar ────┘

Analogy

Imagine three witnesses describing the same road incident.

One sees color and shape.

One estimates distance.

One estimates relative motion.

Combining their evidence can be more useful than forcing one witness to answer every question.

Boundary of the analogy

Three human witnesses are not statistically independent sensors, and real sensor fusion requires explicit models, calibration and uncertainty handling.

8. Perception: From Pixels to Objects

A perception system can perform tasks such as:

Classification

“What kind of object is this?”

Example:

crop → {car, bus, bicycle, pedestrian, ...}

Object detection

“What objects are present, and where?”

image
 ↓
bounding boxes + class labels + confidence

Semantic segmentation

“What class does each pixel belong to?”

road | sidewalk | vehicle | pedestrian | sky | ...

Instance segmentation

“What pixels belong to each individual object instance?”

These are different tasks.

9. Confidence Is Not Certainty

Suppose a detector returns:

pedestrian: 0.94

This does not mean:

“There is a 94% guarantee that a pedestrian exists.”

A model's output needs interpretation, calibration and context.

This is especially important in safety-critical systems.

The general principle connects directly to C24–C25:

Classification outputs should be evaluated, and uncertainty should not be confused with certainty.

10. Localization

Perception answers:

“What is around me?”

Localization answers:

“Where am I?”

A vehicle may combine:

  • GNSS;
  • IMU;
  • map information;
  • visual landmarks;
  • LiDAR geometry;
  • odometry.

Conceptually:

sensor observations + prior estimate
                ↓
          state estimation
                ↓
         current vehicle pose

A pose typically includes position and orientation.

11. Mapping

A map gives prior structural information.

Examples:

  • lane topology;
  • intersections;
  • road geometry;
  • speed restrictions;
  • other static infrastructure.

But a map cannot perfectly predict the current world.

A parked truck may block a lane even though the map says nothing unusual exists there.

Therefore:

MAP = prior structural knowledge

SENSORS = current observations

DECISION = combination of both

12. Prediction

Prediction asks:

“What might other agents do next?”

Suppose a nearby pedestrian is walking toward a crossing.

Possible future trajectories include:

┌── continue
pedestrian┼── stop
          └── cross

The system should often reason over multiple plausible futures, not only one guaranteed future.

Sequence-model connection

RNNs/LSTMs from Unit III provide a historical example of modelling temporal dependence.

Modern systems may use other sequence architectures as well; that is beyond the minimum syllabus requirement here.

13. Planning

Planning converts the estimated situation into a desired action or trajectory.

For example:

Current state
    ↓
possible trajectories
 ┌─────┬─────┬─────┐
 ↓     ↓     ↓
left  straight  stop
       │
       ▼
evaluate safety / legality / progress / comfort
       │
       ▼
selected trajectory

Planning is not simply “choose the label with highest probability.”

It is a constrained decision problem.

14. Reinforcement Learning Connection

The RL concepts from C40–C42 can be used to understand some decision-making formulations.

A simplified MDP-style interpretation is:

  • state \(s\): current driving situation;
  • action \(a\): high-level driving choice;
  • transition \(P(s'|s,a)\): what may happen after the choice;
  • reward \(R(s,a,s')\): numerical preference for desirable outcomes;
  • policy \(\pi(a|s)\): action-selection strategy.

Example:

state:
ego vehicle approaching intersection

actions:
{slow, stop, turn, continue}

reward:
safety + progress + legality + comfort

Important caution

A real vehicle should not be reduced to a toy reward function.

Safety constraints, verification, fallback behaviour, perception errors and system architecture matter enormously.

15. Control

Planning says:

“Follow this trajectory.”

Control says:

“What steering, braking and acceleration commands make the vehicle follow it?”

Thus:

planning ≠ control

A simplified loop is:

desired trajectory
      ↓
compare with current vehicle state
      ↓
calculate control action
      ↓
steering / throttle / brake
      ↓
new vehicle state
      ↓
repeat

This is an important example of AI interacting with a physical system.

16. Why Safety Is Different From Ordinary ML Accuracy

Suppose a classifier has:

99% accuracy

That single number is not enough to establish driving safety.

Questions become:

  • What kinds of errors remain?
  • Under which weather conditions?
  • Which objects are missed?
  • How often are rare dangerous events misclassified?
  • Does performance degrade in unfamiliar locations?
  • What happens when a sensor fails?
  • What happens when confidence is low?

The cost of errors is asymmetric.

Missing a pedestrian can be much more consequential than misclassifying a decorative roadside sign.

This connects directly to the confusion-matrix ideas from Unit II.

17. False Positives vs False Negatives in Driving

Suppose the task is “is there a pedestrian in the vehicle's path?”

Actual Prediction Meaning
Pedestrian Pedestrian TP
No pedestrian Pedestrian FP
Pedestrian No pedestrian FN
No pedestrian No pedestrian TN

A false negative can correspond to a dangerous missed hazard.

A false positive can trigger unnecessary caution, braking or route changes.

Therefore:

The correct operating threshold depends on the task, costs, operating environment and safety design—not merely overall accuracy.

18. Dataset Shift

Training data might contain:

clear weather
daylight
known road types
common vehicle models

Deployment can contain:

night
fog
rain
construction
rare vehicles
unusual road layouts

This difference is a form of distribution/data shift.

The model may perform differently when deployment data differ from training data.

Memory anchor

Train-world ≠ always real-world.

19. Edge Cases

An autonomous vehicle must reason about events that may be rare in the training set.

Examples:

  • unusual roadworks;
  • an object partly hidden behind another object;
  • a pedestrian wearing unusual clothing;
  • a vehicle stopped in an unexpected location;
  • debris on the road;
  • unusual lane markings.

These cases are important precisely because they may be underrepresented.

20. Human Oversight and Fallbacks

A safety-oriented system should not assume:

“The model will always be correct.”

Instead, architecture can include:

normal model output
      ↓
confidence / consistency checks
      ↓
safe operating envelope?
   ┌───────┴───────┐
  yes             no
   ↓               ↓
continue       fallback / minimal-risk response

The exact mechanism depends on system design.

The key principle is:

When confidence or system health is inadequate, the system needs a defined safe behaviour rather than silent failure.

21. Worked Case Study — Pedestrian at a Crossing

Suppose a vehicle approaches a crossing.

Step 1 — Sensing

Camera and other sensors observe the scene.

Step 2 — Perception

The system estimates:

pedestrian detected
position ≈ crossing area
confidence = high

Step 3 — Localization

The vehicle estimates its own position relative to the road and crossing.

Step 4 — Prediction

The pedestrian's motion suggests a possible crossing trajectory.

Step 5 — Planning

The planner compares:

  • continue;
  • slow;
  • stop.

Given the estimated risk, it selects a conservative trajectory.

Step 6 — Control

The controller applies braking.

Step 7 — Feedback

New sensor data arrives.

The system updates the state and repeats the loop.

What is the important lesson?

The result was not produced by “one AI algorithm.”

It came from a pipeline of interacting estimation, prediction, decision and control components.

22. A Numerical Decision Example

Suppose a simplified planner evaluates three candidate actions using a toy score:

\[ S(a)=\alpha\,\text{progress}(a)-\beta\,\text{risk}(a)-\gamma\,\text{discomfort}(a) \]

Take:

\[ \alpha=1,\qquad \beta=5,\qquad \gamma=1. \]
Action Progress Risk Discomfort
Continue 10 0.8 2
Slow 7 0.2 3
Stop 3 0.05 4

Then:

\[ S(\text{continue})=10-5(0.8)-2=4 \]
\[ S(\text{slow})=7-5(0.2)-3=3 \]
\[ S(\text{stop})=3-5(0.05)-4=-1.25 \]

This toy calculation shows how a decision rule can combine multiple criteria.

Critical limitation

This is not a safe real-world driving objective.

It is a teaching example for understanding multi-objective decision scoring.

Safety-critical systems require far more structure than one hand-designed scalar score.

23. What AI/ML Is Doing — and What It Is Not Doing

AI/ML is particularly useful for:

  • recognising complex patterns from sensor data;
  • predicting behaviour;
  • learning representations;
  • estimating probabilities;
  • adapting to large data distributions.

But not every component must be neural-network-based.

A complete vehicle can contain:

ML models
+
state estimation
+
geometric algorithms
+
search/planning
+
optimization
+
control systems
+
safety rules
+
monitoring

This is a crucial systems-engineering lesson.

24. Common Architecture Errors

Trap 1 — “CNN drives the car”

Why it feels right: cameras are images and CNNs are image models.

Actually: a CNN can support perception, but perception is only one stage.

Trap 2 — “Prediction = planning”

Prediction estimates possible future behaviour.

Planning chooses what the vehicle should do.

Trap 3 — “High accuracy means safe”

Accuracy is only one evaluation statistic.

Rare, high-consequence failures can dominate safety.

Trap 4 — “Map = current truth”

Maps represent prior knowledge.

Sensors observe current conditions.

Trap 5 — “RL automatically learns safe driving”

A learned policy depends on its state/action/reward design, training distribution, environment, constraints and deployment safeguards.

📝 2-mark style

📝 5-mark style
**Q:** Explain the role of machine learning in autonomous vehicles. A strong answer can structure the response as: 1. sensor data acquisition; 2. perception; 3. object/scene understanding; 4. prediction; 5. planning/decision making; 6. control; 7. feedback and monitoring; 8. safety/failure considerations.

Application question

Q: Why is a confusion matrix relevant to autonomous driving perception?

Because different error types can have different consequences. In hazard detection, false negatives and false positives need to be interpreted separately rather than hidden inside a single accuracy value.
