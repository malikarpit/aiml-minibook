01

Why SGD Exists

Full-batch gradient descent uses every training example for every update:

\[ \boxed{ \nabla J(\mathbf w) = \frac1n \sum_{i=1}^{n} \nabla L_i(\mathbf w) } \]

For a very large dataset, repeatedly processing the entire dataset can be expensive.

So we can estimate the full gradient from:

  • one example → SGD,
  • a subset → mini-batch GD.
02

Full-Batch Gradient Descent

👨‍🏫 Teacher Intuition — Bilingual Mental Model
Socho tum 10 lakh (1,000,000) students ka feedback lekar syllabus revise kar rahe ho: 1. **Batch GD:** Tum sabhi 10 lakh students ke form bharne ka wait karte ho, sabka average nikalte ho, phir 1 kadam badhate ho. Ye bohot accurate hai lekin har kadam par ghanton lag jayenge! 2. **Pure SGD:** Tum sadak par chalte hue 1 student ko pakadte ho aur uska feedback lekar turant step le lete ho. Ye bohot fast hai, lekin vo 1 student shayaad unusual ho, isiliye tumhara path kafi hil-dul (noisy zig-zag) karega. 3. **Mini-Batch GD:** Tum 64 ya 128 students ka ek sample group bulate ho. Unka average kafi stable hota hai (variance $\sigma^2 / B$ ho jata hai), aur GPU matrix multiplication ise superfast process kar leta hai! Production deep learning mein 99.9% yahi use hota hai.

Given:

\[ J(\mathbf w) = \frac1n\sum_{i=1}^{n}L_i(\mathbf w), \]

the update is:

\[ \boxed{ \mathbf w_{t+1} = \mathbf w_t - \eta \frac1n \sum_{i=1}^{n} \nabla L_i(\mathbf w_t). } \]

Conceptually:

all examples
    ↓
all gradients
    ↓
average
    ↓
update
03

Stochastic Gradient Descent

Choose one example (i) randomly and use:

\[ \nabla L_i(\mathbf w) \]

as an estimate of the full gradient.

The update is:

\[ \boxed{ \mathbf w_{t+1} = \mathbf w_t - \eta\nabla L_i(\mathbf w_t). } \]

Conceptually:

one example
    ↓
one gradient estimate
    ↓
update
04

Why One Example Can Work

If (i) is selected uniformly:

\[ P(i)=\frac1n. \]

Then:

\[ E_i\[\nabla L_i(\mathbf w)\]

= \sum_{i=1}\^{n} \frac1n\nabla L_i(\mathbf w). ]

Therefore:

\[ \boxed{ E_i[\nabla L_i(\mathbf w)] = \nabla J(\mathbf w). } \]

So the single-example gradient is an unbiased estimator of the full gradient under uniform sampling.

Python & NumPy From-Scratch Verification

PYTHON
import numpy as np

# Synthetic linear dataset: y = 2*x + 1 + noise
np.random.seed(42)
n = 1000
X = np.random.randn(n, 1)
y = 2.0 * X + 1.0 + np.random.randn(n, 1) * 0.2

# Mini-batch gradient calculation
batch_size = 32
indices = np.random.choice(n, batch_size, replace=False)
X_batch, y_batch = X[indices], y[indices]

# w = [w_weight, w_bias]
w = np.array([[0.0], [0.0]])
X_b = np.hstack([X_batch, np.ones((batch_size, 1))])

# Gradient for MSE: (2/B) * X^T (X*w - y)
pred = X_b @ w
errors = pred - y_batch
grad_mb = (2.0 / batch_size) * (X_b.T @ errors)

print(f"Batch size: {batch_size} from total {n} examples")
print(f"Sample predictions (first 3):
{pred[:3]}")
print(f"Mini-batch gradient vector:
{grad_mb}")

Suppose the individual gradients are:

\[ 2,\quad4,\quad8. \]

The full gradient is:

\[ \frac{2+4+8}{3} = \boxed{\frac{14}{3}\approx4.67}. \]

An SGD step might use:

\[ 2 \]

or:

\[ 4 \]

or:

\[ 8. \]

Each is different from (4.67).

But the expectation is:

\[ E\[\hat g\]

= \frac{2+4+8}{3} = 4.67. ]

06

Mini-Batch Gradient Descent

Choose a batch:

\[ B \]

with:

\[ \|B\|=b. \]

The batch gradient estimate is:

\[ \boxed{ \hat g_B(\mathbf w) = \frac1b \sum_{i\in B} \nabla L_i(\mathbf w) } \]

and:

\[ \boxed{ \mathbf w_{t+1} = \mathbf w_t-\eta\hat g_B(\mathbf w_t). } \]

Conceptually:

small group of examples
        ↓
individual gradients
        ↓
average
        ↓
update
07

Three Regimes

Method Examples/update Gradient character

Full-batch GD \(n\) exact empirical gradient SGD \(1\) noisy estimate Mini-batch (1\<b\<n) intermediate estimate

In practice, the term "SGD" is sometimes used broadly for mini-batch training; always interpret the convention from context.

08

Gradient Noise

For one example:

\[ \hat g_i=\nabla L_i. \]

Usually:

\[ \hat g_i\ne\nabla J. \]

Therefore the update direction fluctuates.

Visual intuition:

full gradient:
        ↓

SGD:
      ↙ ↓ ↘
       ↘ ↓
      ↙

The trajectory can zig-zag while still moving toward lower objective values on average.

09

Variance of a Gradient Estimate

Let:

\[ g_i=\nabla L_i(\mathbf w) \]

and:

\[ g=\nabla J(\mathbf w). \]

For a scalar component, variance measures spread around the expectation:

\[ Var(g_i). \]

For a vector, variance is understood component-wise or through a covariance matrix; for this foundation, the scalar-component picture is sufficient.

SGD can therefore be thought of as:

correct expected direction
+
random sampling variation
10

Mini-Batch Noise Reduction

Under the simplified assumption that sampled gradient estimates are independent and have common variance:

\[ \sigma_g^2, \]

the average of (b) samples has:

\[ \boxed{ Var(\hat g_B)=\frac{\sigma_g^2}{b}. } \]

Therefore:

\[ \boxed{ SD(\hat g_B) = \frac{\sigma_g}{\sqrt b}. } \]

This is a foundational idealized result.

Real training can violate the independence assumption because examples may be correlated or sampled without replacement.

11

Numerical Variance Example

⚠️ University Exam Trap & Common Misconception
**The "Unbiased" vs "Zero Error" Fallacy:** In exams, questions often ask: *"Does SGD's single-sample gradient equal the true gradient?"* The correct answer is: **No, but it is an unbiased estimator.**
$$\mathbb{E}[\nabla L_i(w)] = \nabla J(w)$$
The expectation over random selection equals the true gradient, but the instantaneous gradient $\nabla L_i(w)$ has variance $\text{Var}(\nabla L_i) = \sigma^2$. Because of this variance, SGD will never settle quietly at the exact minimum with a constant learning rate—it will bounce around in a ball of radius $O(\eta)$. To guarantee convergence, you MUST decay the learning rate ($\sum \eta_t = \infty$ and $\sum \eta_t^2 \lt \infty$).

Suppose:

\[ \sigma_g^2=100. \]

For:

\[ b=25, \]

the idealized mini-batch variance is:

\[ \frac{100}{25} = \boxed4. \]

Therefore standard deviation:

\[ \sqrt4 = \boxed2. \]

For:

\[ b=100, \]

variance becomes:

\[ \frac{100}{100} = \boxed1. \]

Thus larger batches generally give smoother estimates under the simplified assumptions.

Mini-Batch Example

⚠️ University Exam Trap & Common Misconception
**The "Unbiased" vs "Zero Error" Fallacy:** In exams, questions often ask: *"Does SGD's single-sample gradient equal the true gradient?"* The correct answer is: **No, but it is an unbiased estimator.**

Suppose selected gradients are:

\[ 1,\quad5,\quad7,\quad11. \]

Then:

\[ \hat g_B = \frac{1+5+7+11}{4} = \boxed6}. \]

If the full dataset gradient were (5.7), this batch gives (6), a reasonably close estimate in this particular example.

There is no guarantee that an arbitrary batch will be close.

Epoch

An epoch commonly means one pass through the training dataset.

If:

\[ n=10,000 \]

and:

\[ b=100, \]

then, assuming every example is used exactly once:

\[ \frac{10,000}{100} = \boxed{100} \]

updates occur per epoch.

Therefore:

batch size
→ examples per update

epoch
→ approximately one complete pass through data
14

Batch Size Trade-Off

Small batch

less memory
frequent updates
more noise

Large batch

more memory
fewer updates per epoch
less sampling noise

Neither is universally superior.

Hardware, data, model, learning rate, and optimization objective all matter.

Why Mini-Batches Are a Compromise

Full batch
    │
    ├─ stable estimate
    └─ expensive update

SGD
    │
    ├─ cheap update
    └─ noisy estimate

Mini-batch
    │
    ├─ partially smooth
    ├─ computationally efficient
    └─ still frequent updates

This is the main practical motivation.

16

Worked Training Trace

Consider:

\[ L_1(w)=(w-1)^2, \]
\[ L_2(w)=(w-3)^2, \]
\[ L_3(w)=(w-5)^2. \]

The full objective is:

\[ J(w) = \frac13 \[(w-1)^2+(w-3)^2+(w-5)^2\]

. ]

Gradients:

\[ L_1'(w)=2(w-1), \]
\[ L_2'(w)=2(w-3), \]
\[ L_3'(w)=2(w-5). \]

Therefore:

\[ J'(w) = \frac13 \[2(w-1)+2(w-3)+2(w-5)\]

. ]

Simplify:

\[ \boxed{ J'(w)=2w-6. } \]

The optimum is:

\[ 2w-6=0 \]

so:

\[ \boxed{w^*=3}. \]
17

SGD Update from (w=0)

Take:

\[ w_0=0, \qquad \eta=0.1. \]

If example 1 is selected:

\[ L_1'(0)=-2. \]

Then:

\[ w_1 = 0-0.1(-2) = \boxed{0.2}. \]

If instead example 3 is selected:

\[ L_3'(0)=-10. \]

Then:

\[ w_1 = 0-0.1(-10) = \boxed1}. \]

Same starting point, different random example, different update.

That is stochastic behaviour.

18

Expected Update at (w=0)

The three individual gradients are:

\[ -2,\quad-6,\quad-10. \]

Their average is:

\[ \frac{-2-6-10}{3} = \boxed{-6}. \]

And:

\[ J'(0)=-6. \]

Thus:

\[ \boxed{ E[\hat g]=J'(0) } \]

under uniform sampling.

19

Why Gradient Noise Exists

Different examples may have:

  • different features,
  • different targets,
  • different prediction errors,
  • different gradients.

Therefore:

\[ \nabla L_1,\nabla L_2,\ldots,\nabla L_n \]

need not point in exactly the same direction.

Sampling only one or a few examples therefore creates variation in the update.

20

Noise Is Not Automatically Bad

Gradient noise can:

  • make the trajectory less smooth,
  • allow frequent inexpensive updates,
  • sometimes help exploration in non-convex objectives.

But do not conclude:

"more noise is always better."

The effect depends on:

  • learning rate,
  • batch size,
  • objective,
  • model,
  • data,
  • sampling strategy.
21

Learning Rate + Batch Size

The update is:

\[ \mathbf w_{t+1} = \mathbf w_t-\eta\hat g_B. \]

Two independent ideas appear:

η
→ how strongly the estimate changes parameters

batch size
→ how noisy the estimate tends to be

A small batch with a huge learning rate can be particularly unstable.

A huge batch with an excessively tiny learning rate can make progress slow.

22

Data Shuffling

A common conceptual training cycle is:

shuffle data
↓
split into batches
↓
batch 1 → update
↓
batch 2 → update
↓
...
↓
end epoch

Shuffling reduces the chance that a fixed ordering repeatedly creates systematic update patterns.

The exact sampling strategy is an implementation choice.

23

Feature Scaling Connection

The supplied Lecture09 states that feature scaling improves gradient-descent convergence speed and stability.

This remains relevant to mini-batch methods because the gradients themselves depend on feature scales.

The optimization chain is:

feature scale
→ gradient scale
→ update scale
→ optimization trajectory

Standardization from the supplied lecture is:

\[ \boxed{ x_j\leftarrow \frac{x_j-\mu_j}{\sigma_j} } \]

and min-max scaling is:

\[ \boxed{ x_j\leftarrow \frac{x_j-\min(x_j)} {\max(x_j)-\min(x_j)} }. \]
24

Objective vs Gradient vs Estimate

These are different objects:

\[ \boxed{J(\mathbf w)} \]

= objective.

\[ \boxed{\nabla J(\mathbf w)} \]

= exact gradient of the empirical objective.

\[ \boxed{\hat g_B(\mathbf w)} \]

= gradient estimate from a selected batch.

Thus:

objective
≠ exact gradient
≠ estimated gradient
25

Bias vs Variance

For an estimator (\hat g) of (g):

Unbiased

\[ \boxed{ E[\hat g]=g } \]

Biased

\[ E\[\hat g\]

\ne g. ]

Variance

Measures random spread around the expectation.

Remember:

bias
→ systematic error in expectation

variance
→ randomness/spread

An unbiased estimator can still have large variance.

26

Hinglish Teacher Explanation

Full-batch GD mein har update ke liye poora dataset use hota hai.

SGD mein:

"Ek example uthao, gradient nikalo, update karo."

Mini-batch mein:

"Kuch examples uthao, unke gradients average karo, update karo."

So:

full batch
→ accurate but expensive

SGD
→ cheap but noisy

mini-batch
→ middle ground

Agar examples randomly choose ho rahe hain:

\[ E\[\hat g\]

=\nabla J. ]

Matlab har individual update exact nahi hai, lekin long-run average direction full gradient ke around correct hai.

Batch size (b) badhne par idealized independent setting mein:

\[ Var(\hat g_B)=\frac{\sigma_g^2}{b}. \]

Yaani batch bada:

gradient estimate smoother.

Lekin batch bada karna free nahi hai --- memory aur computation per update badh sakte hain.

Numerical Protocol

Full batch

1. Calculate every per-example gradient
2. Average
3. Update

SGD

1. Select one example
2. Calculate its gradient
3. Update

Mini-batch

1. Select B
2. Calculate each gradient
3. Average
4. Update

Expectation question

1. Identify sampling probabilities
2. List possible gradient values
3. Multiply each by probability
4. Add
5. Compare with full gradient
29

Common Traps

  • Thinking an SGD gradient must equal the full gradient.
  • Thinking unbiased means noise-free.
  • Forgetting the (1/b) averaging factor.
  • Confusing batch size with epoch.
  • Treating (1/b) variance reduction as an exact universal law.
  • Assuming larger batches are always better.
  • Ignoring learning-rate interaction.
  • Confusing the objective with its gradient estimate.
