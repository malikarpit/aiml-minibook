What You Will Build

    Prob --> BCE["Binary Cross-Entropy Loss: -[y log p̂ + (1-y) log(1-p̂)]"]

This chapter implements the complete binary classification pipeline:

features X
   ↓
linear score z = Xw + b
   ↓
sigmoid p = σ(z)
   ↓
predicted probability
   ↓
threshold
   ↓
class 0 / class 1
   ↓
confusion matrix + precision/recall/F1/ROC-AUC

Training follows a separate path:

(X, y)
  ↓
linear score
  ↓
sigmoid probability
  ↓
binary log loss
  ↓
gradient
  ↓
parameter update
  ↓
repeat

The important conceptual split is:

The model produces a score/probability; the threshold converts that probability into a class label.

That distinction becomes extremely important when you later study precision, recall, ROC and AUC.

03

Why Not Just Use Linear Regression for Classes?

Suppose the target is:

y = 0 → not spam
y = 1 → spam

A linear regression model produces:

\[ \hat y = w^Tx+b. \]

There is no guarantee that:

\[ 0 \le \hat y \le 1. \]

A linear model might predict:

-0.7
0.21
0.81
1.34

The values -0.7 and 1.34 are awkward if we want to interpret output as a probability.

Logistic regression keeps the linear structure but passes the score through a function that maps the real line into (0, 1).

linear score
z ∈ (-∞, +∞)
      │
      ▼
 sigmoid
      │
      ▼
 p ∈ (0, 1)
04

One-Minute Intuition

Think of logistic regression as a two-stage machine.

Stage A — evidence score

The model combines features:

\[ z = w_1x_1 + w_2x_2 + \cdots + w_dx_d+b. \]

A large positive value means evidence toward class 1.

A large negative value means evidence toward class 0.

A value near zero means the model is uncertain.

Stage B — squash the score

The sigmoid converts that score into a bounded value:

\[ p = \sigma(z). \]

Example:

z = -4  →  p ≈ 0.018
z = -1  →  p ≈ 0.269
z =  0  →  p = 0.500
z = +1  →  p ≈ 0.731
z = +4  →  p ≈ 0.982

Hinglish

Pehle model features ko combine karke ek raw score banata hai. Phir sigmoid us score ko 0 aur 1 ke beech laata hai. Positive score class 1 ki taraf signal deta hai, negative score class 0 ki taraf.

05

Real-World Analogy

Imagine a bank trying to predict whether an application should be labelled:

0 = low-risk according to the trained target definition
1 = high-risk according to the trained target definition

The model might use:

income
existing debt
credit history length
number of late payments

It does not jump directly from these numbers to the final class.

It first computes an evidence score:

positive evidence
      +
      -
negative evidence
      ↓
   score z
      ↓
 sigmoid
      ↓
 probability p

The final decision is a separate policy choice, such as:

\[ \hat y = 1 \quad \text{if } p \ge 0.5. \]

The threshold need not always be 0.5; later we will see why changing the threshold changes precision and recall.

06

Model Definition

For sample \(x_i\), logistic regression defines:

\[ z_i=w^Tx_i+b. \]

Then:

\[ \boxed{p_i=P(y_i=1\mid x_i)=\sigma(z_i)} \]

where:

\[ \boxed{ \sigma(z)=\frac{1}{1+e^{-z}} } \]

The model is still linear in the features before the sigmoid.

This is why logistic regression remains a linear classifier in feature space.

07

Coding Representation

Use the following shape convention.

X : (n_samples, n_features)
y : (n_samples,)
w : (n_features,)
b : scalar
p : (n_samples,)

The central computation is:

PYTHON
z = X @ w + b

Then:

PYTHON
p = sigmoid(z)

Shape check

If:

X = (100, 2)
w = (2,)

then:

X @ w = (100,)

which can be added to scalar b.

A large proportion of ML implementation bugs are actually shape bugs. Make shape inspection routine.

09

Implement the Sigmoid

The first implementation is:

PYTHON
def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

Test it:

PYTHON
values = np.array([-2.0, 0.0, 2.0])
print(sigmoid(values))

Expected approximate values:

[0.1192, 0.5000, 0.8808]

Check the symmetry:

\[ \sigma(-z)=1- \sigma(z). \]

For example:

\[ \sigma(2)\approx0.8808 \]

and

\[ 1-\sigma(2)\approx0.1192=\sigma(-2). \]

PYTHON

PYTHON

The sigmoid should preserve ordering while compressing the scale.

11

Numerical Stability of the Sigmoid

The simple implementation is mathematically correct, but extreme values deserve attention.

For a very negative z, -z is very large and:

PYTHON
np.exp(-z)

can overflow in floating-point arithmetic.

A more stable implementation can split positive and negative values:

PYTHON
def sigmoid_stable(z):
    z = np.asarray(z, dtype=float)
    out = np.empty_like(z)

    positive = z >= 0
    negative = ~positive

    out[positive] = 1.0 / (1.0 + np.exp(-z[positive]))

    exp_z = np.exp(z[negative])
    out[negative] = exp_z / (1.0 + exp_z)

    return out

Now test:

PYTHON
z = np.array([-1000.0, -10.0, 0.0, 10.0, 1000.0])
p = sigmoid_stable(z)

print(p)
assert np.all(np.isfinite(p))

Engineering lesson

A formula can be mathematically correct and still require numerical engineering before it is safe to use in software.

12

Probability Is Not Yet a Class

Suppose:

p = 0.18
p = 0.51
p = 0.92

These are probability outputs in the model's classification framework.

A hard classifier could use:

PYTHON
def predict_class(p, threshold=0.5):
    return (p >= threshold).astype(int)

Then:

0.18 → 0
0.51 → 1
0.92 → 1

Notice that changing the threshold changes the labels without retraining the model.

This is one reason probability outputs are useful.

13

Why the Log Loss Exists

The model should not simply learn whether its hard prediction is correct.

During training we need a differentiable objective.

For binary classification, a standard objective is binary cross-entropy, also called binary log loss:

\[ \boxed{ J(w,b)= - \frac1n\sum_{i=1}^{n} \left[ y_i\log p_i+(1-y_i)\log(1-p_i) \right] } \]

where:

\[ p_i=\sigma(x_i^Tw+b). \]

The loss strongly penalizes confident wrong predictions.

14

Loss Intuition

Suppose the true class is:

\[ y=1. \]

Then the contribution is:

\[ - log(p). \]

Examples:

p = 0.90 → small loss
p = 0.60 → moderate loss
p = 0.10 → large loss
p = 0.01 → very large loss

For a true class 0, the relevant term becomes:

\[ - log(1-p). \]

Hinglish

Agar reality 1 hai aur model 0.99 bolta hai, to model ko reward-type small loss milega. Agar reality 1 hai aur model 0.01 confidence se bolta hai, to loss bahut bada hoga. Matlab wrong + confident = very costly.

15

Stable Binary Log Loss

A direct implementation is:

PYTHON
def log_loss(y, p, eps=1e-12):
    p = np.clip(p, eps, 1.0 - eps)
    return -np.mean(
        y * np.log(p) +
        (1.0 - y) * np.log(1.0 - p)
    )

The clipping prevents:

log(0)

which is undefined.

A useful identity for logistic regression is the stable per-example expression:

\[ \ell_i=\log(1+e^{z_i})-y_i z_i. \]

In NumPy this can be implemented using np.logaddexp:

PYTHON
def logistic_log_loss_from_logits(y, z):
    return np.mean(
        np.logaddexp(0.0, z) - y * z
    )

This avoids explicitly creating probabilities before evaluating the loss.

For teaching, know both forms:

probability form → easy to understand
logit form       → numerically safer
16

The Gradient We Need

For the parameter vector \(w\), the logistic-regression gradient is:

\[ \boxed{ \nabla_w J = \frac1n X^T(p-y) } \]

and for the bias:

\[ \boxed{ \frac{\partial J}{\partial b} = \frac1n\sum_{i=1}^{n}(p_i-y_i) } \]

The elegant result is:

prediction error = p - y

feature gradient = Xᵀ(error) / n
bias gradient    = mean(error)

This same error pattern will reappear throughout neural networks.

17

Why the Gradient Has This Form — Derivation Roadmap

For one sample:

\[ z=w^Tx+b \]
\[ p=\sigma(z) \]

and:

\[ \ell=-[y\log p+(1-y)\log(1-p)]. \]

The chain rule gives:

\[ \frac{\partial \ell}{\partial z} = \frac{\partial \ell}{\partial p} \frac{\partial p}{\partial z}. \]

The sigmoid derivative is:

\[ \boxed{ \sigma'(z)=\sigma(z)(1-\sigma(z)) } \]

so:

\[ \frac{\partial \ell}{\partial z}=p-y. \]

Then because:

\[ z=w^Tx+b, \]

we have:

\[ \frac{\partial z}{\partial w}=x \]

and therefore:

\[ \boxed{ \nabla_w \ell=(p-y)x } \]

Averaging over samples yields:

\[ \boxed{ \nabla_wJ=\frac1nX^T(p-y) } \]

This cancellation is one of the most useful derivations to understand rather than memorize blindly.

18

Gradient Descent Update

Once the gradient is available:

\[ \boxed{ w\leftarrow w-\eta\nabla_wJ } \]

and:

\[ \boxed{ b\leftarrow b-\eta\frac{\partial J}{\partial b} } \]

where \(\eta\) is the learning rate.

The complete loop becomes:

initialize w, b
      ↓
compute z
      ↓
compute p
      ↓
compute loss
      ↓
compute gradients
      ↓
update w, b
      ↓
repeat
19

First From-Scratch Class

Implement a minimal estimator.

PYTHON
import numpy as np

class LogisticRegressionScratch:
    def __init__(self, learning_rate=0.1, epochs=1000):
        self.learning_rate = learning_rate
        self.epochs = epochs
        self.w = None
        self.b = None
        self.loss_history = []

    def _sigmoid(self, z):
        z = np.asarray(z, dtype=float)
        out = np.empty_like(z)

        positive = z >= 0
        negative = ~positive

        out[positive] = 1.0 / (1.0 + np.exp(-z[positive]))
        ez = np.exp(z[negative])
        out[negative] = ez / (1.0 + ez)
        return out

    def fit(self, X, y):
        X = np.asarray(X, dtype=float)
        y = np.asarray(y, dtype=float)

        n_samples, n_features = X.shape
        self.w = np.zeros(n_features)
        self.b = 0.0
        self.loss_history = []

        for _ in range(self.epochs):
            z = X @ self.w + self.b
            p = self._sigmoid(z)

            loss = -np.mean(
                y * np.log(np.clip(p, 1e-12, 1.0)) +
                (1.0 - y) * np.log(np.clip(1.0 - p, 1e-12, 1.0))
            )

            error = p - y
            dw = (X.T @ error) / n_samples
            db = np.mean(error)

            self.w -= self.learning_rate * dw
            self.b -= self.learning_rate * db

            self.loss_history.append(loss)

        return self

    def predict_proba(self, X):
        X = np.asarray(X, dtype=float)
        z = X @ self.w + self.b
        p1 = self._sigmoid(z)
        return np.column_stack([1.0 - p1, p1])

    def predict(self, X, threshold=0.5):
        p1 = self.predict_proba(X)[:, 1]
        return (p1 >= threshold).astype(int)

This is intentionally small. The objective is to expose the learning mechanism instead of hiding it behind an API.

PYTHON

22

Manual Trace of One Gradient Step

Use a single sample to understand the update.

Let:

\[ x=2, \quad y=1, \quad w=0, \quad b=0. \]

Then:

\[ z=wx+b=0. \]

Sigmoid:

\[ p=\sigma(0)=0.5. \]

Error:

\[ p-y=0.5-1=-0.5. \]

For one sample:

\[ \frac{\partial \ell}{\partial w}=(p-y)x. \]

Therefore:

\[ \frac{\partial \ell}{\partial w}=(-0.5)(2)=-1. \]

With learning rate:

\[ \eta=0.1, \]

the update is:

\[ w_{new}=0-0.1(-1)=0.1. \]

For the bias:

\[ \frac{\partial \ell}{\partial b}=-0.5 \]

so:

\[ b_{new}=0-0.1(-0.5)=0.05. \]

Interpretation

The example had target 1, while the initial model was neutral (p=0.5). The update moves parameters so that this feature value is more likely to produce class 1 next time.

23

Decision Boundary

For threshold 0.5, logistic regression predicts class 1 when:

\[ \sigma(z)\ge0.5. \]

Because:

\[ \sigma(0)=0.5, \]

the boundary is:

\[ z=0. \]

Therefore:

\[ \boxed{ w^Tx+b=0 } \]

This is a line in 2D, a plane in 3D, and a hyperplane in higher dimensions.

Important connection

The sigmoid creates nonlinear output probabilities, but the default decision boundary in feature space remains linear.

    X2[:, 0].min(),

Finite-Difference Gradient Check

A correct symbolic gradient is easier to trust when compared against a numerical approximation.

For parameter \(w_j\):

\[ \boxed{ \frac{\partial J}{\partial w_j} \approx \frac{J(w_j+\epsilon)-J(w_j-\epsilon)}{2\epsilon} } \]

Implement a small helper:

PYTHON
def loss_for_params(X, y, w, b):
    z = X @ w + b
    p = sigmoid_stable(z)
    p = np.clip(p, 1e-12, 1.0 - 1e-12)
    return -np.mean(
        y * np.log(p) +
        (1.0 - y) * np.log(1.0 - p)
    )

Then compare an analytical gradient to the finite-difference gradient.

PYTHON
Xg = np.array([
    [1.0, 2.0],
    [2.0, -1.0],
    [-1.0, 1.5],
])

yg = np.array([1.0, 0.0, 1.0])
wg = np.array([0.2, -0.4])
bg = 0.1

z = Xg @ wg + bg
pg = sigmoid_stable(z)
error = pg - yg
analytical = (Xg.T @ error) / len(yg)

epsilon = 1e-6
numeric = np.zeros_like(wg)

for j in range(len(wg)):
    w_plus = wg.copy()
    w_minus = wg.copy()
    w_plus[j] += epsilon
    w_minus[j] -= epsilon

    numeric[j] = (
        loss_for_params(Xg, yg, w_plus, bg)
        - loss_for_params(Xg, yg, w_minus, bg)
    ) / (2 * epsilon)

print("analytical:", analytical)
print("numeric:   ", numeric)
assert np.allclose(
    analytical,
    numeric,
    rtol=1e-5,
    atol=1e-6,
)

Why this matters

This is not “extra math for no reason.” A gradient bug can make every later experiment meaningless.

Important Library Difference: Regularization

A common source of confusion is comparing a scratch implementation with a library model while silently using different objectives.

Your scratch model above minimizes the unregularized binary log loss.

A library estimator may include regularization by default.

That changes the optimization objective.

Therefore, when comparing implementations, explicitly record:

model objective
regularization type
regularization strength
solver
maximum iterations
preprocessing
random seed, when relevant

Do not call two models “equivalent” merely because both are named logistic regression.

36

What Logistic Regression Learns

Suppose:

\[ w=[2,-1]. \]

Then:

\[ z=2x_1-x_2+b. \]

Feature interpretation is conditional on the rest of the model:

  • positive coefficient pushes the score upward as the feature increases, holding other model inputs fixed;
  • negative coefficient pushes the score downward, holding other inputs fixed;
  • coefficient magnitude depends strongly on feature scaling.

Avoid the beginner mistake:

“A bigger coefficient always means a more important feature.”

That is not valid when feature scales differ.

37

Log-Odds Interpretation

The logistic model has an elegant interpretation.

Starting from:

\[ p=\frac{1}{1+e^{-z}}, \]

we obtain:

\[ \frac{p}{1-p}=e^z. \]

Taking logarithms:

\[ \boxed{ \log\frac{p}{1-p}=z=w^Tx+b } \]

So logistic regression is linear in the log-odds.

Increasing feature \(x_j\) by one unit changes the log-odds by \(w_j\), holding other features fixed.

A coefficient of zero means that feature has no effect on the log-odds in this fitted linear expression. More generally, it changes the odds multiplicatively by:

\[ \boxed{e^{w_j}} \]

for a one-unit increase, subject to the model assumptions and other features being held fixed.

This is useful conceptually even when your practical implementation only needs the sigmoid and gradient descent.

Edge Case: Perfect Separation

A dataset may be perfectly linearly separable.

Then the training objective can keep improving as the coefficient magnitudes become very large, while the hard classifications remain unchanged.

Conceptually:

separation already correct
        ↓
confidence can keep increasing
        ↓
weights can grow

This is one reason regularization and stopping criteria matter in real implementations.

Do not interpret “loss is getting lower” as automatically meaning “the model is becoming more useful.”

Always inspect validation behaviour too.

40

Edge Case: Class Imbalance

Suppose:

980 class 0
20 class 1

A classifier can achieve high accuracy while performing poorly on the minority class.

That is why the course places the confusion matrix, precision, recall and F1 immediately beside classification.

Logistic regression is not immune to imbalance merely because it outputs probabilities.

Practical responses may include:

  • better evaluation metrics;
  • threshold analysis;
  • class weighting;
  • resampling strategies;
  • collecting better data.

The correct choice depends on the actual application.

41

What the Model Can and Cannot Represent

Default logistic regression produces a linear decision boundary:

\[ w^Tx+b=0. \]

Therefore it may struggle with patterns such as XOR without feature engineering.

Example concept:

class 1   class 0
class 0   class 1

No single straight line can separate those points in the original 2D coordinates.

Possible responses include:

feature engineering
       ↓
nonlinear features
       ↓
linear model in expanded feature space

or a model family capable of nonlinear boundaries, such as trees or neural networks.

42

Optional Extension: Polynomial Features

A feature transformation can let logistic regression model nonlinear boundaries in the original variables while remaining linear in transformed features.

Example:

\[ \phi(x_1,x_2)= [x_1,x_2,x_1^2,x_2^2,x_1x_2]. \]

Then:

\[ z=w^T\phi(x)+b. \]

The classifier is still linear in \(\phi(x)\), but not necessarily linear in the original \((x_1,x_2)\).

input features
      ↓
feature map
      ↓
linear logistic model
      ↓
nonlinear boundary in original space

This connects directly with the feature-expansion idea later discussed in the supplied Unit II material.

Common Bugs

Bug 1 — Wrong sign in the update

Wrong:

PYTHON
w += learning_rate * dw

Correct gradient-descent direction:

PYTHON
w -= learning_rate * dw

Bug 2 — Wrong label encoding

The loss assumes 0/1, but the data contains -1/+1.

Bug 3 — log(0)

Clip probabilities or use a stable logit-based loss.

Bug 4 — Overflow in exp

Use a stable sigmoid implementation.

Bug 5 — Test leakage

Do not fit a scaler on the entire dataset before the split.

Bug 6 — Wrong ROC-AUC input

Use a probability/score, not only hard predictions.

Bug 7 — Comparing unlike objectives

A regularized library model is not exactly the same objective as an unregularized scratch model.

Bug 8 — Confusing coefficient sign with causality

A learned coefficient is a model parameter, not automatically a causal conclusion.

Complexity

For one full-batch gradient step with:

  • \(n\) samples;
  • \(d\) features;

matrix multiplication and gradient computation are approximately:

\[ \boxed{O(nd)} \]

per epoch.

If you run \(T\) epochs:

\[ \boxed{O(Tnd)} \]

for the core dense computations.

Memory for the dense feature matrix is approximately:

\[ \boxed{O(nd)} \]

plus parameter and temporary arrays.

The exact runtime depends on vectorization, data layout and hardware.
