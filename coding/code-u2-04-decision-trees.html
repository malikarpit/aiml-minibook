What You Will Build

graph TD
    Node["Parent Node: Impurity I(S)"] --> Split["Find Best Feature & Threshold that Maximizes Information Gain"]
    Split --> Left["Left Child: S_left (x_j <= threshold)"]
    Split --> Right["Right Child: S_right (x_j > threshold)"]
    Left & Right --> Stop{"Stopping Condition: depth >= max_depth OR pure?"}
    Stop -- Yes --> Leaf["Create Leaf Node with Majority Class"]
    Stop -- No --> Recurse["Recursively Split Subsets"]
    style Split fill:#0f172a,stroke:#fbbf24,color:#fbbf24,stroke-width:2px
    style Leaf fill:#065f46,stroke:#34d399,color:#ffffff

The complete learning loop is:

data
  ↓
consider candidate questions
  ↓
measure impurity before split
  ↓
measure impurity after split
  ↓
choose best reduction
  ↓
split data
  ↓
repeat recursively
  ↓
stop when a criterion is met
  ↓
store a prediction at leaves

For a classification tree, a node asks a question such as:

Is age ≤ 30?
Is income ≤ 50,000?
Is feature_2 ≤ 1.7?

The tree then routes each sample left or right.

03

One-Minute Intuition

A decision tree is a learned flowchart.

Instead of computing one weighted sum of all features, it asks a sequence of questions:

root
                 │
           Is x₁ ≤ 4.5?
             /       \
           yes        no
           /            \
    Is x₂ ≤ 1.2?      class 1
      /    \
   class0  class1

The learning problem is therefore:

Which question should I ask next?

A good split makes the resulting groups more class-pure.

Hinglish

Decision tree ek learned flowchart hai. Har node par model ek question poochta hai. Achha question woh hai jo data ko aise groups mein baant de jahan classes zyada clear ho jaayein.

04

Real-World Analogy

Suppose you are manually classifying fruit.

You could ask:

Is weight ≤ 150 g?
      ↓
Is color score ≤ 0.4?
      ↓
Is diameter ≤ 7 cm?

Eventually you reach:

mostly apple
mostly orange
mostly banana

A tree learns which questions produce the clearest groupings.

This differs from logistic regression:

Logistic Regression
all features → weighted sum → sigmoid

Decision Tree
features → question → branch → question → branch → leaf

A sample is routed using:

\[ \boxed{x_j \le t} \]

where:

  • \(x_j\) is the chosen feature;
  • \(t\) is the chosen threshold.

If true:

left

otherwise:

right

07

Why a Tree Needs Impurity

At the root, imagine the node contains:

4 zeros
4 ones

That node is mixed.

A useful split should produce children closer to:

left:  4 zeros, 0 ones
right: 0 zeros, 4 ones

A useless split might produce:

left:  2 zeros, 2 ones
right: 2 zeros, 2 ones

So the algorithm needs a numerical score that answers:

How mixed is this node?

This is the role of an impurity measure.

08

Class Proportions

Suppose a node contains \(n\) samples and class \(k\) appears \(n_k\) times.

The class proportion is:

\[ \boxed{ p_k=\frac{n_k}{n} } \]

For a binary node with:

6 class 0
2 class 1

we have:

\[ p_0=6/8=0.75 \]
\[ p_1=2/8=0.25. \]

These proportions feed into Gini and entropy.

09

Gini Impurity

For \(K\) classes:

\[ \boxed{ G=1-\sum_{k=1}^{K}p_k^2 } \]

For a pure node:

p = [1, 0]

so:

\[ G=1-(1^2+0^2)=0. \]

For a balanced binary node:

p = [0.5, 0.5]

so:

\[ G=1-(0.25+0.25)=0.5. \]

Thus:

pure node       → Gini 0
balanced binary → Gini 0.5

Hinglish

Gini zero ka matlab node mein classes mixed nahi hain — node perfectly pure hai. Binary case mein 0.5 maximum impurity ke paas hota hai jab dono classes equally mixed hon.

10

Implement Gini Impurity

PYTHON
def gini_impurity(y):
    y = np.asarray(y)

    if len(y) == 0:
        return 0.0

    _, counts = np.unique(
        y,
        return_counts=True,
    )

    probabilities = counts / len(y)
    return 1.0 - np.sum(probabilities ** 2)

Test:

PYTHON
assert np.isclose(
    gini_impurity(np.array([0, 0, 0])),
    0.0,
)

assert np.isclose(
    gini_impurity(np.array([0, 1])),
    0.5,
)
11

Entropy

An alternative impurity measure is entropy:

\[ \boxed{ H=-\sum_{k=1}^{K}p_k\log_2p_k } \]

For a pure node:

\[ H=0. \]

For a balanced binary node:

\[ H=-0.5\log_2(0.5)-0.5\log_2(0.5)=1. \]

Thus for binary classification:

pure node        → entropy 0
balanced node    → entropy 1

Entropy is sensitive to how evenly the classes are distributed.

12

Implement Entropy Safely

Because:

\[ \log(0) \]

is undefined, ignore zero-probability terms.

PYTHON
def entropy(y):
    y = np.asarray(y)

    if len(y) == 0:
        return 0.0

    _, counts = np.unique(
        y,
        return_counts=True,
    )

    probabilities = counts / len(y)
    nonzero = probabilities > 0

    return -np.sum(
        probabilities[nonzero]
        * np.log2(probabilities[nonzero])
    )

Test:

PYTHON
assert np.isclose(
    entropy(np.array([0, 0, 0])),
    0.0,
)

assert np.isclose(
    entropy(np.array([0, 1])),
    1.0,
)
13

Before/After Impurity

Suppose a node is split into left and right children.

A sensible weighted impurity is:

\[ \boxed{ I_{split}= \frac{n_L}{n}I(L)+ \frac{n_R}{n}I(R) } \]

where:

  • \(n_L\) = number of left samples;
  • \(n_R\) = number of right samples;
  • \(n=n_L+n_R\).

A good split has low weighted child impurity.

14

Impurity Reduction

Define parent impurity as \(I(P)\).

Then the improvement from a split is:

\[ \boxed{ Gain=I(P)- \left[ \frac{n_L}{n}I(L)+ \frac{n_R}{n}I(R) \right] } \]

For entropy, this is commonly called information gain.

For Gini, it is more accurate to call it impurity reduction or Gini gain rather than pretending every criterion has exactly the same terminology.

The best split maximizes this reduction.

15

Manual Gini Calculation

Parent node:

4 zeros
4 ones

Therefore:

\[ G(P)=0.5. \]

Suppose a candidate split gives:

Left:  4 zeros, 0 ones
Right: 0 zeros, 4 ones

Then:

\[ G(L)=0, \qquad G(R)=0. \]

Weighted child impurity:

\[ \frac48(0)+\frac48(0)=0. \]

Therefore gain:

\[ 0.5-0=0.5. \]

That is an ideal split.

16

Manual Entropy Calculation

For the same parent:

\[ H(P)=1. \]

After the perfect split:

\[ H(L)=0, \qquad H(R)=0. \]

Weighted child entropy:

\[ 0. \]

Information gain:

\[ 1-0=1. \]

Again, the split receives maximal improvement for this tiny binary example.

17

Candidate Thresholds

For numerical features, a simple scratch implementation can consider thresholds halfway between sorted unique values.

Suppose:

1.0, 2.0, 5.0, 6.0

Candidate thresholds can be:

\[ 1.5, \quad 3.5, \quad 5.5. \]

Why midpoints?

Because all values on one side of a threshold remain unchanged until the threshold crosses a sample value.

This is a practical simplification for a teaching implementation.

18

Implement Candidate Thresholds

PYTHON
def candidate_thresholds(values):
    values = np.sort(np.unique(values))

    if len(values) < 2:
        return np.array([])

    return (values[:-1] + values[1:]) / 2.0

Test:

PYTHON
thresholds = candidate_thresholds(
    np.array([1.0, 2.0, 5.0, 6.0])
)

print(thresholds)
assert np.allclose(
    thresholds,
    np.array([1.5, 3.5, 5.5]),
)

Split a Dataset

PYTHON
def split_dataset(X, y, feature_index, threshold):
    left_mask = X[:, feature_index] <= threshold
    right_mask = ~left_mask

    return (
        X[left_mask],
        y[left_mask],
        X[right_mask],
        y[right_mask],
    )

Basic test:

PYTHON
X_left, y_left, X_right, y_right = split_dataset(
    X,
    y,
    feature_index=0,
    threshold=3.5,
)

assert len(X_left) + len(X_right) == len(X)
assert np.all(X_left[:, 0] <= 3.5)
assert np.all(X_right[:, 0] > 3.5)

This function is the routing engine of the tree.

20

Weighted Child Impurity

PYTHON
def weighted_child_impurity(
    y_left,
    y_right,
    impurity_fn,
):
    n_left = len(y_left)
    n_right = len(y_right)
    n_total = n_left + n_right

    if n_total == 0:
        return 0.0

    return (
        (n_left / n_total) * impurity_fn(y_left)
        + (n_right / n_total) * impurity_fn(y_right)
    )

This implementation is generic enough to work with:

PYTHON
gini_impurity
tree_entropy

without rewriting the splitting logic.

21

Best Split Search

Now search all features and candidate thresholds.

PYTHON
def best_split(X, y, impurity_fn=gini_impurity):
    n_samples, n_features = X.shape

    best = None
    parent_impurity = impurity_fn(y)

    for feature_index in range(n_features):
        thresholds = candidate_thresholds(
            X[:, feature_index]
        )

        for threshold in thresholds:
            (
                X_left,
                y_left,
                X_right,
                y_right,
            ) = split_dataset(
                X,
                y,
                feature_index,
                threshold,
            )

            if len(y_left) == 0 or len(y_right) == 0:
                continue

            child_impurity = weighted_child_impurity(
                y_left,
                y_right,
                impurity_fn,
            )

            gain = parent_impurity - child_impurity

            if best is None or gain > best["gain"]:
                best = {
                    "feature_index": feature_index,
                    "threshold": threshold,
                    "gain": gain,
                    "child_impurity": child_impurity,
                }

    return best

This is the heart of tree induction.

Verify Candidate Splits Manually

Print every candidate:

PYTHON
def inspect_splits(X, y, impurity_fn=gini_impurity):
    parent = impurity_fn(y)
    rows = []

    for feature_index in range(X.shape[1]):
        for threshold in candidate_thresholds(X[:, feature_index]):
            _, yl, _, yr = split_dataset(
                X,
                y,
                feature_index,
                threshold,
            )

            weighted = weighted_child_impurity(
                yl,
                yr,
                impurity_fn,
            )

            rows.append({
                "feature": feature_index,
                "threshold": threshold,
                "left_n": len(yl),
                "right_n": len(yr),
                "child_impurity": weighted,
                "gain": parent - weighted,
            })

    return rows

Then inspect the rows sorted by gain.

PYTHON
rows = inspect_splits(X, y)
rows = sorted(
    rows,
    key=lambda r: r["gain"],
    reverse=True,
)

for row in rows:
    print(row)

This is one of the best debugging techniques for decision trees because it makes the supposedly “intelligent” split selection fully visible.

24

Leaf Prediction

At a leaf, a simple classification rule is majority class.

PYTHON
def majority_class(y):
    values, counts = np.unique(
        y,
        return_counts=True,
    )
    return values[np.argmax(counts)]

For:

[0, 0, 1]

prediction is:

0

For:

[0, 1, 1, 1]

prediction is:

1

For ties, np.argmax chooses the first maximum according to the sorted class ordering returned by np.unique. In a more complete implementation, define a tie-breaking policy explicitly.

Node Data Structure

A small Python dataclass keeps the tree readable.

PYTHON
from dataclasses import dataclass
from typing import Optional

@dataclass
class Node:
    feature_index: Optional[int] = None
    threshold: Optional[float] = None
    left: Optional["Node"] = None
    right: Optional["Node"] = None
    prediction: Optional[int] = None

Interpretation:

prediction is not None
        ↓
       leaf

feature_index is not None
        ↓
   internal node
26

Stopping Conditions

Without stopping rules, recursive splitting can continue until every training sample is isolated.

That can lead to memorization.

Useful stopping controls include:

pure node
max_depth
minimum samples required to split
minimum samples in a leaf
no useful split

For the first implementation, use:

max_depth
min_samples_split
27

Why `max_depth` Controls Complexity

Compare:

depth 1 → one decision question

depth 2 → up to four leaf regions in a binary tree

depth 3 → more regions
...

As depth increases, the tree can carve the input space into increasingly specific regions.

That usually increases training flexibility.

But more flexibility can increase variance and overfitting.

This connects directly to the course's generalization material.

28

Recursive Tree Builder

PYTHON
def build_tree(
    X,
    y,
    depth=0,
    max_depth=3,
    min_samples_split=2,
    impurity_fn=gini_impurity,
):
    node = Node()

    # Stop if the node is pure.
    if len(np.unique(y)) == 1:
        node.prediction = int(y[0])
        return node

    # Stop if we cannot legally split further.
    if depth >= max_depth:
        node.prediction = int(majority_class(y))
        return node

    if len(y) < min_samples_split:
        node.prediction = int(majority_class(y))
        return node

    split = best_split(
        X,
        y,
        impurity_fn=impurity_fn,
    )

    if split is None or split["gain"] <= 0:
        node.prediction = int(majority_class(y))
        return node

    feature_index = split["feature_index"]
    threshold = split["threshold"]

    left_mask = X[:, feature_index] <= threshold
    right_mask = ~left_mask

    node.feature_index = feature_index
    node.threshold = threshold

    node.left = build_tree(
        X[left_mask],
        y[left_mask],
        depth=depth + 1,
        max_depth=max_depth,
        min_samples_split=min_samples_split,
        impurity_fn=impurity_fn,
    )

    node.right = build_tree(
        X[right_mask],
        y[right_mask],
        depth=depth + 1,
        max_depth=max_depth,
        min_samples_split=min_samples_split,
        impurity_fn=impurity_fn,
    )

    return node

This function is deliberately explicit.

Do not compress it into clever one-liners while learning.

29

Prediction by Tree Traversal

A sample follows one path from root to leaf.

PYTHON
def predict_one(node, x):
    if node.prediction is not None:
        return node.prediction

    if x[node.feature_index] <= node.threshold:
        return predict_one(node.left, x)

    return predict_one(node.right, x)

For a matrix:

PYTHON
def predict_tree(root, X):
    return np.array([
        predict_one(root, x)
        for x in X
    ])

The training algorithm is recursive; prediction is a simple path traversal.

Wrap the Implementation

Create a small estimator-style interface.

PYTHON
class DecisionTreeClassifierScratch:
    def __init__(
        self,
        max_depth=3,
        min_samples_split=2,
        criterion="gini",
    ):
        self.max_depth = max_depth
        self.min_samples_split = min_samples_split
        self.criterion = criterion
        self.root = None

    def _impurity(self):
        if self.criterion == "gini":
            return gini_impurity
        if self.criterion == "entropy":
            return entropy
        raise ValueError(
            "criterion must be 'gini' or 'entropy'"
        )

    def fit(self, X, y):
        X = np.asarray(X, dtype=float)
        y = np.asarray(y, dtype=int)

        if X.ndim != 2:
            raise ValueError("X must be 2D")
        if y.ndim != 1:
            raise ValueError("y must be 1D")
        if len(X) != len(y):
            raise ValueError("X and y must align")

        self.root = build_tree(
            X,
            y,
            max_depth=self.max_depth,
            min_samples_split=self.min_samples_split,
            impurity_fn=self._impurity(),
        )
        return self

    def predict(self, X):
        if self.root is None:
            raise RuntimeError("fit the model first")

        X = np.asarray(X, dtype=float)
        return predict_tree(self.root, X)

This is now a usable educational classifier.

Manual Trace of One Prediction

2.2 <= 3.5 → True

Go left.

class 0

Another sample:

Then:

Go right.

prediction = 1

Tree prediction is not gradient descent

Why the Root Split Is Chosen

At each node:

current data subset
      ↓
all candidate features
      ↓
all candidate thresholds
      ↓
calculate impurity reduction
      ↓
choose best

So the root is not chosen because a human “looks at the plot.”

The plot is useful only for us to visualize what the algorithm discovered.

35

Gini vs Entropy

Both are impurity measures.

Gini
  ↓
1 - Σ p²

Entropy
  ↓
-Σ p log₂ p

Both are:

0 at a pure node
larger when the node is mixed

Their numerical values are on different scales, so do not compare a Gini value of 0.3 directly against an entropy value of 0.3 as though they mean the same amount of impurity.

The important algorithmic idea is shared:

Prefer splits that create purer children according to the selected criterion.

Feature Importance — Conceptual View

Trees can assign importance to features based on how much they contribute to impurity reduction across the tree.

The intuition is:

large total impurity reduction
             ↓
more contribution to tree decisions

But treat feature importance carefully.

High tree importance does not automatically prove:

causal importance
real-world importance
ethical importance

The metric is model-specific.

For this scratch implementation, feature importance is intentionally omitted from the core to keep the learning target focused on split induction and recursion.

44

Why Trees Handle Different Feature Scales Differently

Consider a feature:

age = 18, 25, 31, 42

Suppose a good split is:

\[ age\le30. \]

Multiply age by 10:

180, 250, 310, 420

The equivalent split is:

\[ age'\le300. \]

The ordering has not changed.

Therefore the tree can often find an equivalent partition without standardization.

This differs from gradient-based models such as logistic regression, where scale can strongly affect optimization behaviour.

Practical takeaway

Logistic regression → scaling often important for GD
Decision tree       → scaling usually not required for split logic
45

Why Trees Can Represent Nonlinear Boundaries

Suppose the data requires a rectangular rule:

x1 > 2
AND
x2 < 5

A tree can represent this naturally:

x1 > 2?
   ↓ yes
x2 < 5?
   ↓ yes
class 1

A single logistic-regression boundary cannot represent every such pattern.

This is a major conceptual reason trees remain useful.

46

But a Tree Can Become Too Specific

A deep tree can keep splitting until leaves contain tiny groups.

Extreme example:

one training sample
        ↓
one highly specific leaf
        ↓
training prediction memorized

Training performance can approach perfection while test performance degrades.

The key generalization question is:

Is the tree learning reusable structure or memorizing accidental details of the training sample?

Comparing Scratch and Library Trees

Do not use only:

PYTHON
np.array_equal(scratch_pred, library_pred)

as the definition of correctness.

A better validation ladder is:

1. impurity functions match known values
2. candidate thresholds are correct
3. split scores are correct
4. root split is sensible
5. recursive structure is sensible
6. controlled dataset predictions are sensible
7. held-out metrics are reasonable
8. library model gives broadly consistent behaviour

A scratch implementation can differ in tie-breaking or stopping details while still implementing the intended algorithm correctly.

50

Important Library Difference: Exact Objective and Details

Two decision tree implementations may differ because of:

  • impurity criterion;
  • split search details;
  • tie handling;
  • minimum leaf constraints;
  • stopping rules;
  • feature handling;
  • pruning controls;
  • numerical implementation details.

Therefore:

Do not claim “my tree is wrong” merely because its exact structure differs from the library tree.

First confirm that the core split logic and evaluation behaviour are sound.

53

Edge Cases

Edge case 1 — Pure node

No split is useful. Return a leaf.

Edge case 2 — Constant feature

There may be no meaningful threshold candidate.

Edge case 3 — All features constant

The tree must stop rather than recurse forever.

Edge case 4 — Tiny node

Minimum-sample stopping rules matter.

Edge case 5 — Zero gain

If no split reduces impurity, stop.

Edge case 6 — Tie between splits

A deterministic tie-breaking rule improves reproducibility.

Edge case 7 — More than two classes

The impurity formulas already generalize to \(K\gt 2\), but the scratch implementation's type hints and examples are focused on binary classification for clarity.

Optional Extension — Multi-Class Trees

For labels:

0, 1, 2

Gini remains:

\[ G=1-(p_0^2+p_1^2+p_2^2). \]

Entropy becomes:

\[ H=-\sum_{k=0}^{2}p_k\log_2p_k. \]

The recursive split algorithm does not fundamentally change.

What changes is:

class distribution
majority-class leaf prediction
metric selection

Try this only after the binary version is fully understood.

Optional Extension — Regression Trees

The same tree idea can be used for continuous targets.

Instead of class impurity, a regression tree can reduce within-node squared error or variance.

Conceptually:

classification tree
   ↓
make classes purer

regression tree
   ↓
make numerical targets more homogeneous

This is useful because it demonstrates that the tree is a general recursive partitioning framework, not merely a classifier.

Common Bugs

Bug 1 — Forgetting the child-size weights

Wrong idea:

average impurity of left and right

without considering how many samples each child contains.

Correct:

\[ \frac{n_L}{n}I(L)+\frac{n_R}{n}I(R). \]

Bug 2 — Accepting an empty child

Every candidate split must leave samples on both sides.

Bug 3 — Recursive infinite growth

Always implement stopping conditions.

Bug 4 — Using the wrong inequality consistently

<= threshold vs > threshold must partition all samples exactly once.

Bug 5 — Mixing labels and predictions

The split criterion must use true labels at training time.

Bug 6 — Accidental data leakage in experiments

Do not choose hyperparameters from the test set repeatedly.

Bug 7 — Assuming the deepest tree is the best tree

Training fit and generalization are different objectives.

Bug 8 — Treating feature importance as causal evidence

It is a model-derived statistic, not proof of cause.

66

Complexity of the Teaching Implementation

Suppose the current node contains \(n\) samples and \(d\) features.

A simple threshold search may examine up to roughly \(O(n)\) candidate thresholds per feature.

Evaluating each split naively may itself scan the node samples, giving a teaching implementation whose split search can approach:

\[ O(dn^2) \]

per node in the worst-case style of this straightforward code.

Recursive tree construction therefore can be expensive on large datasets.

Production implementations use optimized data structures and split-search strategies.

The important learning point is:

Readable from-scratch code and optimized production code solve the same conceptual problem at different engineering levels.

Prediction in a binary tree takes time proportional to tree depth:

\[ O(h) \]

for one sample in the simplest view, where \(h\) is the path length.

Why Decision Trees Connect to Ensembles

A single tree can have high variance.

This motivates ensemble methods such as:

many trees
   ↓
combine predictions
   ↓
reduce dependence on one exact tree

Examples include random forests and gradient boosting.

These are beyond the core DSC-14 Unit II tree topic in this coding chapter, but understanding the single-tree algorithm is the foundation for the later family.

**Overfitting & Infinite Tree Depth Trap:** If you don't enforce `max_depth` or `min_samples_split`, a decision tree will continue splitting until every single training example is in its own pure leaf node! This produces 100% training accuracy but abysmal test accuracy due to extreme overfitting! Always use stopping criteria and tree pruning.
