CODE-U4-04 — Autoencoders From Scratch and PyTorch Representation Learning

Purpose: Build an autoencoder as an explicit encoder → latent representation → decoder system, implement reconstruction loss, train a compact model with PyTorch, and use reconstruction error for representation learning and a simple anomaly-detection experiment.

The central computation is:

input x
  ↓
encoder
  ↓
latent z
  ↓
decoder
  ↓
reconstruction x̂
  ↓
reconstruction loss
  ↓
backpropagation
  ↓
parameter update

The key idea is:

The model learns a representation useful for reconstructing the input under a chosen objective.

03

Why Autoencoders Exist

A standard supervised network receives:

input
 ↓
prediction
 ↓
compare with target label

An autoencoder can use:

input
 ↓
representation
 ↓
reconstruction
 ↓
compare with original input

Thus:

\[ target=x. \]

But this would seem pointless if the network were allowed to simply copy the input perfectly through unlimited capacity.

The useful case introduces a constraint:

input dimension
      ↓
smaller latent dimension
      ↓
reconstruct

The bottleneck forces the network to preserve information useful for reconstruction.

04

Autoencoder Architecture

\[ \boxed{ z=E_\theta(x) } \]
\[ \boxed{ \hat x=D_\phi(z) } \]

Combined:

\[ \boxed{ \hat x= D_\phi(E_\theta(x)) } \]

Diagram:

INPUT x
   │
   ▼
ENCODER Eθ
   │
   ▼
LATENT z
   │
   ▼
DECODER Dφ
   │
   ▼
RECONSTRUCTION x̂

The latent code is often lower dimensional, but an autoencoder can also be overcomplete depending on the architecture and regularization.

05

Reconstruction Objective

A general objective:

\[ \boxed{ \min_{\theta,\phi} \frac1n \sum_{i=1}^{n} L \left( x_i, D_\phi(E_\theta(x_i)) \right) } \]

For mean squared error:

\[ \boxed{ L(x,\hat x) = \frac1d \sum_{j=1}^{d} (x_j-\hat x_j)^2 } \]

or equivalently:

\[ L(x,\hat x) = \frac1d \|x-\hat x\|_2^2. \]
06

Reconstruction Numerical

Suppose:

\[ x= [1,2,3] \]

and:

\[ \hat x= [1,3,2]. \]

Difference:

\[ x-\hat x= [0,-1,1]. \]

Squared error:

\[ 0^2+(-1)^2+1^2=2. \]

Mean squared error:

\[ \frac{2}{3} \approx0.667. \]

Be precise about whether your implementation uses:

sum squared error

or:

mean squared error
07

Why the Bottleneck Matters

Suppose:

input = 784 dimensions
latent = 784 dimensions

with a powerful enough network.

The model may learn an almost direct copy.

Now:

input = 784
latent = 32

The network has far less capacity in the central representation.

It must learn what information can be retained to reconstruct the input.

This is the central representation-learning mechanism in a basic undercomplete autoencoder.

A Small NumPy Reconstruction Function

PYTHON
import numpy as np
PYTHON
def mse_reconstruction_loss(
    x,
    x_hat,
):
    x = np.asarray(
        x,
        dtype=float,
    )

    x_hat = np.asarray(
        x_hat,
        dtype=float,
    )

    if x.shape != x_hat.shape:
        raise ValueError(
            "x and x_hat must have the same shape."
        )

    return float(
        np.mean(
            (x - x_hat) ** 2
        )
    )

Linear Autoencoder From Scratch

A simple linear autoencoder:

\[ z=xW_e+b_e \]
\[ \hat x=zW_d+b_d. \]

Implementation:

PYTHON
def linear_autoencoder_forward(
    X,
    W_e,
    b_e,
    W_d,
    b_d,
):
    Z = X @ W_e + b_e

    X_hat = (
        Z @ W_d
        + b_d
    )

    cache = {
        "Z": Z,
        "X_hat": X_hat,
    }

    return X_hat, cache

This is intentionally simple.

It demonstrates that:

encoder
+
decoder

are still just parameterized transformations.

11

Nonlinear Autoencoder

A more expressive model:

\[ z= \phi(XW_e+b_e) \]
\[ \hat X= \psi(zW_d+b_d). \]

Example:

PYTHON
def relu(x):
    return np.maximum(
        0.0,
        x,
    )
PYTHON
def nonlinear_autoencoder_forward(
    X,
    W_e,
    b_e,
    W_d,
    b_d,
):
    Z = X @ W_e + b_e

    latent = relu(Z)

    X_hat = (
        latent @ W_d
        + b_d
    )

    return (
        X_hat,
        {
            "Z": Z,
            "latent": latent,
        },
    )

The network can now learn nonlinear representations.

12

PyTorch Dense Autoencoder

PYTHON
import torch
import torch.nn as nn
PYTHON
class Autoencoder(nn.Module):
    def __init__(
        self,
        input_dim,
        latent_dim,
    ):
        super().__init__()

        self.encoder = nn.Sequential(
            nn.Linear(
                input_dim,
                128,
            ),
            nn.ReLU(),

            nn.Linear(
                128,
                latent_dim,
            ),
        )

        self.decoder = nn.Sequential(
            nn.Linear(
                latent_dim,
                128,
            ),
            nn.ReLU(),

            nn.Linear(
                128,
                input_dim,
            ),
        )

    def encode(self, x):
        return self.encoder(x)

    def decode(self, z):
        return self.decoder(z)

    def forward(self, x):
        z = self.encode(x)
        x_hat = self.decode(z)

        return x_hat, z

This exposes the latent representation explicitly.

Training Loop

PYTHON
epochs = 5

history = []

for epoch in range(epochs):
    model.train()

    total_loss = 0.0
    total_examples = 0

    for images, _ in train_loader:
        x = images.view(
            images.size(0),
            -1,
        )

        optimizer.zero_grad()

        x_hat, z = model(x)

        loss = loss_fn(
            x_hat,
            x,
        )

        loss.backward()
        optimizer.step()

        total_loss += (
            loss.item()
            * x.size(0)
        )

        total_examples += (
            x.size(0)
        )

    mean_loss = (
        total_loss
        / total_examples
    )

    history.append(
        mean_loss
    )

    print(
        f"epoch={epoch+1} "
        f"loss={mean_loss:.6f}"
    )

The target is the input:

target = x

not:

target = class label

Denoising Autoencoder

A denoising autoencoder receives a corrupted input but targets the clean input.

Pipeline:

clean x
   ↓
corrupt
   ↓
x_noisy
   ↓
encoder
   ↓
latent
   ↓
decoder
   ↓
x_hat
   ↓
compare with CLEAN x

This is different from:

noisy x
→ reconstruct noisy x

The target remains the clean data.

Add Noise

PYTHON
def add_gaussian_noise(
    x,
    noise_std=0.2,
):
    noisy = (
        x
        + noise_std
        * torch.randn_like(x)
    )

    return torch.clamp(
        noisy,
        0.0,
        1.0,
    )

During training:

PYTHON

    noise_std=0.2,
)

)

    x_hat,
    x,
)

Again:

input to model = noisy
target = clean

Why Denoising Can Help Representation Learning

The model cannot simply memorize the corrupted pixels.

It must infer a clean structure from an imperfect observation.

Conceptually:

corruption
 ↓
remove irrelevant variation
 ↓
recover useful structure

This can encourage a representation that captures stable patterns.

The usefulness depends on the corruption process and task.

28

Simple Anomaly Detection

Suppose an autoencoder is trained mostly on normal data.

Then:

normal example
→ familiar structure
→ lower reconstruction error

while:

unusual example
→ less familiar structure
→ potentially higher reconstruction error

So define:

\[ \boxed{ score(x)=L(x,\hat x) } \]

and flag examples whose score exceeds a selected threshold.

This is a common autoencoder application.

But it is not guaranteed to work:

A sufficiently expressive autoencoder can sometimes reconstruct anomalies well.

Threshold selection must be based on validation data and the intended false-positive/false-negative trade-off.

29

Anomaly-Score Implementation

PYTHON
@torch.no_grad()
def reconstruction_errors(
    model,
    loader,
):
    model.eval()

    errors = []

    for images, _ in loader:
        x = images.view(
            images.size(0),
            -1,
        )

        x_hat, _ = model(x)

        batch_errors = torch.mean(
            (x_hat - x) ** 2,
            dim=1,
        )

        errors.append(
            batch_errors.cpu()
        )

    return torch.cat(
        errors
    )

Use:

PYTHON
errors = reconstruction_errors(
    model,
    test_loader,
)

Inspect:

PYTHON
print(
    errors.mean().item(),
    errors.max().item(),
)

33

Autoencoder vs PCA

Both can reduce dimensionality.

A basic linear autoencoder can have a close relationship to PCA under appropriate architectural/loss conditions.

But a general nonlinear autoencoder:

linear
→ nonlinear
→ latent

can learn transformations that linear PCA cannot represent.

Therefore:

Autoencoder = not simply "PCA in another library"

The exact relationship depends on architecture, constraints and optimization.

34

Identity Mapping Problem

If:

latent dimension
>= input dimension

and the model has enough capacity, it may learn something close to:

\[ \hat x\approx x \]

without learning the kind of compressed representation you intended.

Therefore useful autoencoder design often depends on:

bottleneck
regularization
noise
sparsity
architecture
35

Sparse Autoencoder Preview

A sparse autoencoder encourages only a small subset of hidden units to be strongly active.

Conceptually:

many hidden units
+
sparsity constraint

This can encourage selective representations.

For this coding book, treat sparse autoencoders as an extension rather than a core implementation.

36

Convolutional Autoencoder Preview

For images, a dense autoencoder first flattens:

28 × 28
→ 784

A convolutional autoencoder instead keeps spatial structure:

image
 ↓
Conv
 ↓
feature maps
 ↓
latent representation

The core loop remains:

        x_hat,

x → reconstruction → loss(reconstruction, x)

The training machinery is the same.

The target construction is different.

Common Autoencoder Mistakes

⚠️ University Lab Viva Trap & Runtime Gotcha
**Identity Mapping & Capacity Overfitting Trap:** If the latent dimension is larger than or equal to input dimension ($d_{latent} \ge d_{input}$) without regularization or noise, the autoencoder simply learns the identity function $f(x) = x$ by heart! It memorizes inputs without learning any useful representations. Always ensure bottleneck compression or use Denoising Autoencoders with input corruptions!

Mistake 1 — Calling the latent vector the output

The latent vector is the internal representation.

The decoder output is the reconstruction.

Mistake 2 — Training with class labels

A basic autoencoder reconstructs the input.

Mistake 3 — Evaluating only training reconstruction error

A model can memorize training data.

Inspect held-out reconstruction.

Mistake 4 — Confusing reconstruction error with classification accuracy

They answer different questions.

Mistake 5 — Using a threshold chosen on the test set

For anomaly detection, threshold selection should be separated from final test evaluation.

Mistake 6 — Assuming anomalies always reconstruct badly

Not guaranteed.

Viva Questions

Q1. What is an autoencoder?

A neural network that encodes an input into a latent representation and decodes it to reconstruct the input.

Q2. What is the latent representation?

The internal code produced by the encoder.

Q3. Why use a bottleneck?

To constrain the representation so the model cannot simply copy every input detail through an unconstrained identity path.

Q4. What is reconstruction loss?

A measure of the difference between the original input and its reconstruction.

Q5. What is a denoising autoencoder?

An autoencoder trained on corrupted inputs to reconstruct the corresponding clean inputs.

Q6. Why can autoencoders be used for anomaly detection?

If trained on normal patterns, unusual inputs may sometimes produce larger reconstruction errors.

Q7. Is high reconstruction error guaranteed for anomalies?

No.

Q8. Is an autoencoder the same as PCA?

No. A linear autoencoder can relate closely to PCA under specific conditions, while nonlinear autoencoders can learn nonlinear representations.

Q9. What is the difference between encoder and decoder?

Encoder maps input to latent representation; decoder maps latent representation toward reconstruction.

Q10. Why is backpropagation used?

The reconstruction loss must be differentiated through encoder and decoder parameters to train the network.
