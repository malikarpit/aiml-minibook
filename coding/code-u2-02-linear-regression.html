08

Why We Need Optimization

The model has unknown parameters:

\[ w,\quad b. \]

We want:

\[ \boxed{ (w^*,b^*) = \arg\min_{w,b} J(w,b) } \]

where:

\[ J(w,b) = \frac1n \sum_i (wx_i+b-y_i)^2. \]

This is the learning problem.

09

Deriving the Gradient — Scalar Form

For one feature:

\[ \hat y_i=wx_i+b. \]

Define:

\[ e_i=wx_i+b-y_i. \]

Then:

\[ J(w,b)= \frac1n\sum_ie_i^2. \]

Differentiate with respect to \(w\):

\[ \boxed{ \frac{\partial J}{\partial w} = \frac2n \sum_i e_i x_i } \]

and with respect to \(b\):

\[ \boxed{ \frac{\partial J}{\partial b} = \frac2n \sum_i e_i. } \]

The factor 2 comes from differentiating the square.

10

Gradient Derivation Step by Step

Start:

\[ J= \frac1n \sum_i(wx_i+b-y_i)^2. \]

For \(w\):

\[ \frac{\partial J}{\partial w} = \frac1n \sum_i 2(wx_i+b-y_i) \frac{\partial}{\partial w} (wx_i+b-y_i). \]

Since:

\[ \frac{\partial}{\partial w} (wx_i+b-y_i) = x_i, \]

we get:

\[ \boxed{ \frac{\partial J}{\partial w} = \frac2n \sum_i (wx_i+b-y_i)x_i. } \]

Similarly:

\[ \frac{\partial}{\partial b} (wx_i+b-y_i)=1, \]

so:

\[ \boxed{ \frac{\partial J}{\partial b} = \frac2n \sum_i (wx_i+b-y_i). } \]

This is exactly the kind of scalar-to-vector calculus progression emphasized by Lecture 9.

11

Gradient Descent

Use:

\[ \boxed{ w_{t+1} = w_t-\eta \frac{\partial J}{\partial w} } \]

and:

\[ \boxed{ b_{t+1} = b_t-\eta \frac{\partial J}{\partial b}. } \]

Here:

\[ \eta\gt 0 \]

is the learning rate.

12

From-Scratch Gradient-Descent Implementation

PYTHON
def fit_linear_regression_gd(
    x,
    y,
    learning_rate=0.01,
    epochs=1000,
):
    w = 0.0
    b = 0.0

    loss_history = []

    n = len(x)

    for _ in range(epochs):
        predictions = w * x + b
        errors = predictions - y

        loss = np.mean(errors ** 2)
        loss_history.append(loss)

        grad_w = (2 / n) * np.sum(
            errors * x
        )

        grad_b = (2 / n) * np.sum(
            errors
        )

        w -= learning_rate * grad_w
        b -= learning_rate * grad_b

    return w, b, loss_history

This is the core implementation.

Do not treat the code as magic.

Every line corresponds to a mathematical step.

17

Gradient Sanity Check

At a parameter setting:

PYTHON
w = 0.5
b = 0.5

calculate the analytical gradient.

Then approximate the derivative numerically using finite differences.

For \(w\):

\[ \boxed{ \frac{\partial J}{\partial w} \approx \frac{ J(w+\epsilon,b)-J(w-\epsilon,b) }{ 2\epsilon } } \]

This is one of the best debugging techniques for gradient implementations.

18

Numerical Gradient Implementation

PYTHON
def numerical_gradient_w(
    x,
    y,
    w,
    b,
    eps=1e-6,
):
    plus = mse(
        y,
        w * (x) + eps * x + b,
    )

    minus = mse(
        y,
        w * (x) - eps * x + b,
    )

    return (plus - minus) / (2 * eps)

A cleaner implementation is to define a scalar objective function first:

PYTHON
def objective(x, y, w, b):
    return mse(
        y,
        w * x + b,
    )

Then:

PYTHON
def numerical_gradient_w(
    x,
    y,
    w,
    b,
    eps=1e-6,
):
    plus = objective(
        x,
        y,
        w + eps,
        b,
    )

    minus = objective(
        x,
        y,
        w - eps,
        b,
    )

    return (plus - minus) / (2 * eps)

Compare with:

PYTHON
def analytic_grad_w(
    x,
    y,
    w,
    b,
):
    predictions = w * x + b
    errors = predictions - y
    n = len(x)

    return (2 / n) * np.sum(
        errors * x
    )

Test:

PYTHON
np.testing.assert_allclose(
    analytic_grad_w(
        x, y, 0.5, 0.5
    ),
    numerical_gradient_w(
        x, y, 0.5, 0.5
    ),
    rtol=1e-5,
    atol=1e-7,
)

This catches many subtle calculus/coding errors.

Why Gradient Checking Matters

Suppose your code runs:

no syntax error
no exception

but your gradient has the wrong sign.

Then:

gradient descent
↓
moves uphill
↓
loss increases

Gradient checking can reveal that the implementation does not match the mathematical derivative.

This is especially valuable later for:

  • logistic regression;
  • neural networks;
  • backpropagation.
20

Matrix Form

Now move to multiple features.

Let:

\[ X\in\mathbb R^{n\times d} \]

and:

\[ w\in\mathbb R^d. \]

Predictions:

\[ \boxed{ \hat y=Xw } \]

under the convention where the intercept has already been included or is handled separately.

Residual:

\[ \boxed{ r=Xw-y } \]

Least squares:

\[ \boxed{ J(w)=\|Xw-y\|_2^2. } \]

This is the exact matrix-norm form shown in the supplied Lecture 9.

21

Intercept via an Augmented Matrix

To include an intercept in the same matrix expression, create:

\[ X'= \begin{bmatrix} 1 & x_{11} & \cdots & x_{1d}\\ 1 & x_{21} & \cdots & x_{2d}\\ \vdots & \vdots & & \vdots\\ 1 & x_{n1} & \cdots & x_{nd} \end{bmatrix} \]

and:

\[ w'= \begin{bmatrix} b\\ w_1\\ \vdots\\ w_d \end{bmatrix}. \]

Then:

\[ \boxed{ \hat y=X'w'. } \]

This is the dummy-feature/intercept trick used in linear models.

Then:

23

Matrix Gradient

For:

\[ J(w) = \|Xw-y\|_2^2, \]

the gradient is:

\[ \boxed{ \nabla J(w) = 2X^T(Xw-y). } \]

This follows from the vector calculus developed in Lecture 9 and the Math Companion.

Gradient descent:

\[ \boxed{ w_{t+1} = w_t - 2\eta X^T(Xw_t-y). } \]
24

Matrix Gradient-Descent Implementation

PYTHON
def fit_linear_regression_matrix_gd(
    X,
    y,
    learning_rate=0.01,
    epochs=1000,
):
    w = np.zeros(X.shape[1])
    loss_history = []

    n = len(X)

    for _ in range(epochs):
        predictions = X @ w
        errors = predictions - y

        loss = np.mean(errors ** 2)
        loss_history.append(loss)

        gradient = (
            2 / n
        ) * X.T @ errors

        w -= learning_rate * gradient

    return w, loss_history

Notice the direct correspondence:

\[ \frac{2}{n}X^T(Xw-y) \]

to:

PYTHON
(2 / n) * X.T @ errors

26

Closed-Form Least Squares

The supplied Lecture 9 gives:

\[ \boxed{ w^*=(X^TX)^{-1}X^Ty } \]

when \(X^TX\) is invertible.

This is the normal-equation solution.

From the gradient:

\[ 2X^T(Xw-y)=0. \]

Therefore:

\[ X^TXw=X^Ty. \]

If invertible:

\[ w=(X^TX)^{-1}X^Ty. \]
27

Never Explicitly Invert Unless Needed

Although the formula contains:

\[ (X^TX)^{-1}, \]

a numerical implementation should generally avoid explicitly computing an inverse just to solve a linear system.

Instead, use:

PYTHON
np.linalg.solve(
    X.T @ X,
    X.T @ y,
)

This is usually a better numerical practice.

A pseudoinverse can be used when the straightforward inverse does not exist:

PYTHON
np.linalg.pinv(X) @ y

The exact numerical method depends on matrix conditioning and the problem.

28

Closed-Form Implementation

PYTHON
def linear_regression_closed_form(
    X,
    y,
):
    return np.linalg.solve(
        X.T @ X,
        X.T @ y,
    )

Run:

PYTHON
w_closed = linear_regression_closed_form(
    X,
    y,
)

print(w_closed)

For the exact toy data, expect approximately:

[2.0, 3.0]

where the first parameter is the intercept due to the augmented column.

29

Gradient Descent vs Closed Form

Both target the same least-squares objective in the standard setup.

Closed form

\[ w^*=(X^TX)^{-1}X^Ty \]

or an equivalent linear-system solution.

Gradient descent

\[ w_{t+1} = w_t-\eta\nabla J(w_t). \]

Conceptually:

Closed form
→ solve directly

Gradient descent
→ approach iteratively
30

Why Gradient Descent Still Matters

The existence of a closed-form linear-regression solution does not make gradient descent unimportant.

The gradient-based approach connects directly to:

linear regression
↓
logistic regression
↓
neural networks
↓
deep learning

Your Lecture 9 explicitly notes gradient descent as a backbone of deep-learning optimization.

So this lab is teaching both:

one model

and:

a reusable optimization pattern.
31

Compare Solutions

PYTHON
w_gd, _ = (
    fit_linear_regression_matrix_gd(
        X,
        y,
        learning_rate=0.01,
        epochs=5000,
    )

Do not require exact equality between an iterative numerical solution and a closed-form solution.

32

Why They May Differ

Possible reasons:

  • too few epochs;
  • learning rate too small;
  • learning rate too large;
  • numerical precision;
  • poorly scaled features;
  • ill-conditioned matrix.

This is why the comparison should be:

approximately equal under a sufficiently converged stable optimization setup.

34

Why Scaling Changes the Optimization Geometry

Imagine a loss surface that is:

very wide in one direction
very narrow in another

Gradient descent can bounce across the narrow direction while making slow progress along the wide direction.

Scaling can make the geometry more balanced.

Conceptually:

poorly scaled
    ↓
elongated contours
    ↓
awkward steps

better scaled
    ↓
more balanced contours
    ↓
better convergence

This is optimization intuition, not merely a data-cleaning trick.

35

Closed Form and Scaling

A subtle point:

Scaling can be less important for obtaining a direct closed-form least-squares solution than for iterative optimization behaviour.

If you solve the same numerical least-squares problem accurately, the optimizer can still find the solution without standardization under suitable conditions.

The supplied Lecture 9's strongest scaling claim concerns optimization speed/stability and, earlier, scale-sensitive distance calculations.

Important Intercept Trap

⚠️ University Lab Viva Trap & Runtime Gotcha
**Dummy Bias Column Trap:** In matrix form $\hat{y} = X w$, $w$ has shape `(d+1, 1)` including the bias $b = w_0$. If you forget to prepend a column of ones (`np.hstack([np.ones((n, 1)), X])`), your regression line is forced to pass through the origin $(0, 0)$, causing severe underfitting!

If:

PYTHON
X

already has a column of ones and:

PYTHON
LinearRegression(
    fit_intercept=True
)

is used, the model has two intercept mechanisms.

Better options:

Option A

Keep the column of ones and use:

PYTHON
LinearRegression(
    fit_intercept=False
)

Option B

Do not manually add the column of ones and use:

PYTHON
fit_intercept=True

Choose one representation and stay consistent.

Test Loss Monotonicity Carefully

In full-batch gradient descent on a convex quadratic with a sufficiently small fixed learning rate, the loss may decrease monotonically.

But do not make:

PYTHON
assert every(loss[i+1] < loss[i])

a universal test for every implementation.

Depending on:

  • learning rate;
  • batch strategy;
  • numerical precision;
  • stopping;
  • objective scaling;

temporary increases can occur.

A better basic test is:

final loss < initial loss

under a stable configuration.

Why Polynomial Regression Is Still “Linear” in Parameters

For:

\[ \hat y = w_0+w_1x+w_2x^2, \]

the function is nonlinear in \(x\).

But it is linear in the parameters:

\[ w_0,w_1,w_2. \]

Therefore we can create features:

\[ [1,x,x^2] \]

and apply linear regression to the transformed representation.

This is a powerful example of:

feature representation
       ↓
hypothesis flexibility

Exam Bridge

Be ready to connect code to equations.

Model

\[ \boxed{ \hat y=Xw } \]

Residual

\[ \boxed{ r=Xw-y } \]

Loss

\[ \boxed{ J=\|Xw-y\|_2^2 } \]

Gradient

\[ \boxed{ \nabla J=2X^T(Xw-y) } \]

under this exact unnormalized objective.

Update

\[ \boxed{ w\leftarrow w-\eta\nabla J } \]

Closed form

\[ \boxed{ w^*=(X^TX)^{-1}X^Ty } \]

when the inverse exists.
