CODE-U4-05 — Generative Adversarial Networks

Purpose: Understand GANs as an adversarial optimization system, implement the core generator/discriminator logic, build a simple image GAN in PyTorch, visualize generated samples, and diagnose common failure modes such as mode collapse and unstable training.

The conceptual pipeline is:

random noise z
      ↓
  GENERATOR
      ↓
fake sample
      ↓
┌──────────────────────┐
│ discriminator         │
│ real? / fake?         │
└──────────────────────┘
      ↑
real sample

The two networks have competing objectives:

Generator
→ produce samples that look real

Discriminator
→ distinguish real samples from generated samples

03

Why GANs Exist

An autoencoder is centered around:

input
 ↓
encode
 ↓
latent
 ↓
decode
 ↓
reconstruction

A GAN instead learns through competition:

noise
 ↓
generator
 ↓
fake sample
       ↘
         discriminator
       ↗
real sample

The generator does not need a target image corresponding to each latent vector.

Instead, it learns from the discriminator's feedback.

04

Generator

Let:

\[ z\sim p_z(z) \]

be a random latent vector.

The generator maps:

\[ \boxed{ x_f=G_\theta(z) } \]

from the latent space to the data space.

For an image generator:

random vector
     ↓
dense / upsampling layers
     ↓
feature representation
     ↓
image
05

Discriminator

The discriminator receives either:

real sample x

or:

generated sample G(z)

and produces a real/fake score:

\[ \boxed{ D_\phi(x)\in(0,1) } \]

under the standard sigmoid interpretation.

Conceptually:

real image
    ↓
D
    ↓
high real score

fake image
    ↓
D
    ↓
low real score
06

Classical GAN Objective

The classical minimax value function is:

\[ \boxed{ V(D,G) = \mathbb{E}_{x\sim p_{data}} [\log D(x)] + \mathbb{E}_{z\sim p_z} [\log(1-D(G(z)))] } \]

with the game:

\[ \boxed{ \min_G\max_D V(D,G) } \]

Read the two terms separately.

Real-data term

\[ \mathbb E[\log D(x)] \]

encourages the discriminator to assign high scores to real samples.

Fake-data term

\[ \mathbb E[\log(1-D(G(z)))] \]

encourages the discriminator to assign low real scores to generated samples.

The generator tries to make generated samples increasingly difficult for the discriminator to distinguish from real data.

07

Practical Generator Objective

The original minimax generator term can provide weak gradients in some regimes.

A common practical non-saturating generator loss is:

\[ \boxed{ L_G = -\mathbb E_z [\log D(G(z))] } \]

Interpretation:

generator wants:
D(G(z)) → 1

This is a standard implementation expansion.

For core syllabus understanding, know:

G → fool D
D → distinguish real/fake

and the classical minimax objective.

08

Discriminator Loss

A practical binary-cross-entropy formulation is:

\[ \boxed{ L_D = -\mathbb E_x[\log D(x)] - \mathbb E_z[\log(1-D(G(z)))] } \]

Interpretation:

real → target 1
fake → target 0

So the discriminator is effectively solving a binary classification problem whose training data consist of:

real examples
+
generated examples
09

Adversarial Training

GAN training alternates between the two players.

Conceptually:

Step A
Train discriminator
       ↓
make D better at real/fake separation

Step B
Train generator
       ↓
make G better at fooling D

Step C
repeat

The crucial implementation detail is:

When training one network, avoid accidentally updating the other network's parameters through the same loss.

10

Toy One-Dimensional GAN Intuition

Before images, imagine real data concentrated near:

\[ x\approx2. \]

The generator initially produces:

x_fake ≈ -3

The discriminator can easily separate them.

After training:

generator output
≈ 0

then
≈ 1

then
≈ 2

The generator distribution moves toward the real distribution.

This simple one-dimensional picture is often easier to understand than starting with images.

11

Latent Noise

A generator needs an input source.

A common choice:

\[ z\sim\mathcal N(0,I) \]

or a simple uniform distribution.

Example:

PYTHON
import torch

z = torch.randn(
    16,
    64,
)

Interpretation:

16 samples
64 latent dimensions each

Different latent vectors should ideally produce different generated samples.

12

Why Latent Space Is Useful

Suppose:

z₁
z₂
z₃
...

are different points in latent space.

The generator learns:

\[ G(z_i) \]

that should resemble samples from the target data distribution.

This gives a generative mapping:

latent space
    ↓
generator
    ↓
data space
13

Simple Generator for 28×28 Images

Use a dense educational architecture.

PYTHON
import torch
import torch.nn as nn
PYTHON
class Generator(nn.Module):
    def __init__(
        self,
        latent_dim=64,
    ):
        super().__init__()

        self.net = nn.Sequential(
            nn.Linear(
                latent_dim,
                128,
            ),
            nn.ReLU(),

            nn.Linear(
                128,
                256,
            ),
            nn.ReLU(),

            nn.Linear(
                256,
                784,
            ),
            nn.Tanh(),
        )

    def forward(self, z):
        x = self.net(z)

        return x.view(
            -1,
            1,
            28,
            28,
        )

This is intentionally simple.

For serious image generation, convolutional architectures are generally much more appropriate.

14

Why `Tanh` Here?

The generator ends with:

PYTHON
nn.Tanh()

which produces values approximately in:

\[ [-1,1]. \]

Therefore the image preprocessing should use the matching range.

Example:

PYTHON
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize(
        (0.5,),
        (0.5,),
    ),
])

Now the data are mapped approximately into:

[-1, 1]

The output/data ranges are deliberately aligned.

15

Simple Discriminator

PYTHON
class Discriminator(nn.Module):
    def __init__(self):
        super().__init__()

        self.net = nn.Sequential(
            nn.Flatten(),

            nn.Linear(
                784,
                256,
            ),
            nn.LeakyReLU(
                0.2,
            ),

            nn.Linear(
                256,
                128,
            ),
            nn.LeakyReLU(
                0.2,
            ),

            nn.Linear(
                128,
                1,
        )
        )

    def forward(self, x):
        return self.net(x)

Notice:

There is no sigmoid at the output.

The discriminator returns a logit.

A numerically stable BCE-with-logits loss can then be used during training.

16

Why Logits Instead of Sigmoid?

Use:

PYTHON
nn.BCEWithLogitsLoss()

rather than:

sigmoid
+
BCELoss

as a practical framework pattern.

Conceptually:

discriminator
 ↓
logit
 ↓
BCE-with-logits loss

The fused loss is designed to handle the sigmoid/BCE combination more stably.

Discriminator Training Step

Take a real batch:

PYTHON
real, _ = next(
    iter(loader)
)

real = real.to(device)

batch_size = real.size(0)

Create real labels:

PYTHON
real_targets = torch.ones(
    batch_size,
    1,
    device=device,
)

Generate fake images:

PYTHON
z = torch.randn(
    batch_size,
    64,
    device=device,
)

fake = G(z)

Fake labels:

PYTHON
fake_targets = torch.zeros(
    batch_size,
    1,
    device=device,
)
20

Discriminator Update

PYTHON
d_optimizer.zero_grad()

real_logits = D(real)

fake_logits = D(
    fake.detach()
)

real_loss = loss_fn(
    real_logits,
    real_targets,
)

fake_loss = loss_fn(
    fake_logits,
    fake_targets,
)

d_loss = (
    real_loss
    + fake_loss
) / 2.0

d_loss.backward()

d_optimizer.step()

Why:

PYTHON
fake.detach()

?

Because during the discriminator update we want gradients to update \(D\), not \(G\).

This is one of the most important GAN coding details.

21

Generator Update

Now train \(G\).

We want the discriminator to classify generated samples as real.

So use:

PYTHON
generator_targets = torch.ones(
    batch_size,
    1,
    device=device,
)

Then:

PYTHON
g_optimizer.zero_grad()

fake = G(z)

fake_logits = D(
    fake
)

g_loss = loss_fn(
    fake_logits,
    generator_targets,
)

g_loss.backward()

g_optimizer.step()

Notice:

fake.detach()

was used during discriminator training but is not used during generator training.

The generator needs the gradient path through the discriminator.

22

Why the Generator Can Learn Through the Discriminator

The path is:

\[ z \rightarrow G(z) \rightarrow D(G(z)) \rightarrow L_G. \]

The gradient is:

\[ L_G \rightarrow D \rightarrow G \rightarrow \theta_G. \]

So the discriminator acts as a differentiable critic whose feedback reaches the generator.

This is a direct application of the backpropagation concepts from Unit III.

23

Full GAN Training Loop

PYTHON
epochs = 5

g_history = []
d_history = []

for epoch in range(epochs):
    for real, _ in loader:
        real = real.to(device)

        batch_size = real.size(0)

        # -------------------------
        # 1. Train discriminator
        # -------------------------
        z = torch.randn(
            batch_size,
            64,
            device=device,
        )

        fake = G(z)

        real_targets = torch.ones(
            batch_size,
            1,
            device=device,
        )

        fake_targets = torch.zeros(
            batch_size,
            1,
            device=device,
        )

        d_optimizer.zero_grad()

        real_logits = D(real)

        fake_logits = D(
            fake.detach()
        )

        d_loss = (
            loss_fn(
                real_logits,
                real_targets,
            )
            +
            loss_fn(
                fake_logits,
                fake_targets,
            )
        ) / 2.0

        d_loss.backward()
        d_optimizer.step()

        # -------------------------
        # 2. Train generator
        # -------------------------
        z = torch.randn(
            batch_size,
            64,
            device=device,
        )

        fake = G(z)

        generator_targets = torch.ones(
            batch_size,
            1,
            device=device,
        )

        g_optimizer.zero_grad()

        fake_logits = D(fake)

        g_loss = loss_fn(
            fake_logits,
            generator_targets,
        )

        g_loss.backward()
        g_optimizer.step()

        g_history.append(
            g_loss.item()
        )

        d_history.append(
            d_loss.item()
        )

    print(
        f"epoch={epoch + 1} "
        f"G={g_history[-1]:.4f} "
        f"D={d_history[-1]:.4f}"
    )

The exact training dynamics can vary substantially across environments.

26

Why Loss Curves Alone Are Not Enough

GAN losses are unusual because:

G and D are optimizing against each other

A generator loss increasing does not automatically mean:

generation quality got worse

Similarly:

D loss ≈ some "nice" number

does not certify a good generator.

Use:

losses
+
visual samples
+
diversity
+
training stability
+
application-specific evaluation

where appropriate.

27

Mode Collapse

Mode collapse occurs when the generator produces insufficiently diverse samples.

Example:

desired:
A B C D E F G H

collapsed:
A A A A A A A A

The generated samples may individually look plausible while representing only a narrow part of the target distribution.

28

Detecting Mode Collapse

Warning signs:

different z values
       ↓
almost identical outputs

Test:

PYTHON
z_a = torch.randn(
    32,
    64,
    device=device,
)

with torch.no_grad():
    generated = G(z_a)

Flatten:

PYTHON
flat = generated.view(
    generated.size(0),
    -1,
)

Pairwise distances:

PYTHON
distances = torch.cdist(
    flat,
    flat,
)

If many different latent inputs produce extremely similar outputs, investigate possible diversity problems.

This is a diagnostic, not a complete mode-collapse metric.

29

Latent Interpolation

A powerful visualization experiment:

Take:

\[ z_0 \]

and:

\[ z_1. \]

Interpolate:

\[ z(\lambda) = (1-\lambda)z_0 + \lambda z_1. \]

Code:

PYTHON
z0 = torch.randn(
    1,
    64,
    device=device,
)

z1 = torch.randn(
    1,
    64,
    device=device,
)

alphas = torch.linspace(
    0,
    1,
    8,
    device=device,
)

interpolated = torch.cat([
    (1 - a) * z0 + a * z1
    for a in alphas
])

Generate:

PYTHON
with torch.no_grad():
    images = G(
        interpolated
    ).cpu()

If the learned latent mapping is useful, neighbouring latent points may produce smoothly changing samples.

This is an observational experiment, not a universal guarantee.

31

Discriminator Output Inspection

For real samples:

PYTHON
with torch.no_grad():
    real_scores = torch.sigmoid(
        D(real)
    )

For fake samples:

PYTHON
with torch.no_grad():
    fake_scores = torch.sigmoid(
        D(fake)
    )

Interpret under the standard sigmoid convention:

near 1 → discriminator sees real-like
near 0 → discriminator sees fake-like

Do not confuse these with calibrated probabilities in every possible discriminator setting.

GAN Training Diagnostics

Record:

G loss
D loss
D(real) mean
D(fake) mean
sample images
sample diversity

These provide more information than one loss value.

Example:

PYTHON
print(
    "D(real):",
    torch.sigmoid(
        real_logits
    ).mean().item(),
)

print(
    "D(fake):",
    torch.sigmoid(
        fake_logits
    ).mean().item(),
)

Common GAN Training Failure

Failure pattern

D becomes extremely confident
G receives weak/usefully poor learning signal

Possible causes include:

  • learning-rate imbalance;
  • architecture mismatch;
  • insufficient generator capacity;
  • insufficient discriminator capacity;
  • training instability;
  • poor objective choice.

Do not diagnose the exact cause from one scalar loss.

Inspect the complete training state.

34

Another Failure — Generator Repeats One Pattern

Likely concern:

mode collapse

Investigate:

latent diversity
sample diversity
D/G balance
learning rates
architecture
training schedule

Do not immediately assume that every repeated-looking output means mode collapse; visual inspection should cover a meaningful sample set.

Another Failure — Both Losses Oscillate

GAN training is an adversarial game.

Oscillation can occur because:

G changes
 ↓
D changes
 ↓
G reacts
 ↓
D reacts

So the optimization landscape is coupled.

This is fundamentally different from a simple single-objective supervised problem.

Conditional GAN — Conceptual Extension

A conditional generator can receive a class condition \(y\):

\[ \boxed{ G(z,y) } \]

Diagram:

noise z ──────┐
              ├──► G ───► generated image
class y ──────┘

The discriminator can also receive the condition.

Now the generator attempts:

"generate a sample of this class"

rather than:

"generate any realistic sample"

This is an architecture-level extension.

GAN vs Supervised Classification

Discriminator training looks like classification:

real → 1
fake → 0

But the overall GAN is not simply a static binary classifier.

The fake examples are produced by a generator that is simultaneously learning from discriminator feedback.

The two models therefore form a coupled system.

Common Coding Bugs

Bug 1 — Forgetting detach() during D update

The discriminator update may then backpropagate into the generator.

Bug 2 — Detaching during G update

Then the generator receives no useful gradient path through the discriminator.

Bug 3 — Double sigmoid

Using:

sigmoid output
+
BCEWithLogitsLoss

is incorrect.

Use either:

logit + BCEWithLogitsLoss

or:

sigmoid + BCELoss

with the corresponding numerical considerations.

Bug 4 — Data/output scale mismatch

For example:

real images ∈ [-1,1]
generator output ∈ [0,1]

creates an avoidable mismatch.

Bug 5 — Reusing stale noise

Always regenerate training noise unless intentionally running a fixed-noise evaluation.

Viva Questions

⚠️ University Lab Viva Trap & Runtime Gotcha
**Vanishing Gradients for Generator & Saturated Loss:** Minimizing $\log(1 - D(G(z)))$ causes severe vanishing gradients early in training because $D$ easily rejects early fakes ($D(G(z)) \approx 0$). In practice, we train the Generator to MAXIMIZE $\log D(G(z))$ (non-saturating heuristic) instead! Also, if the Discriminator becomes too powerful too quickly, gradients vanish completely and training collapses.

Q1. What is a GAN?

A generative framework containing a generator and discriminator trained through an adversarial objective.

Q2. What does the generator do?

Maps latent noise to generated samples.

Q3. What does the discriminator do?

Distinguishes real training samples from generated samples.

Q4. What is adversarial training?

Alternating optimization in which the generator and discriminator have competing objectives.

Q5. What is mode collapse?

A failure in which generated outputs lack sufficient diversity and may repeatedly represent only a narrow set of patterns.

Q6. Why does the generator receive a gradient through the discriminator?

Because the generator loss depends on the discriminator's output for generated samples, creating a differentiable path from loss through discriminator to generator.

Q7. What is the role of latent noise?

It provides a source of variation from which the generator constructs different samples.

Q8. Why use fixed latent vectors for visualization?

To compare generator changes across training checkpoints without changing the input noise.

Q9. Why are GAN losses hard to interpret alone?

Because the two losses belong to competing objectives and their magnitudes depend on the coupled training dynamics.

Q10. How does a conditional GAN differ?

It incorporates additional conditioning information such as a class label.
