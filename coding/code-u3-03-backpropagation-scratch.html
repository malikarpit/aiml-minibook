CODE-U3-03 — Gradient Descent and Backpropagation From Scratch

Purpose: Turn the MLP forward pass into a trainable model by deriving and implementing gradients with backpropagation, then using gradient descent to update the parameters.

This chapter contains one of the most important computational ideas in modern machine learning:

forward pass
    ↓
prediction
    ↓
loss
    ↓
backpropagation
    ↓
gradients
    ↓
gradient descent
    ↓
updated parameters
    ↓
repeat

Two ideas must remain distinct:

Backpropagation computes gradients efficiently.

Gradient descent uses those gradients to update parameters.

They work together, but they are not the same operation.

03

The Full Training Loop

A trainable network repeatedly performs:

1. Forward pass
2. Compute loss
3. Backward pass / backpropagation
4. Update parameters
5. Repeat

Mathematically:

\[ \theta = \{W^{(1)},b^{(1)},W^{(2)},b^{(2)},\ldots\}. \]

Then:

\[ \hat y=f_\theta(x) \]

and:

\[ J(\theta)=\text{loss}(\hat y,y). \]

Backpropagation calculates:

\[ \nabla_\theta J. \]

Gradient descent updates:

\[ \boxed{ \theta \leftarrow \theta-\eta\nabla_\theta J } \]
04

Why We Need Backpropagation

Imagine a network with thousands or millions of parameters.

For every parameter \(\theta_j\), we need:

\[ \frac{\partial J}{\partial\theta_j}. \]

Computing every derivative independently from scratch would repeat enormous amounts of work.

The chain rule lets us reuse intermediate derivatives.

The result is an efficient backward computation through the same graph used during the forward pass.

Conceptually:

Forward:
input → layer 1 → layer 2 → loss

Backward:
loss → layer 2 → layer 1 → input

The backward direction is where the name backpropagation comes from.

05

A Minimal Trainable Network

Use:

2 inputs
 ↓
2 hidden neurons
 ↓
1 sigmoid output

Mathematically:

\[ Z_1=XW_1+b_1 \]
\[ A_1=ReLU(Z_1) \]
\[ Z_2=A_1W_2+b_2 \]
\[ \hat Y=\sigma(Z_2). \]

Use binary cross-entropy:

\[ \boxed{ J= -\frac1n \sum_{i=1}^n \left[ y_i\log(\hat y_i) + (1-y_i)\log(1-\hat y_i) \right] } \]

For numerical safety, predictions should be clipped slightly before taking logarithms if using the probability form directly.

07

Binary Cross-Entropy

Implementation:

PYTHON
def binary_cross_entropy(
    y_true: np.ndarray,
    y_pred: np.ndarray,
    eps: float = 1e-12,
) -> float:
    y_true = np.asarray(y_true, dtype=float)
    y_pred = np.asarray(y_pred, dtype=float)

    if y_true.shape != y_pred.shape:
        raise ValueError("y_true and y_pred must have the same shape.")

    y_pred = np.clip(y_pred, eps, 1.0 - eps)

    loss = -np.mean(
        y_true * np.log(y_pred)
        + (1.0 - y_true) * np.log(1.0 - y_pred)
    )

    return float(loss)
08

Why We Clip Probabilities

The logarithm becomes problematic at:

\[ \log(0). \]

A prediction numerically equal to exactly 0 or 1 can therefore cause unstable loss calculations.

Clipping:

PYTHON
y_pred = np.clip(
    y_pred,
    eps,
    1.0 - eps,
)

keeps the calculation finite.

For production numerical implementations, one can also compute the binary cross-entropy directly from logits using stable identities. That approach avoids explicitly forming problematic logarithms of probabilities and is preferred in many frameworks.

09

First Derivative — Sigmoid

The sigmoid is:

\[ \sigma(z)=\frac{1}{1+e^{-z}}. \]

Its derivative has a useful form:

\[ \boxed{ \sigma'(z) = \sigma(z)(1-\sigma(z)) } \]

Implementation:

PYTHON
def sigmoid_derivative_from_output(a):
    return a * (1.0 - a)

Notice that this function expects the sigmoid output \(a=\sigma(z)\), so we do not have to recompute the exponential.

10

ReLU Derivative

ReLU:

\[ ReLU(z)=\max(0,z). \]

For nonzero \(z\):

\[ \boxed{ ReLU'(z)= \begin{cases} 1,&z\gt 0\\ 0,&z\lt 0 \end{cases} } \]

Implementation:

PYTHON
def relu_derivative(z):
    return (z > 0).astype(float)

At \(z=0\), ReLU is not classically differentiable. In practical implementations a subgradient/convention is chosen; this implementation returns 0 at zero.

11

The Key Derivative Shortcut for Binary Cross-Entropy + Sigmoid

This combination is especially useful.

Let:

\[ \hat y=\sigma(z) \]

and binary cross-entropy:

\[ L= -\left[ y\log\hat y+(1-y)\log(1-\hat y) \right]. \]

Applying the chain rule gives:

\[ \boxed{ \frac{\partial L}{\partial z} = \hat y-y } \]

for one example.

For the mean batch loss:

\[ \boxed{ dZ_2= \frac{1}{n} (\hat Y-Y) } \]

where the division by \(n\) reflects the mean loss convention.

This simplification is extremely important in practical neural-network derivations.

For one sample:

x
 ↓

 ↓
A1 = ReLU(Z1)
 ↓
Z2 = A1W2 + b2
 ↓
Yhat = sigmoid(Z2)
 ↓
L = BCE(Y, Yhat)

Backpropagation walks backward:

L
↓
Z2
↓
A1
↓
Z1
↓
W1 / b1

Each arrow contributes one factor from the chain rule.

13

Chain Rule Intuition

Suppose:

\[ u=f(x) \]

and:

\[ v=g(u). \]

Then:

\[ \frac{dv}{dx} = \frac{dv}{du} \frac{du}{dx}. \]

In a neural network, the same idea is applied repeatedly.

You can think:

final effect
×
local effect
×
earlier local effect
×
...

So a parameter's gradient answers:

“If I change this parameter slightly, how much does the final loss change?”

14

Backpropagation Derivation — Output Layer

Start with:

\[ Z_2=A_1W_2+b_2 \]

and:

\[ L=L(Z_2). \]

Define:

\[ dZ_2=\frac{\partial L}{\partial Z_2}. \]

For sigmoid + binary cross-entropy:

\[ \boxed{ dZ_2=\frac{1}{n}(\hat Y-Y) } \]

Now derive \(W_2\).

Since:

\[ Z_2=A_1W_2+b_2 \]

the gradient is:

\[ \boxed{ dW_2=A_1^TdZ_2 } \]

and:

\[ \boxed{ db_2=\sum_{\text{batch}}dZ_2 } \]

for the mean-loss convention.

15

Hidden Layer Gradient

The hidden activation is:

\[ A_1=ReLU(Z_1). \]

First move backward through the matrix multiplication:

\[ Z_2=A_1W_2+b_2. \]

Then:

\[ \boxed{ dA_1=dZ_2W_2^T } \]

Now move through ReLU:

\[ \boxed{ dZ_1=dA_1\odot ReLU'(Z_1) } \]

where \(\odot\) means element-wise multiplication.

16

First Layer Gradients

Since:

\[ Z_1=XW_1+b_1, \]

we obtain:

\[ \boxed{ dW_1=X^TdZ_1 } \]

and:

\[ \boxed{ db_1=\sum_{\text{batch}}dZ_1 } \]

The complete gradient flow is therefore:

dZ2
 ↓
dW2, db2
 ↓
dA1
 ↓
dZ1
 ↓
dW1, db1
17

Backward Function From Scratch

PYTHON
def mlp_backward(
    X,
    Y,
    cache,
    W2,
):
    Z1 = cache["Z1"]
    A1 = cache["A1"]
    Y_hat = cache["Y_hat"]

    n = X.shape[0]

    # Output layer: sigmoid + binary cross-entropy
    dZ2 = (Y_hat - Y) / n

    dW2 = A1.T @ dZ2
    db2 = np.sum(dZ2, axis=0)

    # Hidden layer
    dA1 = dZ2 @ W2.T
    dZ1 = dA1 * relu_derivative(Z1)

    dW1 = X.T @ dZ1
    db1 = np.sum(dZ1, axis=0)

    return {
        "dW1": dW1,
        "db1": db1,
        "dW2": dW2,
        "db2": db2,
    }

The code should now look almost identical to the mathematical derivation.

That is the target.

18

Forward Function for Training

PYTHON
def mlp_forward_train(
    X,
    W1,
    b1,
    W2,
    b2,
):
    Z1 = X @ W1 + b1
    A1 = np.maximum(0.0, Z1)

    Z2 = A1 @ W2 + b2
    Y_hat = 1.0 / (1.0 + np.exp(-Z2))

    cache = {
        "Z1": Z1,
        "A1": A1,
        "Z2": Z2,
        "Y_hat": Y_hat,
    }

    return Y_hat, cache

For highly extreme logits, use the numerically safer sigmoid implementation from the previous chapter.

19

Gradient Descent Update

Once we have gradients:

\[ W_1 \leftarrow W_1-\eta dW_1 \]
\[ b_1 \leftarrow b_1-\eta db_1 \]
\[ W_2 \leftarrow W_2-\eta dW_2 \]
\[ b_2 \leftarrow b_2-\eta db_2. \]

Implementation:

PYTHON
def update_parameters(
    params,
    grads,
    learning_rate,
):
    params["W1"] -= learning_rate * grads["dW1"]
    params["b1"] -= learning_rate * grads["db1"]
    params["W2"] -= learning_rate * grads["dW2"]
    params["b2"] -= learning_rate * grads["db2"]

    return params

PYTHON
rng = np.random.default_rng(42)

params = {
    "W1": rng.normal(0.0, 0.5, size=(2, 4)),

    "W2": rng.normal(0.0, 0.5, size=(4, 1)),

Train:

PYTHON
history = []

learning_rate = 0.1
epochs = 5000

for epoch in range(epochs):
    Y_hat, cache = mlp_forward_train(
        X,
        params["W1"],
        params["b1"],
        params["W2"],
        params["b2"],
    )

    loss = binary_cross_entropy(Y, Y_hat)
    history.append(loss)

    grads = mlp_backward(
        X,
        Y,
        cache,
        params["W2"],
    )

    params = update_parameters(
        params,
        grads,
        learning_rate,
    )

    if epoch % 500 == 0:
        print(epoch, loss)

The exact numerical trajectory depends on initialization, activation, learning rate and implementation choices.

The expected conceptual result is that the network can learn a nonlinear mapping that a single perceptron cannot represent.

24

Why Backpropagation Is More Than “Going Backwards”

Backpropagation does not simply reverse the network.

It performs a structured application of the chain rule.

For each operation:

forward operation
    ↓
local derivative
    ↓
multiply by upstream gradient
    ↓
gradient for previous node

So:

\[ \text{gradient at current node} = \text{upstream gradient} \times \text{local derivative}. \]

This is the same idea repeated throughout the computational graph.

25

Computational Graph Example

Consider:

\[ z=w x+b \]
\[ a=ReLU(z) \]
\[ \hat y=\sigma(a). \]

Then:

x, w, b
   ↓
   z
   ↓
 ReLU
   ↓
   a
   ↓
sigmoid
   ↓
 yhat
   ↓
 loss

Suppose you want:

\[ \frac{\partial L}{\partial w}. \]

The chain is:

\[ \boxed{ \frac{\partial L}{\partial w} = \frac{\partial L}{\partial \hat y} \frac{\partial \hat y}{\partial a} \frac{\partial a}{\partial z} \frac{\partial z}{\partial w} } \]

This is backpropagation in its simplest form.

26

Numerical Gradient Checking

A hand-derived gradient should be tested.

Use central finite differences:

\[ \boxed{ \frac{\partial J}{\partial\theta} \approx \frac{ J(\theta+\epsilon)-J(\theta-\epsilon) } {2\epsilon} } \]

The method gives a numerical approximation to the derivative.

27

Implement Finite-Difference Check

PYTHON
def finite_difference_gradient(
    loss_function,
    parameter,
    epsilon=1e-5,
):
    numerical = np.zeros_like(parameter, dtype=float)

    iterator = np.nditer(
        parameter,
        flags=["multi_index"],
        op_flags=["readwrite"],
    )

    while not iterator.finished:
        idx = iterator.multi_index
        original = parameter[idx]

        parameter[idx] = original + epsilon
        loss_plus = loss_function()

        parameter[idx] = original - epsilon
        loss_minus = loss_function()

        parameter[idx] = original

        numerical[idx] = (
            loss_plus - loss_minus
        ) / (2.0 * epsilon)

        iterator.iternext()

    return numerical

For a complete implementation, be careful that the loss function references the same parameter array and restores its original value after every perturbation.

28

Relative Gradient Error

A useful comparison is:

\[ \boxed{ error= \frac{ \|\nabla_{analytic}-\nabla_{numeric}\|_2 }{ \|\nabla_{analytic}\|_2+ \|\nabla_{numeric}\|_2+ \epsilon } } \]

Interpretation:

very small
   ↓
good agreement

large
   ↓
likely derivative or implementation bug

Implementation:

PYTHON
def relative_error(a, b, eps=1e-12):
    numerator = np.linalg.norm(a - b)
    denominator = (
        np.linalg.norm(a)
        + np.linalg.norm(b)
        + eps
    )

    return numerator / denominator
29

What Gradient Checking Can Catch

It can expose:

  • wrong transpose;
  • missing bias gradient;
  • missing batch normalization factor;
  • wrong activation derivative;
  • sign errors;
  • parameter-update mistakes;
  • accidentally modifying the wrong tensor;
  • incorrect loss derivatives.

Gradient checking is one of the strongest debugging techniques for a hand-written neural-network implementation.

30

Gradient Checking Should Use Tiny Problems

Gradient Descent From First Principles

Suppose:

\[ J(w)=w^2. \]

Then:

\[ \frac{dJ}{dw}=2w. \]

Update:

\[ w_{t+1}=w_t-\eta(2w_t) \]

so:

\[ \boxed{ w_{t+1}=(1-2\eta)w_t } \]

For stable convergence toward zero:

\[ |1-2\eta|\lt 1. \]

Therefore:

\[ \boxed{ 0\lt \eta\lt 1 } \]

for this specific one-dimensional example.

This is not a universal neural-network learning-rate rule.

It is a mathematical demonstration of why step size affects stability.

Learning Rate Experiment

Try:

PYTHON
def optimize_quadratic(
    w0,
    learning_rate,
    steps,
):
    w = float(w0)
    history = [w]

    for _ in range(steps):
        grad = 2.0 * w
        w = w - learning_rate * grad
        history.append(w)

    return np.array(history)

PYTHON
for eta in [0.1, 0.4, 0.9, 1.1]:

Batch Gradient Descent in the Example

Our XOR example uses all four examples in every gradient calculation.

That is full-batch gradient descent.

For:

\[ J= \frac1n\sum_i\ell_i \]

we compute:

\[ \nabla J = \frac1n \sum_i\nabla\ell_i. \]

The code therefore performs:

forward on all samples
 ↓
one average loss
 ↓
one gradient
 ↓
one update
36

Mini-Batch Extension

With a mini-batch \(B\):

\[ \boxed{ \theta \leftarrow \theta - \eta \frac1{|B|} \sum_{i\in B} \nabla_\theta\ell_i } \]

The practical structure becomes:

for epoch:
    shuffle data

    for each mini-batch:
        forward
        loss
        backprop
        update

This is the foundation of the training loops used by modern deep-learning frameworks.

Common Backpropagation Errors

Error 1 — Missing transpose

For:

\[ dW_2=A_1^TdZ_2 \]

the transpose is essential under the row-batch convention.

Error 2 — Wrong batch scaling

If your loss is a mean over \(n\) examples, gradients must reflect that averaging convention.

Error 3 — ReLU derivative applied to \(A\) instead of \(Z\)

The derivative depends on whether the pre-activation \(Z\) was positive.

Error 4 — Updating before all gradients are computed

Compute gradients from the same parameter state first.

Then update the parameters.

A safe pattern is:

forward
↓
backward
↓
all gradients available
↓
update all parameters

Error 5 — Mixing old and new parameters

Do not update \(W_1\) and then compute \(dW_2\) using a different parameter state unless your algorithm explicitly requires it.

Error 6 — Wrong loss/output pairing

A common educational pairing is:

sigmoid + binary cross-entropy

Another is:

softmax + multi-class cross-entropy

The derivative formulas depend on the chosen combination.

Numerical Stability and Saturation

Sigmoid values near 0 or 1 have derivative:

\[ \sigma'(z)=\sigma(z)(1-\sigma(z)) \]

which becomes small when the output saturates.

This means:

very negative z → sigmoid near 0 → small derivative

very positive z → sigmoid near 1 → small derivative

This contributes to weak gradient signals in saturated regions.

This is one reason activation functions and initialization matter.

Training-Class Design

A more structured implementation can store parameters and gradients together.

PYTHON
class ScratchMLP:
    def __init__(
        self,
        input_dim,
        hidden_dim,
        output_dim=1,
        seed=42,
    ):
        rng = np.random.default_rng(seed)

        self.W1 = rng.normal(
            0.0,
            0.5,
            size=(input_dim, hidden_dim),
        )
        self.b1 = np.zeros(hidden_dim)

        self.W2 = rng.normal(
            0.0,
            0.5,
            size=(hidden_dim, output_dim),
        )
        self.b2 = np.zeros(output_dim)

    def forward(self, X):
        Z1 = X @ self.W1 + self.b1
        A1 = np.maximum(0.0, Z1)

        Z2 = A1 @ self.W2 + self.b2
        Y_hat = 1.0 / (1.0 + np.exp(-Z2))

        return Y_hat, {
            "Z1": Z1,
            "A1": A1,
            "Z2": Z2,
            "Y_hat": Y_hat,
        }

Then add:

PYTHON
def step(self, X, Y, learning_rate):
    ...

and:

PYTHON
def fit(self, X, Y, epochs, learning_rate):
    ...

The class is an organizational tool. The mathematics should remain explicit.

After you understand manual derivatives, automatic differentiation becomes extremely valuable.

The difference is that the framework handles derivative bookkeeping.

This is why understanding backpropagation manually is valuable even when you rarely implement it manually in production.

Viva Questions

⚠️ University Lab Viva Trap & Runtime Gotcha
**Hadamard Elementwise vs Matrix Product in Backprop:** When calculating $\delta_1 = (\delta_2 W_2^T) \odot g'(Z_1)$, the activation derivative must be multiplied ELEMENTWISE ($\odot$), NOT matrix multiplied! Also, always implement a numerical gradient check $(f(\theta + \epsilon) - f(\theta - \epsilon)) / (2\epsilon)$ to verify that analytical derivatives have zero typos before training!

Q1. What is backpropagation?

An efficient chain-rule procedure for computing gradients of the loss with respect to network parameters.

Q2. What does gradient descent do?

It updates parameters in the direction opposite the gradient.

Q3. Are backpropagation and gradient descent the same?

No.

Backpropagation computes gradients; gradient descent uses them for updates.

Q4. What is a computational graph?

A representation of computations as nodes and dependencies, which makes forward evaluation and reverse-mode differentiation systematic.

Q5. Why is the chain rule important?

It lets us compute how a final loss changes with respect to an earlier parameter by multiplying local derivatives along a dependency path.

Q6. Why is gradient checking useful?

It compares analytic gradients with a numerical approximation and can reveal implementation errors.

Q7. Why can the learning rate be too large?

Updates can overshoot useful regions and make the optimization unstable.

Q8. Why can the learning rate be too small?

Training can become unnecessarily slow.

Q9. What is an epoch?

One complete pass through the training dataset.

Q10. Why store forward activations?

Backpropagation needs intermediate values to compute local derivatives and parameter gradients efficiently.

Q11. Why can a sigmoid saturate?

Its output approaches 0 or 1 for large-magnitude inputs, making its derivative small.

Q12. What is a mini-batch?

A subset of the training data used to estimate a gradient and perform one parameter update.

Master Challenge — Reproduce the Entire Derivation

Without looking at notes, derive:

\[ Z_1=XW_1+b_1 \]
\[ A_1=ReLU(Z_1) \]
\[ Z_2=A_1W_2+b_2 \]
\[ \hat Y=\sigma(Z_2) \]

and then:

\[ dZ_2 \rightarrow dW_2,db_2 \rightarrow dA_1 \rightarrow dZ_1 \rightarrow dW_1,db_1. \]

Finally write the parameter update equations.

This is an important mastery gate because it forces you to understand the computational graph rather than memorize isolated formulas.

One-Screen Formula Map

Forward

\[ Z_1=XW_1+b_1 \]
\[ A_1=ReLU(Z_1) \]
\[ Z_2=A_1W_2+b_2 \]
\[ \hat Y=\sigma(Z_2) \]

Loss

\[ J= -\frac1n \sum [ Y\log\hat Y + (1-Y)\log(1-\hat Y) ] \]

Backprop

\[ dZ_2=\frac1n(\hat Y-Y) \]
\[ dW_2=A_1^TdZ_2 \]
\[ db_2=\sum dZ_2 \]
\[ dA_1=dZ_2W_2^T \]
\[ dZ_1=dA_1\odot ReLU'(Z_1) \]
\[ dW_1=X^TdZ_1 \]
\[ db_1=\sum dZ_1 \]

Update

\[ W\leftarrow W-\eta dW \]
\[ b\leftarrow b-\eta db \]
