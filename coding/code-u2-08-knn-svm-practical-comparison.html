👨‍🏫 Teacher Intuition — Bilingual Implementation Model

04

The Three Models

KNN

KNN predicts using nearby training examples.

Conceptually:

new point
   ↓
calculate distances
   ↓
find K nearest points
   ↓
vote
   ↓
predicted class

KNN is a local method.

SVM

SVM seeks a decision boundary with a useful margin between classes.

Conceptually:

training points
   ↓
find separating boundary
   ↓
maximize margin
   ↓
retain critical boundary-defining examples
   ↓
classify new point

Those critical training examples are called support vectors.

Decision Tree

A decision tree recursively asks feature-based questions and routes an example to a leaf.

Conceptually:

feature question
   ↓
left/right branch
   ↓
another question
   ↓
...
   ↓
leaf prediction

The comparison is useful because the three models encode different assumptions:

KNN
→ local similarity

SVM
→ margin / boundary geometry

Decision Tree
→ recursive feature-based partitioning

Scaling

Scaling is particularly important for KNN because KNN depends directly on distances.

For example:

PYTHON
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

X_train_s = scaler.fit_transform(X_train)
X_test_s = scaler.transform(X_test)

The critical rule is:

fit on train
transform train
transform test

Do not fit a separate scaler to the test set.

09

KNN From Scratch

9.1 Core idea

Given a new point:

  1. compute its distance to each training point;
  2. select the K smallest distances;
  3. inspect their class labels;
  4. choose the majority class.

For Euclidean distance:

\[ d(x,z) = \sqrt{ \sum_j (x_j-z_j)^2 }. \]

Because the square root is monotonic, ranking by squared Euclidean distance gives the same nearest-neighbour order.

10

Minimal KNN Implementation

PYTHON
import numpy as np


def euclidean_distance(a, b):
    return np.sqrt(np.sum((a - b) ** 2))


def knn_predict_one(
    X_train,
    y_train,
    x_query,
    k=5,
):
    distances = []

    for x_train, label in zip(X_train, y_train):
        d = euclidean_distance(
            x_train,
            x_query,
        )
        distances.append((d, label))

    distances.sort(
        key=lambda item: item[0]
    )

    nearest = distances[:k]

    labels = [
        label
        for _, label in nearest
    ]

    values, counts = np.unique(
        labels,
        return_counts=True,
    )

    return values[np.argmax(counts)]


def knn_predict(
    X_train,
    y_train,
    X_query,
    k=5,
):
    return np.array(
        [
            knn_predict_one(
                X_train,
                y_train,
                x,
                k=k,
            )
            for x in X_query
        ]
    )

This implementation deliberately uses simple loops.

The purpose is transparency.

12

Why K Matters

Imagine:

K = 1

Prediction depends on one neighbour.

Very sensitive to individual examples.

As K grows:

K small
→ local / flexible
→ potentially noisy

K large
→ smoother / more global
→ potentially oversmoothed

There is no universally correct K.

Choose it using the development protocol.

13

KNN Complexity Intuition

Basic KNN has almost no expensive training phase.

Most work happens at prediction:

for each query:
    calculate distance to many training points

For a simple dense implementation:

  • prediction cost grows with the number of stored training examples;
  • each distance also depends on feature dimension.

This is one reason KNN can become expensive at inference time.

16

SVM — Core Mental Model

Support Vector Machines are fundamentally about finding a useful separating boundary.

For a linear separator:

\[ w^Tx+b=0. \]

The classifier uses the sign of:

\[ w^Tx+b. \]

The important geometric idea is the margin.

Rather than choosing an arbitrary separating line, the classical SVM formulation seeks a boundary with a large margin between the classes.

17

Support Vectors

Not every training point is equally important for determining the final boundary.

The most influential boundary-defining observations are the:

support vectors

Conceptually:

class A      |      class B

 A A A       |       B B B
    A     SV | SV      B
        SV   |   SV
               ↑
          boundary region

Do not interpret support vectors as “the only data the model trains on.”

They are the critical examples associated with the learned margin/boundary.

18

Linear vs Nonlinear SVM

A linear SVM uses:

w^T x + b

as a linear decision function.

For more complex boundaries, kernel methods can implicitly work in transformed feature spaces.

Conceptually:

input
 ↓
similarity/kernel relationship
 ↓
higher-dimensional representation
 ↓
linear separation there

The kernel idea is deeper than this chapter requires mathematically.

For the practical, focus on:

margin
support vectors
C
kernel
classification
evaluation
19

SVM Hyperparameter: C

C controls the trade-off between:

large margin
vs
penalizing training violations

Conceptually:

smaller C
→ stronger preference for wider margin
→ allows more violations

larger C
→ stronger penalty for violations
→ may fit training data more aggressively

This is a model-capacity / regularization trade-off.

35

Common Mistake — Scaling Before the Split

⚠️ University Lab Viva Trap & Runtime Gotcha
**The Scaling Failure & Support Vector Definition Traps:** 1. **k-NN Scaling Leakage / Omission:** Agar tum k-NN chalane se pehle `StandardScaler` nahi lagate, toh bada scale wala feature distance ko dominate karega aur test accuracy drastically drop ho jayegi. Par scaling hamesha train split par `fit` karke test par `transform` karna, poore dataset par ek saath fit mat karna! 2. **Support Vectors Viva Question:** "Do all data points affect the SVM decision boundary?" Answer: NO! Only the support vectors lying on or inside the margin band define $w$ and $b$. If you move non-support vectors, the hyperplane does not change at all!

Wrong:

PYTHON
X_scaled = scaler.fit_transform(X)

X_train, X_test, y_train, y_test = train_test_split(
    X_scaled,
    y,
)

Why risky?

Because the transformation has already seen the entire dataset.

Safer:

split
 ↓
fit scaler on train
 ↓
transform train
 ↓
transform test

Common Mistake — Ignoring Scaling for KNN

Suppose:

feature 1: 0–1
feature 2: 0–1,000,000

Distance can be dominated by feature 2.

That changes what “nearest” means.

So scaling is not cosmetic for KNN.

It changes the geometry.

Common Mistake — Calling SVM “Just a Classifier”

SVM is not best remembered as:

“another classifier.”

Remember:

classifier
+
margin
+
support vectors
+
regularization / C
+
kernel possibility

That mental model transfers to later ML concepts.

Common Mistake — Treating Tree Depth as a Universal Number

A tree with:

max_depth=5

is not automatically good.

Depth is a hyperparameter selected for the data and objective.

The important lesson is:

Model settings are experimental choices, not magic constants.
