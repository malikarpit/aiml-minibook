03

Value-Based vs Policy-Based Learning

Q-learning:

state
 ↓
Q(s,a)
 ↓
choose high-value action

Policy gradient:

state
 ↓
πθ(a|s)
 ↓
sample action

The difference is fundamental.

Q-learning

The primary learned object is:

\[ Q(s,a). \]

Policy gradient

The primary learned object is:

\[ \boxed{ \pi_\theta(a|s) } \]

a parameterized probability distribution over actions.

04

Why Use a Stochastic Policy?

Suppose a state has three possible actions.

The policy might output:

left  = 0.10
right = 0.70
up    = 0.20

The agent does not have to behave deterministically.

Sampling allows exploration naturally.

As learning progresses, the probability distribution can shift.

Conceptually:

early:
[0.33, 0.34, 0.33]

after learning:
[0.05, 0.90, 0.05]

This is different from epsilon-greedy exploration because the policy itself represents the action-selection distribution.

05

Parameterized Policy

Let:

\[ \theta \]

represent the network parameters.

Then:

\[ \boxed{ \pi_\theta(a|s) } \]

means:

probability of taking action \(a\) in state \(s\) under parameters \(\theta\).

A neural network can map state features to logits:

\[ z=f_\theta(s). \]

Then softmax converts logits into action probabilities:

\[ \pi_\theta(a|s) = \frac{e^{z_a}} {\sum_j e^{z_j}}. \]

In PyTorch, a categorical distribution can be parameterized directly by logits or probabilities. The current PyTorch documentation provides torch.distributions.Categorical with sample() and log_prob(), and explicitly describes REINFORCE using these operations. turn114329search0cite

09

One-Step Intuition

Suppose:

\[ \log\pi_\theta(a|s) \]

changes when the policy parameters move.

If the observed return is:

\[ G=+10 \]

then:

\[ -G\log\pi(a|s) \]

encourages increasing the probability of the chosen action.

If:

\[ G=-10 \]

the sign reverses, encouraging the policy away from that action.

This is a simplified intuition for the REINFORCE update.

10

Discounted Returns

Given episode rewards:

r₀, r₁, ..., r_{T-1}

compute:

\[ G_t= r_t+\gamma r_{t+1} +\gamma^2r_{t+2} +\cdots. \]

Python:

PYTHON
import numpy as np
PYTHON
def discounted_returns(
    rewards,
    gamma,
):
    returns = np.zeros(
        len(rewards),
        dtype=float,
    )

    running = 0.0

    for t in reversed(
        range(len(rewards))
    ):
        running = (
            rewards[t]
            + gamma * running
        )

        returns[t] = running

    return returns

12

Normalize Returns

Policy-gradient estimates can be noisy.

A common practical experiment is to standardize sampled returns:

\[ \boxed{ \hat G_t= \frac{ G_t-\mu_G }{ \sigma_G+\epsilon } } \]

Implementation:

PYTHON
def normalize_returns(
    returns,
    eps=1e-8,
):
    returns = np.asarray(
        returns,
        dtype=float,
    )

    mean = returns.mean()
    std = returns.std()

    return (
        returns - mean
    ) / (
        std + eps
    )

This changes the scale of the learning signal.

It does not change the underlying goal of maximizing expected return.

13

Why Normalization Can Help

Suppose one episode produces:

returns ≈ 0 to 2

and another produces:

returns ≈ 0 to 500

The second episode can dominate gradient magnitude.

Normalization can make optimization numerically better behaved.

But:

It is a variance/scale-control technique, not a universal guarantee of better performance.

Build a Tiny Policy Network

Use PyTorch:

PYTHON
import torch
import torch.nn as nn
from torch.distributions import Categorical

Model:

PYTHON
class PolicyNetwork(nn.Module):
    def __init__(
        self,
        state_dim,
        action_dim,
        hidden_dim=64,
    ):
        super().__init__()

        self.network = nn.Sequential(
            nn.Linear(
                state_dim,
                hidden_dim,
            ),
            nn.ReLU(),
            nn.Linear(
                hidden_dim,
                action_dim,
            ),
        )

    def forward(self, state):
        return self.network(state)

The network outputs logits, not probabilities.

15

Why Output Logits Instead of Softmax?

Categorical can accept logits directly.

That is convenient and numerically preferable to manually computing probabilities in many situations.

PYTHON
logits = policy_network(state)
dist = Categorical(
    logits=logits
)

Then:

PYTHON
action = dist.sample()
log_prob = dist.log_prob(action)

The current PyTorch documentation supports both probs= and logits= for Categorical, and states that logits are interpreted as unnormalized log probabilities. turn114329search0cite

Policy Gradient Numerical

Suppose:

\[ G=8 \]

and:

\[ \log\pi_\theta(a|s)=\log(0.25). \]

Then one scalar contribution to the loss is:

\[ -8\log(0.25). \]

Because:

\[ \log(0.25)\lt 0, \]

the contribution is positive.

The optimizer works through the derivative of the log-probability with respect to the policy parameters.

You do not need to calculate a complete neural-network gradient by hand for every parameter in an exam.

The important exam-level understanding is:

return
×
log-probability gradient

forms the policy-learning signal.

Policy Gradient vs Q-Learning Decision Process

Q-learning:

state
 ↓
Q values
 ↓
argmax / epsilon-greedy
 ↓
action

REINFORCE:

state
 ↓
policy logits
 ↓
probability distribution
 ↓
sample
 ↓
action

Memory anchor:

Q-learning learns values and derives actions; policy gradients learn action probabilities directly.

43

Why Policy Gradients Are Useful

Policy gradients are attractive when:

  • the policy itself is the object you want to optimize;
  • the action space or policy representation makes direct parameterization convenient;
  • stochastic policies are useful;
  • continuous-action settings are relevant.

The exact trade-offs depend heavily on the environment and algorithm variant.

Do not treat “policy gradient” as one single algorithm.

REINFORCE is the basic Monte-Carlo policy-gradient example.

44

REINFORCE Limitation — High Variance

The update uses sampled returns.

Different trajectories can produce very different:

\[ G_t. \]

Therefore the gradient estimate can be noisy.

Conceptually:

trajectory A → high return
trajectory B → low return
trajectory C → medium return

The policy update changes according to the sampled outcomes.

This explains why policy-gradient training can require many episodes.

45

REINFORCE vs TD Learning

Q-learning:

bootstrapped target
r + γ max Q(next)

REINFORCE:

sampled return
G_t

Thus:

Q-learning → bootstrap from current value estimates

REINFORCE → wait for sampled trajectory return

This is an important algorithmic comparison.

RL Debugging Protocol

When REINFORCE appears not to learn:

1. Verify environment rewards.
2. Verify action space.
3. Verify logits shape.
4. Verify probability distribution sums to 1.
5. Verify sampled action is valid.
6. Verify log_prob has gradient.
7. Verify returns are correct.
8. Verify the negative sign.
9. Inspect gradient norms.
10. Try a tiny deterministic environment.
11. Try normalized returns.
12. Run multiple seeds.

Do not immediately increase the network size.

First verify the learning signal.

53

Viva Questions

⚠️ University Lab Viva Trap & Runtime Gotcha
**Minus Sign in Policy Loss & Full Return Normalization:** 1. PyTorch optimizers MINIMIZE losses. Since we want to MAXIMIZE expected return, policy loss MUST have a minus sign: `loss = -(log_prob * G).sum()`. 2. Raw returns $G_t$ have high variance. Subtracting a baseline or standardizing returns `(G - G.mean()) / (G.std() + 1e-8)` stabilizes gradient variance and prevents training collapse!

Q1. What does a policy gradient learn?

The parameters of a policy that directly determines action probabilities.

Q2. What is REINFORCE?

A Monte-Carlo policy-gradient method using sampled returns to estimate the gradient.

Q3. Why do we use log probability?

The log-derivative form gives a practical likelihood-ratio/score-function gradient estimator.

Q4. Why is there a negative sign in the loss?

Deep-learning optimizers minimize losses, while policy-gradient objectives are naturally written as maximization of expected return.

Q5. Why sample actions?

A stochastic policy supports exploration and defines a probability distribution over actions.

Q6. What is a baseline?

A quantity subtracted from returns to reduce variance of the policy-gradient estimator under suitable conditions.

Q7. What is advantage?

A relative learning signal often written as:

\[ A(s,a)=Q(s,a)-V(s). \]

In Monte-Carlo settings an estimate such as \(G_t-V(s_t)\) may be used.

Q8. How does Q-learning differ from REINFORCE?

Q-learning learns action values; REINFORCE directly optimizes policy parameters.

Q9. Why can REINFORCE be noisy?

Its gradient estimate depends on sampled trajectories and returns.

Q10. What is the actor-critic idea?

Use one model to represent the policy and another to estimate value/advantage for a lower-variance learning signal.
