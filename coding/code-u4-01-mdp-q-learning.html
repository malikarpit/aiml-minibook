CODE-U4-01 — Markov Decision Processes and Q-Learning

Purpose: Turn reinforcement-learning theory into executable experiments by modelling an environment as a Markov Decision Process (MDP), implementing tabular Q-learning from scratch, adding exploration, and training an agent in a small grid-world and Gymnasium environment.

The central progression is:

state
  ↓
choose action
  ↓
environment
  ↓
reward + next state
  ↓
update Q-value
  ↓
repeat

Unlike supervised learning, the agent is not simply given a correct label for every state.

It learns from interaction and reward.

03

Reinforcement Learning Is an Interaction Problem

Supervised learning:

input → correct target
        ↓
      loss
        ↓
     update

Reinforcement learning:

state
 ↓
action
 ↓
environment
 ↓
reward + next state
 ↓
learning update

The agent must learn:

What should I do now if I want good long-term outcomes?

This is a sequential decision problem.

04

MDP Representation

A finite MDP can be represented by:

\[ \boxed{ (S,A,P,R,\gamma) } \]

where:

  • \(S\) = states;
  • \(A\) = actions;
  • \(P(s'|s,a)\) = transition probability;
  • \(R(s,a,s')\) = reward;
  • \(\gamma\) = discount factor.

The code will represent a small finite environment explicitly.

05

Markov Property

The Markov idea is:

The current state contains the information required to characterize the future transition/reward process, so the future depends on the past through the current state.

Formally, the transition structure is represented as:

\[ P(s_{t+1}|s_t,a_t). \]

This does not mean the whole history is irrelevant in every real problem.

It means that the chosen state representation is intended to contain the information needed for the decision process.

A poor state representation can make the environment appear non-Markov from the learner's perspective.

06

Returns

An immediate reward is not necessarily the final objective.

Define the discounted return from time \(t\):

\[ \boxed{ G_t= R_{t+1} +\gamma R_{t+2} +\gamma^2R_{t+3} +\cdots } \]

For a finite sequence:

rewards = [r1, r2, r3]

the return from the beginning is:

\[ G_0=r_1+\gamma r_2+\gamma^2r_3. \]
07

Discount Factor Intuition

\[ 0\le\gamma\lt 1 \]

is common in continuing/discounted formulations.

Interpretation:

γ near 0
→ focus strongly on immediate reward

γ near 1
→ future rewards matter much more

Hinglish:

Gamma decide karta hai ki future reward ko kitni importance deni hai.

Do not confuse:

γ = discount factor

with:

α = Q-learning learning rate

They have different jobs.

08

Worked Return Example

Suppose:

\[ r_1=5,\quad r_2=2,\quad r_3=10 \]

and:

\[ \gamma=0.5. \]

Then:

\[ G_0 = 5+0.5(2)+0.5^2(10) \]
\[ =5+1+2.5 \]
\[ =8.5. \]

The future rewards matter, but their influence is discounted.

09

Value vs Q-Value

State value:

\[ \boxed{ V^\pi(s)= \mathbb E_\pi[G_t\mid S_t=s] } \]

It evaluates a state under a policy.

Action value:

\[ \boxed{ Q^\pi(s,a)= \mathbb E_\pi[G_t\mid S_t=s,A_t=a] } \]

It evaluates a state-action pair.

For action selection:

\[ a^*=\arg\max_a Q(s,a) \]

is directly useful because it compares candidate actions within the current state.

10

Bellman Optimality Idea

The optimal Q-function satisfies:

\[ \boxed{ Q^*(s,a) = \mathbb E \left[ R_{t+1} + \gamma \max_{a'} Q^*(s',a') \mid s,a \right] } \]

Interpretation:

value of current action
=
immediate reward
+
discounted value of best next action

Q-learning turns this recursive relation into a sample-based update.

11

Q-Learning Update

The central equation is:

\[ \boxed{ Q(s,a) \leftarrow Q(s,a) + \alpha \left[ r+ \gamma\max_{a'}Q(s',a') - Q(s,a) \right] } \]

Define TD target:

\[ \boxed{ target= r+ \gamma\max_{a'}Q(s',a') } \]

and TD error:

\[ \boxed{ \delta= target-Q(s,a) } \]

Then:

\[ Q(s,a)\leftarrow Q(s,a)+\alpha\delta. \]

This is the single most important implementation equation in this chapter.

12

Why the Update Works

Suppose the current estimate says:

Q = 2

but the newly observed target is:

target = 8

Then:

\[ \delta=8-2=6. \]

With:

\[ \alpha=0.5 \]

the update is:

\[ Q_{new}=2+0.5(6)=5. \]

The estimate moves toward the target rather than jumping all the way to it.

13

Terminal-State Detail

Suppose a transition ends the episode.

Then there may be no future action value to add.

A common tabular implementation therefore uses:

\[ target=r \]

for a terminal transition.

For a non-terminal transition:

\[ target= r+ \gamma\max_{a'}Q(s',a'). \]

Code must therefore distinguish terminal transitions.

14

Build a Tiny Grid World

Use a small deterministic environment:

S . . .
. X . .
. . . .
. . . G

where:

S = start
G = goal
X = blocked cell

Actions:

0 = up
1 = right
2 = down
3 = left

The agent receives:

step reward = -0.01
goal reward = +1

A step cost gives the learner an incentive to reach the goal efficiently rather than wandering forever.

15

State Representation

A simple grid can map:

(row, col)

to a single state ID:

\[ state=row\times n_{cols}+col. \]

Example for a 4×4 grid:

(0,0) → 0
(0,1) → 1
...
(3,3) → 15

This lets us store Q-values in a matrix:

rows = states
columns = actions
16

Grid-World Environment

PYTHON
import numpy as np
PYTHON
class GridWorld:
    def __init__(self):
        self.rows = 4
        self.cols = 4

        self.start = (0, 0)
        self.goal = (3, 3)

        self.blocked = {
            (1, 1),
        }

        self.n_states = self.rows * self.cols
        self.n_actions = 4

        self.state = self.start

    def state_id(self, position):
        r, c = position
        return r * self.cols + c

    def reset(self):
        self.state = self.start
        return self.state_id(self.state)

    def step(self, action):
        r, c = self.state

        moves = {
            0: (-1, 0),  # up
            1: (0, 1),   # right
            2: (1, 0),   # down
            3: (0, -1),  # left
        }

        if action not in moves:
            raise ValueError("Invalid action.")

        dr, dc = moves[action]

        nr = r + dr
        nc = c + dc

        candidate = (nr, nc)

        if (
            nr < 0
            or nr >= self.rows
            or nc < 0
            or nc >= self.cols
            or candidate in self.blocked
        ):
            candidate = self.state

        self.state = candidate

        if self.state == self.goal:
            return (
                self.state_id(self.state),
                1.0,
                True,
            )

        return (
            self.state_id(self.state),
            -0.01,
            False,
        )

This environment is intentionally minimal.

Random Policy Baseline

Before learning, establish a baseline.

PYTHON
def run_random_episode(
    env,
    max_steps=100,
):
    state = env.reset()

    total_reward = 0.0

    for _ in range(max_steps):
        action = np.random.randint(
            env.n_actions
        )

        next_state, reward, done = env.step(
            action
        )

        total_reward += reward
        state = next_state

        if done:
            return total_reward, True

    return total_reward, False

20

Epsilon-Greedy Action Selection

Exploration/exploitation tension:

explore → try uncertain actions
exploit → choose the best current estimate

Epsilon-greedy:

\[ \boxed{ a= \begin{cases} \text{random action},&u\lt \epsilon\\ \arg\max_aQ(s,a),&u\ge\epsilon \end{cases} } \]

where:

\[ u\sim Uniform(0,1). \]

Implementation:

PYTHON
def epsilon_greedy_action(
    Q,
    state,
    epsilon,
    rng,
):
    if rng.random() < epsilon:
        return int(
            rng.integers(Q.shape[1])
        )

    return int(
        np.argmax(Q[state])
    )
21

Tie Handling

Initially all actions may have equal Q-values.

Plain:

PYTHON
np.argmax(Q[state])

always chooses the first maximum.

That introduces a deterministic tie bias.

A stronger educational implementation randomly selects among tied best actions:

PYTHON
def greedy_action_random_tie(
    Q,
    state,
    rng,
):
    values = Q[state]

    best = np.flatnonzero(
        values == np.max(values)
    )

    return int(
        rng.choice(best)
    )

Then use this inside the exploitation branch.

22

Q-Learning Training Loop

PYTHON
def train_q_learning(
    env,
    episodes=2000,
    alpha=0.8,
    gamma=0.95,
    epsilon=0.1,
    max_steps=100,
    seed=42,
):
    rng = np.random.default_rng(seed)

    Q = np.zeros(
        (env.n_states, env.n_actions),
        dtype=float,
    )

    episode_returns = []
    episode_lengths = []

    for _ in range(episodes):
        state = env.reset()

        total_reward = 0.0

        for step in range(max_steps):
            action = epsilon_greedy_action(
                Q,
                state,
                epsilon,
                rng,
            )

            next_state, reward, done = env.step(
                action
            )

            if done:
                target = reward
            else:
                target = (
                    reward
                    + gamma
                    * np.max(Q[next_state])
                )

            td_error = (
                target
                - Q[state, action]
            )

            Q[state, action] += (
                alpha * td_error
            )

            total_reward += reward
            state = next_state

            if done:
                break

        episode_returns.append(
            total_reward
        )
        episode_lengths.append(
            step + 1
        )

    return (
        Q,
        np.array(episode_returns),
        np.array(episode_lengths),
    )

Greedy Evaluation

Training should use exploration.

Evaluation should normally turn exploration off.

PYTHON
def evaluate_q_policy(
    env,
    Q,
    episodes=100,
    max_steps=100,
):
    successes = 0
    returns = []

    for _ in range(episodes):
        state = env.reset()
        total_reward = 0.0

        for _ in range(max_steps):
            action = int(
                np.argmax(Q[state])
            )

            next_state, reward, done = env.step(
                action
            )

            total_reward += reward
            state = next_state

            if done:
                successes += 1
                break

        returns.append(total_reward)

    return (
        successes / episodes,
        np.array(returns),
    )

Evaluate:

PYTHON
success_rate, eval_returns = (
    evaluate_q_policy(
        env,
        Q,
    )

PYTHON
def moving_average(
    values,
    window=100,
):
    values = np.asarray(values)

    if len(values) < window:
        return values

    return np.convolve(
        values,
        np.ones(window) / window,
        mode="valid",
    )

Epsilon Decay

Fixed epsilon is simple.

A common experiment is decay:

PYTHON
epsilon_start = 1.0
epsilon_end = 0.05
decay_rate = 0.995

Update:

PYTHON
epsilon = max(
    epsilon_end,
    epsilon * decay_rate,
)

Interpretation:

early training
→ explore more

later training
→ exploit learned knowledge more often

Do not assume one decay schedule is universally optimal.

33

Q-Learning Numerical

Suppose:

\[ Q(s,a)=2 \]
\[ r=4 \]
\[ \gamma=0.9 \]

and:

\[ \max_{a'}Q(s',a')=10. \]

Then:

\[ target=4+0.9(10)=13. \]

TD error:

\[ \delta=13-2=11. \]

With:

\[ \alpha=0.5 \]

new Q-value:

\[ Q_{new}=2+0.5(11)=7.5. \]

This should be an automatic exam calculation.

34

Terminal Numerical

Suppose:

\[ Q(s,a)=3 \]

and the transition reaches the goal with:

\[ r=1. \]

Because the episode terminates:

\[ target=1. \]

If:

\[ \alpha=0.2 \]

then:

\[ Q_{new} = 3+0.2(1-3) \]
\[ =3-0.4 \]
\[ =2.6. \]

The update moves the estimate toward the terminal reward.

Q-Learning vs Dynamic Programming

Dynamic programming methods use a known transition/reward model.

Q-learning instead learns from sampled experience.

Conceptually:

Known model
→ reason directly about transitions

Unknown model
→ interact with environment
→ sample experience
→ update Q

Q-learning is therefore a model-free value-learning method.

42

Off-Policy Intuition

Q-learning updates toward:

\[ \max_{a'}Q(s',a'). \]

The behaviour policy may be epsilon-greedy, while the target of the update is based on the greedy best-next-action estimate.

This is the key idea behind its off-policy character.

For the syllabus, remember:

The agent can explore using one behaviour rule while learning the value associated with a greedy target.

43

Why Q-Learning Does Not Need the Transition Table

The update uses an observed sample:

\[ (s,a,r,s'). \]

It does not require you to explicitly provide:

\[ P(s'|s,a). \]

The environment generates the next state.

The agent learns from experience.

Common Implementation Errors

Error 1 — Bootstrapping from terminal states

Do not add a future-state value after a true terminal transition.

Error 2 — Confusing terminated and truncated

Current Gymnasium APIs distinguish them.

Error 3 — Evaluating while exploring

Evaluation with random actions can underestimate the learned greedy policy.

Error 4 — Wrong action dimension

Q-table columns must equal the number of available actions.

Error 5 — Using the wrong state encoding

The Q-table row must correspond consistently to the environment's state.

Error 6 — Confusing \(\alpha\) and \(\gamma\)

α → learning/update step
γ → future-reward discount

Error 7 — No exploration

A purely greedy agent can lock into poor choices before it has useful estimates.

Why Evaluation Must Be Separate

Suppose training uses:

\[ \epsilon=0.1. \]

Then 10% of actions may be exploratory.

A measured training success rate mixes:

learned behaviour
+
intentional random exploration

Evaluation can instead use:

epsilon = 0

so that the measured behaviour reflects the learned greedy policy more directly.

Viva Questions

⚠️ University Lab Viva Trap & Runtime Gotcha
**Q-Learning Off-Policy vs SARSA On-Policy Trap:** Q-Learning uses $\max_{a'} Q(s', a')$ for the TD target (the best possible action regardless of what the agent actually does), making it OFF-POLICY. SARSA uses $Q(s', a')$ where $a'$ is the action actually sampled by $\epsilon$-greedy, making it ON-POLICY. In viva, using the chosen action $a'$ in Q-Learning's update is the classic failure trap!

Q1. What is an MDP?

A formal framework for sequential decision-making defined by states, actions, transition dynamics, rewards and a discount factor.

Q2. What is the Markov property?

The chosen current state contains the information needed to characterize future dynamics given the current action.

Q3. What is Q-learning?

A model-free, value-based reinforcement-learning algorithm that learns action-value estimates through sampled transitions.

Q4. Write the Q-learning update.

\[ Q(s,a) \leftarrow Q(s,a) + \alpha [ r+\gamma\max_{a'}Q(s',a') -Q(s,a) ]. \]

Q5. What is TD error?

The difference between the learning target and the current estimate.

Q6. Why use epsilon-greedy?

To balance exploration and exploitation.

Q7. What is \(\gamma\)?

Discount factor controlling the relative importance of future rewards.

Q8. What is \(\alpha\)?

Learning rate controlling the size of the Q-value update.

Q9. Why is Q-learning called model-free?

It can learn from experienced transitions without requiring an explicit transition model.

Q10. Why should terminal states be treated specially?

There is no future action value after the episode truly terminates.
