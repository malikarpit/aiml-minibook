CODE-U4-03 — NLP Preprocessing and Text Classification Pipeline

Purpose: Build an end-to-end text-classification pipeline, beginning with raw language and moving through tokenization, normalization, stemming/lemmatization, vector representation, TF-IDF and supervised classification.

The central pipeline is:

RAW TEXT
   ↓
TOKENIZATION
   ↓
NORMALIZATION
   ↓
OPTIONAL STEMMING / LEMMATIZATION
   ↓
NUMERICAL REPRESENTATION
   ↓
CLASSIFIER
   ↓
PREDICTION
   ↓
EVALUATION

The important engineering lesson is:

A text classifier is not just a classifier. It is a complete representation + learning + evaluation pipeline.

Start With the Task

Classify a message as spam or not spam.

Data:

message                                label
------------------------------------------------
"Win a free phone today!"              spam
"Meeting moved to 4 PM."               ham
"Claim your prize now."                spam

This is a supervised learning problem.

Formally:

\[ D= \{(x_i,y_i)\}_{i=1}^{n} \]

where:

  • \(x_i\) = text document;
  • \(y_i\) = class label.
04

Why Raw Text Cannot Be Passed Directly to a Classical Classifier

A classical ML classifier expects numerical features.

The string:

"machine learning is useful"

must become some numerical representation such as:

[1, 1, 1, 1, ...]

or:

[0.18, 0.74, ...]

or an embedding vector.

Therefore:

\[ \boxed{ \text{text} \rightarrow \text{representation} \rightarrow \text{classifier} } \]

This representation step is one of the most important parts of NLP engineering.

Why `.split()` Is Not a Complete NLP Tokenizer

Consider:

"Hello, world!"

Simple splitting gives:

["Hello,", "world!"]

Punctuation is attached to words.

Consider:

"can't"

A simplistic tokenizer may not represent the linguistic units you actually need.

Real tokenization can involve:

word tokens
subword tokens
character tokens
special tokens
punctuation handling

For this course coding layer, start with a simple tokenizer so the mechanics remain visible.

Lowercasing

A common normalization:

PYTHON
def normalize_lowercase(text):
    return text.lower()

Example:

"Machine Learning"

becomes:

"machine learning"

Why?

It can reduce duplicate vocabulary entries:

Machine
machine
MACHINE

However, lowercasing is not always correct.

Case can carry information in some applications:

US
vs
us

So:

Preprocessing must be task-aware.

09

Basic Punctuation Normalization

A simple demonstration:

PYTHON
import re

def normalize_text(text):
    text = text.lower()

    text = re.sub(
        r"[^a-z0-9\s]",
        " ",
        text,
    )

    text = re.sub(
        r"\s+",
        " ",
        text,
    )

    return text.strip()

Test:

PYTHON
print(
    normalize_text(
        "Hello, WORLD!! NLP."
    )
)

Possible result:

hello world nlp

Do not automatically remove punctuation in every NLP application.

For sentiment, social media, code, legal text or stylistic analysis, punctuation may contain useful information.

10

Stopwords — Use With Caution

Stopwords are common words such as:

the
is
of
and

Removing them can reduce vocabulary size.

But blindly removing them can damage meaning.

Example:

"This is not good."

If preprocessing accidentally removes:

not

the semantic meaning can be severely changed.

Therefore:

Never use stopword removal as a reflex. Validate whether it helps the task.

11

Stemming

Stemming uses a heuristic procedure to reduce related word forms.

Example:

connected
connecting
connection

may be reduced to stem-like forms depending on the algorithm.

The result may not be a valid dictionary word.

This is acceptable in some information-retrieval/classification settings because the goal is often feature normalization rather than linguistic elegance.

12

Stemming With NLTK

PYTHON
from nltk.stem import PorterStemmer

stemmer = PorterStemmer()

words = [
    "connect",
    "connected",
    "connecting",
    "connection",
]

stems = [
    stemmer.stem(word)
    for word in words
]

print(stems)

The exact outputs depend on the stemmer.

The important concept is:

surface forms
   ↓
heuristic reduction
   ↓
stem
13

Lemmatization

Lemmatization aims to map a word to a linguistically meaningful base form, taking more linguistic information into account.

Conceptually:

running
   ↓
run
better
   ↓
good

depending on the linguistic resources and settings.

The result is generally intended to be a valid lexical form.

14

Stemming vs Lemmatization

Property Stemming Lemmatization
reduction method heuristic linguistic/base-form analysis
output may not be a real word generally lexical base form
complexity usually lower usually higher
linguistic awareness limited greater
coding goal feature reduction linguistic normalization

Exam memory:

Stemming cuts heuristically; lemmatization reasons toward a meaningful lemma.

A Small Preprocessing Function

Keep preprocessing modular.

PYTHON
def preprocess(
    text,
    lowercase=True,
    remove_punctuation=True,
):
    if lowercase:
        text = text.lower()

    if remove_punctuation:
        text = re.sub(
            r"[^a-z0-9\s]",
            " ",
            text,
        )

    text = re.sub(
        r"\s+",
        " ",
        text,
    )

    return text.strip()

Test:

PYTHON
for text in texts:
    print(preprocess(text))

This makes the transformation visible before vectorization.

17

Bag of Words

Bag of Words ignores most word order and counts token occurrences.

Vocabulary:

\[ V=[cat,dog,fish] \]

Document:

cat dog cat

vector:

\[ \boxed{ [2,1,0] } \]

This is a count representation.

18

Build Bag-of-Words From Scratch

PYTHON
from collections import Counter
PYTHON
def build_vocabulary(
    documents,
):
    vocab = {}

    for document in documents:
        for token in document:
            if token not in vocab:
                vocab[token] = len(vocab)

    return vocab

Convert token lists:

PYTHON
tokenized = [
    simple_tokenize(
        preprocess(text)
    )
    for text in texts
]

Build:

PYTHON
vocab = build_vocabulary(
    tokenized
)

print(vocab)
19

Vectorize One Document

PYTHON
def bow_vector(
    tokens,
    vocabulary,
):
    vector = np.zeros(
        len(vocabulary),
        dtype=float,
    )

    for token in tokens:
        if token in vocabulary:
            vector[
                vocabulary[token]
            ] += 1

    return vector

Build matrix:

PYTHON
import numpy as np

X_bow = np.vstack([
    bow_vector(
        tokens,
        vocab,
    )
    for tokens in tokenized
])

print(X_bow.shape)

Now the text is numerical.

20

Bag-of-Words Limitation

Compare:

dog bites man

and:

man bites dog

A pure unigram count representation can be identical.

Therefore:

same counts
≠
same meaning

This is why n-grams and learned sequence representations are useful.

21

N-Grams

A bigram contains two consecutive tokens.

Example:

"machine learning is useful"

bigrams:

machine learning
learning is
is useful

Python:

PYTHON
def make_ngrams(
    tokens,
    n,
):
    return [
        tuple(tokens[i:i+n])
        for i in range(
            len(tokens) - n + 1
        )
    ]

For bigrams:

PYTHON
print(
    make_ngrams(
        [
            "machine",
            "learning",
            "is",
            "useful",
        ],
        2,
    )
)
22

TF-IDF

TF-IDF combines:

TF

how common a term is within a document

with:

IDF

how discriminative that term is across the collection.

A basic formulation:

\[ \boxed{ TFIDF(t,d) = TF(t,d)\times IDF(t) } \]

and commonly:

\[ \boxed{ IDF(t)= \log\frac{N}{df(t)} } \]

where:

  • \(N\) = number of documents;
  • \(df(t)\) = number of documents containing term \(t\).

Different implementations can use smoothed or normalized variants.

Always state the convention being used.

23

TF-IDF Numerical

Suppose:

\[ N=100 \]

documents exist.

A term occurs in:

\[ df=10 \]

documents.

Then using natural logarithm:

\[ IDF = \log\frac{100}{10} = \log(10) \]
\[ \approx2.303. \]

If:

\[ TF=0.2 \]

then:

\[ TFIDF = 0.2(2.303) \]
\[ \approx0.461. \]

PYTHON

The matrix is usually sparse.

That is important because text vocabularies can be large while each individual document contains only a small fraction of all possible terms.

25

Why Sparse Matrices Matter

Suppose:

50,000 vocabulary terms

A document may contain only:

100 terms

A dense vector stores all 50,000 positions.

A sparse representation stores mainly the nonzero entries.

This is computationally important for classical NLP.

26

Train/Test Split Before Fitting the Vocabulary

This is a critical leakage rule.

Bad:

PYTHON
vectorizer.fit_transform(
    all_texts
)

then split into train/test.

The vocabulary and IDF statistics have now been learned from the test data.

Correct:

split
 ↓
fit vectorizer on training text
 ↓
transform training text
 ↓
transform test text using same fitted vectorizer
27

sklearn Pipeline Prevents This Error

Use:

PYTHON
from sklearn.model_selection import train_test_split
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

Example:

PYTHON
X_train, X_test, y_train, y_test = (
    train_test_split(
        texts,
        y,
        test_size=0.25,
        stratify=y,
        random_state=42,
    )
)

Pipeline:

PYTHON
text_model = Pipeline([
    (
        "tfidf",
        TfidfVectorizer(
            lowercase=True,
            ngram_range=(1, 2),
        ),
    ),
    (
        "classifier",
        LogisticRegression(
            max_iter=1000,
        ),
    ),
])

Train:

PYTHON
text_model.fit(
    X_train,
    y_train,
)

Evaluate:

PYTHON
predictions = text_model.predict(
    X_test
)

The vectorizer is fitted within the training process.

32

Why Linear Models Often Fit Sparse Text Features Naturally

TF-IDF produces a high-dimensional sparse vector.

A linear classifier can assign one weight per vocabulary feature:

\[ z=w^Tx+b. \]

Conceptually:

word / n-gram
   ↓
feature value
   ↓
weight
   ↓
contribution to class score

This is one reason linear models are such a useful classical NLP baseline.

A large coefficient is an association within the trained model, not proof that the term causes the class.

34

Text Classification Error Analysis

Find wrong predictions:

PYTHON
for text, true, pred in zip(
    X_test,
    y_test,
    predictions,
):
    if true != pred:
        print(
            "TEXT:",
            text,
        )
        print(
            "TRUE:",
            true,
            "PRED:",
            pred,
        )

Ask:

  • Is the text ambiguous?
  • Is the vocabulary unseen?
  • Is the label noisy?
  • Is the example unusually short?
  • Did preprocessing remove a crucial word?
  • Does the error involve negation?

This is more informative than simply printing F1.

35

Unknown Vocabulary

At test time, new words may appear that were absent from training.

A fitted TF-IDF vectorizer handles unknown vocabulary terms by not giving them learned feature positions.

This is expected.

The important rule is:

Never refit the vectorizer on the test set just to include its words.

Doing so changes the feature space using test information.

36

Negation Experiment

Compare:

good

with:

not good

Pure unigram features may represent:

not
good

but a simple classifier may not fully encode the phrase relation.

Common NLP Coding Mistakes

⚠️ University Lab Viva Trap & Runtime Gotcha
**Laplace Add-1 Smoothing in Naive Bayes:** If a word in the test document never appeared in class $c$ in the training data, its conditional probability $P(w|c) = 0$. Since probabilities are multiplied: $P(c) \prod P(w_i|c)$, a single zero wipes out the entire score to 0! Always add Laplace smoothing $\frac{count + 1}{\sum count + V}$ to ensure zero probability trap never happens!

Mistake 1 — Treating tokenization as “just splitting”

Tokenization is a representation decision.

Mistake 2 — Removing all punctuation automatically

Some punctuation can carry meaning.

Mistake 3 — Removing stopwords blindly

Words such as “not” can matter substantially.

Mistake 4 — Fitting TF-IDF before the split

This leaks test information.

Mistake 5 — Using only accuracy

Classification errors may be asymmetric.

Mistake 6 — Assuming stemming is always better

The downstream task decides.

Mistake 7 — Dense conversion of huge sparse matrices

This can consume large amounts of memory.

Viva Questions

Q1. What is NLP?

The field concerned with computational processing of human language.

Q2. What is tokenization?

Breaking text into chosen computational units such as words, subwords or characters.

Q3. What is stemming?

Heuristic reduction of word forms toward a common stem.

Q4. What is lemmatization?

Mapping word forms toward linguistically meaningful base forms.

Q5. What is Bag of Words?

A representation based primarily on token occurrence/counts while largely ignoring order.

Q6. What is TF-IDF?

A weighting scheme combining term frequency with inverse document frequency.

Q7. Why is IDF useful?

It downweights terms occurring in many documents and increases the relative importance of terms that are more document-specific.

Q8. Why use n-grams?

To capture local token-order information absent from simple unigram bag-of-words.

Q9. Why must TF-IDF be fitted only on training data?

Because vocabulary and IDF statistics learned from test data would leak information into the training pipeline.

Q10. Why is sparse representation useful?

Text-feature matrices can have very high dimensionality with most entries zero.
