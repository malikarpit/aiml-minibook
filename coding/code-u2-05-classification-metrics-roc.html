00

Why This Lab Exists

A classification model usually does more than return a final class label.

It can produce a score such as:

email A → 0.93 spam score
email B → 0.18 spam score
email C → 0.61 spam score

The coding problem is therefore not only:

"Did the model predict correctly?"

It is also:

score
  ↓
threshold
  ↓
predicted label
  ↓
compare with truth
  ↓
TP / FP / FN / TN
  ↓
metrics

A good implementation must preserve this separation. Otherwise it is easy to mix up model scores, labels, thresholds, and metrics.

02

Learning Representation

2.1 Ground truth

For binary classification use:

PYTHON
y_true = np.array([0, 0, 1, 1, 0, 1])

where, by convention for this chapter:

0 = Negative
1 = Positive

Do not silently reverse this meaning later.

2.2 Predicted labels

PYTHON
y_pred = np.array([0, 1, 1, 1, 0, 0])

These are already discrete decisions.

2.3 Continuous scores

A classifier can instead produce:

PYTHON
scores = np.array([0.20, 0.72, 0.93, 0.61, 0.14, 0.45])

A threshold converts them into labels:

PYTHON
y_pred = (scores >= threshold).astype(int)

For example:

PYTHON
threshold = 0.50

means scores at least 0.50 become positive.

Critical distinction

score ≠ label
threshold ≠ model
metric ≠ threshold

ROC analysis is particularly useful because it studies what happens as the threshold changes.

03

Confusion Matrix From Scratch

The binary confusion matrix records four mutually exclusive outcomes.

Actual Predicted Result
1 1 TP
0 1 FP
1 0 FN
0 0 TN

A simple implementation is often clearer than trying to remember a library-specific matrix orientation.

PYTHON
import numpy as np


def confusion_counts(y_true, y_pred):
    y_true = np.asarray(y_true).astype(int)
    y_pred = np.asarray(y_pred).astype(int)

    if y_true.shape != y_pred.shape:
        raise ValueError("y_true and y_pred must have the same shape")

    if not np.all(np.isin(y_true, [0, 1])):
        raise ValueError("y_true must contain only 0 and 1")

    if not np.all(np.isin(y_pred, [0, 1])):
        raise ValueError("y_pred must contain only 0 and 1")

    tp = np.sum((y_true == 1) & (y_pred == 1))
    fp = np.sum((y_true == 0) & (y_pred == 1))
    fn = np.sum((y_true == 1) & (y_pred == 0))
    tn = np.sum((y_true == 0) & (y_pred == 0))

    return int(tp), int(fp), int(fn), int(tn)

3.1 Line-by-line logic

np.asarray(...)

This lets the function accept lists or NumPy arrays.

Shape check

Metrics compare one prediction to one truth value.

PYTHON
y_true.shape == y_pred.shape

must therefore hold.

Boolean masks

For TP:

PYTHON
(y_true == 1) & (y_pred == 1)

means both conditions are true.

Summing a Boolean array counts the number of True values.

Take:

PYTHON
y_true = [1, 0, 1, 0, 1]
y_pred = [1, 1, 0, 0, 1]

Trace row by row:

i Actual Predicted Outcome
0 1 1 TP
1 0 1 FP
2 1 0 FN
3 0 0 TN
4 1 1 TP

Therefore:

TP = 2
FP = 1
FN = 1
TN = 1

Before coding any metric, manually reconstructing these four numbers is an excellent debugging technique.

05

Metric Functions From Scratch

5.1 Accuracy

PYTHON
def accuracy_from_counts(tp, fp, fn, tn):
    total = tp + fp + fn + tn
    return (tp + tn) / total if total else 0.0

Formula:

\[ Accuracy = \frac{TP+TN}{TP+FP+FN+TN} \]

Use accuracy when the overall fraction of correct predictions is actually the question you care about.

5.2 Precision

PYTHON
def precision_from_counts(tp, fp):
    denom = tp + fp
    return tp / denom if denom else 0.0
\[ Precision = \frac{TP}{TP+FP} \]

Coding interpretation:

Among everything predicted positive, how much was actually positive?

5.3 Recall / TPR

PYTHON
def recall_from_counts(tp, fn):
    denom = tp + fn
    return tp / denom if denom else 0.0
\[ Recall = TPR = \frac{TP}{TP+FN} \]

Coding interpretation:

Among actual positives, how many did the classifier find?

5.4 Specificity

PYTHON
def specificity_from_counts(tn, fp):
    denom = tn + fp
    return tn / denom if denom else 0.0
\[ Specificity = \frac{TN}{TN+FP} \]

5.5 False Positive Rate

PYTHON
def fpr_from_counts(tn, fp):
    denom = fp + tn
    return fp / denom if denom else 0.0
\[ FPR = \frac{FP}{FP+TN} \]

and:

\[ FPR = 1-Specificity \]

5.6 F1 score

PYTHON
def f1_from_counts(tp, fp, fn):
    p = precision_from_counts(tp, fp)
    r = recall_from_counts(tp, fn)
    denom = p + r
    return 2 * p * r / denom if denom else 0.0

Equivalent count form:

\[ F_1 = \frac{2TP}{2TP+FP+FN} \]

The harmonic mean is deliberately used, so a very low precision or recall pulls F1 downward.

06

One Combined Metric Function

For experiments, avoid scattering calculations across a notebook.

PYTHON
def binary_metrics(y_true, y_pred):
    tp, fp, fn, tn = confusion_counts(y_true, y_pred)

    return {
        "TP": tp,
        "FP": fp,
        "FN": fn,
        "TN": tn,
        "accuracy": accuracy_from_counts(tp, fp, fn, tn),
        "precision": precision_from_counts(tp, fp),
        "recall": recall_from_counts(tp, fn),
        "specificity": specificity_from_counts(tn, fp),
        "fpr": fpr_from_counts(tn, fp),
        "f1": f1_from_counts(tp, fp, fn),
    }

This gives you a small reusable evaluation core.

07

Numerical Example

Suppose:

TP = 60
FP = 20
FN = 10
TN = 110

Then:

\[ Accuracy = \frac{60+110}{200}=0.85 \]
\[ Precision = \frac{60}{80}=0.75 \]
\[ Recall = \frac{60}{70}\approx0.8571 \]
\[ Specificity = \frac{110}{130}\approx0.8462 \]
\[ FPR = \frac{20}{130}\approx0.1538 \]
\[ F_1 = \frac{2(60)}{120+20+10}=\frac{120}{150}=0.80 \]

These values are excellent unit tests for your functions.

Unit Tests You Should Actually Write

Do not trust a metric implementation because it “looks right”.

PYTHON
m = binary_metrics(
    np.array([1, 0, 1, 0, 1]),
    np.array([1, 1, 0, 0, 1])
)

assert m["TP"] == 2
assert m["FP"] == 1
assert m["FN"] == 1
assert m["TN"] == 1

Known formulas:

PYTHON
assert np.isclose(m["accuracy"], 3 / 5)
assert np.isclose(m["precision"], 2 / 3)
assert np.isclose(m["recall"], 2 / 3)
assert np.isclose(m["specificity"], 1 / 2)
assert np.isclose(m["fpr"], 1 / 2)
assert np.isclose(m["f1"], 2 / 3)

Edge-case tests

Test at least:

  1. all predictions negative;
  2. all predictions positive;
  3. no actual positives;
  4. no actual negatives;
  5. perfect predictions;
  6. completely wrong predictions.

Your convention for undefined ratios must be explicit. Returning 0.0 is acceptable for this educational implementation, but you should know that production libraries may expose a configurable zero_division policy.

09

Thresholding Scores

Write thresholding as its own function.

PYTHON
def scores_to_labels(scores, threshold=0.5):
    scores = np.asarray(scores, dtype=float)

    if not 0.0 <= threshold <= 1.0:
        raise ValueError("threshold must be between 0 and 1")

    return (scores >= threshold).astype(int)

The function makes an important architectural boundary explicit:

model score
    ↓
scores_to_labels()
    ↓
y_pred
    ↓
binary_metrics()

11

Building ROC Points From Scratch

For ROC we need:

\[ TPR = Recall = \frac{TP}{TP+FN} \]

and:

\[ FPR = \frac{FP}{FP+TN} \]

At each threshold, compute both.

PYTHON
def roc_points_from_scratch(y_true, scores):
    y_true = np.asarray(y_true).astype(int)
    scores = np.asarray(scores, dtype=float)

    if y_true.shape != scores.shape:
        raise ValueError("y_true and scores must have the same shape")

    thresholds = np.r_[np.inf, np.sort(np.unique(scores))[::-1], -np.inf]

    points = []

    for threshold in thresholds:
        y_pred = (scores >= threshold).astype(int)
        tp, fp, fn, tn = confusion_counts(y_true, y_pred)
        tpr = recall_from_counts(tp, fn)
        fpr = fpr_from_counts(tn, fp)

        points.append((fpr, tpr, threshold))

    return np.array(points, dtype=float)

The key idea is more important than the exact implementation detail:

threshold 1 → confusion matrix → TPR/FPR
threshold 2 → confusion matrix → TPR/FPR
threshold 3 → confusion matrix → TPR/FPR
...
12

A More Efficient Threshold Sweep

The previous implementation is educational because it makes the logic obvious.

For small course datasets this is fine.

For larger datasets you can sort scores once and update counts incrementally.

A conceptual efficient strategy:

1. sort samples by decreasing score
2. begin with every sample predicted negative
3. moving one threshold downward flips one sample to positive
4. update TP/FP in O(1)
5. record TPR/FPR

This reduces repeated full-array scans.

Do not optimize before the simple implementation is correct.

13

AUC From Scratch With the Trapezoidal Rule

⚠️ University Lab Viva Trap & Runtime Gotcha
**Confusion Matrix Axis Orientation & Accuracy Paradox:** 1. Scikit-learn orientation is `y_true` as ROWS and `y_pred` as COLUMNS: `[[TN, FP], [FN, TP]]`. Swapping rows and columns reverses Precision and Recall! 2. Accuracy Paradox: On an imbalanced dataset with 99 negative and 1 positive, a dumb model predicting 0 always gets 99% accuracy! Never evaluate an imbalanced model on Accuracy alone—always report Precision, Recall, and F1!

Given ordered ROC points:

\[ (x_i,y_i)=(FPR_i,TPR_i) \]

approximate area by:

\[ AUC \approx \sum_i (x_{i+1}-x_i)\frac{y_i+y_{i+1}}{2} \]

Implementation:

PYTHON
def trapezoid_auc(fpr, tpr):
    fpr = np.asarray(fpr, dtype=float)
    tpr = np.asarray(tpr, dtype=float)

    if fpr.shape != tpr.shape:
        raise ValueError("fpr and tpr must have the same shape")

    order = np.argsort(fpr)
    fpr = fpr[order]
    tpr = tpr[order]

    return float(np.trapz(tpr, fpr))

Important implementation note

You are learning the algorithmic idea here. The exact numerical routine available in a particular NumPy version can change over time, so for production code prefer a currently supported integration API or the metric implementation provided by your chosen ML library.

For a small educational lab, you can also implement the summation manually:

PYTHON
def trapezoid_auc_manual(fpr, tpr):
    order = np.argsort(fpr)
    x = np.asarray(fpr)[order]
    y = np.asarray(tpr)[order]

    area = 0.0
    for i in range(len(x) - 1):
        width = x[i + 1] - x[i]
        height = (y[i] + y[i + 1]) / 2.0
        area += width * height

    return float(area)

This version is ideal for a first-principles coding submission.

Confusion Matrix Visualization

For a small educational implementation, a simple text representation is often enough:

PYTHON
def print_confusion_table(tp, fp, fn, tn):
    print("                 Predicted")
    print("                0       1")
    print(f"Actual 0      {tn:4d}    {fp:4d}")
    print(f"       1      {fn:4d}    {tp:4d}")

This removes ambiguity caused by different library matrix conventions.

With scikit-learn, you can inspect the actual matrix before using any downstream metric:

PYTHON
from sklearn.metrics import confusion_matrix

cm = confusion_matrix(y_true, y_pred)
print(cm)

Default binary layout is:

[[TN, FP],
 [FN, TP]]

Always verify the orientation rather than relying on memory.

Class Imbalance Experiment

Create a deliberately imbalanced dataset:

19

Decision Rules and Application Context

Do not write:

“F1 is always better than accuracy.”

Instead ask:

What is the task?
What counts as positive?
What is the cost of FP?
What is the cost of FN?
Is the class distribution imbalanced?
Do I need a thresholded decision or ranking quality?

Examples:

Task Potential emphasis
spam filtering precision / recall trade-off
safety screening recall may be critical
rare-event retrieval precision-recall behaviour matters
balanced educational classification accuracy may be informative
score-ranking model ROC-AUC can summarize ranking discrimination

These are examples, not universal prescriptions.

20

Common Coding Bugs

Bug 1 — swapping FP and FN

Symptom:

precision looks like recall

Fix:

Return to the question:

  • FP = predicted positive, actually negative.
  • FN = predicted negative, actually positive.

Bug 2 — using labels for AUC

Wrong:

PYTHON
roc_auc_score(y_true, y_pred)

That discards score information.

AUC normally evaluates continuous decision scores/probability-like outputs:

PYTHON
roc_auc_score(y_true, scores)

Bug 3 — inconsistent positive class

If you encode positive as 1 in training but interpret 0 as positive during evaluation, every metric interpretation breaks.

Bug 4 — threshold hidden inside evaluation code

A metric function should not secretly select a threshold. Keep thresholding separate.

Bug 5 — dividing by zero

A dataset can contain no predicted positives or no actual positives. Decide what your implementation does.

Bug 6 — trusting a plot without checking arrays

Print or inspect the first few (threshold, FPR, TPR) values before interpreting the ROC curve.

22

ROC Sanity Checks

A correct ROC construction should exhibit the familiar endpoints in the threshold sweep, subject to the exact score/tie-handling implementation:

very strict threshold → almost nothing predicted positive
very permissive threshold → almost everything predicted positive

You should be able to recover the conceptual endpoints:

(0, 0)
...
(1, 1)

Check that:

  • FPR is between 0 and 1;
  • TPR is between 0 and 1;
  • thresholds correspond to changing score cutoffs;
  • the plotted x-axis is FPR;
  • the plotted y-axis is TPR.
23

Manual AUC Example

Suppose your ROC points are:

\[ (0,0),\;(0,0.5),\;(0.25,0.75),\;(1,1) \]

Trapezoid 1:

\[ (0-0)\frac{0+0.5}{2}=0 \]

Trapezoid 2:

\[ (0.25-0)\frac{0.5+0.75}{2}=0.15625 \]

Trapezoid 3:

\[ (1-0.25)\frac{0.75+1}{2}=0.65625 \]

Therefore:

\[ AUC=0.8125 \]

This is a good numerical test for your AUC implementation.

Master Implementation Skeleton

PYTHON
import numpy as np


def confusion_counts(y_true, y_pred):
    y_true = np.asarray(y_true).astype(int)
    y_pred = np.asarray(y_pred).astype(int)

    if y_true.shape != y_pred.shape:
        raise ValueError("shape mismatch")

    tp = np.sum((y_true == 1) & (y_pred == 1))
    fp = np.sum((y_true == 0) & (y_pred == 1))
    fn = np.sum((y_true == 1) & (y_pred == 0))
    tn = np.sum((y_true == 0) & (y_pred == 0))
    return int(tp), int(fp), int(fn), int(tn)


def safe_divide(a, b):
    return a / b if b != 0 else 0.0


def binary_metrics(y_true, y_pred):
    tp, fp, fn, tn = confusion_counts(y_true, y_pred)

    precision = safe_divide(tp, tp + fp)
    recall = safe_divide(tp, tp + fn)
    specificity = safe_divide(tn, tn + fp)
    fpr = safe_divide(fp, fp + tn)
    accuracy = safe_divide(tp + tn, tp + fp + fn + tn)
    f1 = safe_divide(2 * precision * recall, precision + recall)

    return {
        "TP": tp,
        "FP": fp,
        "FN": fn,
        "TN": tn,
        "accuracy": accuracy,
        "precision": precision,
        "recall": recall,
        "specificity": specificity,
        "fpr": fpr,
        "f1": f1,
    }


def scores_to_labels(scores, threshold=0.5):
    scores = np.asarray(scores, dtype=float)
    return (scores >= threshold).astype(int)


def roc_points_from_scratch(y_true, scores):
    y_true = np.asarray(y_true).astype(int)
    scores = np.asarray(scores, dtype=float)
    thresholds = np.r_[np.inf, np.sort(np.unique(scores))[::-1], -np.inf]

    points = []
    for t in thresholds:
        pred = (scores >= t).astype(int)
        tp, fp, fn, tn = confusion_counts(y_true, pred)
        tpr = safe_divide(tp, tp + fn)
        fpr = safe_divide(fp, fp + tn)
        points.append((fpr, tpr, t))

    return np.array(points, dtype=float)


def trapezoid_auc(fpr, tpr):
    order = np.argsort(fpr)
    x = np.asarray(fpr)[order]
    y = np.asarray(tpr)[order]

    area = 0.0
    for i in range(len(x) - 1):
        area += (x[i + 1] - x[i]) * (y[i] + y[i + 1]) / 2.0
    return area

This is the conceptual implementation you should understand before relying on a library.

Complexity and Practical Behaviour

For n examples:

  • basic confusion counts: O(n) time, O(1) auxiliary counting space beyond input arrays;
  • one threshold evaluation: O(n);
  • naive ROC sweep that rescans for every unique threshold: up to O(n^2);
  • sorting scores once: O(n log n);
  • incremental ROC construction after sorting: approximately O(n) after sorting.

This comparison is useful because it shows how a conceptually simple algorithm can become inefficient if implemented naively.
