CODE-U3-04 — Convolutional Neural Networks

Purpose: Move from generic dense networks to image-aware neural networks by implementing a small 2D convolution manually, understanding tensor shapes and parameter sharing, then building a practical CNN image-classification model with PyTorch.

The central progression is:

image
  ↓
local receptive fields
  ↓
convolution / cross-correlation operation
  ↓
feature maps
  ↓
nonlinearity
  ↓
pooling / downsampling
  ↓
deeper features
  ↓
classifier

This chapter deliberately has two layers:

  1. from-scratch mechanics — enough NumPy code to understand exactly what a convolutional layer does;
  2. framework implementation — a practical CNN for image classification using PyTorch.

02

Why CNNs Exist

👨‍🏫 Teacher Intuition — Bilingual Implementation Model
Dense MLP mein agar 1000x1000 ki image dalo, toh pehle hi layer mein lakho parameters ho jayenge aur spatial structure (aankhein, naak) gayab ho jayegi. CNN ek chhota sliding glass (kernel / filter) use karta hai jo image par ghoomta hai. Filter sharing ka matlab: wahi 3x3 filter poori image mein horizontal edge ya vertical edge dhundhta hai. Max Pooling resolution ko aadha kar deta hai par sabse strong features ko preserve rakhta hai!

An image is not naturally just a long flat feature vector.

Consider a grayscale image:

28 × 28

A nearby group of pixels often forms a useful local pattern:

edge
corner
stroke
texture
shape fragment

A dense layer ignores this local structure unless it learns it indirectly.

A CNN builds local spatial processing directly into the architecture.

The design ideas are:

local connectivity
+
parameter sharing
+
hierarchical feature extraction

These are the concepts to understand before memorizing Conv2d.

03

Image Representation

A grayscale image can be represented as:

\[ H\times W \]

or, with an explicit channel dimension:

\[ C\times H\times W. \]

For a batch:

\[ N\times C\times H\times W. \]

For RGB:

C = 3

A typical PyTorch image tensor uses:

(batch, channels, height, width)

for Conv2d.

batch = 32
channels = 3
height = 64
width = 64

Then:

PYTHON
X.shape == (32, 3, 64, 64)

32 images
3 channels per image
64 rows
64 columns

Do not read:

32 × 3 × 64 × 64

as one flat feature count.

It is a structured tensor.

05

What a Convolutional Filter Does

Take a small kernel:

\[ K\in\mathbb{R}^{k_H\times k_W}. \]

For a grayscale image region:

\[ P\in\mathbb{R}^{k_H\times k_W} \]

a simple local response is:

\[ s= \sum_i\sum_j K_{ij}P_{ij}+b. \]

The kernel moves across the image.

At each location:

patch
 ↓
element-wise multiply
 ↓
sum
 ↓
bias
 ↓
one output value

Repeating this creates a feature map.

06

Important Terminology

Term Meaning
kernel/filter learnable local weight pattern
feature map spatial output produced by a filter
channel one input/output feature plane
stride step size of the kernel movement
padding extra border values added around input
receptive field input region influencing an output unit
pooling local downsampling operation
parameter sharing same filter weights reused across locations
07

One Tiny Manual Example

Input:

\[ X= \begin{bmatrix} 1&2&3\\ 4&5&6\\ 7&8&9 \end{bmatrix} \]

Kernel:

\[ K= \begin{bmatrix} 1&0\\ 0&-1 \end{bmatrix} \]

Top-left patch:

\[ \begin{bmatrix} 1&2\\ 4&5 \end{bmatrix} \]

Response:

\[ 1(1)+0(2)+0(4)+(-1)(5) \]
\[ =1-5=-4. \]

Move one step right.

Patch:

\[ \begin{bmatrix} 2&3\\ 5&6 \end{bmatrix} \]

Response:

\[ 2-6=-4. \]

The same kernel is reused.

That is parameter sharing.

08

CNN Implementation Note — Convolution vs Cross-Correlation

Deep-learning libraries commonly implement the sliding weighted-sum operation called Conv2d without explicitly flipping the kernel as in the strict mathematical definition of convolution.

For learning the architecture, the important mechanics are:

learnable kernel
 ↓
slide over local regions
 ↓
weighted sum
 ↓
feature map

Do not get stuck on terminology before understanding the computation.

09

Grayscale 2D Convolution From Scratch

Start with one image and one kernel.

PYTHON
import numpy as np
PYTHON
def conv2d_valid(
    image: np.ndarray,
    kernel: np.ndarray,
    stride: int = 1,
) -> np.ndarray:
    image = np.asarray(image, dtype=float)
    kernel = np.asarray(kernel, dtype=float)

    if image.ndim != 2:
        raise ValueError("image must be 2D.")

    if kernel.ndim != 2:
        raise ValueError("kernel must be 2D.")

    if stride <= 0:
        raise ValueError("stride must be positive.")

    kh, kw = kernel.shape
    h, w = image.shape

    if h < kh or w < kw:
        raise ValueError("Kernel must fit inside image.")

    out_h = 1 + (h - kh) // stride
    out_w = 1 + (w - kw) // stride

    output = np.zeros((out_h, out_w), dtype=float)

    for i in range(out_h):
        for j in range(out_w):
            r = i * stride
            c = j * stride

            patch = image[
                r:r + kh,
                c:c + kw,
            ]

            output[i, j] = np.sum(
                patch * kernel
            )

    return output

This is deliberately explicit.

Do not optimize it yet.

11

Output-Size Formula

For one spatial dimension:

\[ \boxed{ O= \left\lfloor \frac{I+2P-D(K-1)-1}{S} +1 \right\rfloor } \]

where:

  • \(I\) = input size;
  • \(O\) = output size;
  • \(K\) = kernel size;
  • \(P\) = padding;
  • \(S\) = stride;
  • \(D\) = dilation.

For the common simple case \(D=1\):

\[ \boxed{ O= \left\lfloor \frac{I+2P-K}{S} \right\rfloor+1 } \]

For height and width, apply the formula separately.

12

Output-Size Numerical

Input:

28 × 28

Kernel:

3 × 3

Stride:

1

Padding:

0

Then:

\[ O= \frac{28-3}{1}+1 =26. \]

So:

28 × 28
    ↓
3 × 3 kernel, stride 1, no padding
    ↓
26 × 26

Compute the spatial output size of a CNN layer.

13

Same-Padding Intuition

With an odd kernel such as:

3 × 3

padding can preserve spatial dimensions when stride is 1.

Conceptually:

input border
   ↓
pad around border
   ↓
kernel can inspect border-neighbourhoods
   ↓
same-sized feature map

Padding prevents the spatial dimensions from shrinking too quickly across many layers.

14

Stride

Stride controls how far the kernel moves.

Stride 1

move one pixel

Stride 2

move two pixels

Larger stride generally reduces spatial resolution.

Example:

28 × 28
3 × 3
stride 2
padding 0
\[ O= \left\lfloor \frac{28-3}{2} \right\rfloor+1 = 13. \]

So:

28 × 28 → 13 × 13
15

Multiple Filters

A realistic CNN layer uses many filters.

Suppose:

input channels = 3
output channels = 16
kernel = 3 × 3

Each output filter has weights for all three input channels.

Weight shape:

\[ 16\times3\times3\times3. \]

Each output channel gets one feature map.

Therefore:

3-channel image
      ↓
16 learned filters
      ↓
16 output feature maps
16

CNN Parameter Count

For a standard convolutional layer:

input channels  = C_in
output channels = C_out
kernel          = K_h × K_w

weights:

\[ C_{out}C_{in}K_hK_w. \]

With one bias per output channel:

\[ \boxed{ C_{out}C_{in}K_hK_w+C_{out} } \]

Example:

Cin  = 3
Cout = 16
kernel = 3 × 3

Weights:

\[ 16(3)(3)(3)=432. \]

Biases:

\[ 16. \]

Total:

\[ \boxed{448} \]

Notice what is not present:

image height
image width

The same kernel parameters are reused spatially.

17

Why Parameter Sharing Matters

A dense layer connected to every pixel would have a large number of independent weights.

A CNN instead learns a local detector and reuses it across positions.

Conceptually:

same filter
   ├── top-left
   ├── top-middle
   ├── center
   ├── bottom-right
   └── ...

The model can therefore learn:

“this local pattern is useful regardless of exactly where it appears.”

This creates translation-related inductive bias.

18

Multi-Channel Convolution From Scratch

For a batch-free input:

channels × height × width

and one filter:

channels × kernel_height × kernel_width

the output at each spatial location is the sum across channels.

PYTHON
def conv2d_multi_channel_valid(
    image: np.ndarray,
    kernel: np.ndarray,
    bias: float = 0.0,
    stride: int = 1,
) -> np.ndarray:
    image = np.asarray(image, dtype=float)
    kernel = np.asarray(kernel, dtype=float)

    if image.ndim != 3:
        raise ValueError(
            "image must have shape (channels, height, width)."
        )

    if kernel.ndim != 3:
        raise ValueError(
            "kernel must have shape (channels, kh, kw)."
        )

    if image.shape[0] != kernel.shape[0]:
        raise ValueError(
            "Image and kernel channel counts must match."
        )

    _, h, w = image.shape
    _, kh, kw = kernel.shape

    out_h = 1 + (h - kh) // stride
    out_w = 1 + (w - kw) // stride

    output = np.zeros((out_h, out_w))

    for i in range(out_h):
        for j in range(out_w):
            r = i * stride
            c = j * stride

            patch = image[
                :,
                r:r + kh,
                c:c + kw,
            ]

            output[i, j] = (
                np.sum(patch * kernel)
                + bias
            )

    return output

The operation is now:

channel 1 response
+
channel 2 response
+
...
+
channel C response
+
bias

ReLU After Convolution

A convolution produces:

\[ Z. \]

We commonly apply a nonlinear activation:

\[ A=ReLU(Z). \]

Thus:

image
 ↓
convolution
 ↓
feature map
 ↓
ReLU
 ↓
activated feature map

Implementation:

PYTHON
activated = np.maximum(
    feature_map,
    0.0,

This is the same ReLU concept learned in the MLP chapter.

20

Pooling

Pooling summarizes local regions.

For max pooling:

\[ output_{i,j} = \max \left( \text{local window} \right). \]

Example:

2 × 2 patch

1 7
3 2

max pool:

7

A simple NumPy implementation:

PYTHON
def max_pool2d(
    feature_map: np.ndarray,
    pool_size: int = 2,
    stride: int = 2,
) -> np.ndarray:
    feature_map = np.asarray(
        feature_map,
        dtype=float,
    )

    if feature_map.ndim != 2:
        raise ValueError("feature_map must be 2D.")

    h, w = feature_map.shape

    if h < pool_size or w < pool_size:
        raise ValueError("Pool window must fit.")

    out_h = 1 + (h - pool_size) // stride
    out_w = 1 + (w - pool_size) // stride

    output = np.zeros((out_h, out_w))

    for i in range(out_h):
        for j in range(out_w):
            r = i * stride
            c = j * stride

            patch = feature_map[
                r:r + pool_size,
                c:c + pool_size,
            ]

            output[i, j] = np.max(patch)

    return output
21

Why Pooling Exists

Pooling can:

  • reduce spatial resolution;
  • lower downstream computation;
  • summarize strong local responses;
  • increase the effective region represented by later units.

But remember:

Pooling is not the essence of CNNs.

The core architectural ideas are local connectivity, learned filters and feature maps.

Modern CNN architectures can also downsample through strided convolutions rather than explicit pooling.

22

Receptive Field Intuition

A neuron's receptive field is the region of the original input that can influence its activation.

One convolution:

local region

Two stacked convolutional layers:

larger effective input region

Deeper layers can therefore respond to increasingly larger spatial structures.

Conceptually:

pixels
 ↓
edges
 ↓
corners/textures
 ↓
parts
 ↓
objects

This is an architectural intuition, not a guarantee that each neuron corresponds to a human-interpretable concept.

PyTorch CNN

Now use the framework.

PYTHON
import torch
import torch.nn as nn

Define:

PYTHON
class SmallCNN(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()

        self.features = nn.Sequential(
            nn.Conv2d(
                in_channels=1,
                out_channels=16,
                kernel_size=3,
                padding=1,
            ),
            nn.ReLU(),

            nn.MaxPool2d(
                kernel_size=2,
                stride=2,
            ),

            nn.Conv2d(
                in_channels=16,
                out_channels=32,
                kernel_size=3,
                padding=1,
            ),
            nn.ReLU(),

            nn.MaxPool2d(
                kernel_size=2,
                stride=2,
            ),
        )

        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Linear(
                32 * 7 * 7,
                128,
            ),
            nn.ReLU(),
            nn.Linear(
                128,
                num_classes,
            ),
        )

    def forward(self, x):
        x = self.features(x)
        return self.classifier(x)

This architecture assumes:

input image = 1 × 28 × 28

because each 2×2 pooling layer halves the spatial size:

28 → 14 → 7

Loss and Optimizer

For multi-class classification:

PYTHON
loss_fn = nn.CrossEntropyLoss()

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=1e-3,
)

The network outputs logits:

(batch, classes)

The target contains integer class indices.

You do not need to apply softmax before CrossEntropyLoss.

A common beginner mistake is:

PYTHON
softmax(logits)
→ CrossEntropyLoss

for no reason.

Let the loss function handle the appropriate transformation internally.

30

Training Loop

PYTHON
def train_one_epoch(
    model,
    loader,
    optimizer,
    loss_fn,
    device,
):
    model.train()

    total_loss = 0.0
    total_correct = 0
    total_examples = 0

    for images, labels in loader:
        images = images.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()

        logits = model(images)

        loss = loss_fn(
            logits,
            labels,
        )

        loss.backward()
        optimizer.step()

        total_loss += (
            loss.item() * images.size(0)
        )

        predictions = logits.argmax(
            dim=1
        )

        total_correct += (
            (predictions == labels)
            .sum()
            .item()
        )

        total_examples += images.size(0)

    return (
        total_loss / total_examples,
        total_correct / total_examples,
    )

        total_correct += (
            (predictions == labels)
            .sum()
            .item()
        )

        total_examples += images.size(0)

    return (
        total_loss / total_examples,
        total_correct / total_examples,
    )

The important difference:

training → gradient computation + update

evaluation → no update

Compare Dense and CNN Parameter Logic

Imagine:

28 × 28 grayscale image

A dense layer from all pixels to 128 units has approximately:

\[ 28\times28\times128+128. \]

A 3×3 convolution with 16 filters has:

\[ 16\times1\times3\times3+16. \]

The difference is large.

The CNN is exploiting local connectivity and weight sharing instead of learning a completely separate weight for every image-position-to-neuron connection.

Common CNN Mistakes

⚠️ University Lab Viva Trap & Runtime Gotcha
**Output Spatial Dimension Formula Trap:** Output dimension is $O = \lfloor \frac{W - K + 2P}{S} \rfloor + 1$. In viva, examiners frequently ask: 'If input is 28x28, filter is 5x5, stride is 1, and no padding (P=0), what is output size?' Answer: $(28 - 5 + 0)/1 + 1 = 24 \times 24$. If you forget $+1$, your dimension calculation fails and PyTorch throws a runtime shape mismatch error!

Mistake 1 — Flattening the image immediately

This throws away the explicit spatial structure that motivates the CNN.

Mistake 2 — Wrong channel order

Do not casually move between:

H × W × C

and:

C × H × W

without checking the API.

Mistake 3 — Wrong flatten size

Calculate the final spatial dimensions instead of guessing.

Mistake 4 — Applying softmax before CrossEntropyLoss

Usually unnecessary.

Mistake 5 — Calling model.train() during evaluation

This changes the behaviour of training-mode layers.

Mistake 6 — Reading one feature map as one human concept

Feature representations can be distributed.

Viva Questions

Q1. Why are CNNs useful for images?

They explicitly exploit local spatial structure through local connectivity and shared filters.

Q2. What is a kernel?

A learnable set of local weights applied across input regions.

Q3. What is a feature map?

The spatial output generated by applying a filter across an input.

Q4. Why does parameter sharing reduce parameters?

The same filter weights are reused at multiple spatial positions.

Q5. What does stride control?

The spatial step between successive filter positions.

Q6. What does padding do?

It adds border context and can control spatial output dimensions.

Q7. What is pooling?

A local aggregation/downsampling operation such as maximum selection.

Q8. What is a receptive field?

The portion of the input that can influence a particular activation.

Q9. Why can deeper CNNs detect more complex patterns?

Stacked layers combine increasingly transformed local representations, giving later units larger effective receptive fields.

Q10. How many parameters does a standard convolutional layer have?

\[ C_{out}C_{in}K_hK_w+C_{out} \]

when one bias is used per output channel.
