CODE-U3-05 — RNN and LSTM

Purpose: Extend neural networks from independent examples to ordered sequences by implementing a simple recurrent neural network (RNN), understanding hidden-state recurrence and backpropagation-through-time intuition, then building an LSTM sequence model in PyTorch.

The architectural story is:

MLP
 ↓
input at one moment is enough

RNN
 ↓
current input + previous hidden state

LSTM
 ↓
gated memory for longer dependencies

The key idea is that a sequence model carries information forward through time.

02

Why Sequential Data Is Different

👨‍🏫 Teacher Intuition — Bilingual Implementation Model
Standard neural network maanta hai ki har input independent hai. Lekin bhasha aur samay (time-series) mein agla lafz pichle lafzon par nirbhar karta hai. RNN ke paas ek memory state $h_t$ hoti hai jo har step par aage pass hoti hai. Lekin lambe sentence mein purana context gayab ho jata hai (vanishing gradient). LSTM (Long Short-Term Memory) ek express conveyor belt (Cell State $C_t$) banata hai jahan information bina kisi destructive non-linearity ke sedha aage badhti hai!

Suppose the input is:

"The movie was not good"

A model should not interpret each word as completely independent.

Order matters.

Compare:

"not good"

with:

"good, not ..."

The surrounding sequence can change interpretation.

The same principle appears in:

  • time-series signals;
  • stock-price sequences;
  • sensor measurements;
  • speech;
  • text;
  • event logs.

A sequential model therefore needs some mechanism for carrying context.

03

Core RNN Idea

At time \(t\), an RNN receives:

  • current input \(x_t\);
  • previous hidden state \(h_{t-1}\).

It computes:

\[ \boxed{ h_t= \phi( W_{xh}x_t+ W_{hh}h_{t-1}+ b_h ) } \]

Then an output can be computed:

\[ \boxed{ y_t=W_{hy}h_t+b_y } \]

or:

\[ y_t=\psi(W_{hy}h_t+b_y) \]

depending on the task.

The hidden state is therefore a learned recurrent summary.

04

RNN Computational Graph

For a sequence:

x₁ → [RNN cell] → h₁
                ↓
x₂ → [RNN cell] → h₂
                ↓
x₃ → [RNN cell] → h₃
                ↓
...

A clearer view:

┌─────────────┐
x₁ ────→│             │──→ h₁
        │   RNN cell  │
h₀ ────→│             │
        └─────────────┘
               │
               ▼
        ┌─────────────┐
x₂ ────→│   same      │──→ h₂
h₁ ────→│ parameters   │
        └─────────────┘
               │
               ▼
        ┌─────────────┐
x₃ ────→│   same      │──→ h₃
h₂ ────→│ parameters   │
        └─────────────┘

The same recurrent parameters are reused at every time step.

That is another form of parameter sharing.

Sequence Tensor Shape

With batch-first convention:

(batch, sequence_length, input_features)

Example:

32 sequences
10 time steps
8 features per time step

Shape:

(32, 10, 8)

This convention is convenient in PyTorch when:

PYTHON
batch_first=True

Do not confuse it with libraries/settings using:

(sequence_length, batch, features)

Always inspect the API.

From-Scratch Single RNN Cell

Start with one step.

PYTHON
import numpy as np
PYTHON
def tanh(x):
    return np.tanh(x)
PYTHON
def rnn_cell(
    x_t,
    h_prev,
    W_xh,
    W_hh,
    b_h,
):
    return np.tanh(
        x_t @ W_xh
        + h_prev @ W_hh
        + b_h
    )

This uses row-vector convention.

Dimensions:

x_t    → (input_dim,)
h_prev → (hidden_dim,)
W_xh   → (input_dim, hidden_dim)
W_hh   → (hidden_dim, hidden_dim)
b_h    → (hidden_dim,)

Output:

h_t → (hidden_dim,)
09

Manual RNN Step

Suppose:

\[ x_t= \begin{bmatrix} 1\\ 2 \end{bmatrix} \]

and:

\[ h_{t-1}= \begin{bmatrix} 0.5\\ -0.5 \end{bmatrix}. \]

The cell first computes:

\[ z_t=x_tW_{xh}+h_{t-1}W_{hh}+b_h. \]

Then:

\[ h_t=\tanh(z_t). \]

The important difference from an MLP is:

current input
+
previous hidden state

not just:

current input
10

Process a Whole Sequence

PYTHON
def rnn_forward(
    X,
    W_xh,
    W_hh,
    b_h,
    h0=None,
):
    X = np.asarray(X, dtype=float)

    if X.ndim != 2:
        raise ValueError(
            "X must have shape (sequence_length, input_dim)."
        )

    seq_len, input_dim = X.shape
    hidden_dim = W_hh.shape[0]

    if W_xh.shape != (
        input_dim,
        hidden_dim,
    ):
        raise ValueError("W_xh has incorrect shape.")

    if W_hh.shape != (
        hidden_dim,
        hidden_dim,
    ):
        raise ValueError("W_hh has incorrect shape.")

    if b_h.shape != (hidden_dim,):
        raise ValueError("b_h has incorrect shape.")

    if h0 is None:
        h = np.zeros(hidden_dim)
    else:
        h = np.asarray(h0, dtype=float).copy()

    hidden_states = []

    for t in range(seq_len):
        h = rnn_cell(
            X[t],
            h,
            W_xh,
            W_hh,
            b_h,
        )

        hidden_states.append(h.copy())

    return np.stack(hidden_states)

Output shape:

(sequence_length, hidden_dim)
11

Why Store Every Hidden State?

At inference time, sometimes only the final state is needed.

During training, however, BPTT needs the intermediate states.

For:

x₁ → h₁
x₂ → h₂
x₃ → h₃

the gradient through time depends on:

h₁
h₂
h₃

So a practical implementation caches the sequence of hidden states and other intermediates.

12

Unrolling the RNN

Suppose sequence length is 4.

The recurrent computation becomes:

shared W
x₁ → h₁ ─────────────→
          shared W
x₂ → h₂ ─────────────→
          shared W
x₃ → h₃ ─────────────→
          shared W
x₄ → h₄

When drawn this way, the graph looks deep.

That is why training can be interpreted as applying ordinary backpropagation to the unrolled network.

This is BPTT:

Backpropagation Through Time.

13

The BPTT Idea

Suppose the total loss is:

\[ L=L_1+L_2+\cdots+L_T. \]

The final hidden state can depend on all previous states.

Therefore:

\[ \frac{\partial L}{\partial h_t} \]

can contain contributions from later time steps.

Conceptually:

loss at t=4
   ↓
h₄
↑
h₃
↑
h₂
↑
h₁

and:

loss at t=3
   ↓
h₃
↑
h₂
↑
h₁

The gradient can therefore travel backward through many recurrent transitions.

14

Why Vanishing Gradients Can Occur

Repeated chain-rule multiplication can produce very small gradient factors.

A simplified intuition:

gradient
 × local derivative
 × recurrent weight effect
 × local derivative
 × ...

If the magnitudes repeatedly contract:

\[ |factor|\lt 1 \]

then long products can become very small.

This is the vanishing-gradient problem.

It can make learning long-range dependencies difficult for simple RNNs.

15

Exploding Gradients

The opposite can happen.

If repeated multiplications effectively amplify the gradient:

\[ |factor|\gt 1 \]

then the gradient can grow rapidly.

This is the exploding-gradient problem.

A practical mitigation sometimes used is gradient clipping.

Example in PyTorch:

PYTHON
torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0,
)

Clipping does not solve every optimization problem. It is a mechanism for limiting extreme gradient magnitudes.

16

Why LSTM Exists

LSTM introduces an explicit cell state and gates designed to regulate information flow.

The high-level goal is:

what should be forgotten?
what should be written?
what should be exposed?

The cell has:

  • forget gate;
  • input gate;
  • candidate state;
  • output gate;
  • cell state;
  • hidden state.

This provides a richer mechanism for preserving and modifying information across time.

17

LSTM Equations

A common notation is:

\[ f_t= \sigma( W_f x_t+ U_f h_{t-1}+ b_f ) \]

Forget gate.

\[ i_t= \sigma( W_i x_t+ U_i h_{t-1}+ b_i ) \]

Input gate.

Candidate:

\[ \tilde c_t= \tanh( W_c x_t+ U_c h_{t-1}+ b_c ) \]

Cell update:

\[ \boxed{ c_t= f_t\odot c_{t-1} + i_t\odot\tilde c_t } \]

Output gate:

\[ o_t= \sigma( W_o x_t+ U_o h_{t-1}+ b_o ) \]

Hidden state:

\[ \boxed{ h_t= o_t\odot\tanh(c_t) } \]

where:

\[ \odot \]

means element-wise multiplication.

18

Gate Intuition

Use this mental model:

FORGET GATE
"What old memory should remain?"

        ↓

INPUT GATE
"What new information should be written?"

        ↓

CELL STATE
"Longer-lived memory pathway"

        ↓

OUTPUT GATE
"What should be exposed as the hidden state?"

Hinglish

LSTM basically har time-step par decide karta hai: purani memory mein se kya rakhna hai, nayi information mein se kya add karna hai, aur current hidden output mein kya dikhana hai.

19

LSTM Cell From Scratch

Implement one cell.

PYTHON
def sigmoid(x):
    return 1.0 / (
        1.0 + np.exp(-x)
    )
PYTHON
def lstm_cell(
    x_t,
    h_prev,
    c_prev,
    W_f,
    U_f,
    b_f,
    W_i,
    U_i,
    b_i,
    W_c,
    U_c,
    b_c,
    W_o,
    U_o,
    b_o,
):
    f = sigmoid(
        x_t @ W_f
        + h_prev @ U_f
        + b_f
    )

    i = sigmoid(
        x_t @ W_i
        + h_prev @ U_i
        + b_i
    )

    c_candidate = np.tanh(
        x_t @ W_c
        + h_prev @ U_c
        + b_c
    )

    c = (
        f * c_prev
        + i * c_candidate
    )

    o = sigmoid(
        x_t @ W_o
        + h_prev @ U_o
        + b_o
    )

    h = o * np.tanh(c)

    return (
        h,
        c,
        {
            "f": f,
            "i": i,
            "c_candidate": c_candidate,
            "c": c,
            "o": o,
        },
    )

This is intentionally explicit.

The point is to see every gate.

20

LSTM Sequence Forward Pass

PYTHON
def lstm_forward(
    X,
    parameters,
    h0=None,
    c0=None,
):
    X = np.asarray(X, dtype=float)

    seq_len, input_dim = X.shape
    hidden_dim = parameters["U_f"].shape[0]

    if h0 is None:
        h = np.zeros(hidden_dim)
    else:
        h = np.asarray(h0, dtype=float).copy()

    if c0 is None:
        c = np.zeros(hidden_dim)
    else:
        c = np.asarray(c0, dtype=float).copy()

    hidden_states = []
    cell_states = []
    caches = []

    for t in range(seq_len):
        (
            h,
            c,
            cache,
        ) = lstm_cell(
            X[t],
            h,
            c,
            parameters["W_f"],
            parameters["U_f"],
            parameters["b_f"],
            parameters["W_i"],
            parameters["U_i"],
            parameters["b_i"],
            parameters["W_c"],
            parameters["U_c"],
            parameters["b_c"],
            parameters["W_o"],
            parameters["U_o"],
            parameters["b_o"],
        )

        hidden_states.append(h.copy())
        cell_states.append(c.copy())
        caches.append(cache)

    return (
        np.stack(hidden_states),
        np.stack(cell_states),
        caches,
    )
21

LSTM Parameter Dimensions

Let:

input dimension  = d
hidden dimension = h

For each of the four transformations:

input → hidden

the matrix is roughly:

\[ d\times h. \]

For each recurrent transformation:

\[ h\times h. \]

There are four gate/candidate groups.

So the recurrent weights scale approximately with:

\[ 4(dh+h^2) \]

plus biases.

This is why LSTM has substantially more parameters than a basic RNN of the same hidden size.

22

RNN vs LSTM

Property Vanilla RNN LSTM
recurrent hidden state Yes Yes
explicit cell state No Yes
gates No Yes
architecture complexity Lower Higher
parameter count Lower Higher
long-dependency handling Can be difficult Designed to improve memory handling
implementation simpler more involved

Do not memorize:

“RNN bad, LSTM good.”

The correct lesson is:

LSTM adds a more sophisticated memory mechanism, at the cost of additional parameters and computation.

Sequence Classification Model

A common classification architecture is:

sequence
 ↓
embedding / feature representation
 ↓
LSTM
 ↓
final hidden representation
 ↓
linear classifier
 ↓
class logits

Example:

PYTHON
class SequenceClassifier(nn.Module):
    def __init__(
        self,
        input_size,
        hidden_size,
        num_classes,
    ):
        super().__init__()

        self.lstm = nn.LSTM(
            input_size=input_size,
            hidden_size=hidden_size,
            batch_first=True,
        )

        self.classifier = nn.Linear(
            hidden_size,
            num_classes,
        )

    def forward(self, x):
        output, (h_n, c_n) = self.lstm(x)

        final_hidden = h_n[-1]

        logits = self.classifier(
            final_hidden
        )

        return logits

This is useful when one label is associated with an entire sequence.

Always inspect dimensions.

Sequence-to-Sequence vs Sequence Classification

Do not assume every sequence problem uses only the final hidden state.

Sequence classification

many inputs
 ↓
one label

Example:

sentence → sentiment

Sequence labeling

many inputs
 ↓
one output per time step

Example:

tokens → part-of-speech tags

Sequence generation

previous context
 ↓
next-token prediction
 ↓
repeat

Architecture and output handling depend on the problem.

def make_binary_sequence_dataset(
    n_samples=1000,
    seq_len=10,
    seed=42,
):
    rng = np.random.default_rng(seed)

    X = rng.integers(
        0,
        2,
        size=(n_samples, seq_len, 1),
    ).astype(np.float32)

    y = (
        X.sum(axis=1).squeeze(-1) > 0
    ).astype(np.int64)

    return X, y

Resetting State Matters

When training independent sequences, do not accidentally carry hidden state from one unrelated sequence into another unless that is intentional.

Typical batch processing handles this by starting with fresh initial states or by explicitly passing state between related chunks.

The principle is:

independent sample
→ appropriate state reset

continuous stream
→ state may be carried forward intentionally

BPTT Practical Intuition

Suppose:

x₁ → h₁ → h₂ → h₃ → loss

and you want the effect of parameters used at \(t=1\).

Their influence travels:

parameter at t=1
   ↓
h₁
   ↓
h₂
   ↓
h₃
   ↓
loss

So the gradient must account for that entire dependency path.

This is why long sequences can create difficult gradient-flow behaviour.

Truncated BPTT Preview

For very long streams, training can sometimes backpropagate through only a window of time.

Conceptually:

long sequence
────────────────────────────

window 1
[───────]

window 2
        [───────]

window 3
                [───────]

This reduces computational/memory cost but changes the gradient horizon.

For the syllabus foundation, understand the idea without treating it as a required implementation technique.

Common RNN Errors

Error 1 — Mixing (batch, sequence, feature) with (sequence, batch, feature)

Pick a convention.

With PyTorch:

PYTHON
batch_first=True

is convenient for:

batch, sequence, feature

Error 2 — Forgetting that the same weights are reused through time

The recurrent cell is not a different independent layer at each time step.

Error 3 — Treating hidden state as permanent automatically

State persistence must be intentional.

Error 4 — Using final hidden state for every sequence task

Some tasks need all time-step outputs.

Error 5 — Ignoring gradient behaviour

Long recurrent computations can make gradient flow difficult.

40

Common LSTM Errors

Error 1 — Confusing hidden state and cell state

LSTM carries both.

Error 2 — Writing gate equations with mismatched dimensions

All gate outputs need the hidden-state dimension.

Error 3 — Forgetting element-wise multiplication

The equations use:

\[ \odot \]

not matrix multiplication.

Error 4 — Assuming the gates are hand-designed

The gate weights are learned parameters.

Error 5 — Saying LSTM “stores everything”

It learns gates that regulate information; it does not guarantee perfect memory.

RNN vs MLP

An MLP sees each input example as a fixed vector.

An RNN adds:

\[ h_{t-1} \]

to the current computation.

So:

MLP:
x → prediction

RNN:
x₁
 ↓
h₁
 ↓
x₂ + h₁ → h₂
 ↓
x₃ + h₂ → h₃

The sequence history becomes part of the representation.

LSTM Parameter Count Exercise

Suppose:

input_dim = 8
hidden_dim = 16

A standard LSTM has four gate/candidate groups.

Ignoring implementation-specific packing details, conceptually each group has:

\[ 8\times16 \]

input weights,

\[ 16\times16 \]

recurrent weights,

and a hidden-sized bias.

So the total scales roughly as:

\[ 4(8\times16+16\times16+16) \]
\[ =4(128+256+16) \]
\[ =4(400) \]
\[ =1600. \]

The exact framework parameter layout may store multiple bias vectors or pack matrices together, so use the actual model inspection to verify implementation details.

Manual Scalar Gradient-Flow Exercise

Consider:

\[ h_t=a h_{t-1} \]

for a scalar \(a\).

Repeatedly:

\[ h_t=a^t h_0. \]

The sensitivity of \(h_t\) to \(h_0\) is:

\[ \frac{\partial h_t}{\partial h_0}=a^t. \]

Now compare:

a = 0.5
a = 1.0
a = 1.5

After many time steps:

0.5^t → very small
1.0^t → unchanged
1.5^t → very large

This tiny equation captures the mathematical intuition behind vanishing and exploding gradients in repeated transformations.

48

Why LSTM's Cell State Is Important

The LSTM cell state provides a pathway with multiplicative gating:

\[ c_t= f_t\odot c_{t-1} + i_t\odot\tilde c_t. \]

The gates control what passes along the memory path.

The architecture was designed to make useful long-term information easier to preserve than in a basic RNN.

Do not describe the cell state as a magical permanent memory.

It is a learned state updated at every time step.

PyTorch Sequence Text Architecture Preview

A common structure is:

PYTHON
class TextClassifier(nn.Module):
    def __init__(
        self,
        vocab_size,
        embedding_dim,
        hidden_dim,
        num_classes,
    ):
        super().__init__()

        self.embedding = nn.Embedding(
            vocab_size,
            embedding_dim,
        )

        self.lstm = nn.LSTM(
            embedding_dim,
            hidden_dim,
            batch_first=True,
        )

        self.classifier = nn.Linear(
            hidden_dim,
            num_classes,
        )

    def forward(self, token_ids):
        x = self.embedding(token_ids)

        output, (h_n, c_n) = self.lstm(x)

        return self.classifier(
            h_n[-1]
        )

Viva Questions

⚠️ University Lab Viva Trap & Runtime Gotcha
**RNN Batch Shape & State Resetting Trap:** In PyTorch `nn.RNN`/`nn.LSTM`, default tensor shape is `(seq_len, batch_size, input_size)`, NOT `(batch_size, seq_len, input_size)` unless `batch_first=True` is explicitly specified! Also, when training on sequential batches, forgetting to detach hidden states between sequences via `h.detach()` attempts backpropagation through the entire dataset history, running out of CUDA memory!

Q1. Why do we need RNNs?

To model ordered/sequential data where previous context can influence later predictions.

Q2. What is the hidden state?

A recurrent representation that carries information from earlier time steps into later computations.

Q3. What is recurrence?

The current hidden state depends on the previous hidden state.

Q4. What is BPTT?

Backpropagation applied through the unrolled recurrent computation across time steps.

Q5. Why can vanilla RNNs suffer from vanishing gradients?

Repeated chain-rule multiplication can produce very small gradient magnitudes across long sequences.

Q6. What is exploding gradient?

Gradient magnitude becomes excessively large during backpropagation.

Q7. What problem does LSTM try to address?

It introduces gated memory mechanisms designed to improve information and gradient flow across longer dependencies.

Q8. What is the LSTM cell state?

A recurrent memory state updated through gated retention and writing.

Q9. What are the four main LSTM gate/candidate components?

Forget gate, input gate, candidate cell content and output gate.

Q10. Why are recurrent parameters shared across time?

The same transition rule is applied at every sequence position.

Q11. Why might a sequence classifier use the final hidden state?

It can serve as a learned summary of the sequence for a one-label-per-sequence task.

Q12. Does every sequence task use only the final hidden state?

No. Sequence labeling and generation often use outputs from multiple/all time steps.

Math You Need Now

Vanilla RNN

\[ h_t= \phi( W_{xh}x_t+ W_{hh}h_{t-1} +b_h ) \]

Output

\[ y_t=W_{hy}h_t+b_y \]

LSTM

\[ f_t=\sigma(\cdots) \]
\[ i_t=\sigma(\cdots) \]
\[ \tilde c_t=\tanh(\cdots) \]
\[ c_t=f_t\odot c_{t-1} +i_t\odot\tilde c_t \]
\[ o_t=\sigma(\cdots) \]
\[ h_t=o_t\odot\tanh(c_t) \]

Gradient-flow intuition

\[ \frac{\partial h_t}{\partial h_0} \sim \prod_{\tau=1}^{t} \text{local transition factors}. \]

Long products can become very small or very large.
