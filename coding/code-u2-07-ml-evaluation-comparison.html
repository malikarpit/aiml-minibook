CODE-U2-07 — ML Evaluation and Model Comparison Lab

Purpose: Turn the Unit II algorithms into a disciplined experimental workflow: train multiple classifiers on the same task, evaluate them correctly, compare them fairly, and explain why their results differ.

This is the integration chapter for the Unit II practical block.

The official DSC-14 practical component asks for regression/classification models such as Decision Trees, k-NN and SVM, together with evaluation and comparison. The resource guide also recommends treating practical work as a pipeline of input → representation → algorithm → parameters → loss/reward → training/update → output → evaluation.
Source boundary: the experiment design below is a coding-book expansion of that practical requirement; it is not claimed to reproduce an instructor's exact experiment sheet.

By the end of this lab you should be able to:

  • create one reproducible classification experiment;
  • prepare data without leakage;
  • compare at least three classifiers under the same train/test split;
  • use a confusion matrix;
  • calculate accuracy, precision, recall and F1;
  • inspect ROC curves and AUC when probability/decision scores are available;
  • recognize class-imbalance effects;
  • distinguish model quality from threshold choice;
  • record hyperparameters and results in a comparison table;
  • explain why one model is preferable for a stated application.

The important shift is:

"Run three models"
        ↓
not enough

"Run three models fairly, evaluate several dimensions,
inspect errors, and justify the choice"
        ↓
actual ML experiment
02

Practical Scenario

👨‍🏫 Teacher Intuition — Bilingual Implementation Model
University lab exam ya interview mein sabse badi galti ye hoti hai ki students alag-alag models ko alag-alag splits ya alag metrics par compare kar dete hain. Scientific method ka golden rule hai: 'Fair Comparison'. Ek hi frozen train set, ek hi frozen test set, aur ek hi evaluation pipeline. Sirf accuracy mat dekho—dekhna padega ki kaunsa model explainable hai, kiski inference speed fast hai, aur kaunsa class imbalance mein fail nahi hota!

Use a small binary classification dataset.

A convenient first experiment is the breast-cancer dataset available through scikit-learn. It is useful for learning the evaluation workflow because it is already numerical and supports binary classification.

For an external real-world dataset, do not assume that a dataset is perfectly clean, balanced, representative, or clinically suitable merely because a library provides it.

The goal here is to practice the workflow, not to make a medical deployment claim.

03

Experimental Question

Write the question before writing code.

Example:

Which of Decision Tree, k-NN and SVM gives the strongest held-out classification performance for this dataset under the chosen preprocessing and evaluation protocol?

A stronger version is:

Which model gives the best trade-off among recall, precision, F1 and ROC-AUC under a fixed experimental protocol?

This prevents a common mistake:

metric chosen after seeing results

Instead:

task
 ↓
evaluation objective
 ↓
metric
 ↓
experiment
04

Controlled Experiment Design

Keep these quantities fixed across models:

Experimental factor Keep consistent? Reason
Dataset Yes Same task
Train/test split Yes Fair comparison
Random seed Yes Reproducibility
Target labels Yes Same prediction task
Evaluation set Yes Same evidence
Primary metric Yes Comparable objective
Preprocessing policy Consistent with model needs Prevent accidental differences
Hyperparameter tuning budget Comparable Avoid giving one model an unfair advantage

A model comparison is weak when one model receives extensive tuning and another receives default settings.

Environment

PYTHON
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline

from sklearn.tree import DecisionTreeClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import SVC

from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score,
    confusion_matrix,
    roc_auc_score,
    roc_curve,
    classification_report,
)

Recommended reproducibility seed:

PYTHON
RANDOM_STATE = 42

The exact integer is not mathematically special. It is simply a fixed experiment seed.

Load the Data

PYTHON
data = load_breast_cancer()

X = pd.DataFrame(data.data, columns=data.feature_names)
y = pd.Series(data.target, name="target")

print(X.shape)
print(y.value_counts())
print(X.head())

Inspect:

PYTHON
print(X.dtypes)
print(X.isna().sum().sum())
print(y.value_counts(normalize=True))

Questions to answer before training:

  • How many samples exist?
  • How many features exist?
  • Are features numeric?
  • Are there missing values?
  • Is the target binary?
  • Is the class distribution balanced?

Do not skip this step.

07

Train/Test Split

Use stratification for this binary classification example.

PYTHON
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.20,
    stratify=y,
    random_state=RANDOM_STATE,
)

Why stratify=y?

It attempts to preserve class proportions across train and test subsets.

The deeper principle is:

The test set must remain an honest approximation of unseen data.

08

Leakage: The Rule That Must Not Be Broken

Suppose you standardize features using:

PYTHON
scaler.fit(X)

before the train/test split.

The scaler has now seen test-set information.

Even though the labels were not used, the transformation statistics were influenced by the test data.

Correct:

training data
    ↓
fit scaler
    ↓
transform training data

same fitted scaler
    ↓
transform test data

Incorrect:

all data
  ↓
fit scaler
  ↓
split

The safest implementation is a pipeline.

09

Model 1 — Decision Tree

Decision Trees generally do not require feature standardization for the ordinary split mechanism.

PYTHON
tree = DecisionTreeClassifier(
    max_depth=4,
    random_state=RANDOM_STATE,
)

Train:

PYTHON
tree.fit(X_train, y_train)

Predict:

PYTHON
tree_pred = tree.predict(X_test)

Probability/score:

PYTHON
tree_prob = tree.predict_proba(X_test)[:, 1]
10

Model 2 — k-Nearest Neighbours

Distance-based methods are sensitive to feature scale.

Therefore use:

PYTHON
knn = Pipeline(
    steps=[
        ("scaler", StandardScaler()),
        ("model", KNeighborsClassifier(n_neighbors=5)),
    ]
)

Train:

PYTHON
knn.fit(X_train, y_train)

Predict:

PYTHON
knn_pred = knn.predict(X_test)
knn_prob = knn.predict_proba(X_test)[:, 1]

Important lesson:

Preprocessing is part of the model pipeline.

Do not treat scaling as an unrelated cosmetic operation.

11

Model 3 — Support Vector Machine

A common educational SVM pipeline is:

PYTHON
svm = Pipeline(
    steps=[
        ("scaler", StandardScaler()),
        ("model", SVC(
            kernel="rbf",
            probability=True,
            random_state=RANDOM_STATE,
        )),
    ]
)

Train:

PYTHON
svm.fit(X_train, y_train)

Predict:

PYTHON
svm_pred = svm.predict(X_test)
svm_prob = svm.predict_proba(X_test)[:, 1]

For a learning lab, probability=True is convenient when you want probability estimates for ROC-AUC workflows. In other configurations, an SVM can expose a decision score through decision_function() instead.

12

A Unified Evaluation Function

Repeated metric code is a source of mistakes.

Write one evaluation function.

PYTHON
def evaluate_binary_classifier(
    model_name: str,
    y_true,
    y_pred,
    y_score,
):
    cm = confusion_matrix(y_true, y_pred)

    return {
        "model": model_name,
        "accuracy": accuracy_score(y_true, y_pred),
        "precision": precision_score(y_true, y_pred, zero_division=0),
        "recall": recall_score(y_true, y_pred, zero_division=0),
        "f1": f1_score(y_true, y_pred, zero_division=0),
        "roc_auc": roc_auc_score(y_true, y_score),
        "tn": cm[0, 0],
        "fp": cm[0, 1],
        "fn": cm[1, 0],
        "tp": cm[1, 1],
    }

Then:

PYTHON
results = [
    evaluate_binary_classifier(
        "Decision Tree",
        y_test,
        tree_pred,
        tree_prob,
    ),
    evaluate_binary_classifier(
        "k-NN",
        y_test,
        knn_pred,
        knn_prob,
    ),
    evaluate_binary_classifier(
        "SVM",
        y_test,
        svm_pred,
        svm_prob,
    ),
]

results_df = pd.DataFrame(results)
print(results_df)
13

Why the Confusion Matrix Must Be Inspected

A single score compresses information.

The confusion matrix keeps the error structure visible.

PYTHON
for name, model, predictions in [
    ("Decision Tree", tree, tree_pred),
    ("k-NN", knn, knn_pred),
    ("SVM", svm, svm_pred),
]:
    cm = confusion_matrix(y_test, predictions)
    print(name)
    print(cm)

Visualization:

PYTHON
from sklearn.metrics import ConfusionMatrixDisplay

ConfusionMatrixDisplay.from_predictions(y_test, tree_pred)
plt.title("Decision Tree — Confusion Matrix")
plt.show()

Repeat for other models.

Interpret:

  • TP — positive examples correctly found;
  • TN — negative examples correctly rejected;
  • FP — negative examples incorrectly called positive;
  • FN — positive examples incorrectly missed.
14

Metric Interpretation

Accuracy

fraction of all predictions that are correct

Useful when class costs are reasonably symmetric and class distribution is not problematic.

Precision

among predicted positives, how many are actually positive?

High precision means relatively few false positives among positive predictions.

Recall

among actual positives, how many did the model find?

High recall means relatively few false negatives.

F1

Harmonic mean of precision and recall.

Use it when both matter and you want one combined summary.

ROC-AUC

Summarizes ranking/discrimination behaviour across thresholds.

Do not confuse it with:

"accuracy at the default threshold"

They answer different questions.

15

Classification Report

PYTHON
print(classification_report(y_test, svm_pred, zero_division=0))

This gives class-wise precision, recall and F1 plus aggregate summaries.

For a serious experiment, do not paste the report into notes without interpreting it.

Write:

Model X has higher recall for the positive class, but Model Y has fewer false positives. Under the stated application objective, ___ is preferable because ___.

16

ROC Curve Comparison

PYTHON
tree_fpr, tree_tpr, _ = roc_curve(y_test, tree_prob)
knn_fpr, knn_tpr, _ = roc_curve(y_test, knn_prob)
svm_fpr, svm_tpr, _ = roc_curve(y_test, svm_prob)

plt.figure()

plt.plot(
    tree_fpr,
    tree_tpr,
    label=f"Decision Tree (AUC={roc_auc_score(y_test, tree_prob):.3f})",
)

plt.plot(
    knn_fpr,
    knn_tpr,
    label=f"k-NN (AUC={roc_auc_score(y_test, knn_prob):.3f})",
)

plt.plot(
    svm_fpr,
    svm_tpr,
    label=f"SVM (AUC={roc_auc_score(y_test, svm_prob):.3f})",
)

plt.plot([0, 1], [0, 1], linestyle="--")

plt.xlabel("False Positive Rate")
plt.ylabel("True Positive Rate")
plt.title("ROC Comparison")
plt.legend()
plt.show()

The main reading pattern is:

x-axis → false-positive rate
y-axis → true-positive rate / recall

A curve closer to the desirable top-left region generally indicates stronger ranking performance over thresholds.

17

Threshold Experiment

The model's score is not identical to the final class decision.

For a probability-like score:

PYTHON
threshold = 0.50

custom_pred = (svm_prob >= threshold).astype(int)

Now compare with another threshold:

PYTHON
threshold = 0.30

custom_pred = (svm_prob >= threshold).astype(int)

Evaluate both.

PYTHON
for threshold in [0.30, 0.50, 0.70]:
    pred = (svm_prob >= threshold).astype(int)

    print(
        threshold,
        precision_score(y_test, pred, zero_division=0),
        recall_score(y_test, pred, zero_division=0),
        f1_score(y_test, pred, zero_division=0),
    )

The lesson:

Changing the threshold changes the confusion matrix and therefore changes precision/recall/F1.

ROC-AUC evaluates a ranking across thresholds rather than committing to only one threshold.

Model Comparison Table

Build a compact report:

PYTHON
comparison = results_df[
    ["model", "accuracy", "precision", "recall", "f1", "roc_auc"]
].copy()

print(
    comparison.sort_values(
        by="f1",
        ascending=False,
    )
)

Do not automatically select the model in the first row.

Instead ask:

  1. What is the task?
  2. Which error matters most?
  3. Is the class distribution problematic?
  4. Are threshold-dependent metrics important?
  5. Is interpretability important?
  6. Is computational cost relevant?
  7. Is performance stable under different splits?
19

Fairness of the Comparison

A stronger experiment repeats the comparison under cross-validation.

For example:

PYTHON
from sklearn.model_selection import StratifiedKFold, cross_validate

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=RANDOM_STATE,
)

You can evaluate multiple metrics:

PYTHON
scoring = {
    "accuracy": "accuracy",
    "precision": "precision",
    "recall": "recall",
    "f1": "f1",
    "roc_auc": "roc_auc",
}

Example:

PYTHON
cv_result = cross_validate(
    svm,
    X,
    y,
    cv=cv,
    scoring=scoring,
    return_train_score=False,
)

for metric in scoring:
    values = cv_result[f"test_{metric}"]
    print(
        metric,
        values.mean(),
        values.std(),
    )

Interpretation:

mean → average validation performance
std  → variation across folds

A model with slightly lower mean but much larger stability can deserve investigation.

20

Why Cross-Validation Is Not a Magic Wand

Cross-validation reduces dependence on one particular train/test split.

It does not automatically solve:

  • data leakage;
  • poor labels;
  • distribution shift;
  • unrepresentative data;
  • bad preprocessing;
  • careless hyperparameter selection;
  • an inappropriate metric.

Think:

better evaluation protocol
≠
perfect experiment
21

Overfitting Experiment With Tree Depth

Decision trees provide an especially useful demonstration.

Train several trees:

PYTHON
depths = [1, 2, 3, 4, 6, 8, None]

tree_records = []

for depth in depths:
    model = DecisionTreeClassifier(
        max_depth=depth,
        random_state=RANDOM_STATE,
    )

    model.fit(X_train, y_train)

    train_pred = model.predict(X_train)
    test_pred = model.predict(X_test)

    tree_records.append({
        "depth": depth,
        "train_accuracy": accuracy_score(y_train, train_pred),
        "test_accuracy": accuracy_score(y_test, test_pred),
    })

depth_df = pd.DataFrame(tree_records)
print(depth_df)

Plot:

PYTHON
plt.figure()

plt.plot(
    depth_df["depth"].astype(str),
    depth_df["train_accuracy"],
    marker="o",
    label="Train",
)

plt.plot(
    depth_df["depth"].astype(str),
    depth_df["test_accuracy"],
    marker="o",
    label="Test",
)

plt.xlabel("Tree depth")
plt.ylabel("Accuracy")
plt.title("Decision Tree Capacity Experiment")
plt.legend()
plt.show()

The experiment makes the Unit II concept visible:

too simple
   ↓
underfitting

useful capacity
   ↓
good generalization

too flexible
   ↓
overfitting risk
22

Error Analysis

Do not stop at metrics.

Find examples where two models disagree.

PYTHON
tree_pred = tree.predict(X_test)
svm_pred = svm.predict(X_test)

disagreement = np.where(tree_pred != svm_pred)[0]

print("Number of disagreements:", len(disagreement))
print(X_test.iloc[disagreement].head())

Now ask:

  • Which model is correct more often on disagreement cases?
  • Are disagreements concentrated near the decision boundary?
  • Do the examples look unusual?
  • Does one model systematically produce more false negatives?

This is the beginning of practical model diagnosis.

24

Common Mistakes

⚠️ University Lab Viva Trap & Runtime Gotcha
**The Unequal Split & Test-Set Snooping Trap:** If you train Model A on Split 1 and Model B on Split 2, your comparison is invalid because test difficulties differ! Also, tuning hyperparameters directly on the test set causes test-set contamination (snooping). For proper comparison, use K-Fold Cross Validation on the training split, and evaluate all candidates once on the frozen holdout test set!

Mistake 1 — Different test sets

Bad comparison:

Model A → test split A
Model B → test split B

The evidence is no longer directly comparable.

Mistake 2 — Scaling before splitting

This creates leakage.

Mistake 3 — Choosing by accuracy automatically

Accuracy can hide class-specific failures.

Mistake 4 — Comparing tuned model vs untuned model

Hyperparameter budget matters.

Mistake 5 — Treating AUC as a threshold

AUC is a summary of ranking/discrimination over thresholds; it is not itself the deployed decision threshold.

Mistake 6 — Looking only at a metric table

The confusion matrix can reveal an important difference hidden by an aggregate number.

Mistake 7 — Reporting many decimals without interpretation

0.9734 vs 0.9718

is not automatically meaningful.

Discuss:

  • protocol;
  • sample size;
  • variability;
  • metric relevance;
  • practical significance.

Extension — Add SVM, k-NN and Decision Tree Fairly

For your university practical requirement, maintain a three-model minimum:

Decision Tree
      │
      ├── interpretable split structure
      └── little preprocessing dependence

k-NN
      │
      ├── distance based
      └── scale sensitive

SVM
      │
      ├── margin-based
      └── commonly scale sensitive

The point of the comparison is not to memorize which model "always wins."

There is no universal winner.

Debugging Checklist

When results look suspicious:

[ ] Was the target correct?
[ ] Was the split stratified?
[ ] Was preprocessing fitted only on training data?
[ ] Did I accidentally use test data during tuning?
[ ] Are positive/negative labels interpreted correctly?
[ ] Did I inspect class counts?
[ ] Did I inspect the confusion matrix?
[ ] Did I use score/probability values for ROC-AUC rather than hard labels?
[ ] Did every model receive the same evaluation set?

30

Practical Viva Questions

Q1. Why should the same test set be used?

Because otherwise the models are evaluated on different evidence, weakening the fairness of the comparison.

Q2. Why is scaling important for k-NN?

Because distance calculations depend on feature magnitudes.

Q3. Why might a Decision Tree not need ordinary feature standardization?

Its basic split decisions depend on threshold ordering rather than Euclidean distance.

Q4. Why can accuracy be misleading?

A classifier can obtain high accuracy while performing poorly on a minority class.

Q5. Why does threshold matter?

It converts a continuous model score into a discrete class decision.

Q6. Why use ROC-AUC?

To evaluate ranking/discrimination across decision thresholds rather than only at one threshold.

Q7. What does cross-validation add?

It estimates performance across multiple train/validation partitions, providing information about variability as well as average performance.

Q8. What is leakage?

Information from outside the training partition influences model fitting or preprocessing in a way that would not be available at genuine prediction time.
