What We Are Building

graph TD
    Var["Select Unassigned Variable via MRV (Fewest Legal Values)"] --> Val["Select Value via LCV (Least Constraining Value)"]

A CSP is naturally different from ordinary route search.

Instead of:

find a path from A to G

we often need:

assign values to variables
+
satisfy every constraint

This lab will build:

↓
backtracking search
↓
constraint checking
↓
MRV variable selection
↓
forward checking
↓
trace + tests
↓

02

CSP Mental Model

👨‍🏫 Teacher Intuition — Bilingual Implementation Model
CSP mein hum koi rasta nahi dhundh rahe, hum ek aisi state dhundh rahe hain jahan sabhi shartein (constraints) satisfy ho jayein. Backtracking basically intelligent trial-and-error hai. MRV (Minimum Remaining Values) ka funda hai 'Fail-First': jo variable sabse ziddi hai (jiske paas sabse kam options bache hain), use pehle assign karo. Agar fail hona hi hai, toh pehle hi step par ho jao taaki lakho bekaar branches explore na karni padein!

A CSP contains three core components:

\[ \boxed{ (X,D,C) } \]

where:

  • \(X\) = variables;
  • \(D\) = domains of possible values;
  • \(C\) = constraints.

Example:

Variables:
    A, B, C

Domains:
    {1, 2, 3}

Constraints:
    A != B
    B != C

The goal is to find an assignment:

A = ?
B = ?
C = ?

such that every constraint is satisfied.

03

Why CSP Deserves Its Own Implementation

Ordinary graph search usually asks:

“Which state should I expand next?”

CSP solving asks:

“Which variable should I assign next, which value should I try, and does the partial assignment violate a constraint?”

So the computational structure becomes:

partial assignment
      ↓
choose variable
      ↓
choose value
      ↓
check constraints
      ↓
if valid → recurse
if invalid → backtrack

This is search over assignments.

04

A First Toy CSP

Use:

Variables:
    A, B, C

Domains:
    A ∈ {1,2,3}
    B ∈ {1,2,3}
    C ∈ {1,2,3}

Constraints:
    A != B
    B != C

Possible solution:

A = 1
B = 2
C = 1

because:

\[ 1\ne2 \]

and:

\[ 2\ne1. \]

Notice:

A and C are allowed to share a value.

The solver must enforce exactly the constraints we define.

05

Representation

A practical Python representation:

PYTHON
variables = ["A", "B", "C"]

domains = {
    "A": [1, 2, 3],
    "B": [1, 2, 3],
    "C": [1, 2, 3],
}

A partial assignment:

PYTHON
assignment = {
    "A": 1,
    "B": 2,
}

A constraint can be represented as a callable.

Example:

PYTHON
def different(x, y):
    return x != y

Then:

PYTHON
constraints = [
    ("A", "B", different),
    ("B", "C", different),
]

This representation is intentionally explicit.

06

Constraint Checking

Given:

PYTHON
assignment = {"A": 1, "B": 1}

and:

PYTHON
A != B

the assignment is invalid.

But if:

PYTHON
assignment = {"A": 1}

we cannot evaluate A != B yet because B has not been assigned.

This gives us an important distinction:

complete violation
vs
not enough information yet

A partial assignment should be rejected only when an already-evaluable constraint is violated.

07

Consistency Function

Write:

PYTHON
def is_consistent(
    variable,
    value,
    assignment,
    constraints,
):
    ...

Its job:

Temporarily consider variable=value and determine whether the partial assignment violates any applicable constraint.

08

Basic Consistency Implementation

PYTHON
def is_consistent(
    variable,
    value,
    assignment,
    constraints,
):
    for var_a, var_b, constraint in constraints:
        if variable not in (var_a, var_b):
            continue

        if var_a == variable:
            other = var_b
        else:
            other = var_a

        if other not in assignment:
            continue

        if var_a == variable:
            if not constraint(value, assignment[other]):
                return False
        else:
            if not constraint(assignment[other], value):
                return False

    return True

This assumes the constraint callable is directional:

constraint(value_a, value_b)

If a constraint is symmetric, such as:

PYTHON
a != b

the distinction does not matter.

For asymmetric constraints, order must be handled deliberately.

09

Backtracking Idea

The core algorithm:

If assignment is complete:
    return assignment

Choose an unassigned variable

For each possible value:
    If value is consistent:
        assign value
        recursively solve
        if solution:
            return solution
        remove assignment

Return failure

The key operation is:

assign
→ recurse
→ undo

That is why it is called backtracking.

10

Backtracking Pseudocode

BACKTRACK(assignment):

    if assignment is complete:
        return assignment

    variable ← select unassigned variable

    for value in domain(variable):

        if value is consistent:

            assignment[variable] ← value

            result ← BACKTRACK(assignment)

            if result is not failure:
                return result

            remove assignment[variable]

    return failure

The backtracking point is:

remove assignment[variable]
11

Basic Backtracking Solver

PYTHON
def backtrack(
    variables,
    domains,
    constraints,
    assignment=None,
):
    if assignment is None:
        assignment = {}

    if len(assignment) == len(variables):
        return assignment.copy()

    unassigned = [
        v for v in variables
        if v not in assignment
    ]

    variable = unassigned[0]

    for value in domains[variable]:
        if is_consistent(
            variable,
            value,
            assignment,
            constraints,
        ):
            assignment[variable] = value

            result = backtrack(
                variables,
                domains,
                constraints,
                assignment,
            )

            if result is not None:
                return result

            del assignment[variable]

    return None

This is deliberately simple.

Do not optimize it before you understand the search tree.

13

Why Order Matters

Suppose:

A has values [1,2,3]
B has values [1,2,3]
C has values [1,2,3]

Trying:

A=1
B=1

fails immediately if:

\[ A\ne B. \]

The solver can backtrack before assigning C.

This is called early failure detection.

The sooner an impossible partial assignment is detected, the smaller the search tree can become.

14

Search Tree View

For:

A,B,C ∈ {1,2}
A != B
B != C

the naive assignment tree begins:

{}
              /    \
            A=1    A=2
            /        \
         B=1        B=2
          X          ...
         B=2
         /
       C=1

Invalid branches are cut as soon as the corresponding constraint becomes evaluable.

This is the key advantage of backtracking over blindly generating every complete assignment first.

15

Why Brute Force Is Worse

If there are:

\[ n \]

variables and each has approximately:

\[ d \]

values, the complete assignment space can contain roughly:

\[ \boxed{d^n} \]

combinations.

That grows exponentially.

Backtracking attempts to avoid exploring combinations that are already impossible.

Important distinction

Backtracking does not magically remove exponential worst-case behaviour.

It prunes parts of the search tree.

Testing the Solver — Valid Solution

PYTHON
def all_constraints_satisfied(
    assignment,
    constraints,
):
    for var_a, var_b, constraint in constraints:
        if var_a not in assignment or var_b not in assignment:
            return False

        if not constraint(
            assignment[var_a],
            assignment[var_b],
        ):
            return False

    return True

Then:

PYTHON
assert solution is not None
assert all_constraints_satisfied(
    solution,
    constraints,
)

This tests the actual mathematical requirement.

20

Traceable Backtracking

A trace makes backtracking visible:

PYTHON
def backtrack_trace(
    variables,
    domains,
    constraints,
    assignment=None,
    trace=None,
):
    if assignment is None:
        assignment = {}

    if trace is None:
        trace = []

    if len(assignment) == len(variables):
        return assignment.copy(), trace

    variable = next(
        v for v in variables
        if v not in assignment
    )

    for value in domains[variable]:
        consistent = is_consistent(
            variable,
            value,
            assignment,
            constraints,
        )

        trace.append({
            "variable": variable,
            "value": value,
            "consistent": consistent,
            "assignment_before": assignment.copy(),
        })

        if not consistent:
            continue

        assignment[variable] = value

        result, trace = backtrack_trace(
            variables,
            domains,
            constraints,
            assignment,
            trace,
        )

        if result is not None:
            return result, trace

        del assignment[variable]

        trace.append({
            "backtrack": variable,
            "assignment_after_undo": assignment.copy(),
        })

    return None, trace

Then inspect the trace.

21

Why Tracing Is Especially Useful for CSP

CSP errors can be subtle.

You may think:

“The solver didn't find a solution.”

But the real bug might be:

constraint encoded backwards
wrong variable selected
domain accidentally mutated
assignment not undone
value skipped

Trace output lets you locate the first incorrect decision.

Classic Practical Example — Map Coloring

Use regions:

A, B, C, D

Each domain:

{Red, Green, Blue}

Constraint:

Adjacent regions must have different colors.

A graph:

A ----- B
| \     |
|  \    |
C ----- D

Represent adjacency:

PYTHON
neighbors = {
    "A": {"B", "C", "D"},
    "B": {"A", "D"},
    "C": {"A", "D"},
    "D": {"A", "B", "C"},
}

A simple consistency rule:

PYTHON
def not_same_color(color_a, color_b):
    return color_a != color_b

This is an excellent practical CSP because the representation is visual.

23

Map Coloring Solver

Create:

PYTHON
variables = list(neighbors)

domains = {
    v: ["R", "G", "B"]
    for v in variables
}

Convert each adjacency relation into a constraint.

Be careful not to create accidental duplicate semantics.

A simpler approach is to make consistency check directly from the neighbor graph:

PYTHON
def color_consistent(
    variable,
    value,
    assignment,
    neighbors,
):
    for neighbor in neighbors[variable]:
        if assignment.get(neighbor) == value:
            return False

    return True

This can be cleaner than a generic triple-based constraint representation for this specific application.

24

Why Representation Should Match the Problem

A general constraint framework is useful for reuse.

But a problem-specific representation can be easier to debug.

This is an important engineering lesson:

generic abstraction
        vs
simple problem-specific representation

Do not automatically maximize abstraction.

Use the smallest representation that keeps the logic clear.

26

CSP Heuristic — MRV

Backtracking becomes more effective if we choose the variable with the minimum remaining values.

\[ \boxed{ \text{MRV}= \text{choose the unassigned variable with the smallest current domain} } \]

Example:

A → {R,G,B}
B → {R}
C → {G,B}

Choose:

B

because it has only one remaining value.

Why?

A small-domain variable is close to becoming impossible.

Testing it early can expose failure sooner.

27

MRV Implementation

PYTHON
def select_mrv_variable(
    variables,
    domains,
    assignment,
):
    unassigned = [
        v for v in variables
        if v not in assignment
    ]

    return min(
        unassigned,
        key=lambda v: len(domains[v]),
    )

Then replace:

PYTHON
variable = unassigned[0]

with:

PYTHON
variable = select_mrv_variable(
    variables,
    domains,
    assignment,
)

This does not change the underlying problem.

It changes which branch we try first.

28

Why MRV Is a Search Heuristic

The CSP may have the same solution set.

MRV changes:

search order

not:

constraint definition.

This is conceptually similar to heuristic-guided graph search:

same problem
+
better decision about what to explore next
29

Forward Checking

After assigning a value, remove incompatible values from neighboring unassigned variables.

Example:

A = Red

and:

B != A

then B's domain changes:

{Red, Green, Blue}
        ↓
{Green, Blue}

This is forward checking.

It detects future impossibility earlier.

30

Forward-Checking Mental Model

Assign A = Red
      ↓
propagate consequence
      ↓
remove Red from B's domain
      ↓
remove Red from C's domain
      ↓
if some domain becomes empty
      ↓
BACKTRACK immediately

The key word is:

propagation

31

Safe Domain-Copy Implementation

For a learning implementation, copying domains before recursion is simple and safe:

PYTHON
new_domains = {
    variable: values.copy()
    for variable, values in domains.items()
}

Then prune:

PYTHON
new_domains[neighbor].remove(value)

Do not silently mutate shared state and hope recursion restores it correctly.

Explicit copying is often easier to understand while learning.

32

Forward-Checking Solver Sketch

PYTHON
def forward_check(
    variable,
    value,
    assignment,
    domains,
    neighbors,
):
    new_domains = {
        v: values.copy()
        for v, values in domains.items()
    }

    new_domains[variable] = [value]

    for neighbor in neighbors[variable]:
        if neighbor in assignment:
            continue

        new_domains[neighbor] = [
            candidate
            for candidate in new_domains[neighbor]
            if candidate != value
        ]

        if not new_domains[neighbor]:
            return None

    return new_domains

This simple version is appropriate for a basic map-colouring example.

33

MRV + Forward Checking

A stronger solver can combine:

MRV
+
forward checking
+
backtracking

Flow:

select smallest domain
        ↓
try candidate
        ↓
propagate
        ↓
if any domain empty
        ↓
backtrack

This often reduces search effort dramatically on structured CSPs.

34

Important Warning About Domain Mutation

This is a classic recursive-programming bug.

Bad pattern:

PYTHON
domains[neighbor].remove(value)

followed by recursion without reliable restoration.

Why bad?

A failed branch may leave the domain permanently changed.

Then later branches see corrupted state.

Safer learning patterns:

copy domains

or:

record every mutation and restore exactly

The first is easier to reason about.

35

CSP Testing Strategy

Test three levels.

Level 1 — Constraint function

PYTHON
assert different(1, 2)
assert not different(1, 1)

Level 2 — Partial consistency

A=1, B=2

should satisfy:

\[ A\ne B. \]

Level 3 — Whole solver

Returned assignment must satisfy every constraint.

This separates:

constraint bug

from:

search bug.

39

CSP Failure Debugging Checklist

If the solver says “no solution” unexpectedly:

1. Verify every domain
2. Verify every constraint
3. Print current assignment
4. Print selected variable
5. Print candidate value
6. Print consistency result
7. Check domain mutation
8. Check backtracking undo
9. Check duplicate/reversed constraints
10. Verify the problem is actually satisfiable

Do not immediately increase recursion depth or change Python settings.

40

Common CSP Coding Mistakes

⚠️ University Lab Viva Trap & Runtime Gotcha
**In-Place Domain Mutation Bug:** Forward Checking and AC-3 prune values from neighbor domains. If you mutate domains in-place without creating a copy or tracking pruned values, when backtracking occurs the pruned values are permanently lost! Always pass deep copies of domains or maintain a prune-log to restore state during backtrack!

Mistake 1

Checking constraints that involve unassigned variables as though their values were known.

Mistake 2

Forgetting to undo an assignment during backtracking.

Mistake 3

Mutating domains without restoring/copying them.

Mistake 4

Assuming MRV changes the set of valid solutions.

It changes search order.

Mistake 5

Confusing variables and values.

variable = course
value = time slot

not the other way around.

Mistake 6

Encoding constraints incorrectly.

Mistake 7

Testing only successful CSPs.

Unsatisfiable instances are essential tests.
